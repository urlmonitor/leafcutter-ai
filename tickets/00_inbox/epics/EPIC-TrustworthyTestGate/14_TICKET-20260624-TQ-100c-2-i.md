# An AC marked done with zero covering tests is flagged by the integrity check

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `TQ-100c-2-i` — An AC marked done with zero covering tests is flagged by the integrity check — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `TQ-100c-2-i`. Component: `testing-quality`. Assigned agent: `python-coder`. Estimated complexity: `S`.

## Acceptance Criteria

```gherkin
Given an AC whose work_status is done and for which no test in the suite
  carries a "# covers:" tag naming that AC,
When the pre-pytest integrity check runs,
Then it flags the done AC as having zero covering tests (a done feature with no
  protecting test) and fails loudly with a message naming the AC
And a done feature is not allowed to silently exist with no enforcing test
And the flag is distinct from a normal test failure (it is a coverage-gap
  integrity violation, not an assertion failure).
```

## Test Requirements

- `test_done_ac_with_zero_covering_tests_flagged`: The integrity check flags (non-zero) a done AC that has zero covering tests.
