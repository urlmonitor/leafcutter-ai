# The pin is stripped from production builds and retained in dev, test and the Atlas

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-124b-3` — The pin is stripped from production builds and retained in dev, test and the Atlas — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-124b-3`. Component: `guardrail-engine`. Assigned agent: `frontend-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a screen component that renders an element carrying both
  `data-testid="stock-badge"` and `data-ac="UXP-100d-2"`
When the application is built for production
Then neither attribute appears in the emitted markup
And the same build-time transform removes both, configured in one place rather
  than two

Given the same screen component
When the application is built for development, built for test, or served in
  the Atlas
Then both `data-testid` and `data-ac` appear in the emitted markup with their
  authored values
```

## Files Touched

Files touched were derived from the AC's technical requirements and planned tests rather than declared (record GE-124b-3).

- `leafcutter-web/next.config.mjs` — the single build-time property-strip transform (one property list covering data-testid and data-ac), gated on build mode
- `leafcutter-web/__tests__/ge-124b-3.test.ts` — planned tests (new file) from Test Requirements

The planned test file was previously `leafcutter-web/__tests__/test_ge_124b_3.py`. That is a Python file inside a vitest tree. Grounded 2026-10-23: `leafcutter-web/package.json` runs `"test": "vitest run"`, and `leafcutter-web/vitest.config.ts` collects only `include: ["**/*.test.{ts,tsx}"]`. Every tracked file under `leafcutter-web/__tests__/` is `*.test.ts(x)` (e.g. `route-gating.test.ts`, `uxp-591-1/uxp-591-1.test.ts`). CI's pytest step runs only `tests/ unit_tests/` (`.github/workflows/ci.yml`), so it would not pick the file up either. A `.py` file there would never run, and the AC would read as covered by tests that cannot execute. The AC's test_spec names only `target_dir: leafcutter-web/__tests__/` and no runner, and its IT-PO note names vitest, so the TS convention applies. The production-build assertions spawn `next build` from the vitest test as a child process, which also satisfies the reachability entry.

With no Python file left, `python-coder` is set to `not_needed`. Everything this ticket edits is `next.config.mjs` plus a vitest test, so it is a single-coder (`frontend-coder`) ticket and the multi-coder Agent Contracts rule no longer applies.

## Implementation Notes

```yaml
- 'THE TRANSFORM DOES NOT EXIST YET — THIS AC CREATES IT. leafcutter-web/next.config.mjs
  is an empty config object as of 2026-08-25: there is no `compiler.reactRemoveProperties`,
  and `data-testid` is NOT currently stripped from production. The criteria''s phrase
  ''the same build-time transform that already strips data-testid'' describes the
  intended end state, not an existing configuration. Build the single transform and
  bring data-testid under it in the same change — that is what makes ''configured
  in one place'' true rather than aspirational.'
- ONE PROPERTY LIST, NOT TWO ENTRIES. The attribute names must live in a single list/pattern
  that the transform consumes, so adding a third inert marker later is one edit. Two
  independently-configured strips drift, for the same reason GE-111, GE-117 and GE-124
  share one AC-id resolver.
- THE RETENTION HALF IS THE LOAD-BEARING HALF AND MUST BE TESTED FIRST. GE-124f-3
  derives a Playwright / Testing-Library selector from data-ac. A transform that also
  strips in the TEST build breaks every such selector while leaving production correct,
  so the failure surfaces as unexplained flaky test breakage rather than as a configuration
  mistake. Assert retention in dev AND in the test build explicitly, not by inference
  from 'production strips it'.
- GATE THE TRANSFORM ON THE BUILD MODE, NOT ON AN ENVIRONMENT VARIABLE SOMEONE MUST
  REMEMBER. A strip that is opt-in per invocation will be missing from the one production
  build that matters.
- 'SCOPE HONESTLY: leafcutter-web (Next.js + SWC, vitest) is the ONLY front-end application
  that exists in this repository. The storefront-vue / storefront-svelte / storefront-jsx
  apps in the mock-data artifact are illustrative, and Next.js `reactRemoveProperties`
  is React-only. Implement and verify for leafcutter-web; record in the reference
  doc (GE-124b-5) that a Vue/Svelte/HTML app joining the repo needs its own equivalent
  transform, so the gap is visible rather than assumed covered.'
- Do not strip data-screen (GE-124f-1) without deciding it deliberately — the Atlas
  reads it, and it is a different contract from the pin.
```
