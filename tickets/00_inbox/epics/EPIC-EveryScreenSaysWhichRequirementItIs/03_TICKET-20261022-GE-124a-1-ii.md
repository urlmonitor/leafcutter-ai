## Implementation Notes

```yaml
- TWO SEPARATE COLLECTIONS IN THE RECORD, NOT ONE MERGED LIST. The shared reader must
  emit declares[] and pins[] as distinct fields that are never unioned at any point
  in the pipeline. A single merged 'ac_ids' convenience field — even one added later
  for a report — reintroduces the substitution this AC exists to block, because every
  downstream consumer would then read one list and lose which surface each id came
  from.
- The declaration scan is bounded to the leading comment region (GE-124a-2); the pin
  scan is over element attributes. A whole-file grep for '@ac' or for an id pattern
  would collapse the two surfaces at the source and make this AC untestable.
- 'The separation must hold in the persisted store fields too: declared_by is populated
  only from declares[], pinned_by only from pins[] (GE-124g-1). Verify the two paths
  at the boundary, not only in memory.'
```
