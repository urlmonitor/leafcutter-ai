## Implementation Notes

```yaml
- cmd_create_only builds its payload's branch value as f"feature/{branch_name}" --
  a restatement of the request, not an observation. cmd_setup_ticket does the same
  with f"feature/{slug}". Both must be replaced by a read of the repository. cmd_create_fastlane_worktree
  already demonstrates the discipline for base_commit (read back from the created
  workspace's HEAD, BO-2400f-13-iv); the same read-back must govern branch name and
  kind on every creation path.
- The read must be an INDEPENDENT observation of the repository, not a value the creation
  step cached on its way past. A report derived from the request and then compared
  against itself is vacuous -- the comparison and the report must not share a source.
- The read-back and its comparison apply to the reconnect/reuse path too. That path
  is where the existing branch can differ most from the request, and it is the path
  that currently reports a payload assembled entirely from arguments.
- On a mismatch both values must be carried as separate machine-readable fields (requested,
  actual) and the run must report FAILURE, not success with a warning attached.
- BP-600a-2 instructs callers to read the branch name out of this tool's reported
  output. That instruction is sound only once the output is derived from the artefact,
  and must not be cited as already covering this record.
- Template and deployed copies change together and are verified in parity via the
  build.py round-trip (ADR-001).
```
