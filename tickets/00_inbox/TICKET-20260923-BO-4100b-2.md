# A check that found nothing cannot refuse

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-4100b-2` — A check that found nothing cannot refuse — so that the acceptance criterion is satisfied.

## Context

## Acceptance Criteria

```gherkin
Given a check whose own completed comparison reports zero items drifted and
  zero items missing,
When the check issues its verdict,
Then the verdict permits the commit,
And given the check refuses a commit, its report names at least one specific
  item it found,
And the number of items named in a refusal equals the non-zero finding count
  the check reported for itself.
```

- [ ] AC-1: the verdict permits the commit
- [ ] AC-2: given the check refuses a commit, its report names at least one specific
- [ ] AC-3: the number of items named in a refusal equals the non-zero finding count

## Implementation Notes

```yaml
- 'The verdict must be a function of the reported finding set. Today it is not: check_build_drift.main()
  returns 2 on gaps, and gaps is excluded from BOTH the drifted and the missing fields
  of its own RESULT line (drifted_total = len(violations) + missing). That arithmetic
  is exactly how a run prints drifted=0 missing=0 and refuses anyway. Every condition
  that can refuse must be represented in the reported counts.'
- The invariant must hold for the INDETERMINATE exit (2) as well as the BLOCKED exit
  (1). An exit that is not a pass must either name findings or state, as its own reported
  category with a non-zero count, that it could not determine an answer. 'Refused
  with nothing named' must not be reachable by any path.
- Applies to both drift gates in the same change; their RESULT vocabularies are required
  to stay identical, so an invariant enforced in one and not the other makes the two
  runs incomparable.
- The named-item count and the reported finding count must be produced from one data
  structure, not computed twice. Two independent counts that agree today is the shape
  of the defect, not a fix for it.
- 'The verified == 0 floor is an exception that must be preserved and made explicit:
  a gate that compared nothing refuses with no findings by design. It must report
  that as its own stated category rather than as an unexplained refusal.'
- Templates and their deployed scripts/commit_guardian/ copies change together and
  are verified in parity via the build.py round-trip (ADR-001).
```
