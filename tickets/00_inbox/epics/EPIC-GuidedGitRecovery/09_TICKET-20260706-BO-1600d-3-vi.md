## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-1600d-3-vi` — In a large object store, recovery removes only the detected corrupt objects, never every empty file — so that the acceptance criterion is satisfied.

## Context

## Acceptance Criteria

```gherkin
Given a repository with a large object store that contains both the specific
  zero-byte corrupt loose objects identified by detection and other files, and
  where scanning the whole store for every empty file would be slow and unsafe
When the recovery step engine performs the remove-zero-byte-objects action
Then it removes only the specific corrupt loose objects that detection (BO-1600c)
  identified and listed, referenced by their concrete object paths
And it does NOT blindly delete every empty file it can find in the object store
And the dry-run plan names the exact objects that will be removed so the human can
  confirm the removal set is the detected set, not a blanket sweep
```
