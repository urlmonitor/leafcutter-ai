### Implementation notes (added 2026-10-15, before the build)

This AC **deletes** data, so the BLOCKING PRECONDITIONS recorded in the AC's `amended_by`
are build requirements, not background. Each must be honoured in code and pinned by a test:

1. **Pin state.** Nothing writes `pinned_until` on a Snapshot. Reclamation must treat an
   absent pin source as pin-state-unknown and decline to reclaim that generation (or read
   a real pin source) — never as not-pinned.
2. **Population.** Build on the widened evaluation now on main (KM-400f-1-i..vi), not a
   completed-only view. Fixtures must reproduce the real observed shape: failed
   publications, an active pointer to an incompletely published generation, no
   retirement time.
3. **In-progress generations.** Refuse any generation whose publication has not reached a
   terminal outcome (`building`, `validated`); include one outside both bounds in the
   fixtures and prove it survives.
4. **Assessment first.** Since KM-400f-1-vi, `evaluate_retention` can return
   `assessment.status` of `could_not_assess` or `partial`, and in the could-not-assess
   report `reclaimable` is the STRING `"undetermined"`, not a list. Reclaim only when
   `assessment.status == "assessed"` and `reclaimable` is a list; never iterate it
   otherwise. A refused evaluation reclaims nothing and says so.

Where the code lives now: retention evaluation is `knowledge/adapters/neo4j_retention.py`
(moved out of `neo4j_projection.py` in #1237, which is near the 400-line file-size cap);
publication and removal are in `neo4j_projection.py`. Reclaim by each generation's own key
(as `_remove_own_generation` does), never by status, and never touch another repository.

When that publication succeeds

Given a repository whose generations are all inside the declared bound
When a new generation is published successfully
Then the publication reports a reclaimed count of zero
And it reports that figure explicitly rather than omitting it

Given publication of G33 fails before the active pointer is switched
When the operation returns
Then no generation of either repository is reclaimed
And G32 remains the active generation
And the failure result reports a reclaimed count of zero
