## Acceptance Criteria

```gherkin
A state diagram documents the run lifecycle for the interactive pause/resume
mechanism, showing the states running, paused-awaiting-input, resumed, and
cancelled, and the transitions between them:
  - running -> paused-awaiting-input when an interactive gate is reached with
    no reachable answerer;
  - paused-awaiting-input -> resumed when a valid answer is applied by type;
  - paused-awaiting-input -> cancelled when a "cancel" answer is applied, and
    running -> cancelled for a genuine cancellation;
  - paused-awaiting-input -> unresumable when the pause becomes stale/expired.
The diagram makes clear that paused-awaiting-input and cancelled are distinct
states and that only paused-awaiting-input is eligible for resume, so a reader
can see how a run moves from running into a durable pause and back.
```
