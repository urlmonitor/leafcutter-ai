summary: "Specifies referential integrity for assigned_agent, and records ADR-035, the decision that the fast lane's producer roster becomes data but not an open one."
description: "Two artifacts, one line of work. The fast lane is intended to gain the ability to dispatch whichever producer an acceptance criterion names, instead of hardcoding a single coder. Before any of that is safe the field it would dispatch on has to mean something, and today it does not. assigned_agent is unconstrained free text in the store schema with no registry cross-check, even though the very same validator performs referential integrity for the components field one field over. The store already carries the consequences: 23 records name finalize-feature-workflow, which is a workflow script rather than an agent, 1 names create-ticket, a retired slash command, and a further 16 wrap otherwise-valid names in literal quote characters so they would not string-match their unquoted twins. Forty records in total. This is not latent: generate_ticket_from_ac.py writes the field verbatim into a generated ticket's phase map and build-feature.js dispatches on that map, so an invalid value already reaches a live dispatch target in the heavy lane. ACS-100i-9 requires that a record naming a producer that is not a registered agent is refused, and that the commit-time gate and the store-wide pass reach the same rule rather than drifting apart. ACS-100i-9-i refuses a quote-wrapped name as the distinct value it is rather than quietly unwrapping it, because silent normalisation would hide the authoring defect that produced it. ACS-100i-9-ii, which was not asked for and is the better for existing, requires that a registry the check cannot read produces a did-not-run result rather than a quiet pass. ACS-100i-10 and its child make the no-declared-producer state something the store can be asked about instead of a silence discovered one ticket at a time, and pin null to the same default as an absent key; the python-coder fallback is deliberately left in place because roughly 737 records rely on it and removing it would refuse them all. ACS-100i-11 requires the forty bad records to be corrected in the same change as the rule and before it, since the rule cannot land green while they exist. ADR-035 records the decision behind all of this. The roster becomes data rather than literals, but it does not become open: a closed allowlist of a small number of agent ids, each with a hand-written prompt, a canonical self-name used in its dispatch, and a declared proof obligation, refusing any set that names a producer outside it. The registry cannot express dispatchability today, which is the reason for the closed form: of 60 agents only 24 carry is_ticket_phase, 17 templates self-declare internal-only while their registry spawned_by says otherwise, 2 entries have no deployed template at all, and agents holding a confirmation gate cannot be workflow phases. The second decision is that a non-code deliverable proves itself by a declared-artifact diff re-read by the lane plus at least one content assertion, never by the producing agent's own report, because diff-presence alone cannot tell a real document from a placeholder. The third is sequencing: no producer joins the roster until this validation lands, the up-front refusal ships, and the two defects that stop the lane completing a single run are fixed. The ADR is honest that a closed roster means the store can declare a producer the lane refuses, and that this refusal is designed behaviour rather than a gap. It also records what the analysis could not establish, including that doc_links.relationship is not the enum the proof mechanism assumed but unconstrained free text with over twenty values in use, of which creates appears eleven times store-wide, so the declared-output-path input that decision two depends on does not yet exist in usable form."
