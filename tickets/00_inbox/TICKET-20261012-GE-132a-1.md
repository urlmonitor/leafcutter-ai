## Acceptance Criteria

```gherkin
Given the registered checks that can refuse a commit include check-complexity, which
  has a remedy declaration, and check-folder-density, which has none and is on the
  recorded list of checks excused because they had no declaration when this rule
  arrived,
When a change to the registered checks or to the remedy declarations is committed,
Then the commit is not refused on account of either check.

Given a change registers a new check, check-widget-names, that can refuse a commit,
  and adds no remedy declaration for it,
When that change is committed,
Then the commit is refused, naming check-widget-names and stating that a check needs
  a remedy declaration before it can be registered.

Given the same change also adds check-widget-names to the excused list,
When that change is committed,
Then the commit is still refused, naming check-widget-names, because the excused
  list may lose entries and never gain one.

Given the remedy declarations hold an entry for check-docstrings, and no registered
  check has that name,
When a change to the registered checks or to the remedy declarations is committed,
Then the commit is refused, naming check-docstrings as a declaration for a check that
  is not registered.
```
