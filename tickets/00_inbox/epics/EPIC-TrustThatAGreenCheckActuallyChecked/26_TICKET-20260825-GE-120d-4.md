# A working copy created by set-up passes the parity sweep with no manual repair

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-120d-4` — A working copy created by set-up passes the parity sweep with no manual repair — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-120d-4`. Component: `guardrail-engine`. Assigned agent: `test-writer`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a working copy created by running the real set-up command, with no manual step applied
  to it afterwards,
When the parity sweep of GE-120b-4 is run against that copy,
Then every check reaches the same verdict there as in the main checkout,
And no check reports a could-not-check outcome,
And the sweep is run against the copy exactly as set-up left it — applying any manual repair
  first invalidates the result and the run is reported as invalid rather than as a pass,
And the sweep is driven by the same set-up command a person would run, not by a test fixture
  that reproduces what set-up is believed to do.

Coverage note: this is the end-to-end criterion for the whole tree, and its value depends
entirely on the last clause. A fixture that stands up a working copy the way the author
believes set-up does will pass while the real command still fails — that substitution is how
this defect class survived, one layer down (CLAUDE.md, "Real-artifact behavioral spot-check
before declaring done").
```

- [ ] AC-1: every check reaches the same verdict there as in the main checkout
- [ ] AC-2: no check reports a could-not-check outcome
- [ ] AC-3: the sweep is run against the copy exactly as set-up left it — applying any manual repair
- [ ] AC-4: the sweep is driven by the same set-up command a person would run, not by a test fixture

## Implementation Notes

```yaml
- 'DRIVE THE REAL SET-UP COMMAND a person would run — the deployed .leafcutter/scripts/setup_ticket_worktree.py
  entry point, invoked the way worktree-agent and the /feature path invoke it — never
  a fixture that reproduces what set-up is believed to do. That substitution is how
  this defect class survived one layer down: the phantom-done hook passed its unit
  tests against hand-authored fixtures while being a no-op on every real ticket.'
- 'NO MANUAL REPAIR between set-up and sweep: no symlink, no copy, no build, no SKIP
  variable. THE INVALIDATION MUST BE MECHANICAL — fingerprint the copy immediately
  after set-up returns and re-check the fingerprint before the sweep, rather than
  trusting the operator not to touch it. The sequence that defeats this AC is: run
  set-up, notice something missing, fix it by reflex, run the sweep, see green. Every
  step of that is reasonable and the result is meaningless, so INVALID must be a reported
  state distinct from both PASS and FAIL.'
- 'REUSE GE-120b-4''s SWEEP UNCHANGED. Do not fork a set-up-specific variant: the
  end-to-end claim must cover the same sweep the tree hardened, or it asserts something
  about a different instrument.'
- 'BOTH CLOSING CONDITIONS MUST HOLD: every check agrees with the main checkout AND
  no check reports could-not-check. Agreement alone is insufficient — a copy in which
  every check honestly reports could-not-check would satisfy it while being exactly
  the unprotected artifact this L1 exists to prevent.'
- 'SEQUENCE: this AC lands BEFORE GE-120b-5 deletes the documented manual workaround.
  GE-120b-5 removes the instruction; this AC demonstrates the instruction is no longer
  needed. Deleting first makes the documentation change a claim rather than a record.'
- 'ENVIRONMENT: the set-up path creates a git worktree that shares the repository
  object store. Run this in isolation from any concurrent drive, and clean up with
  ''git worktree remove'' even on failure — a leaked worktree from a failed run silently
  changes the next run''s environment.'
- The sweep must exercise the DEPLOYED checks in the created copy (ADR-001) — that
  is what a commit in that copy would run. Pointing it at the source tree would measure
  the layout that never fails.
```
