# Enforcement mode is one of three values selected by explicit configuration

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `TQ-100e-1` — Enforcement mode is one of three values selected by explicit configuration — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `TQ-100e-1`. Component: `testing-quality`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given an explicit configuration value that selects the enforcement mode,
When the suite is run,
Then the active enforcement mode is exactly one of: report-only,
  exclude-unbuilt, or blocking
And the active mode is determined solely by that explicit configuration value
  (not by the current date and not by an implicit hardcoded default chosen at
  runtime)
And an unrecognized configuration value is rejected with a message naming the
  three valid modes rather than silently falling back to blocking.
```

## Test Requirements

- `test_enforcement_mode_from_explicit_config`: The active enforcement mode is exactly one of report-only/exclude-unbuilt/blocking, taken solely from the testing_quality.enforcement_mode config key.
- `test_env_override_takes_precedence`: LEAFCUTTER_TEST_ENFORCEMENT_MODE overrides the config-file value and is validated identically.
- `test_unrecognized_mode_rejected`: An unrecognized mode value (config or env) is rejected with a message naming the three valid modes, never silently falling back.
