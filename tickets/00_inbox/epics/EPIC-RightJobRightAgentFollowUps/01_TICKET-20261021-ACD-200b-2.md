## Implementation Notes

```yaml

  value list in config/ac_store_schema.json. The schema check and the record check
  both read it; the hard-coded name list in the record check is deleted, not kept
  in sync.'
- The rule check's trigger-to-specialist map stays in code in the documentation-trigger
  family (user decision D2). It is keyed by trigger name; no third copy of the names
  is added anywhere.
- The parity test runs in the normal test suite and fails naming the trigger and the
  side (list or map) it is missing from.
- The commit hook (templates/scripts/commit_guardian/check_ac_schema.py) and the agent-side
  validator give the same verdict on the same record. The hook's validate_manually
  fallback in templates/scripts/commit_guardian/_ac_schema_validators.py has no documentation_triggers
  check today, so without jsonschema the hook accepts an unknown trigger; the fallback
  must also check documentation_triggers against the one list, and check_ac_schema.py
  is the entry point the reachability test drives.
- Every documentation_triggers value accepted today is still accepted; no record in
  the store changes verdict.
```
