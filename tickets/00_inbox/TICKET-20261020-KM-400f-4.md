# Retained generations and remaining capacity are visible to an operator

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `KM-400f-4` — Retained generations and remaining capacity are visible to an operator — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `KM-400f-4`. Component: `knowledge-management`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

### Implementation notes (added 2026-10-20, before the build)

- **Do not recompute the policy.** Reclaimability comes from `evaluate_retention`
  (`knowledge/adapters/neo4j_retention.py`, KM-400f-1-i..vi) and sweep reclamation from
  `reclaim_superseded` (`knowledge/adapters/retention/reclaim.py`, KM-400f-2), which already
  re-reads records, keeps the active generation, unfinished publications and pinned / possibly-live
  continuations, and reports reclaimed / retained with a reason each. Capacity figures come from
  `knowledge/adapters/retention/capacity.py` (KM-400f-3): reuse its counts, `CapacityCeiling`,
  `resolve_capacity` and per-axis report shape.
- **`status` (extend, don't add a parallel surface — KM-400e-5).** In `knowledge/cli_sync.py`,
  `status` gains the optional `--retention-max-generations/--retention-min-age-seconds` and the four
  `--capacity-*` flags (same all-or-none refusals, before network access). It adds:
  `retention_bound` (or a statement that none was declared), `generations` = every verdict from
  `evaluate_retention` with identifier, source revision (`source_sha`), retirement time
  (`retired_at`, or the stated age basis when never retired), `reclaimable` and the reason;
  `retained_count` and `exceeding_bound_count`; and `capacity` with usage for this repository and
  for the whole backend against the ceiling (`unknown` when none is declared — shown, never omitted).
  Without a retention bound, still list every generation but state reclaimability as
  `undetermined (no retention bound declared)`, never as reclaimable or not. `status` writes nothing.
- **Repository usage.** Whole-backend counts are the KM-400f-3 queries. Repository counts: the
  nodes and relationships whose `generation_key` is one of this repository's generation keys
  (`scope_key(repository_id, generation_id)` for each of its Snapshot records), plus the Snapshot
  records themselves.
- **Sweep reclamation.** A new `reclaim` command (no `--generation-id`): requires the retention
  bound (refuse undeclared before network access), runs `prepare_writable`-style read-only preflight
  semantics where applicable, then `reclaim_superseded` once and returns its summary. Zero reclaimable
  → status ok, `reclaimed: 0` and a reason per retained generation. The existing `cleanup
  --generation-id` stays as it is.
- **Docs.** `docs/how-to/run-knowledge-retrieval.md` must gain a capacity-and-retention section
  demonstrating `status` listing, reading headroom and `reclaim`, and stating the configurable bound
  and thresholds. That how-to is ABOVE the 300-line doc-length cap and the gate refuses any growth:
  make room by condensing existing content (e.g. Step 12's history paragraph now duplicated in the
  reference docs) so the file does not grow. Reference details go in
  `docs/reference/knowledge-publication-capacity.md` / `knowledge-retention-bound.md`.
- **Layout limits.** `knowledge/adapters/` is at the folder-density cap; put new helpers in
  `knowledge/adapters/retention/` or a new `knowledge/cli_*.py` module. `cli_sync.py` must stay under
  400 measured lines — put `status`/`reclaim` assembly in a new `knowledge/cli_generations.py` if
  needed. New live tests go under `tests/knowledge_live/publication/`. Test doubles:
  `tests/knowledge/_km_400f_2_support.py` (`ReclaimDouble`) and
  `tests/knowledge/test_km_400f_3.py` (`CapacityDouble`) already answer the needed queries.
- **Reachability test** entry point: `python -m knowledge status` and `python -m knowledge reclaim`.

## Acceptance Criteria

```gherkin
Given the repository holds active generation G32 and retained generations G31 down to G28
And an unexpired pinned continuation is held against G28
And the declared retention bound is at most 3 retained generations and a minimum retirement age of 24 hours
And the backend reports a capacity ceiling of 200,000 nodes and 400,000 relationships
When an operator requests status
Then every retained generation is listed, not only the active one
And each listed generation states its identifier, its source revision, its retirement time and whether it is reclaimable under the current declared bound
And G28 is listed as not reclaimable, giving its unexpired pinned continuation as the reason
And the status states the declared retention bound that reclaimability was evaluated against
And the status reports measured node and relationship usage for this repository and for the whole backend against the reported ceiling
And a ceiling the backend does not report is shown as unknown rather than omitted

Given 32 generations are retained and the declared bound is at most 3
When an operator requests status
Then all 32 are listed with their reclaimability
And the count of retained generations and the count exceeding the declared bound are both reported

Given generations are reclaimable under the declared bound
When an operator requests reclamation without naming a generation identifier
Then every generation reclaimable under that bound is reclaimed in one operation
And the result names the identifiers reclaimed and the identifiers retained, each with the reason it was retained
And the active generation and every generation with an unexpired pinned continuation are among those retained

Given no generation is reclaimable under the declared bound
When an operator requests reclamation without naming a generation identifier
Then the operation succeeds, reclaims nothing, and reports a reclaimed count of zero with the reason each generation was retained

Given an operator follows the operational instructions for this backend
When they reach the capacity and retention section
Then the instructions demonstrate listing retained generations, reading remaining headroom and reclaiming without naming a generation
And they state the declared retention bound and the headroom thresholds the operator can configure
```
