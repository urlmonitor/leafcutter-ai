# Allowlist entries suppress findings only when the allowlist path segments are a suffix of the finding path segments

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-113c-3` — Allowlist entries suppress findings only when the allowlist path segments are a suffix of the finding path segments — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-113c-3`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `S`. Complexity: `low`.

## Acceptance Criteria

```gherkin
Given the secrets scanner processes a finding at a file path,
And an allowlist entry specifies a path for that finding's rule,
When the scanner evaluates whether the allowlist entry suppresses the finding,
Then the finding is suppressed only when one of the following holds:
  - the allowlist path is the literal wildcard "*",
  - the allowlist path segments match the finding path segments exactly, or
  - the allowlist path segments are a segment-by-segment suffix of the finding
    path segments (e.g. allowlist "config/secrets.py" suppresses a finding at
    "src/config/secrets.py" but NOT at "other/secrets.py"),
And basename equality alone is never sufficient to suppress a finding when
  the allowlist entry contains a path separator.
```

## Implementation Notes

```yaml
- Fix targets `_is_suppressed` in canonical template `templates/skills/security-scanner/scripts/scan_secrets.py`
  around line 114 — the buggy comparison `fp_parts != tuple(fp_parts[-len(al_parts):]
  ...)` compares the finding path against a suffix of itself; replace with a correct
  segment-by-segment suffix check `al_parts == fp_parts[-len(al_parts):]` when `len(fp_parts)
  >= len(al_parts)`, else no suffix match.
- Path-qualified allowlist entries (containing a path separator) MUST require true
  segment-suffix match; basename equality alone is insufficient.
- Bare-filename allowlist entries (no path separator) suppress findings at any depth
  by basename equality — this is the intended contract per the current docstring,
  preserved unchanged.
- Wildcard `*` entries (both rule_id and file_path forms) behave as before.
- 'Deployed/template parity (ADR-001): edit the canonical `templates/` copy only;
  `build.py` propagates to the 16 materialized copies. Do NOT hand-edit the copies
  under `.claude/`, `.gemini/`, `.leafcutter/`, `EPIC-LiveSurfaceTesting/`, or `worktrees/**`.'
- 'Preserve the `_is_suppressed` docstring but tighten it to reflect the corrected
  semantics: name the three suppression modes (wildcard, exact-path, path-suffix)
  and note that bare-filename entries suppress by basename.'
- 'Two security exploit paths must be closed and covered by direct tests: **Path A**
  — basename collision across directories (`RULE:src/foo.py:*` must not suppress `deploy/foo.py`);

  must not suppress root-level `foo.py`).'
```
