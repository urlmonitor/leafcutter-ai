## Acceptance Criteria

```gherkin
Given a requirement can declare the files its work changes, each marked existing or to be
  created,
When an author consults the reference documentation for the requirement record,
Then the documentation describes the declared-files list, the form of a declared path
  (relative to the repository root, forward slashes, never a regenerated copy) and the two
  markers,
And it states that this list is the only answer to which files a piece of work changes, and
  that documentation links -- whatever relationship they carry -- are not part of that answer,
And it states which declared entries refuse a requirement (neither present nor marked to be
  created; outside the repository; a regenerated copy; an empty list) and which are only
  reported (marked to be created but already present, on unfinished work),
And it states that a requirement without a list is in the state "no declared files", that
  checks report it as not evaluated rather than passed, and that nothing fills the list in
  automatically,
And an author who has read only this documentation can declare the files for a requirement
  that edits one existing file and creates one new file, and predict which of the two the
  requirement rule check would report if the new file already existed.
```
