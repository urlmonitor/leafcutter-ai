## Implementation Notes

```yaml
- 'RESOLUTION GOES THROUGH THE ONE SHARED ENTRY POINT IN scripts/ac_store/ac_coverage_resolver.py,
  never through a private store read in this hook. IMPLEMENTATION FACT the implementer
  must not rediscover: that module has NO public id-resolution function today — its
  API is ticket-shaped (resolve_coverage, verify_ticket_coverage, compute_verdict)
  and its only record load is the private path-based _load_ac_record. A public id-to-record
  entry point must be ADDED, backed by the existing scripts/commit_guardian/_ac_store_index.get_ac_index
  rather than by a third store walker. ac_coverage_resolver.py is already in build_ac_store''s
  deploy_map, so no new manifest entry is needed for it — but _ac_store_index must
  be reachable from wherever the new entry point lives.'
- BOTH SURFACES ARE RESOLVED. Every id in declares[] and every id in every pin's ac_ids[]
  goes through resolution. A check that resolves only the component-level ids lets
  a typo in a pin ship silently, and the pin is the surface GE-124f-3 derives a test
  selector from, so the typo would resurface later as a selector that matches nothing.
- MISSING AND UNRESOLVED ARE DIFFERENT CODES WITH DIFFERENT REMEDIES AND MUST NEVER
  BE FOLDED. 'You did not say' is fixed by adding a declaration; 'what you said is
  not true' is fixed by correcting the id or authoring the criterion. A reviewer told
  the wrong one wastes the whole remediation. This is the same distinction GE-117
  draws, and the mock-data artifact states it as an invariant.
- THE FINDING NAMES THE IDS THAT DID RESOLVE ALONGSIDE THE ONE THAT DID NOT, so the
  author can see the declaration was read rather than assuming the parser failed.
  For a pin, it additionally names the element's line number (available on the pin
  record, GE-124b-1).
- A nearest-id suggestion (as in the mock record gf-commit-coverage-explorer-unresolved)
  is desirable but must be computed from the shared resolver's index, never from a
  second scan, and must degrade silently to no suggestion rather than failing the
  check.
- Resolution must complete within the pre-commit latency budget over the current store
  (roughly 3,000 records) — rely on _ac_store_index's existing fingerprinted cache
  rather than re-walking the store per id.
- Must handle errors gracefully per the project error handling policy; an unreachable
  store is GE-124c-2-ii's contract, not a resolution failure per id.
```
