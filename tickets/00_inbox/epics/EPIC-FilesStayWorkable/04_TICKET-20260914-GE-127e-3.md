## Acceptance Criteria

```gherkin
Given a tracked file of a kind the size standard covers is refused for its
  length, and the refusal names a further action — something to run, something
  to read, a helper to use, or a specialist to bring in,
When the reader carries out that action exactly as the refusal states it, from
  the place the refusal says to carry it out,
Then the action can be carried out as stated, and it produces the thing the
  refusal says it produces,
And given the refusal states that any work was already done on the author's
  behalf before they read it,
When that claim is checked against what the run producing the refusal actually
  did,
Then that work is observable as having occurred during that run,
And the refusal contains no statement that anything will be done on the
  author's behalf after the refusal is issued,
And given instead a refusal that names no further action at all and claims no
  work of any kind,
When the author reads it,
Then this criterion is satisfied — a refusal that offers nothing is acceptable
  and a refusal that offers something that does not arrive is not, because the
  second converts a known gap into a false belief while the first leaves the
  gap visible.
```

```yaml
- 'NO PACKAGE SURFACE — MEASURED, NOT ASSUMED. WATCHED_REGISTRIES binds hooks_manifest.hooks
  (by id) and the document''s own top level (by mapping key) on commit_guardian.json.
  This record adds neither: its whole effect is to audit, and where necessary DELETE,
  sentences in a printed message. Deleting text registers nothing. `check-file-size`
  is already a manifest id and `file_size` already a top-level key, both read in this
  worktree. Plain -list spec form; no config_schema_fragment invented to satisfy the
  structured-spec validator.'
- 'THE FIRST APPLICATION IS AN INVENTORY OF EVERY SENTENCE THE GUARD PRINTS, AND IT
  MUST BE PERFORMED RATHER THAN ASSUMED. The audited population is every sentence
  in the refusal, including all of the ones inherited from the incumbent message:
  the refactor-and-split instruction, the do-not-strip-content warning, the `@documentation-expert`
  branch, the `/code-refactoring-specialist` branch, the generic fallback branch,
  and the parenthetical about enforcing the check over time. Each is either evidenced
  by carrying it out or deleted. There is no third disposition — softening a sentence
  to "consider" leaves the reader exactly where a dead dispatch leaves them, which
  is the failure GE-122c-1 records.'
- 'THREE MEASURED FACTS ABOUT THE INCUMBENT SENTENCES, RECORDED SO THE AUDIT STARTS
  FROM EVIDENCE RATHER THAN FROM SCRATCH — AND NONE OF THEM IS THE VERDICT, WHICH
  ONLY RUNNING THE ACTION CAN GIVE. (a) `/code-refactoring-specialist` resolves to
  templates/workflows/code-refactoring-specialist.md and IS deployed as a slash command
  in the workspace install, so the pointer is not simply dead. (b) That workflow''s
  own step 1 instructs running `python .agent/skills/code-analysis/scripts/analyze_structure.py`,
  and no file of that name exists anywhere in the workspace — a promise one level
  below the refusal, which this criterion''s evidence bar reaches. (c) The `@documentation-expert`
  branch fires only for a path ending `.md`, and `.md` is not in checked_extensions,
  so that branch is unreachable at every commit: an unreachable sentence cannot be
  evidenced by carrying it out and is therefore deleted, not defended.'
- A COMMIT-TIME HOOK CAN BLOCK AND PRINT; IT CANNOT BRING IN AN AGENT. That is settled
  in this component by GE-122c-1 and it is the ceiling on what any sentence here may
  claim. No sentence may state or imply that a specialist has been engaged, that a
  review has been run, that anything has been queued, or that a report will follow.
  The pre-commit process exits and nothing survives it. Any capability that genuinely
  requires a live session belongs to a live-session surface and must be named as something
  the READER does, never as something that has been done or will be done for them.
- '"ALREADY DONE" IS A CLAIM ABOUT THE RUN THAT PRINTED THE SENTENCE, AND MUST BE
  OBSERVABLE IN THAT RUN. If the refusal says work was performed on the author''s
  behalf — a file parsed, an analysis computed, a candidate division derived — that
  work must be evidenced from the same invocation, not from a prior run, not from
  a cache and not from a capability that exists somewhere in the package. The description
  GE-127e-1 produces is the one such claim this tree creates, and it is honest precisely
  because it is computed in that run and printed in that message.'
- 'DELETION IS THE COMPLIANT MOVE AND MUST NOT BE TRADED FOR SUBSTITUTION. This record
  is a ceiling, not a floor: a refusal that offers nothing passes it. The pressure
  an implementer will feel — to replace a deleted sentence with a vaguer one so the
  message does not look empty — is exactly how the incumbent message came to exist.
  The floor is GE-127e-1''s, and is met by describing the file, never by adding a
  sentence in order to have one.'
- THE AUDIT HAS NO STANDING ENFORCEMENT MECHANISM AND MUST NOT ACQUIRE A FAKE ONE.
  Do not add an approved-sentence allowlist, a message-template registry, or a lint
  rule that checks the refusal text against a fixture — every one of those passes
  on a guard that delivers nothing, which is the family of assertions GE-122c-1's
  coverage note rules out. The durable enforcement is the descriptors below, which
  carry out whatever the message names.
- 'Must follow the repo error-handling policy for any action-verification code that
  reaches the filesystem or a subprocess: specific-exception try/except, log at WARNING
  or higher or re-raise, no bare or blind excepts. Note that verification belongs
  in the TEST, not in the gate — the gate must not attempt to check its own message
  at commit time, which would put I/O of unknown cost on every refusal.'
- CANONICAL VERSUS BUILD OUTPUT, AND THE BUILD IS PART OF THE CHANGE. The message
  the author actually reads is printed by the DEPLOYED copy under .leafcutter/scripts/commit_guardian/.
  A sentence deleted only from templates/scripts/commit_guardian/check_file_size.py
  leaves the unkeepable promise on screen at every real commit while the source-tree
  tests report it gone. Re-run `python scripts/build.py --target-dir .` as part of
  the change, and let the deployed descriptor below be the thing that proves it.
```
