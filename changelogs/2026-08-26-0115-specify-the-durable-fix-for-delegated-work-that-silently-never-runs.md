description: "PR #565 stopped a dead or parked agent being COUNTED as work done. It did not stop an agent parking. These trees specify the rest, authored through the product-owner, business-analyst and IT-PO pipeline. BO-3100 covers the structural axis, that a delegated step cannot silently vanish: declared and build-time-validated spawn authority, a fail-closed exit-time judgement whose verdict is read from the repository rather than from the agent reply, relocating fan-out to the layer that can genuinely await, and correcting written guidance that still asserts a depth limit which does not exist. BO-3200 covers what may be delegated at all: facts read at the source rather than relayed, required cleanup that actually happens, approval asked of a person rather than assumed, large results that arrive whole, and checks that say they could not tell instead of guessing. The governing constraint throughout is mechanical enforcement only. The prompt-level fix already exists and rotted: building-epics SKILL.md section 2.1-R1 was written after the 2026-07-06 retrospective of this exact failure, was in force on 2026-08-18, and the failure recurred twice in one drive; it could not even reach the second stall because the skill is loaded by ticket-supervisor alone and the agent that stalled never loads it. So the Gherkin is built from devices a prose implementation structurally cannot pass: hold the agent reply constant and vary only observable state so a text-reading implementation returns the same verdict twice and fails; remove a capability from the environment and require the behaviour anyway; absence sweeps that restore one old path so a partial fix fails; convention-proof scenarios where name and position match an exempted case but confer nothing. Three limits are recorded honestly rather than papered over. Whether a superseding decision record REASONS well is not mechanically checkable, so BO-3100d-2 states that its acceptance rests partly on human review and carries an instruction not to later close the gap with a prose grep that would read as coverage while proving nothing; BO-3100d-4 adds the half that CAN be guaranteed, a coherence re-read that hands a planning agent every criterion in an area, complete, with an explicit could-not-present-whole outcome, and deliberately no consistency verdict. Three sweeps require exercising every entry point, path or check over real work and may exceed a CI budget: splitting the population is permitted, narrowing the derived set is not, so the honest failure mode is slow rather than quietly smaller. And the IT-PO surfaced a defect in the specification itself, that a whole-project state snapshot lets a parked step inherit a concurrent sibling changes and so defeats the entire guard, with the volatile-exclusion set load-bearing rather than housekeeping because every agent appends to the telemetry log. ADR-036 records a distinction the user drew: documentation-expert remains a supported human entry point, a router so a person need not remember the five leaf authors, while an AC assigned_agent must name the leaf author directly, because in that position it is dispatched as a subagent and must spawn a grandchild it cannot await. All 14 documentation ACs in these trees name leaf authors. The registry still declares documentation-expert as a phase agent with a spawn allowlist, which contradicts the ADR and is recorded as a negative consequence pointing at BO-3100a."
