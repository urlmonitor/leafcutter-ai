## Acceptance Criteria

```gherkin
Given a change is staged that touches a tracked file of a kind the size standard
  covers which already stands above its permitted length,
And the lines that change put into that file cannot be established because the
  account of the change is unreachable,
When the author performs an ordinary commit,
Then the commit does not complete, and the outcome states that the change's
  additions could not be established for that file and that the account of them
  was unreachable,
And given instead the account of the change is reached but cannot be
  interpreted,
When the author performs an ordinary commit,
Then the commit does not complete, and the outcome states that the change's
  additions could not be established for that file and names that as the second
  and different situation,
And given instead a change that genuinely put no measured lines into that
  already-oversized file,
When the author performs an ordinary commit,
Then the commit completes, and the outcome names that situation apart from both
  of the refusing ones — a change that added nothing and a change whose
  additions could not be established are never reported as the same thing.
```

```yaml
- 'REUSE BP-1600a-2-ii''s VERDICT VOCABULARY AND EXIT-STATUS CONTRACT UNCHANGED —
  THE SAME ONE GE-127a-1-i AND GE-127b-1-i PIN. "INDETERMINATE: reason=<text>" naming
  which situation occurred, with exit 2; exit 0 for a clean run; exit 1 for a reported
  finding, which keeps GE-127f-1''s refused-for-length case distinguishable from an
  unestablished one. Both refusing conditions here — the account of the change unreachable,
  and the account reached but uninterpretable — report through that same line with
  DIFFERENT reason text. Do not mint a third verdict set and do not widen the exit-status
  set.'
- THREE STATES, THREE BRANCHES, NEVER ONE FALSY CHECK. The account of the change unreachable;
  the account reached and uninterpretable; a genuine measured count of zero. Collapsing
  the first two into one message loses the only information that tells an operator
  whether the repository or the parser is at fault. Collapsing either into the third
  IS the fail-open this record exists to make impossible. Concretely, this means the
  added-line step must be able to signal its own unavailability to its caller as something
  other than the value 0 — a raised typed error or an explicit unavailability value
  — and the caller must branch on that signal rather than on falsiness. `if not added:`
  is the defect, written.
- THE GENUINE-ZERO ARM STAYS PERMISSIVE AND MUST BE NAMED DISTINCTLY — REFUSING IT
  TO BE SAFE BREAKS TWO DELIVERED THINGS AT ONCE. A change that genuinely added nothing
  is the load-bearing free case of the whole L1 (the urgent correction in a very large
  file) and is the surviving shape of GE-127b-1's delivered boundary descriptor. Refusing
  it would break GE-127f-2's last arm and GE-127b's allow-arm simultaneously. The
  requirement is that it be NAMED distinctly on the exit-0 path, in wording of its
  own, and it must NOT borrow the INDETERMINATE token, which the pinned contract binds
  to exit 2. An INDETERMINATE line that exits 0 makes the token stop predicting the
  commit outcome, which is the single thing reusing that contract buys.
- ONE OUTCOME, EXTENDED IN PLACE, NEVER A SECOND SURFACE. Whatever this run states
  about the availability of the added-line count belongs in the single outcome the
  author already reads from this gate. A second summary printed elsewhere lets one
  line report an established run while the other reports an unestablished one, with
  no way to tell which is authoritative. This is BP-1600a-2-ii's one-summary rule
  applied here.
- 'WHY A GREP-SHAPED OR UNIT-LEVEL TEST CANNOT DISCHARGE THIS RECORD, STATED AS A
  CONSTRAINT. The failure this record forbids is invisible from inside the process:
  with the count degraded to zero, GE-127f-1''s required length collapses to the previous
  length for every file, the whole of GE-127f silently becomes GE-127b again, and
  every permitting arm of GE-127f-1 and GE-127f-2 still passes. Every descriptor must
  therefore drive the real gate as a subprocess against a real repository, construct
  the unavailability by breaking the real input (not by monkeypatching a function
  inside the test process), and read the verdict and the exit status out of the real
  output.'
- 'THE TRAP THAT BIT THIS REPOSITORY TODAY — IF THIS CHANGE ADDS ANY NEW MODULE IMPORTED
  BY check_file_size.py, BOTH HAND-ENUMERATED FIXTURE LISTS MUST BE UPDATED IN THE
  SAME CHANGE. unit_tests/commit_guardian/_ge_127a_1_ordinary_commit_fixture.py (PRODUCTION_MODULES)
  and unit_tests/commit_guardian/_ge_127c_1_scope_fixture.py each copy a hand-maintained

  checks either against the real import graph. When GE-127e-1 added the _file_description
  import, both lists were silently incomplete and six descriptors went red, surfacing

  subject is an unreachable input: a missing fixture entry would look exactly like

- HOOK-RUNNING COMMITS GET THE BUILD-CLASS TIMEOUT, NOT THE SHORT ONE. Any descriptor
  that performs a real `git commit` through a `.pre-commit-config.yaml` must use the
```
