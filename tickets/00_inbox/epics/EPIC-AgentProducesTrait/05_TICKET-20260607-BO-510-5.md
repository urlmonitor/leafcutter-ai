# Ticket-supervisor reads the produces trait to determine which guardrails apply

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-510-5` — Ticket-supervisor reads the produces trait to determine which guardrails apply — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-510-5`. Component: `build-orchestration`. Assigned agent: `llm-expert`. Estimated complexity: `L`.

## Acceptance Criteria

```gherkin
Given a ticket is assigned to a work agent with produces: production_code
  (e.g. python-coder),
When ticket-supervisor loads the agent's registry entry at dispatch time,
Then it reads the "produces" field value
And it uses that value to determine that TDD guardrails apply
  (test-writer before, test-runner after)

Given a ticket is assigned to a work agent with produces: documentation
  (e.g. documentation-expert),
When ticket-supervisor loads the agent's registry entry,
Then it reads produces: documentation
And it determines that TDD guardrails do NOT apply
And it does not inject test-writer or test-runner around the documentation agent

Given a ticket is assigned to a work agent with produces: prompt
  (e.g. llm-expert),
When ticket-supervisor loads the agent's registry entry,
Then it reads produces: prompt
And it determines that TDD guardrails do NOT apply by default
And it applies prompt-quality guardrails instead (if defined for that trait)
```
