## Acceptance Criteria

```gherkin
Given the section of the reference document that describes the forms a
  suppression may take and the ways an entry is matched against a file,
When a reader wants to know whether an entry they have written will always take
  effect,
Then the reference states that an entry which would leave a file with no rule
  still able to report anything about it is DECLINED for that file, that the
  file's results are reported as though the entry were not there, and that no
  other file in the run and no other entry in the same allowlist is affected,
Because the section as written presents matching as the only question — an entry
  either matches a file or it does not — and a reader who has only that section
  will believe every well-formed entry they write is honoured.

Given the same section,
When a reader wants to know what the decision is judged against,
Then the reference states that it is judged against every suppression in force
  for that file taken together rather than one entry at a time, so that the same
  outcome is reached whether the author writes one broad entry or several narrow
  ones that add up to the same thing,
And it states that the quantity counted is the rules still able to report on the
  file and not the results the file happens to produce, so that quieting the only
  result a file currently produces is an ordinary narrowing,
And it states that an entry pinned to a single line number never removes a rule's
  ability to report on the file, and that narrowing a file down to one remaining
  rule is still narrowing,
Because each of these is a boundary a reader will otherwise cross by accident,
  and the longhand form — one narrow entry per rule — is the form the existing
  task guidance actively encourages.

Given the same section,
When a reader wants to know what they will see when an entry of theirs is
  declined,
Then the reference states that a notice is written to the error stream naming the
  allowlist file, the 1-based line number, the declined line verbatim and the file
  it would have left with nothing able to report on it,
And it states that the notice does not stop the commit and does not by itself
  change whether the run reports a problem — what the run reports is decided by
  the results alone,
Because an author who sees results they expected to have quieted needs to be able
  to find out why from the document, and an author who fears a too-broad line will
  take the repository down needs to read that it will not.

Given the same section,
When the reader compares it against the check as it behaves,
Then every case the reference presents as declined is one the check declines, and
  every case it presents as honoured is one the check honours,
And where the two disagree the implementation is authoritative and the
  disagreement is raised as a defect rather than written down as fact,
Because a reference that describes a refusal the check does not make invites
  authors to write entries no one is protecting them from, and one that omits a
  refusal the check does make leaves them reading their own results as a bug.
```
