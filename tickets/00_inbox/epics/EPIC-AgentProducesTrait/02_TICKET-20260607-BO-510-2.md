# Agent template frontmatter carries the produces trait matching the registry

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-510-2` — Agent template frontmatter carries the produces trait matching the registry — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-510-2`. Component: `build-orchestration`. Assigned agent: `llm-expert`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given an agent template file exists at templates/agents/<agent-id>.md,
When the template's YAML frontmatter is parsed,
Then it contains a "produces" field
And the value matches exactly the produces value in the corresponding
  agent_registry.json entry for that agent ID
And the frontmatter field is positioned after the "domain" field
  and before "config_keys" for consistency across all templates

Given an agent has template_path: null in the registry
  (e.g. architect-review-deep, conflict-resolver-deep),
When the validation scans for template frontmatter,
Then it skips agents with no template file
And it does not report a missing-trait error for template-less agents
```
