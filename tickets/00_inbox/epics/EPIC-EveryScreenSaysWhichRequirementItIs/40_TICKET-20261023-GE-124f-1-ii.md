## Implementation Notes

```yaml
- 'OUTSIDE-THE-CHAIN IS A RECORDED STATE, NOT SILENCE. Emit an explicit state on the
  page''s chain record — outside-the-chain — distinct from resolves-to-nothing (GE-124f-1)
  and from linked. The two look identical in a report that only counts findings and
  they mean opposite things: outside-the-chain is fine, resolves-to-nothing is a defect.
  GE-124g-3 needs them apart or a chain-completeness figure would count pages with
  no design as failures, which is a number mixing two things.'
- data-screen IS OPTIONAL AND MUST STAY OPTIONAL. There must be no code path and no
  configuration key that requires a page root to carry a design name. Nothing in GE-124f
  makes the pin or the design name compulsory — a page with no design modelled in
  the product-truth store is simply not part of the chain.
- DO NOT INFER A DESIGN NAME from the route path, the file name or the component name
  in order to 'complete' the chain. An inferred link is an unverified claim presented
  as a resolved one, which is the manufactured traceability GE-124g exists to prevent.
- The state must be reachable by GE-124g-3's reporting without re-deriving it, since
  that AC counts declarations on their own axis and must not fold chain-completeness
  into a coverage figure.
```
