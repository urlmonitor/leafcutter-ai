description: "BO-2400f-13 and its four children, against KI-BO-015. cmd_create_fastlane_worktree creates the branch fast-lane/<slug> but asks _worktree_exists(slug), and that lookup matches only the feature/, ticket/ and ac-authoring/ prefixes. fast-lane/ is absent, so the reuse branch is unreachable code: every run falls through to git worktree add, which exits 128 the moment anything occupies worktrees/<slug>. The lane surfaces {\"worktree_path\": \"\"} and halts at phase one having done nothing, which means the lane could not be re-run on any AC it had already built. Three fast-lane worktrees were live when this was specified, so three ACs were already in that state. The function's own docstring promised re-runs are idempotent and no acceptance criterion asserted it. The chosen ending is a named refusal rather than reuse. Reuse was rejected on correctness, not taste: the lane has no resume semantics because BO-2400f-10 releases the claim on abort, so a leftover workspace is either the residue of a finished run or the debris of a dead one, and building on it would measure a green result against a mainline that no longer exists while BO-2400f-3 promises the latest origin/main. A run-distinct workspace path was rejected because concurrency on one AC is a claim problem already owned by BO-2400f-8, and a live probe confirmed a branch cannot be checked out in two worktrees at once, so a per-run directory would not have helped anyway. That probe result is why the criterion refuses on the branch as well as on the location. Automatically discarding a provably-clean leftover is deliberately out of scope and recorded as deferred. The four children split by what the operator must do next rather than by code structure: the lane's own prior run, a foreign occupant, the refusal being inert, and a free location never being refused. The foreign case treats any occupant that cannot be positively classified as foreign, because guessing probably-mine is the failure that destroys unrecoverable work; classification reads branch identity and never the path, since the defect was originally found via a hand-made directory at exactly the name the lane would have chosen. The fourth child is the counterweight — without it the cheapest implementation passing the other four is one that refuses every run. The refusal payload is discriminated on an outcome field with worktree_path absent rather than blank, so the present-but-empty shape that reads downstream as success cannot be constructed from any return site. Every test_rationale forbids grep-shaped evidence and names the specific trap: a test asserting the lookup returns true for a fast-lane branch would pass while the caller still fell through, because the lookup and the caller are different code. Covering tests must execute the lane under run_workflow_under_e2 or run the workspace command as a real subprocess against a real occupied worktree. Also files KI-BO-017, found while specifying this and deliberately left unfixed: when a fast-lane branch outlives its pruned worktree, the checkout-only reconnect rebuilds on the old branch tip instead of the latest origin/main, silently contradicting BO-2400f-3. It is reachable on every AC the lane has already built, it is the common case rather than an edge because worktrees are periodically reclaimed while branches persist, and it needs its own product decision rather than a quiet reset inside this work."
