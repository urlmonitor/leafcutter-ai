# The schema validator rejects documentation_triggers on any AC that is not level L1

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-2200a-5` — The schema validator rejects documentation_triggers on any AC that is not level L1 — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-2200a-5`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `S`. Complexity: `low`.

## Acceptance Criteria

```gherkin
Given the agent-side AC schema validator,
When it validates an AC whose `level` is `L2` (or `L3`, or `L0`) that carries a
  non-empty `documentation_triggers` field,
Then validation fails with an error stating that `documentation_triggers` is
  permitted only on L1 ACs, and naming the offending AC id and its level.
And when it validates an L1 AC that carries `documentation_triggers`, the L1-only
  rule does not fire (an L1 is permitted to declare triggers).
And the pre-existing enum-value validation of `documentation_triggers` still applies
  on L1 ACs, so a value outside the allowed set is still rejected.
```
