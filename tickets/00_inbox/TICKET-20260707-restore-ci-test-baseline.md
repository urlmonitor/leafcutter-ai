# Restore green CI test baseline on main (build-guard + 6 failing tests)

## Summary

The GitHub Actions "Test suite (pytest)" job cannot run at all on `main` because
`scripts/build.py` aborts at the build step with a self-description validation error —
two dangling `skills_invoked` references (`direct-write` on `documentation-expert`,
`run-tests` on `python-coder`) point to skill templates that do not exist. Because the
build aborts, the full pytest suite never executes in CI, masking all test-health
signal. Once the build-guard is cleared, six additional pre-existing failures in
`unit_tests/commit_guardian/` become visible. This ticket fixes the build-guard and
triages each of the six tests (fix inline if trivial, or `pytest.mark.xfail` with a
documented tracking reference).

## Background

All failures pre-exist on `main` and are unrelated to any in-flight feature. They were
surfaced repeatedly during the GE-114 finalize. The "Test suite (pytest)" CI job is
non-required for merge, but a permanently red build step prevents any future test-health
signal from reaching the team and undermines the phase_1 reliability outcome.

### Acceptable resolutions

**Build-guard (must-do):** Correct the two dangling `skills_invoked` entries in
`config/agent_registry.json`. The decision (remove the entry vs. create a skill stub)
must be justified by reading the actual agent template body before changing the registry.
Do not assume — inspect first, then act.

**Six failing tests (triage-then-resolve):** For each test, determine whether the
underlying implementation is already present (or trivially misplaced/renamed) vs.
genuinely absent. If present → apply the path fix. If genuinely absent → mark
`pytest.mark.xfail(strict=False, reason="<ticket-or-AC-ref>")` with a comment
on the immediately following line identifying which absent implementation the test is
waiting on. A `reason=` string containing only generic text with no traceable reference
is rejected at pr-review.

**hooks_manifest fixes (critical — fix the SOURCE, not the output):**
`scripts/commit_guardian/commit_guardian.json` is a BUILD OUTPUT generated by
`build_phases.py::build_commit_guardian()` via rglob over `templates/scripts/commit_guardian/`.
Any edit applied directly to the generated file is silently overwritten on the next
`build.py` run. The implementer must: (a) identify the source template(s) under
`templates/scripts/commit_guardian/` that define `hooks_manifest` tier fields and hook
ordering, (b) apply the fix there, (c) run `build.py` to regenerate the output, and
(d) confirm the tests pass against the regenerated copy — NOT against a hand-edited
output file.

### Verification requirement

Verification MUST actually execute `build.py` and the pytest suite — not reason about
them. The whole point is a currently-red CI baseline that must be confirmed red before
any fix and green after.
