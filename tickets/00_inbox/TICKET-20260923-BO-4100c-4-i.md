## Acceptance Criteria

```gherkin
Given a workspace carrying the holds-nothing verdict has been disposed of,
When the shared main line and the branch list are inspected afterwards,
Then the shared main line's tip is the same commit it was before the disposal,

  list,

  disposal.
```

## Implementation Notes

```yaml
- Removal must be addressed to ONE resolved workspace path. It must never be expressed
  as a pattern, a prefix, a glob or a name match over the live set -- an implementation
  that disposes of a matching set satisfies every clause of BO-4100c-4 and is the
  shape that does the most damage under repeated unwatched use.
- 'Disposal must not touch the shared main line at all: no fetch, no merge, no ref
  update, no prune of remote-tracking refs. Its tip is asserted unchanged, so any
  of those fails.'
- The blast-radius assertions must be made against a fixture holding several workspaces
  with deliberately SIMILAR names and branches. Against a fixture with one workspace,
  or with obviously distinct names, a prefix-matching implementation passes.
- Branch deletion must be scoped the same way as directory removal; a disposal that
  removes the right directory and the wrong branch passes the directory assertion.
```
