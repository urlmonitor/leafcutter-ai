# Deleting or renaming a page does not falsely block the commit

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-104a-1-iii` — Deleting or renaming a page does not falsely block the commit — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-104a-1-iii`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `S`.

## Acceptance Criteria

```gherkin
Given a commit deletes an existing frontend page at site/app/parts/page.tsx
And the commit does not add any new frontend page
When the page-documentation guardrail runs at pre-commit time
Then the guardrail does NOT block the commit
And it does NOT demand a reference doc for the deleted page

---

Given a commit renames a frontend page from site/app/parts/page.tsx to
  site/app/components/page.tsx
And the matching reference doc for the destination route already exists on disk
  at docs/reference/frontend/components.md
When the page-documentation guardrail runs at pre-commit time
Then the guardrail treats the destination page as documented and allows the commit

---

Given a commit renames a frontend page from site/app/parts/page.tsx to
  site/app/components/page.tsx
And no reference doc exists for the destination route at
  docs/reference/frontend/components.md — neither staged nor on disk
When the page-documentation guardrail runs at pre-commit time
Then the guardrail blocks the commit (when in block mode)
And it emits a FIX message naming docs/reference/frontend/components.md as the
  expected doc for the renamed destination page
```
