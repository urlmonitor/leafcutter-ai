## Implementation Notes

```yaml
- '`state` IS A FIELD ON THE PIN RECORD with at least the values ''ok'' and ''malformed''.
  A malformed pin is a RECORD with ac_ids == [], not an absent record: the distinction
  between ''you did not say'' and ''what you said is not usable'' must survive as
  data all the way to the check, because they are different mistakes with different
  fixes.'
- THIS AC DOES NOT DECIDE THE VERDICT. What a malformed pin earns at commit time is
  GE-124c's decision; this AC only guarantees the state reaches the check distinguishable.
  Do not emit a finding from the reader.
- 'Three input shapes, three code paths, one state: `data-ac=""` (empty value), `data-ac="   "`
  (whitespace only), and a valueless boolean-style attribute `data-ac` with no `=`.
  All three are malformed. An implementation that checks only ''is the attribute present''
  passes the first; one that checks only ''is the string non-empty'' passes the second
  and third.'
- A malformed pin must not contribute to any count of pinned elements (GE-124c-3's
  pass record) and must not populate any criterion's pinned_by (GE-124g-1) — it names
  no criterion, so there is nothing to link.
```
