# Run build.py in worktrees after creation to populate .leafcutter/ build outputs

## Actor / Goal

As the operator running `/build-feature` or `/feature` to create an epic worktree,
I need `build.py` to be invoked automatically after `poetry install` so that
`.leafcutter/` (and its `.claude/workflows/` subdirectory) exists in the fresh
worktree — so that named workflow resolution (`workflow("build-epic")`) succeeds
at runtime without manual post-creation steps.

## Context

When `/build-feature` or `/feature` creates a new worktree, the `.leafcutter/`
directory is absent. It is a build output generated by `scripts/build.py` and is
listed in `.gitignore` (lines 2–3), so it is never present in a freshly-checked-out
branch. The `Workflow` tool resolves named workflows from `.claude/workflows/` at
runtime — which does not exist — causing `workflow("build-epic")` to fail silently
or raise a resolution error.

Root cause chain:
1. `.leafcutter/` is gitignored — only tracked files land in worktrees.
2. `build.py` generates `.leafcutter/` including `.leafcutter/.claude/workflows/build-epic.js`.
3. No post-checkout build step currently exists in `_bootstrap()` inside
   `templates/scripts/setup_ticket_worktree.py`.

Three files require changes (implementation partially described below; see
Implementation Tasks for the complete recipe):

- `templates/scripts/setup_ticket_worktree.py` — add a `build.py` invocation in
  `_bootstrap()` after `poetry install --no-root`, with graceful degradation when
  `build.py` is absent or exits non-zero.
- `templates/skills/feature/SKILL.md` — add a "Build outputs (mandatory)" block to
  Step 4 for epic worktrees documenting the `build.py` step.
- `templates/skills/build-feature-ops-notes/SKILL.md` — add a KI-3 entry documenting
  the failure mode (`.leafcutter/` absent), detection, remedy (`python scripts/build.py`
  in the worktree), and prevention (build step in `_bootstrap()`).

Existing tests live in `tests/test_setup_ticket_worktree.py`; new tests must be
appended to that file following the same `unittest.mock.patch` pattern.

## Implementation Tasks

- [x] In `templates/scripts/setup_ticket_worktree.py`, add to `_bootstrap()` after
  the `poetry install --no-root` call:
  ```python
  build_script = main_repo / "scripts" / "build.py"
  if not build_script.exists():
      print(
          "WARNING: scripts/build.py not found in main_repo; "
          ".leafcutter/ build outputs will be absent from the worktree.",
          file=sys.stderr,
      )
  else:
      try:
          subprocess.run(
              [sys.executable, str(build_script), "--target-dir", "."],
              cwd=worktree_path,
              check=True,
          )
      except subprocess.CalledProcessError as exc:
          print(
              f"WARNING: build.py exited {exc.returncode}; "
              ".leafcutter/ build outputs may be incomplete.",
              file=sys.stderr,
          )
  ```

## Risk & Safety

- Touches money? No.
- Touches data? No.
- Reversibility? The `_bootstrap()` change is purely additive — existing code paths
  are unchanged. A project that does not ship `scripts/build.py` receives a warning
  only; no failure is introduced.
- The `check=True` on the subprocess call is intentional for the success path; the
  `CalledProcessError` handler converts it to a warning rather than propagating the
  failure, consistent with the graceful-degradation requirement.
