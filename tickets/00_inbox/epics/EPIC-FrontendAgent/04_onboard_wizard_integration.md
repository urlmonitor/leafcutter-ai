# 04: Add optional-skill prompts to the onboard wizard for frontend-coder

## Actor / Goal

In order to make `webapp-testing` and `frontend-design` discoverable at install time, we need to extend the `/onboard` wizard so that it asks the user whether they want these optional skills and installs them automatically on approval.

## Context

The `onboard.md` template runs 15 deterministic steps (see template §Deterministic Checklist). The current Step 5 fans out `onboard-config-section` sub-agents for five sections: `testing`, `packages`, `tickets`, `commands`, `project`. Frontend optional skills do not fit neatly into any existing section — they are optional features that are off by default and require a discrete user decision.

The integration should be added as a new named step (e.g. Step 5b or between Steps 5 and 6) that:
1. Detects the runtime context: if the onboard session is running inside Antigravity (heuristic: check for `ANTIGRAVITY` environment variable or equivalent), skip the step entirely and print a one-line note: "webapp-testing skipped — Antigravity provides its own browser."
2. Otherwise, asks the user: "Would you like to install the webapp-testing skill (Playwright-based UI verification)? (yes / skip)"
3. If yes: copies `leafcutter-ai/templates/skills/webapp-testing/SKILL.md` to `.claude/skills/webapp-testing/SKILL.md` (or marks it for inclusion in the build.py run).
4. Asks: "Would you like to install the frontend-design skill (distinctive design guidance for frontend-coder)? (yes / skip)"
5. If yes: copies `leafcutter-ai/templates/skills/frontend-design/SKILL.md` to `.claude/skills/frontend-design/SKILL.md`.
6. Records the user's choices in `skills_config.json` under a new key `frontend.optional_skills` (list of installed skill names).

Step placement: insert between the existing Step 5 (fan-out sub-agents) and Step 6 (merge config fragments), so the optional-skill choices are available when the config is merged.

Note: this ticket modifies `onboard.md` in the templates — it does NOT modify the deployed `.claude/agents/onboard.md`. The deployed version is regenerated by `build.py` on the next run.

## Acceptance Criteria

```gherkin
Given a user runs /onboard in a Claude Code environment
When the wizard reaches the optional-skills step
Then it asks about webapp-testing and frontend-design in sequence
And installs each skill the user approves before continuing

Given a user runs /onboard inside Antigravity
When the wizard reaches the optional-skills step
Then it prints "webapp-testing skipped — Antigravity provides its own browser"
And proceeds without asking about webapp-testing
And still asks about frontend-design (design guidance is platform-agnostic)

Given the user approves webapp-testing during onboard
When onboard completes
Then .claude/skills/webapp-testing/SKILL.md exists in the target repo
And skills_config.json contains frontend.optional_skills: ["webapp-testing"] (or both if frontend-design was also approved)

Given the user skips both optional skills
When onboard completes
Then neither skill file is present
And skills_config.json does not contain frontend.optional_skills (or it is an empty list)
```

## Risk & Safety

- Touches money? No.
- Touches data? No — onboard wizard only writes skill files and skills_config.json. Both are safe to overwrite.
- Reversibility? Fully reversible. Installed skill files can be deleted; skills_config.json entries can be removed. No schema changes.
- Shared contract? The onboard.md template is the entrypoint for all new adopters. Inserting a new step changes the wizard flow; regression risk is that existing onboard runs (re-runs) see an unexpected new prompt. Mitigate by documenting that step 5b only fires when the optional-skill files are absent from `.claude/skills/`.
