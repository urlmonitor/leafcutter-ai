## Acceptance Criteria

```gherkin
Given three leaf code requirements at readiness "reviewed":
  R1 carries test intent marking 2 clauses needs-test and carries no test design,
  R2 carries test intent and a test design covering both needs-test clauses,
  R3 is recorded as requiring no tests,
When the user runs the approval step over all three,
Then R1 stays at "reviewed" and the approval report names R1 with the reason
  "test design pending",
And R2 and R3 move to "approved",
And test intent on its own is never accepted as the test contract that an approved leaf
  code requirement must carry.
```

- [ ] AC-1: R1 stays at "reviewed" and the approval report names R1 with the reason
- [ ] AC-2: R2 and R3 move to "approved"
- [ ] AC-3: test intent on its own is never accepted as the test contract that an approved leaf
