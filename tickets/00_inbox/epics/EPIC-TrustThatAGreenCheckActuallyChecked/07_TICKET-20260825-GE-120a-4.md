# An inspection that resolved none of the targets it was given does not report success

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-120a-4` — An inspection that resolved none of the targets it was given does not report success — so that the acceptance criterion is satisfied.

## Acceptance Criteria

```gherkin
Given the AC store schema validator is invoked with one explicit argument naming a
  directory that contains 27 AC YAML files,
When the validator resolves that argument into the set of files it will inspect, and that
  set is empty,
Then it states that it inspected nothing and names the argument it could not resolve into
  files,
And it reports a failure, replacing the behaviour observed today — the line "No YAML
  files to validate" followed by a success result,
And an invocation whose named targets do resolve to files is unaffected and reports as
  before,
And an invocation given no targets at all, in a context where nothing is in scope — for
  example a commit-time run where no matching file is staged — still reports an ordinary
  pass, because the rule fires on targets that were named but not resolved, never on an
  empty scope,
And an argument form the validator still cannot resolve after any convenience handling is
  added produces the reported failure, so the criterion is not satisfied by teaching the
  validator to expand directory arguments alone.

Coverage note: cover this by invoking the validator with a directory argument against a
directory that genuinely contains AC files, and asserting on the observed result and
message. Both boundary invocations — targets-named-but-unresolved, and no-targets-empty-
scope — must be exercised, or the fix will make legitimate empty-scope runs fail.
```
