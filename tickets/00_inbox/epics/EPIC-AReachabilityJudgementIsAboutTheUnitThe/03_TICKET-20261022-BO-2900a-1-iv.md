## Acceptance Criteria

```gherkin
Given a criterion whose record names the unit that implements it,
  And the criterion's proof also reaches for a second, unrelated unit that
    exposes a runtime way in of its own,
When the criterion is evaluated for eligibility to be marked done,
Then the judgement is about the unit the criterion's record names and about
  the way in that unit exposes,
  And no finding ever names a unit the criterion's record does not name, so no
    author is ever told to drive their proof through an unrelated unit's way
    in,
  And the unit a finding names is the one the record names, not a copy of that
    unit produced by the build,
  And when the criterion's record names no unit at all, the rule returns no
    verdict rather than choosing a unit from whatever the proof happens to
    reach for,
  And when the record names a unit that exposes no runtime way in, the rule
    returns no verdict and the case is left to the separate no-way-in rule,
    unchanged.
```

## Implementation Notes

```yaml
- THE UNIT COMES FROM THE AC RECORD, AND THE IMPORT LIST IS DELETED FROM THE SELECTION
  PATH. Resolve the unit from the AC's own implemented_by entries, filtered to .py
  paths that resolve to an existing file under the project root and outside the test
  root — implemented_by mixes ticket .md paths with code paths (BO-2900a-1's own record
  carries one of each). The fix is to REMOVE the sorted(_local_import_module_names(test_file))
  iteration in _done_proof_entry_point_gate.py::_detect_module_entry_point from the
  unit-selection path, not to reorder it or to use it as a tie-break. After this change,
  neither _local_import_module_names nor _resolve_candidate_unit may be reachable
  from this rule's unit selection at all.
- 'DO NOT USE it_requirements.reference_file_path AS THE DECLARED UNIT. config/ac_store_schema.json
  defines it as the file that must be modified FOR REGISTRATION — an edit surface,
  not the unit under proof. It carries a .py value on 11.9% of done ACs and 112 of
  the 234 done ACs using the object form name a non-.py file. Nor may a new store
  field be introduced to carry the unit: asking the store for something it does not
  hold is the mechanism that produced the empty question in BO-2900a-2-iii.'
- 'IDENTITY IS THE RESOLVED FILE PATH, NEVER THE MODULE STEM. Compare Path(...).resolve()
  of the declared unit against Path(...).resolve() of the candidate. Stem comparison
  is forbidden outright: .leafcutter/ and scripts/ hold same-stem copies of the same
  module, so a ''<module-stem>:main'' spec cannot tell the source from its deployed
  copy. Every entry point recorded in a finding must therefore be spelled ''<repo-relative
  source path>:<callable>'', replacing today''s f''{candidate.stem}:main''.'
- 'THE FINDING MUST NAME THE SOURCE THE RECORD NAMES, NOT A BUILD-OUTPUT COPY. When
  a declared path resolves inside a build-output tree (.leafcutter/, .claude/, or
  a deployed scripts/ copy of a templates/ source), the finding names the declared
  source path. 627 of 811 detections resolve into the build-output tree today. This
  clause is SEPARATE from the wrong-unit clause: an implementer who fixes only the
  alphabetical-sort half still emits findings pointing at a copy of the file rather
  than the file.'
- EVERY DECLARED UNIT IS CONSIDERED WHEN THE RECORD NAMES MORE THAN ONE. Do not silently
  take the first. A finding may name only a unit the record declares; a run that produces
  a finding naming anything else fails this AC regardless of how the unit was chosen.
- THE NO-VERDICT BRANCHES PRODUCE NO FINDING AND NO REFUSAL CAUSE. A record declaring
  no resolvable .py unit, and a declared unit defining no module-level main, both
  return the verdict untouched and emit no reachability finding. The tempting fallback
  — guess from the proof's imports when the record is silent — reinstates the exact
  defect being removed, for exactly the population most likely to be misjudged.
- THE HAND-OFF TO BO-2900a-3 IS UNCHANGED AND UNSHARED. When the declared unit exposes
  no way in, this rule returns no verdict and the no-way-in rule decides independently.
  No cached resolution, no shared mutable state and no merged refusal cause may pass
  between the two — BO-2900e-1 specifies two different messages with two different
  clearing actions.
- NO EMITTED TEXT MAY ASK THE READER TO EDIT THE AC RECORD. BO-2900e-1 requires every
  clearing action to be something done to the CODE. When the record declares no unit,
  the correct output is silence from this rule — not a message telling the author
  to populate implemented_by.
```
