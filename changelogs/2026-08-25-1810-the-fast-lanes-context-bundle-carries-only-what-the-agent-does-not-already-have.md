description: "KI-BO-019 and KI-BO-020, both found by running the lane against a real target. Specification only, no implementation. The bundle half started as a transport bug and turned into a premise failure. The lane asks its bundle agent to return roughly 149 KB verbatim in a JSON string field; the agent wrote it to disk and returned a 47-character pointer instead, and the fail-closed gate correctly refused to proceed. Investigating the transport found that the thing it exists to protect does not exist. A grep for cache_control across templates, scripts and config returns zero hits, so no provider cache breakpoint is set anywhere and the breakpoint marker is a literal HTML comment nothing consumes. The two consumers run under different agent types, test-writer and python-coder, hence different system prompts, so they could never share a cached prefix regardless: a prompt cache matches from the start of the request, system prompt first, and the two diverge long before the bundle appears. And the stable layer is not stable across runs, because the bundle prompt names an architecture index path that does not exist and tells the agent to substitute the nearest one, so that layer is composed by agent judgement. The store had already conceded the first point in writing on 2026-08-18 and 19; work continued against the old claim anyway. Measurement then reframed the fix. The conventions layer is 38,291 bytes and byte-identical to the CLAUDE.md the harness already injects into every agent in that worktree. The acs layer is 90,887 bytes of AC records the test-writer prompt already instructs the agent to read from the store. Together 129,178 of 148,891 bytes are a second copy of something the agent already has, leaving about 20 KB genuinely additive. So the chosen split is duplicate-versus-additive rather than stable-versus-volatile: pass architecture, high-level parents and prior tests, drop conventions and acs entirely, add the read-your-own-records instruction to the coder prompt which lacked it, and pin the architecture layer to a path that exists. Rejecting a returned value that looks like a reference, and stating a size expectation, are kept as a cheap belt on a payload already small by construction, never as the mechanism. This changes the CLI signature, since assemble-bundle marks all five layer arguments required, so six live call sites are audited in the same change including one at pytest collection scope. BO-2400c-1-iii is reset from done to in_progress because its gate half works and its transport half never did. The release half is worse than first filed. Every one of the nine release dispatches passes agentType status-checker and opens its prompt You are the release-phase agent; status-checker refuses role reassignment by design and the lane discards the reply, so every failure path in the lane strands its claims, not just the one observed. Two further findings shape the work. The workflow engine has no command primitive at all, only agent, parallel and prompt, so invoking the release command directly is not expressible today, and no agent among the sixty in the registry declares mutating AC claim state, which means the fix entails adding an agent template. And two of the nine release sites share the label release-on-review-fail, while the test harness keys its stubs on label, so covering all nine is arithmetically impossible until the labels are made unique. The claim dispatch carries the identical persona mismatch and merely happened to comply, with the inverse and more dangerous failure mode of a silent non-claim letting two runs build one criterion concurrently; it is pinned by a no-collateral-change test rather than folded in. BO-2400f-10 is reset from done to in_progress for the same reason as above, and the question of whether the release is meant to reach mainline at all is carried rather than resolved."
