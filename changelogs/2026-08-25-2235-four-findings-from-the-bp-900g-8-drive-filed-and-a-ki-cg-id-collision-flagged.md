It is filed high severity because KI-BP-004 and KI-BP-008 both nominate check_build_drift as the natural home for their own fixes, and both proposals are unreachable while it never fires here; the audit should cover every filter anchored on the consumer path, since check-paths-integrity has the same shape. KI-AR-003 records registry drift created by PR 557: config/agent_registry.json still declares skills_invoked signoff for research-agent and worktree-agent after their sign-off obligation was removed, which build.py reports as two advisory warnings alongside roughly fourteen pre-existing warnings of the same class. The blast radius today is nil, verified by reading the deployed agent body and confirming skills_invoked is not injected into it, but the registry is now wrong about two agents and any future consumer of that field inherits the error. Two second occurrences. KI-BP-008 gains a case with the same outcome as the original but a completely different cause: the deployed build-feature.js was 919 lines against 2416 in source, and the version gate was not involved, because build.py had been halting on an unacknowledged breaking-change gate since 2026-08-18. That gate behaved correctly. What is missing is any link between a build halting and the deployed tree being stale as a result, since a halt is a single event noticed once while the staleness is a standing condition that then persists silently; a halted build and a skipped phase leave identical deployed state and neither is reported at use time, so a fix scoped only to the version gate leaves this route live. KI-BP-011 gains a case reached from a git worktree that blocked a commit: build.py with a worktree target, through a symlinked .leafcutter, deployed into the parent and wrote a manifest with no output_mappings, after which check-build-drift reported every template in the repository as unregistered on a commit containing only a changelog and two acceptance-criteria files. The original entry frames the defect as consumer-install portability; this shows it reached from the package's own recommended worktree workflow, where it actively corrupts shared state. One entry narrowed. The open half remains the fix direction already written there, which is to assert completion against an observable side effect.
