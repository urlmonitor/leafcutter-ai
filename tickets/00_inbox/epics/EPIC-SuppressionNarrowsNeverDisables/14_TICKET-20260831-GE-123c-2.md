  "GENERIC_SECRET:scripts/commit_guardian/check_paths_integrity.py" —

## Implementation Notes

```yaml
- The appended-note signal is whitespace immediately followed by the comment marker
  inside a field — never the marker alone, and never the absence of the named file
  on disk. A suppression may legitimately precede the file it names, so non-existence
  must not be treated as evidence of anything.
- Evaluate the signal per field rather than per spelling, so the same authoring mistake
  is caught in whichever field it lands and no field is left with an untreated variant
  of it. One message per offending line regardless of how many fields carry the signal.
- 'Reject, do not repair: the entry is reported and skipped, never silently stripped
  of the note and honoured. Stripping changes what the entry means on a guess, which
  is the habit this L1 removes.'
- Reuse the single allowlist-diagnostic convention this file already has — error stream,
  allowlist file path, 1-based line number, verbatim line text — and do not add a
  second message shape.
- Classification is never fatal and never alters the scan's exit status, which stays
  determined by the surviving findings alone.
- Edit the canonical template at templates/skills/security-scanner/scripts/scan_secrets.py
  and propagate with build.py; never edit a deployed copy (ADR-001).
- 'This runs on every commit: keep the check a single linear pass with no per-entry
  filesystem access.'
- Tests must never create, modify or delete a .security-allowlist at any real project
  root, workspace root or worktree root; every fixture allowlist lives under tmp_path/tempfile.
- Fixture files must use ordinary source filenames — the per-file scan short-circuits
  environment-named files and never reads their content, so such a fixture cannot
  produce the content findings these criteria depend on.
```
