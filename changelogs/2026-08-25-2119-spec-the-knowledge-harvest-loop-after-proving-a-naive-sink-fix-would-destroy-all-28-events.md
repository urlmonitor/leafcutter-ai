description: "Specification only -- no behaviour changes here. ADR-034 settled who writes a captured learning; this settles what has to be true for the loop to actually run, after a measurement that changed the plan. The starting proposal was small: point the harvester at the sink the writers use, and give it a caller. A dry-run against the real sink killed that. All 28 knowledge_captured events on disk carry an entry_kind the harvester does not recognise -- the 11 values it accepts and the 15 the writers actually emit overlap on zero -- and an unrecognised kind is added to the idempotency record, so it is never offered to a later run. Fixing only the path would have burned all 28 permanently on first run, which is the phantom-done failure mode this repo exists to prevent, arriving disguised as its own remedy. The writers have no controlled vocabulary at all: they emit both component-convention and component_convention, both agent-memory and agent_memory, and five variants of framing. Nine L2/L3 ACs under INF-400c come from that measurement. INF-400c-4 requires one declared sink both sides resolve, with a parity check that fails against today's tree, plus the four shipped emit sites (c-4-i), recovery of the 28 stranded events ordered after the mapping exists (c-4-ii), and two separate streams with the harvester forbidden a fallback onto the telemetry sink (c-4-iii). INF-400c-5 requires one vocabulary shared by classifier and harvester and enforced at an emission helper, with kebab/snake normalisation (c-5-i), a total mapping over the 15 in-flight values taking the corpus to zero unroutable and applied on read so the sink stays immutable (c-5-ii), and rejection that names the value and counts it without ever failing the agent run (c-5-iii). INF-400c-2-ii requires an unroutable event to stay unprocessed, be reported, and be replayable once the rules extend. That last one contradicts INF-400c-2-i, which is work_status done, test-covered, and whose criteria say in as many words to mark the event processed 'so it does not retry indefinitely' -- the harvester's behaviour is not a bug against its AC, it is compliance with it. So c-2-i is superseded by c-2-ii rather than quietly amended: its original intent, no unbounded retry loop, is preserved by c-2-ii's requirement that the backlog be reported on every run instead of discarded. It carries a pointer to the exact test node that still asserts the old behaviour and still passes, because that test must be rewritten in the same commit that implements the replacement or the implementation will fail against it. INF-700a is a new L1 for the remaining gap ADR-034 recorded and no AC covered: the harvester has no caller. Nothing invokes it -- it appears in the agent registry, the docs index, its own card, two ADRs, a changelog and two test files, and is called from none of them. The L1 fixes the outcome, not the mechanism, and leaves the trigger point to the BA and IT PO. It also carries ADR-034's documentation obligation, that while capture is manual no surface may imply otherwise. INF-700 sits under its cap on either reading: covered_by lists four children, while the hook's id-derivation sees one, since INF-400c, INF-400g and INF-400h resolve to INF-400."
