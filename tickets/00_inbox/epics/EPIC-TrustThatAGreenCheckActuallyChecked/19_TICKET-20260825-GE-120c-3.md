# Every registered check is exercised by the harness, and a new check cannot opt out by omission

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-120c-3` — Every registered check is exercised by the harness, and a new check cannot opt out by omission — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-120c-3`. Component: `guardrail-engine`. Assigned agent: `test-writer`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given the guardrail engine's hook manifest, which lists every check it installs,
When the harness sweep runs,
Then the set of checks it actually exercised is compared against the manifest,
And any check present in the manifest with no harness case is reported by name as uncovered,
And the sweep reports a failure when any manifest check is uncovered,
And adding a new check to the manifest without a harness case therefore fails the sweep
  rather than passing silently,
And a harness case naming a check that is not in the manifest is also reported, so the sweep
  cannot be satisfied by exercising a check that is no longer installed.

Coverage note: exercise this by adding an entry to a manifest fixture with no matching
harness case and asserting the sweep names it and fails. A test asserting that the current
manifest is fully covered passes forever and catches nothing on the day check nineteen is
added — which is the day this AC exists for.
```

- [ ] AC-4: adding a new check to the manifest without a harness case therefore fails the sweep

  -> hooks_manifest.hooks[] (54 entries today). Never a hand-maintained id list. This

  a family-wide rule that is not mechanically checked against the family''s own registry

  harness case is UNCOVERED; (b) a harness case naming a check absent from the manifest

  the checks it names is a sweep that looks thorough and exercises ghosts.'

  that only warns is a convention, not a rule.
- EXERCISE WITH A MANIFEST FIXTURE containing an entry that has no harness case. A
  test asserting the current 54 entries are all covered passes forever and catches
  nothing on the day check 55 is added, which is the day this AC exists for.

  which does not go through run_hook.py) are in the manifest and therefore in the

  from a property of the entry — for example a declared marker or the tier value —
  never a hard-coded id, or check 55 inherits the exemption by resemblance.
- 'Expose the comparison as a CALLABLE, not as an assertion buried inside one test:
  GE-120b-4''s parity sweep consumes this as its completeness guarantee and must not
