## Entry

/build-feature's worktree step now decides reuse, naming, staleness and occupancy from repository FACTS — obtained through a new deterministic helper, `templates/scripts/worktree_repo_facts.py` — never from an agent's own judgement or the resolver's own word. When the run's own target resolution already names a reusable linked worktree, no worktree-opening agent is dispatched at all; every phase prompt is rooted there and no later step can replace it. Otherwise the workflow computes the new worktree's exact location itself and tells the opening agent that location; a report of anywhere else stops the run before any phase agent is dispatched, naming both the instructed and the reported location. A stale local branch with no unique commits is silently rebased onto origin/main and the run reports how far behind it was; a branch with unique commits, or an unreachable origin/main, refuses instead of silently building on a wrong base. A location already occupied by something other than the target's own worktree refuses rather than picking a second location. This closes BO-4000 and its three child records (BO-4000a-c), continuing directly from the 2026-09-14 BO-3900 incident.
