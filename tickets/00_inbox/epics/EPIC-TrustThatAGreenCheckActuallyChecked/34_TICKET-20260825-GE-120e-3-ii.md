# A merge whose own resolution introduces the fault is still blocked, and no check treats a merge as grounds to skip

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-120e-3-ii` — A merge whose own resolution introduces the fault is still blocked, and no check treats a merge as grounds to skip — so that the acceptance criterion is satisfied.

## Acceptance Criteria

```gherkin
Given a merge commit in which the author's own resolution introduces exactly the fault a
  check exists to catch — a test file removed by the resolution rather than by either
  incoming state, and frontmatter the author typed into a conflicted region that the check
  rejects,
When that check runs on the commit,
Then it objects and the commit is blocked,
And its objection names the author's resolution and does not name the carried-in work that
  arrived alongside it,
And the identical content arriving unchanged from a state the commit is built on, with no
  resolution of the author's own, is not blocked, in the same verification against the
  same repository,
And no check skips its inspection, in whole or in part, on the grounds that a merge is
  under way — a merge changes which content is attributed to the author, never whether the
  author's content is inspected.

Coverage note: both arms must run in the same test against the same repository, because
the difference between them IS the criterion. A test that only asserts the untouched case
is not blocked passes on a check that has been switched off for merges entirely, which is
the exact regression this AC exists to prevent.
```

## Implementation Notes

```yaml
- BOTH ARMS IN ONE CASE AGAINST ONE REPOSITORY. Do not split the blocked arm and the
  not-blocked arm into separate tests. The difference between identical bytes blocked
  in one arm and passed in the other IS the criterion; two independent tests can both
  pass against a check that has been switched off for merges, which is the regression
  this AC exists to prevent.
- 'TWO REAL SUBJECTS, NOT ONE. Arm A(i): a test file removed by the author''s own
  conflict resolution must still trip check_contract_shrinking. Arm A(ii): frontmatter
  the author typed into a conflicted region must still trip check_doc_frontmatter.
  Both were the observed false-positive sources; both must be shown still catching
  the real thing.'
- THE OBJECTION MUST NAME THE AUTHOR'S RESOLUTION AND MUST NOT NAME THE CARRIED-IN
  WORK. Assert on the objection text, not only on the exit status — a check that blocks
  for the right reason and a check that blocks for the old wrong reason both exit
  non-zero.
- COVER THE NO-SKIP CLAUSE BEHAVIOURALLY, NOT BY GREP. Do not assert the absence of
  the string MERGE_HEAD in any source file. Assert instead that with a merge genuinely
  in progress the author's own faulty content is still blocked — a check that consults
  the marker to decide WHETHER to inspect fails that assertion, and a grep passes
  on dead code (CLAUDE.md, 'Gate / Workflow ACs — Verify Behaviorally, Not by Grep').
- MERGE_HEAD IS PRESENT ONLY WHILE THE MERGE IS IN PROGRESS. The fixture must execute
  the check at that point in the operation — after staging the resolution, before
  the merge commit is created — because that is when the commit path runs and it is
  the only window in which the marker exists at all.
- 'RECORD THE ACCEPTED NARROWING EXPLICITLY, in the test module docstring and in the
  sign-off: under GE-120e-1''s definition, resolving a conflict by taking an incoming
  deletion verbatim matches an incoming state and is therefore not the author''s,
  so an author who accepts an incoming test deletion and separately edits production
  code is no longer blocked by contract-shrinking. That is the observed false positive
  removed on purpose. If it is later judged too wide, the fix belongs in GE-120e-1''s
  definition of authored content, never in an exemption clause here.'
- REUSE GE-120c-1'S OUT-OF-PROCESS HARNESS and the deployed layout, so what is under
  test is the check as the commit path runs it.
```
