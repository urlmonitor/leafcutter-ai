# Agents dispatched for a machine-parsed result return only the structured payload, with any anomaly carried inside it

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BP-300e-6` — Agents dispatched for a machine-parsed result return only the structured payload, with any anomaly carried inside it — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BP-300e-6`. Component: `build-pipeline`. Assigned agent: `llm-expert`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a delivery workflow (/plan-feature, /build-feature, /finalize-feature,
  or the epic and ticket workflows behind them) dispatches an internal helper
  agent whose reply the workflow will machine-parse as a structured result
  (a single JSON object or array) — for example the status-checker agent that
  reports ticket state,
When that agent completes its task and returns its reply,
Then the agent's reply is exactly one structured JSON value (a single object or
  array) and nothing else — no leading or trailing prose, no markdown headings
  (such as a "## Anomalies" section), no explanatory notes, and no commentary
  before or after the payload,
And any anomaly, warning, or caveat the agent needs to report is carried INSIDE
  the structured payload (for example in an "anomalies" or "warnings" field of
  the returned object) rather than appended as free text outside it,
And this contract applies to every agent used as a machine-parsed producer by
  these workflows — it is a requirement on the class "agents whose reply a
  delivery workflow parses", not on any single named agent.
```

## Implementation Notes

```yaml
- 'Update templates/agents/status-checker.md so that, when dispatched for a machine-parsed
  result, its output instruction reads: return ONLY the single JSON object/array —
  no prose and no markdown headings (including the existing ''## Anomalies'' and ''##
  Verdict'' sections) before or after the payload. status-checker is the confirmed
  trigger case: it currently appends an ''## Anomalies'' markdown section after its
  structured output.'
- Anomalies/warnings/caveats must be relocated to a field INSIDE the returned JSON
  payload (e.g. an 'anomalies' or 'warnings' array) rather than emitted as a trailing
  markdown section. Do not remove the agent's ability to report anomalies — change
  only where they are carried.
- 'Identify the full class of machine-parsed producer agents by grepping the delivery
  workflow scripts (templates/workflows-js/*.js) for agent dispatches whose result
  is JSON.parse''d, and apply the same output contract to every member. Known members
  at authoring time: status-checker (primary; ~48 dispatch sites), ac-triage, pt-classifier,
  worktree-agent. Do NOT hard-code this list in the templates — re-derive it from
  the dispatch sites so newly added producers inherit the contract (data-driven, not
  by-name).'
- Edit only the canonical source templates under templates/agents/*.md; rebuild via
  build.py so the deployed .claude/agents/*.md copies stay byte-identical (compiled-output
  drift guard) — never hand-edit the deployed copy.
- Preserve each agent's human-facing / sign-off behavior (e.g. the signoff-skill path
  when a ticket_path is provided). The 'return ONLY JSON' contract applies to the
  machine-parsed dispatch path; it must not strip the sign-off or completion-manifest
  behavior these agents also perform.
- 'This AC is defense-in-depth and independent of the parseAgentJson tolerant reader
  (BP-300e-1): it hardens the producer side while BP-300e-1 hardens the consumer side
  of the same contract. The template change must not assume, require, or be blocked
  by that helper, and must remain correct whether or not BP-300e-1 has shipped.'
```
