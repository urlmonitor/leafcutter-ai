# Collection isolation still surfaces genuine failures among the loadable tests

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `TQ-100a-1-iii` — Collection isolation still surfaces genuine failures among the loadable tests — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `TQ-100a-1-iii`. Component: `testing-quality`. Assigned agent: `python-coder`. Estimated complexity: `S`.

## Acceptance Criteria

```gherkin
Given a suite in which one file cannot be collected and, separately, at least
  one test in a loadable file genuinely fails its assertion,
When the suite is run with collection-error isolation enabled,
Then the loadable-but-failing test is reported as a failure
And the overall run outcome is non-passing (it reflects the genuine failure)
And isolating the uncollectable file does not cause the run to report success
  while a real failure exists among the collectable tests.
```

## Test Requirements

- `test_genuine_failures_still_reported_with_isolation`: With collection isolation enabled, a real assertion failure in a loadable test still fails and is reported (isolation does not mask true failures).
