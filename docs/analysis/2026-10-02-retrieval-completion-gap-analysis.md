# What remains before retrieval works as designed

The dependable core exists: exact source disclosure, bounded population queries, explicit missing fields, immutable graph generations, kernel waits and governed query admission. What remains is a complete question-to-answer journey that consistently reaches and composes these capabilities. More indexed data alone will not repair it.

The recommended order is:

1. **Make ordinary questions reach research, exact lookup and focused clarification.** Repair the observed routing/catalog/input-binding seams before adding methods.
2. **Close one complete answer path.** Preserve the original question, source, facts, budget and evidence through clarification, retrieval, sufficiency and response.
3. **Add a common attempt contract and method-selection loop inside the kernel.** Queries, search and traversal must return comparable, attributable attempts.
4. **Add optional input/term preparation and bounded traversal.** Reuse kernel host handoffs for generation; Jev chooses and evaluates, while System executes and validates.
5. **Finish governed reuse, publication and quality evidence.** Advisory strategy memory is distinct from approved human decisions. Complete real-agent build proof, freshness, evaluation and verified observation without blocking the first exact answer on all future features.

This is analysis and proposed delivery order, not implementation approval, tickets or AC status changes. [ADR-064](../architecture/adrs/ADR-064-persona-discovery-before-feature-planning.md) remains a planning policy only. No broad planning workflow or persona-enforcement system is proposed.

## Minimum critical path

The caller supplies a question and optional context, known IDs or keywords. The host supplies authorized workspace, permissions and a source policy; the result exposes the revision actually used. The caller must not secretly provide an operation, answer requirements, generation SHA or internal population enum to make the happy path work.

A **source** is an authorized evidence location/backend, such as the published graph or approved repository files. A **component** is the subject being researched, such as knowledge management: an optional filter, not the database or retrieval method. A known AC ID should not force a component question. “Test writing” does not establish one AC family until evidence or the caller resolves it.

## AC treatment before implementation

Reuse existing behaviors rather than duplicating them under new IDs. [KM-500](../acceptance-criteria/knowledge-management/KM-500-research-capability-growth/KM-500.yaml) owns research/query growth; [KM-400](../acceptance-criteria/knowledge-management/KM-400-trustworthy-project-knowledge/KM-400.yaml) owns the neutral retrieval guarantees.

- **Complete existing open obligations:** KM-500a-4 (live selection quality), KM-500b-4 (actual coding actor) and KM-500b-5 (query lifecycle) are todo. KM-500d-1, KM-500d-2, KM-500d-3, KM-500e-1 through KM-500e-4, KM-500f-1 through KM-500f-5, KM-500g-1, KM-500g-1-i and KM-500g-2 remain in progress in the inspected store. Their implemented facets and prior tests are useful; status alone is not end-to-end completion evidence.
- **Amend the behavioral scope where the target changes it:** KM-500a-2 currently permits deterministic explicit known-operation bypass. If every ordinary agent question must first pass a Jev method-selection node, specify that normal route separately from the privileged direct typed interface. Extend KM-500a-1/KM-500e-1 for focused ordinary-language clarification, KM-500c-2 for each-attempt adequacy and comparative return, and KM-500c-3 for changed-method retry with shared budgets. Do not retrospectively claim those wider behaviors from their current done status.
- **Add precise missing target contracts:** optional typed argument/five-term host operations, portfolio attempt identity, observed graph/folder frontier and visited state, comparative combine/dedup, optional answer wording, and advisory strategy publication/applicability/reuse. Existing host transport, source policy and approved decision memory are dependencies, not substitutes for these new contracts.
- **Keep conditional families conditional:** KM-500f-1 through KM-500f-5 may assess properly supplied or inspected evidence. Full repository discovery of every proof, source path or fixture is additional integration work. A declaration, graph edge, filename or caller assertion cannot become execution evidence.

BA should preserve the 25 persona origins and map the new clauses to the scenario matrix; PO should choose the P0 release boundary; IT PO should specify the public contracts, source permissions, budgets and dependencies; coder and independent evaluator should work against those agreed clauses. This analysis creates none of those AC changes or signoffs.
