# Build Telemetry Record Schema and Lane Report

Lookup reference for every field in a telemetry record written to
`debugging/logs/agent_telemetry.jsonl`, the lane comparison aggregates
returned by `build_lane_comparison_report`, and the emitter and counter
functions that produce and surface them.

---

## Sink Location

All telemetry records are appended to:

```
debugging/logs/agent_telemetry.jsonl
```

Each line is a newline-terminated JSON object (JSONL format). The parent
directory is created automatically by `emit_agent_telemetry` if it does not
exist. The file is opened in append mode; existing records are never
overwritten.

---

## Telemetry Record Schema

Each call to `emit_agent_telemetry` appends one record to the sink. The
record contains the caller-supplied fields listed below plus a `ts` field
added by the emitter.

**Harness responsibility note:** `duration_ms`, `tokens_in`, `tokens_out`,
and `cache_read_tokens` are measured and supplied by the calling harness
(e.g. ticket-supervisor or a phase agent wrapper). The `agent_telemetry`
module is the emit and report layer only — it writes whatever numeric values
the caller provides without validation.

### Record fields

| Field | Type | Required | Description |
|---|---|---|---|
| `ts` | string (ISO-8601) | Added by emitter | UTC timestamp. Injected by `emit_agent_telemetry` when absent from the caller-supplied dict. Format: `2026-07-21T10:00:00.000000+00:00`. |
| `lane` | string | Yes | Pipeline lane tag (e.g. `"fast"`, `"heavy"`). Used to group records in the lane comparison report. |
| `agent` | string | Yes | Agent identifier (e.g. `"python-coder"`, `"test-writer"`). Must match the agent's registered id. |
| `duration_ms` | integer | Yes | Wall-clock duration of the agent invocation, in milliseconds. Supplied by the harness. |
| `tokens_in` | integer | Yes | Input (prompt) token count consumed by the invocation. Supplied by the harness. |
| `tokens_out` | integer | Yes | Output token count generated by the invocation. Supplied by the harness. |
| `cache_read_tokens` | integer | Yes | Number of cached tokens read during the invocation (prompt-cache hits). Supplied by the harness. |
| `unit_id` | string | No | Ticket or work-unit identifier (e.g. `"BO-2400d-1"`). Omit when not applicable. Written through unchanged when present. |

Additional caller-supplied keys beyond those listed above are written through
to the JSONL line without modification.

### Minimal valid record (as written to disk)

```json
{
  "lane": "fast",
  "agent": "python-coder",
  "duration_ms": 1200,
  "tokens_in": 500,
  "tokens_out": 300,
  "cache_read_tokens": 100,
  "ts": "2026-07-21T10:00:00.000000+00:00"
}
```

### Record with optional unit_id

```json
{
  "lane": "heavy",
  "agent": "test-writer",
  "duration_ms": 4500,
  "tokens_in": 2100,
  "tokens_out": 850,
  "cache_read_tokens": 0,
  "unit_id": "BO-2400d-1",
  "ts": "2026-07-21T10:05:00.000000+00:00"
}
```

## Emitter — `emit_agent_telemetry`

**Module:** `scripts/agent-health/agent_telemetry.py`

### Signature

```python
def emit_agent_telemetry(record: dict, *, sink_path: Path) -> None:
```

### Parameters

| Parameter | Type | Description |
|---|---|---|
| `record` | `dict` | Telemetry dict. Required keys: `lane`, `agent`, `duration_ms`, `tokens_in`, `tokens_out`, `cache_read_tokens`. Optional: `unit_id`. Additional keys pass through unchanged. |
| `sink_path` | `pathlib.Path` | Path to the JSONL sink file. Parent directories are created if absent. File is created if it does not exist; existing content is preserved (append mode). |

### Return value

`None`. The function never raises on sink errors (see Fail-loud behavior below).

### Fail-loud behavior

When an `OSError` occurs (for example: the sink path is a directory, the
filesystem is full, or permissions prevent writing):

1. A `WARNING` is logged via the module-level logger with the sink path and
   the exception message.
2. The module-level `_failed_write_count` counter is incremented by 1.
3. The exception is **not** re-raised. Telemetry is best-effort; the build
   continues even when the sink is unreachable.

The failed-write count accumulates across all calls in the process lifetime
until reset. Operators inspect it via `get_failed_write_count()` (see below)
after a drive to detect a broken sink.

### Usage example

```python
from pathlib import Path
from agent_telemetry import emit_agent_telemetry

emit_agent_telemetry(
    {
        "lane": "fast",
        "agent": "python-coder",
        "duration_ms": 1200,
        "tokens_in": 500,
        "tokens_out": 300,
        "cache_read_tokens": 100,
        "unit_id": "BO-2400d-1",
    },
    sink_path=Path("debugging/logs/agent_telemetry.jsonl"),
)
```

## Failed-Write Counter

Two module-level functions surface and reset the count of dropped records.

### `get_failed_write_count`

```python
def get_failed_write_count() -> int:
```

Returns the number of `emit_agent_telemetry` calls that failed with an
`OSError` since the process started (or since the last `reset_failed_write_count`
call). A non-zero value indicates records were dropped and the sink should be
investigated.

### `reset_failed_write_count`

```python
def reset_failed_write_count() -> None:
```

Resets `_failed_write_count` to 0. Intended for test isolation only — call in
`setUp()` so each test case begins with a clean counter. Do not call in
production code.

### Usage example

```python
from agent_telemetry import get_failed_write_count, reset_failed_write_count

# After a drive completes, check for dropped records:
dropped = get_failed_write_count()
if dropped > 0:
    print(f"WARNING: {dropped} telemetry records were dropped — check the sink.")

# In test setUp:
def setUp(self):
    reset_failed_write_count()
```

## Lane Comparison Report — `build_lane_comparison_report`

**Module:** `scripts/agent-health/generate_health_report.py`

### Signature

```python
def build_lane_comparison_report(sink_path: Path) -> dict:
```

### Parameters

| Parameter | Type | Description |
|---|---|---|
| `sink_path` | `pathlib.Path` | Path to the JSONL file produced by `emit_agent_telemetry`. Typically `debugging/logs/agent_telemetry.jsonl`. |

### Return value

A `dict` keyed by lane string. Each value is an aggregate sub-dict covering
all records for that lane. Returns `{}` when the sink file is absent or
contains no valid records with a `lane` field. Records missing the `lane` key
are silently skipped.

### Aggregate output fields

| Field | Type | How computed | Description |
|---|---|---|---|
| `count` | `int` | `len(records_for_lane)` | Number of records tagged with this lane. |
| `total_duration_ms` | `int` or `float` | `sum(r["duration_ms"] for r in recs)` | Cumulative wall-clock time for all invocations in this lane, in milliseconds. Missing `duration_ms` defaults to 0. |
| `avg_duration_ms` | `float` | `total_duration_ms / count` | Mean invocation duration for this lane, in milliseconds. |
| `total_tokens_in` | `int` or `float` | `sum(r["tokens_in"] for r in recs)` | Total input tokens consumed across all invocations in this lane. Missing `tokens_in` defaults to 0. |
| `total_tokens_out` | `int` or `float` | `sum(r["tokens_out"] for r in recs)` | Total output tokens generated across all invocations in this lane. Missing `tokens_out` defaults to 0. |
| `total_cache_read_tokens` | `int` or `float` | `sum(r["cache_read_tokens"] for r in recs)` | Total cache-hit tokens across all invocations in this lane. Missing `cache_read_tokens` defaults to 0. |
| `avg_total_tokens` | `float` | `mean(tokens_in + tokens_out + cache_read_tokens per record)` | Mean total token usage per invocation (all three token fields summed per record, then averaged over the lane). |

### Usage example

```python
from pathlib import Path
from generate_health_report import build_lane_comparison_report

report = build_lane_comparison_report(
    Path("debugging/logs/agent_telemetry.jsonl")
)

for lane, agg in report.items():
    print(f"{lane}: {agg['count']} invocations, avg {agg['avg_duration_ms']:.0f} ms")
```

### Example return value

```python
{
    "fast": {
        "count": 12,
        "total_duration_ms": 14400,
        "avg_duration_ms": 1200.0,
        "total_tokens_in": 6000,
        "total_tokens_out": 3600,
        "total_cache_read_tokens": 1200,
        "avg_total_tokens": 900.0,
    },
    "heavy": {
        "count": 3,
        "total_duration_ms": 13500,
        "avg_duration_ms": 4500.0,
        "total_tokens_in": 6300,
        "total_tokens_out": 2550,
        "total_cache_read_tokens": 0,
        "avg_total_tokens": 2950.0,
    },
}
```
