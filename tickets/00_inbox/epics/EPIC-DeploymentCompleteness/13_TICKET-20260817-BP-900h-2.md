# Two consecutive builds into the same project produce zero difference

## Actor / Goal

As an adopter who re-runs the build after pulling a package update, I want the
build to leave my project unchanged when nothing has changed, so that I can tell
a real update apart from build churn.

## Context

This ticket was generated from AC store entry `BP-900h-2`. Component:
`build_pipeline`. Assigned agent: `python-coder`. Estimated complexity: `S`.

Added to this epic on 2026-08-17. This is phase_1 exit criterion 3
("consecutive builds produce zero git diff"), which today has no automated
check anywhere. Extends the consumer-simulation job stood up by ticket 12 with a
second build and a git-based comparison.

Depends on ticket 12 both logically and physically — both edit
`.github/workflows/ci.yml`, so they must not run in the same parallel batch.

## Acceptance Criteria

```gherkin
Given the consumer-simulation project from BP-900h-1 has been built once
  and the deployed output committed to a scratch git repository,
When build.py is run a second time against the same target directory with the same inputs,
Then "git status --porcelain" in the scratch repository reports no changes
And no deployed file has been added, removed, or modified
And the job fails, naming every differing path, if any change is reported
```

## Implementation Notes

- Measure idempotency across the **whole deployed tree via git**, not per-phase.
  A per-phase byte comparison is what exists today, and it is what missed these
  defects.
- Add a `.gitignore` to the scratch repository excluding `__pycache__` and
  `*.pyc` — compiled bytecode legitimately differs between runs and would make
  the check permanently red.
- Report the differing paths, do not merely assert a boolean.
- A known real cause of non-idempotency here is absolute paths baked into
  generated output: BP-016 and BP-017 (commits `47fb660ff`, `9bf606c28`) both
  fixed build-shim symlinks pointing at absolute local paths.

## Test Requirements

- `test_second_build_produces_no_git_diff` — build twice into the same target,
  `git add -A` after the first, and assert `git status --porcelain` is empty
  after the second.
- `test_idempotency_check_detects_a_changed_file` — negative case: mutate one
  deployed file between builds and assert the check reports that path. Proves
  the comparison can actually fail.

Target dir: `unit_tests/portability/`.
