## Acceptance Criteria

```gherkin
This edge case complements ACD-1200a-11 (same-ticket dedup) by requiring that
legitimately distinct implementation references are never lost during dedup.

Given an AC whose implemented_by list legitimately contains an entry for a
  different, unrelated implementation path (one that is not the ticket being
  regenerated),
When a ticket is regenerated from that AC and the back-reference for the
  regenerated ticket is written,
Then the unrelated entry is preserved unchanged in the AC's implemented_by list,
And only the stale or duplicate entry that points at the same regenerated ticket
  is collapsed to a single entry,
And the dedup never removes, rewrites, or reorders the unrelated entry.
```

- [ ] AC-2: only the stale or duplicate entry that points at the same regenerated ticket
- [ ] AC-3: the dedup never removes, rewrites, or reorders the unrelated entry.
