# 01: Create llm-expert agent template

## Goal

Create the portable agent template `templates/agents/llm-expert.md` that defines the llm-expert agent's behavior, frontmatter schema, and operational constraints. This template will be deployed to consumer projects via build.py.

## Context

Stub generated by create-epic. Harden with create-ticket (depth 2).

The llm-expert agent is a specialist that owns the craft of writing, auditing, and maintaining LLM instructions inside agent templates, skill files, and slash-command prompts. Its remit includes:
- Writing and editing agent templates (`templates/agents/*.md`)
- Writing and editing skill bodies (`templates/skills/*/SKILL.md`)
- Auditing prompts/instructions for convention violations (shell rules, nesting limits, tool allowlists, signoff protocol adherence)
- Applying skills like `add-agent-to-package` and `add-skill-to-package` when a new template needs to be promoted into the package
- Fielding tickets whose `agents:` map BA/IT PO mark as requiring prompt-engineering or template work

The agent template must include:
- **Frontmatter** with name, description, model, tools, portable, signoff, and requires_verification fields
- **Pre-Flight Reads** section that names PROJECT_CONTEXT.md and relevant SKILL.md files
- **Prompt-Quality Checklist** section with at minimum 5 checklist items covering compound bash violations, tool allowlist mismatches, signoff protocol, spawn_allowlist declaration, and stop-and-ask rules
- **Stop-and-Ask Rule** section that defers infrastructure edits (registry, build pipeline) to workflow-architect
- **Skills** section listing the three skills the agent may invoke (add-agent-to-package, add-skill-to-package, signoff)
- **Implementation Sequence** section with ordered steps
- **Response Payload** section with required completion report format
- **Sign-off** section following the signoff skill recipe
- **Constraints** section establishing the single-command bash rule and scope boundaries

## Acceptance Criteria

```gherkin

And tools includes Bash, Read, Edit, Write, Agent
And model is set to "sonnet"
And portable is true
And signoff is true
And requires_verification is true

Given the agent template body is inspected
When the "Pre-Flight Reads" section is read
Then it lists "PROJECT_CONTEXT.md" and references to skill SKILL.md files

Given the agent template body is inspected
When the "Prompt-Quality Checklist" section is read
Then it contains at least 6 checklist items:
  1. No compound bash commands (&&, ;, ||, chained pipes)
  2. Tool allowlist in frontmatter matches tools used in body
  3. No tools referenced in body absent from allowlist
  4. spawn_allowlist declared for agents spawning sub-agents
  5. Signoff protocol section present for signoff: true agents
  6. Stop-and-ask rules present for scope boundaries
And the checklist includes detection heuristics with example patterns

Given the agent template body is inspected
When the "Stop-and-Ask Rule" section is read
Then it states that llm-expert must defer registry edits to workflow-architect

Given the agent template body is inspected
When the "Skills" section is read
Then it lists add-agent-to-package, add-skill-to-package, and signoff
And includes when to invoke each skill

Given the agent template body is inspected
When the "Sign-off" section is read
Then it follows the signoff skill §2c recipe with appropriate checkboxes

Given the agent template body is inspected
When the "Constraints" section is read
Then it prohibits: editing Python/SQL/frontend files, editing registry or build pipeline, and compound bash commands
```
