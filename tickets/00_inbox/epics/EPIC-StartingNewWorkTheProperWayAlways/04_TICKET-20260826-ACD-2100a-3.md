# The startup charter check finds the agent registry when the run starts inside a worktree

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `ACD-2100a-3` — The startup charter check finds the agent registry when the run starts inside a worktree — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `ACD-2100a-3`. Component: `ac-driven-dev`. Assigned agent: `python-coder`. Estimated complexity: `S`. Complexity: `low`.

## Acceptance Criteria

```gherkin
Given a run started with the process working directory set to a git worktree of
  the project,
And that worktree holds no installed copy of the route's own support files -- a
  directory listing under it shows no registry to read,
And the project itself holds a registry that lists the agent the route uses to
  create the authoring worktree and permits it to run repository commands,
When the route performs its startup check on that agent,
Then the check reads the project's registry and returns a verdict derived from
  its contents,
And the run continues past the check to the next step,
And the check does not report the registry as missing or unreadable.
```

## Implementation Notes

```yaml
- The change must land under templates/. The deployed workflow under .leafcutter/workflows/
  is build output.
- Must use the same resolution ACD-2100a-1 establishes rather than a second, independent
  one. Two resolvers on the same startup path is how the five sites came to disagree
  in the first place.
- The registry must be read from the local filesystem only. Adding a network or agent
  round-trip to satisfy this read reintroduces the failure class ACD-2100b-5 removes.
- A worktree that happens to hold its own installed support directory must still resolve
  to a registry -- the behaviour must not depend on the worktree being empty of one,
  only on the run reaching a real registry.
- 'Must satisfy the repository error-handling policy: the read is external I/O; a
  failure must be reported through the outcomes ACD-2100b-1 and ACD-2100b-2 specify,
  never swallowed into a false verdict.'
- The read must add no measurable startup cost beyond a single file open -- no directory
  tree walk over the project on every run.
```
