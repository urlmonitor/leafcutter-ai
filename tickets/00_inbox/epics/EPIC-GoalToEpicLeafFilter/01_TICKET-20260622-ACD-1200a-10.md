# Leaf collection excludes done and superseded ACs while still recursing into a superseded AC's replacement children

## Context

This ticket was generated from AC store entry `ACD-1200a-10`. Component: `ac-driven-dev`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given the AC store contains these leaf ACs beneath goal ACD-070:
  - ACD-070a-1 (level: L2, status: active, work_status: done)
  - ACD-070a-2 (level: L2, status: active, work_status: todo)
  - ACD-070b-1 (level: L2, status: superseded_by, superseded_by: [ACD-070b-1a, ACD-070b-1b],
      covered_by: [ACD-070b-1a, ACD-070b-1b])
  - ACD-070b-1a (level: L2, status: active, work_status: todo)
  - ACD-070b-1b (level: L2, status: active, work_status: todo)
When the leaf collection over goal ACD-070 runs with its exclusion flags at their defaults,
Then the returned leaf list does NOT contain ACD-070a-1 (it is already done),
And the returned leaf list does NOT contain ACD-070b-1 (it was superseded by a split),
And the returned leaf list DOES contain ACD-070a-2 (active + todo, the unchanged default),
And the returned leaf list DOES contain both ACD-070b-1a and ACD-070b-1b
  (traversal still recurses into a superseded AC's covered_by so the replacement
  children are collected even though their superseded parent is skipped),
And a leaf that is itself active and todo is always emitted unchanged.

And the exclusion is parameterizable via two flags (exclude_done and
  exclude_superseded) that both default to True, so the leaf-collection
  function stays unit-testable with exclusions individually toggled off,
And when both flags are passed as False the returned leaf list contains all
  five ACs (ACD-070a-1, ACD-070a-2, ACD-070b-1, ACD-070b-1a, ACD-070b-1b),
  reproducing the prior unfiltered behavior.
```
