# The maker's answer is one readable answer and nothing else

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-4300c-2` — The maker's answer is one readable answer and nothing else — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-4300c-2`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given each of these outcomes -- ready; refused because the location is
  occupied; refused because the shared project cannot be reached; refused
  because the install failed -- and underlying tools that print their own
  progress messages during the request, such as "HEAD is now at bc5d638 init",
When the channel that carries the workspace maker's answer is read,
Then it holds exactly one answer and nothing else, in every one of the four
  outcomes,
And the answer always states whether the result is ready or refused,
And the underlying tools' own messages are available separately and never
  appear in the answer,
And the way the maker's run ends signals the same outcome that the answer
  states.
```

- [ ] AC-1: it holds exactly one answer and nothing else, in every one of the four
- [ ] AC-2: the answer always states whether the result is ready or refused
- [ ] AC-3: the underlying tools' own messages are available separately and never
- [ ] AC-4: the way the maker's run ends signals the same outcome that the answer

## Implementation Notes

```yaml
- 'stdout is reserved for the one answer: every child process (git, submodule, package
  installers, the build) runs with its stdout and stderr captured and forwarded to
  the maker''s stderr; the answer is a single JSON object (UTF-8, no BOM, one trailing
  newline allowed).'
- Exit code always matches status (0 ok, 2 refused, 1 error, 64 usage); a usage error
  and an internal exception still produce one JSON object.
- The contract is versioned by schema_version; adding a field is compatible, renaming
  or removing one bumps it. workspace_path is the canonical key; worktree_path is
  kept as an alias for existing callers. The per-stage hook checks, hooks_stages_declared,
  inactive_stages and the two ticket fields are additions (compatible); hooks_canary_rejected
  keeps its name and now means "every declared stage fired".
- 'The ticket fields follow the same presence rule as workspace_path: present only
  on an ok answer, and only when the request named a ticket; their value is never
  the path the caller passed in (BO-4300a-1-ii).'
- This record is the single authoritative statement of the result contract. Other
  records that need it (BO-4300a-5, callers' expects_from) point to it rather than
  restating it, so a field added here cannot be missed in a copy.
- The maker never reads stdin and never prompts; every decision it needs arrives as
  an argument of the request, so an unattended caller can never stall on it.
- Proof runs the DEPLOYED maker -- the copy an install delivers, resolved through
  the shared test locator delivered by BO-4300f-4 -- as a separate process against
  real temporary git repositories with a real bare hub. No mock of git, no import
  of the maker module, no grep of its source (CLAUDE.md 'Gate / Workflow ACs -- Verify
  Behaviorally, Not by Grep'); a test never falls back to the templates/ source copy.
- 'Tests must not spawn the package''s own scripts/build.py (CLAUDE.md ''Tests must
  not spawn their own build.py''): the deployed maker comes from the shared deployed
  layout, and fixture projects carry a minimal stub build entry point that installs
  a real, rejecting hook in well under a second. A test that must mutate the package
  and build its own copy says so and justifies it in its ticket.'
- All temporary projects, hubs and workspaces live under the test's temp directory
  and run git with an isolated global and system config; afterwards the developer's
  own repository's branches, registered worktrees and local git config are unchanged
  (BO-4300f-4-i, F14, KI-TQ-012).
```
