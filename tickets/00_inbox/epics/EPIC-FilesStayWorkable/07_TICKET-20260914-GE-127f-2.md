## Acceptance Criteria

```gherkin
Given a tracked file of a kind the size standard covers stands at 600 measured
  lines before the change, against a permitted length of 400,
And a change is staged that replaces five measured lines of that file with five
  different measured lines, so the file still stands at 600,
When the author performs an ordinary commit,
Then the commit does not complete, and the outcome states that the change added
  five lines and that the file is required to stand at 595 or below,
And given instead the same 600-line file and a change that puts 40 measured
  lines into it and takes 40 measured lines out of it, so the file still stands
  at 600,
When the author performs an ordinary commit,
Then the commit does not complete, and the outcome states that the change added
  40 lines and that the file is required to stand at 560 or below — the number
  of lines the change added is read from what the change put into the file, and
  never from the difference between the file's two lengths,
And given the same 600-line file and the same 40 lines in and 40 lines out, with
  the change taking a further 40 measured lines out so the file stands at 560,
When the author performs an ordinary commit,
Then the commit completes,
And given the same 600-line file and a change that takes 12 measured lines out
  of it and puts none in, leaving it at 588,
When the author performs an ordinary commit,
Then the commit completes, and nothing further is required of the change,
And given the same 600-line file and a change that puts content into it that the
  measurement rule does not measure and takes nothing out, so the file still
  stands at 600,
When the author performs an ordinary commit,
Then the commit completes — the change added no measured lines, so the file is
  required only to stand where it already stood, and this is the one remaining
  shape under which a change leaving an already-oversized file at exactly its
  previous length is still accepted.
```

- GROSS, NEVER NET, AND NEVER THE SUBTRACTION THAT IS ALREADY IN HAND. The number
  of measured lines the change added is read from WHAT THE CHANGE PUT INTO THE FILE.
  It must never be derived from the difference between the two lengths the comparison
  already holds. This is the single most likely wrong implementation precisely because
  an implementer holding two lengths and needing a third number will reach for the
  subtraction. Under a net reading the rule is self-referential — the quantity being
  constrained appears on both sides — and collapses to "the file must end at or below
  its previous length", which is GE-127b unchanged. A net reading does not weaken
  this record, it deletes it and the whole of GE-127f with it.
- 'COUNTED IN THE FILE''S OWN UNIT, BY THE FUNCTION THAT PRODUCED BOTH LENGTHS, ON
  BOTH SIDES. _file_size_ratchet.count_content_lines is the single measurement rule
  behind the current length and the previous length; the added-line count must be
  denominated in exactly that unit. THIS IS SHARPER THAN IT LOOKS: counting `+` lines
  out of a textual diff is a SECOND COUNTING RULE wearing a plausible disguise, because
  the measurement rule strips triple-quoted regions and block comments that span lines,
  and a per-line diff read cannot see those regions. Derive the count so that it agrees
  by construction with the one function — for example by measuring the same content
  the function measures on both sides of the change — rather than by a parallel line-classifier
  that happens to agree on today''s fixtures. GE-127d owns which lines count; do not
  restate it and do not write a second version of it here.'
- 'GE-127b-1''s DELIVERED BOUNDARY DESCRIPTOR IS RECONCILED IN THIS SAME CHANGE, AND
  THAT RECONCILIATION IS THIS RECORD''S TO EXECUTE. GE-127b-1 is done and green. test_ge_127b_1_an_oversized_file_left_at_exactly_its_previous_length_commits
  asserts that a change leaving an already-oversized covered file at exactly its previous
  length commits, and GE-127b-1''s it_requirements pin the boundary at strictly greater-than.
  Once this record lands that holds for exactly ONE shape: a change that added no
  MEASURED lines. The descriptor''s fixture today does not say which shape it exercises.
  Required: the descriptor is NOT deleted and its assertion is NOT weakened; its fixture
  is PINNED to a change that adds no measured lines to the oversized file — a pure
  deletion, or an edit touching only content the measurement rule does not measure
  — and its name and description are amended to say so. The case it used to cover
  implicitly and no longer does becomes this record''s first arm, where it is refused.
  GE-127b''s strictly-greater-than boundary survives as the boundary of GE-127b''s
  OWN comparison; what changed is the threshold that comparison is judged against,
  not the direction of the inequality. This is a deliberate narrowing already recorded
  on GE-127b''s amended_by, not a regression, and it is not licence to re-open GE-127b''s
  criteria, which stay untouched. The surviving shape is this record''s last arm:
  adding only unmeasured content is free.'
- 'THE DOCSTRING-ONLY LOOPHOLE IS THE HONEST CONSEQUENCE OF THIS RECORD AND MUST BE
  RECORDED RATHER THAN HIDDEN. Because additions are counted in the same unit as the
  file''s length, a change that adds ONLY docstrings or block comments has added nothing
  measured and is therefore free AT ANY SIZE — an arbitrarily large docstring-only
  addition to an already-oversized file commits. This will look like a bug to whoever
