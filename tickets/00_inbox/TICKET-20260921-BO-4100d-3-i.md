## Implementation Notes

```yaml
- Sanitisation must be reported, not hidden. The requested name and the created name
  must be carried as two separate machine-readable values, so a caller can tell an
  alteration from an exact match without comparing strings itself.
- The sanitisation rule must preserve the kind. An alteration that strips or mangles
  the kind prefix turns a legitimate rename into a BO-4100d-1 violation, and the two
  records would then contradict each other.
- Sanitisation must be deterministic -- the same requested name always yields the
  same branch name -- or the reconnect/reuse lookup cannot find the prior workspace
  and a repeated request produces a second one.
- The set of characters that trigger alteration must be derived from what a branch
  name can actually carry (git's own ref-name rules), not from a hand-written list,
  so a character git rejects and the list omits does not produce a creation failure
  instead of a rename.
- 'This carve-out must not widen BO-4100d-3: a difference between requested and created
  name is acceptable ONLY when it is an alteration this rule produced. Any other difference
  is still the failure BO-4100d-3 reports.'
```
