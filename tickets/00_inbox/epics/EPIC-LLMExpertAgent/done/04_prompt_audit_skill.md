# 04: Create prompt-audit skill

## Goal

Create a `prompt-audit` skill that systematically audits agent templates and skill files against the Prompt-Quality Checklist. The skill encapsulates detection heuristics for compound bash commands, missing signoff protocol, tool allowlist mismatches, and other convention violations.

## Context

Stub generated by create-epic. Harden with create-ticket (depth 2).

The llm-expert agent needs a systematic way to audit templates and detect violations. The prompt-audit skill is a reusable component that:
- Inspects agent template frontmatter for required fields (name, description, model, tools, portable, signoff, spawn_allowlist if applicable)
- Parses tool allowlists and cross-references them against tools actually used in the template body
- Detects compound bash commands in tool call descriptions (&&, ;, ||, pipes that chain side effects)
- Verifies signoff protocol sections exist and follow the correct format
- Checks that spawn_allowlist is declared for agents that spawn sub-agents
- Verifies stop-and-ask rules are documented for scope boundaries
- Reports violations in a structured format so llm-expert can address them systematically

The skill encapsulates the detection heuristics so they can be reused across multiple audit passes and versions of the agent. It loads only Bash and Read tools (read-only inspection).

## Acceptance Criteria

```gherkin
Given the prompt-audit skill is created at templates/skills/prompt-audit/SKILL.md
When the frontmatter is inspected
Then it contains:
  name: "prompt-audit"
  description: "Audit agent templates and skill files against the Prompt-Quality Checklist. Detects violations: compound bash commands, tool allowlist mismatches, missing signoff protocol, missing spawn_allowlist. Reports structured findings."
  allowed-tools: ["Bash", "Read"]
And the skill is portable: true

Given the skill body is read
When the auditor scans a template file
Then it performs the following checks:

Check 1: Frontmatter schema validation
- Required fields exist: name, description, model, tools, portable, signoff
- Field values are valid (model is one of: claude-opus, sonnet, claude-opus-mini)
- tools is a non-empty, comma-separated or array list
- portable is boolean
- signoff is boolean

Check 2: Tool allowlist vs body usage
- Extract tools from frontmatter allowlist (e.g., "Bash, Read, Edit, Write")
- Scan body for tool invocation patterns (e.g., "Bash tool call", "### python-coder", agent spawn patterns)
- Flag any tool mentioned in body that's not in allowlist
- Flag allowlisted tools never mentioned in body (overly permissive)

Check 3: Compound bash detection
- Scan for patterns in Bash descriptions:
  - " && " (and operator)
  - " ; " (semicolon outside quotes)
  - " || " (or operator)
  - "cd <path> &&" (cd followed by another command)
  - "| <command>" where <command> produces side effects (not tail, head, grep)
- Flag occurrences with line number and suggested fix (split into separate tool calls)

Check 4: Signoff protocol validation
- If signoff: true in frontmatter, verify "## Sign-offs" section exists in body
- Verify section contains checkboxes for all needed agents listed in agents: map
- Verify format matches "- [ ] <agent-name>"

Check 5: spawn_allowlist validation
- If agent spawns sub-agents (evidenced by Agent tool invocation or mention of spawning), verify spawn_allowlist is declared in frontmatter
- Flag agents with "Agent" tool but no spawn_allowlist
- Verify spawn_allowlist is a list and contains valid agent names

Check 6: Stop-and-ask rules
- If agent has scope boundaries (e.g., python-coder should not edit non-Python files), verify stop-and-ask rule section exists
- Check for clear statements like "Stop and defer to <agent>" or "Do not edit <file type>"

Given the skill is invoked on a template file
When it completes an audit pass
Then it returns a structured report containing:
  - template_name: the agent/skill name from frontmatter
  - frontmatter_valid: boolean
  - tool_allowlist_valid: boolean
  - no_compound_bash: boolean
  - signoff_protocol_valid: boolean (if applicable)
  - spawn_allowlist_valid: boolean (if applicable)
  - violations: array of violation objects, each with:
    - check_name: string (e.g., "compound_bash_detection")
    - severity: string (one of "error", "warning")
    - line_number: integer
    - description: string
    - suggested_fix: string (optional)
  - passed_checks: array of check names that passed
  - recommendations: array of improvement suggestions

Given a template has multiple violations
When the skill reports
Then violations are sorted by line number
And the report summary shows total_violations, total_errors, total_warnings
```
