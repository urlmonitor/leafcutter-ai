summary: "The documentation orchestrator required a genre-mapping file that has never existed in any commit, so it quietly invented the mapping instead. All references now point at the two files that actually hold that content."
description: "documentation-expert declared a pre-flight read of docs/README.md and its body called that file the single source of truth for where each documentation genre lands. The file has never existed — git log over all branches returns nothing for it, and it was already absent from the day-one extraction tree, so the reference was inherited from the monorepo this package was split out of and arrived orphaned. No acceptance criterion, ticket, ADR, changelog entry or known-issue ever asked for it to be written. The failure was silent rather than loud because the frontmatter marked the read optional while the body called it mandatory and authoritative, and no absent-file behaviour was stated anywhere, so the agent improvised the genre mapping and produced a confidently misfiled document instead of an error. The fix is a pointer change, not new prose, because the content already existed in two places and authoring the file would have created a third source of truth for a mapping that already had two. Genre routing now points at config/doc_types.json, which already carries the classification description, the writer agent and the default path for every genre and whose own comment calls it the single source of truth for exactly that; navigation points at docs/INDEX.md, which the index generator already writes while explicitly excluding README.md, showing the index role had been consciously assigned away from README.md long ago. The pre-flight read is now required with an explicit stop-and-report-a-blocker posture, so an unreadable mapping fails loudly instead of being improvised around. Nineteen live references were repointed across agent templates, the documentation workflow, four repo docs, three agent reference docs and two shipped templates — the last of these mattering most, since those propagate the dead link into every adopter install. Two short notes remain in the templates recording that the file never existed and must not be reintroduced. The change is verified through the build round-trip, so the deployed agent copies carry it too. Filed as KI-DS-003 is the part that is not fixed: the build's self-description validator checks only that the pre_flight_reads key is present and never resolves the paths inside it, so any agent in the package can still declare a read of a nonexistent file and pass the build. There is also no link checker for relative markdown links under the docs tree, which is why the agents README currently carries thirty-two broken links out of thirty-eight in one table."
