## Actor / Goal

## Acceptance Criteria

```gherkin
Given the AC-parent-covered-by pre-commit check is invoked on 6 staged AC YAML files
  that each violate the parent covered_by rule,
And the working copy it runs from does not expose the deployed layout, so the check
  cannot reach the parent-id derivation helper it needs to evaluate any of those files,
When the check finishes,
Then its output states that it did not inspect the staged files, names the prerequisite
  it could not reach, and names what was consequently left unverified — for example
  "parent covered_by links were not evaluated for 6 staged files",
And the outcome is emitted in a form a caller can distinguish from a clean run without
  reading prose: a distinct could-not-check result value, not the same success value a
  clean run produces,
And the behaviour observed today — a single stderr line reading "cannot import
  derive_parent_id ...; skipping check (fail-open)" followed by an ordinary success
  result — no longer satisfies the check's contract,
And this criterion does not by itself decide whether the commit is blocked; the
  per-check block-or-announce decision is governed by GE-120a-2.

Coverage note: this criterion is covered only by a test that EXECUTES the check under a
genuine cannot-reach condition and asserts on the observed result value and output text.
A test that searches the check's source for a warning string does not cover it — a
grep-only test passes on dead code (CLAUDE.md, "Gate / Workflow ACs — Verify
Behaviorally, Not by Grep").
```
