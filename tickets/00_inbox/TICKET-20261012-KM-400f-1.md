Given a declared bound names a generation count but no minimum retirement age
When the retention policy is evaluated
Then the evaluation refuses and names the missing minimum retirement age
And it does not treat generation count alone as the whole bound

do not detect it. Harmless while the evaluation only reports; a data-loss path for any
caller that deletes what it names. Recorded as a BLOCKING PRECONDITION in KM-400f-2's
`amended_by`, and as explicit not-established caveats in both doc pages.

M-1 (carried): after a rollback the active generation can be older than retained ones,
so a limit of 3 retains 4 — the active one plus three newest retired. The AC's
G32/G31/G30 example does not cover this case.

M-2 (carried): sorting on `created_at` raises TypeError when any generation has it null;
one legacy `storage_version` node would crash the whole report rather than yield a verdict.

Neither medium blocks a report-only evaluator. Both belong to the reclaiming path.

`write=False`; OPTIONAL MATCH/MATCH/RETURN only; no SET/MERGE/DELETE and no lock
increment), the count bound is 0-based so a limit of 3 keeps G32/G31/G30 as specified,
and the minimum-age comparison treats exactly-the-minimum as old enough, matching the
AC's "younger than". Cosmetic `_NO_BOUND =` spacing fixed. ruff clean; 5/5 tests green
