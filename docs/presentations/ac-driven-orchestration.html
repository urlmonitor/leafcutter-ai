Part 2 — The proposal

The PO already produces value propositions. They deserve a delivery surface.

L0/L1 ACs are written in deliberate customer language — taglines and value narratives, no engineering jargon. Today they sit as YAML in the store. A stakeholder never sees them.

The idea: a presentation agent that pairs with the PO — it takes the value propositions the PO authors and renders them as stakeholder-ready presentations now, and emails later.

Part 2 — Where it fits in the registry

A new delivery / communication agent class.

Sits alongside the existing authoring & documentation agents — but its audience is stakeholders, not the build pipeline.

exists

documentation-expert

Routes how-tos, ADRs, references, diagrams. Audience: engineers. Surface: the docs tree.

proposed

presentation-agent

Renders PO value propositions into decks & emails. Audience: stakeholders. Surface: presentations / outbound comms.

Pairs with /po the way it-po pairs with the BA — a downstream specialist that consumes one stage's output and produces a new artifact class.

Part 2 — A maturity path for the agent

Decks first. Emails next. Auto-triggered last.

Phase 1 · now

Value-prop decks

On request, render approved L0/L1 ACs into a self-contained stakeholder deck. Manual invocation.

Phase 2 · next

Stakeholder emails

Same value-prop source → a tailored email / update for a named audience & tone.

Phase 3 · later

Auto-triggered

Fires when the PO marks a value proposition approved — delivery becomes a pipeline step, not a chore.
