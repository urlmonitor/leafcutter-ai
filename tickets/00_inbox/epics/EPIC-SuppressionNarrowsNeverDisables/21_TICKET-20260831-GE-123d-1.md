# A quoted value that names a file is not read as a credential, in any file

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-123d-1` — A quoted value that names a file is not read as a credential, in any file — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-123d-1`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a changelog entry staged for commit is a Markdown file containing one
  sentence that instructs a reader to add a suppression, written as the rule
  name GENERIC_SECRET, a colon, and then the quoted repository-relative path
  "docs/foo.md",
When the staged file is checked by the pre-commit secrets check,
Then no generic-credential finding is reported for that line,
And the commit is not blocked,
Because a quoted value that ends in one of the recognised text-file
  extensions (.md, .yaml, .yml, .py, .json, .txt), with or without a leading
  directory path, is a file reference and cannot be a live credential.

Given a source file named "secrets.py" staged for commit contains the
  identical sentence inside a code comment,
When the staged file is checked by the pre-commit secrets check,
Then no generic-credential finding is reported for that line either,
And the commit is not blocked,
Because this narrowing is a property of the VALUE and not of the file's
  location — it is the only part of this feature that applies to source,
  configuration and prose alike.

Given a source file named "secrets.py" staged for commit contains a line
  made of one of the credential keywords the rule recognises (password,
  passwd, secret, token, auth_key), a separator, and a quoted sixteen-
  character value that ends in none of the recognised text-file extensions,
When the staged file is checked by the pre-commit secrets check,
Then the generic-credential finding IS reported, naming the file and its
  1-based line number,
And the commit is blocked,
Because narrowing the rule by value shape must not weaken it for any value
  that is not a file reference.
```

- [ ] AC-2: the commit is not blocked
- [ ] AC-3: no generic-credential finding is reported for that line either
- [ ] AC-4: the commit is not blocked
- [ ] AC-5: the generic-credential finding IS reported, naming the file and its
- [ ] AC-6: the commit is blocked

## Implementation Notes

```yaml
- The file-reference decision must be computed from the full matched quoted value.
  The finding excerpt the pre-commit post-filter receives today is the stripped source
  line truncated to 120 characters, so a value whose closing quote falls past column
  120 would otherwise change verdict by line length alone. Carrying the matched value
  forward and re-reading the line are both acceptable; a verdict that depends on where
  column 120 falls is not.
- 'Both entry points that can report this rule must apply the narrowing identically:
  the pre-commit hook (templates/scripts/commit_guardian/check_secrets.py) and the
  scanner run directly as a CLI or by /security-audit (templates/skills/security-scanner/scripts/scan_secrets.py).
  Define the value-shape vocabulary once, in one place both read. The hook is the
  load-bearing enforcement point because it is the one that gates commits, but a narrowing
  applied only there lets the two tools reach opposite conclusions about the same
  line.'
- The recognised text-file extension set must be exactly the six extensions enumerated
  in the criteria, held as named data at a single site, so adding a seventh is one
  deliberate edit and never an inference from resemblance.
- The shape must be anchored to the END of the quoted value. A value that merely contains
  a recognised extension somewhere inside it is not a file reference and must still
  be reported.
- This feature narrows one rule only. The private-key, cloud-access-key, exchange-API-key
  and high-entropy rules must be unaffected in every file, and a regression arm must
  demonstrate that rather than assume it.
- Because this narrowing is global — the only part of GE-123d that reaches source
  and configuration — its blast radius must be measured, not argued. Scan the tracked
  tree before and after the change and confirm every finding that disappears is file-reference
  shaped. A widening whose effect on the real repository cannot be enumerated has
  not been reviewed.
- 'Per-finding cost must stay proportionate to a pre-commit hot path: no additional
  file reads beyond the one the scanner already performs, and no matcher whose worst
  case is superlinear in line length, because staged files include machine-generated
  long lines.'
- No diagnostic, log line or error message added by this work may reproduce a matched
  value.
- 'ADR-001 parity: the canonical sources are the two files under templates/; the copies
  under scripts/ and .leafcutter/ are build.py outputs and must not be hand-edited.
  Verify the change through the build.py round-trip so the deployed hook and its packaged
  source stay in step.'
```
