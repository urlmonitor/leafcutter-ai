# Until the cut-over completes, automatic housekeeping cannot prune the shared history

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-4300f-3-ii` — Until the cut-over completes, automatic housekeeping cannot prune the shared history — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-4300f-3-ii`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given old-style workspaces still share the main copy's version history,
When enough commits are made in the main copy that version control's automatic
  housekeeping would otherwise start,
Then that housekeeping does not run until the cut-over has retired or brought
  over the last old-style workspace,
And every commit each old-style workspace refers to is still readable afterwards.
```

- [ ] AC-1: that housekeeping does not run until the cut-over has retired or brought
- [ ] AC-2: every commit each old-style workspace refers to is still readable afterwards.

## Implementation Notes

```yaml
- The cut-over sets gc.auto 0 and maintenance.auto false on the main checkout while
  any legacy workspace remains (ADR-018 migration step 2, never applied), records
  the previous values, and restores them only after the last legacy workspace is retired
  or brought over.
- Proof triggers git's automatic housekeeping for real (enough loose objects past
  a lowered threshold) and checks every commit each legacy workspace refers to with
  `git cat-file -e`.
- Proof runs the DEPLOYED maker -- the copy an install delivers, resolved through
  the shared test locator delivered by BO-4300f-4 -- as a separate process against
  real temporary git repositories with a real bare hub. No mock of git, no import
  of the maker module, no grep of its source (CLAUDE.md 'Gate / Workflow ACs -- Verify
  Behaviorally, Not by Grep'); a test never falls back to the templates/ source copy.
- All temporary projects, hubs and workspaces live under the test's temp directory
  and run git with an isolated global and system config; afterwards the developer's
  own repository's branches, registered worktrees and local git config are unchanged
  (BO-4300f-4-i, F14, KI-TQ-012).
```
