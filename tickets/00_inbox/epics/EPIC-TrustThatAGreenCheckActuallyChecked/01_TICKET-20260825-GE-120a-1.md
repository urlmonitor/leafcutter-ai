## Acceptance Criteria

```gherkin
Given the AC-parent-covered-by pre-commit check is invoked on 6 staged AC YAML files
  that each violate the parent covered_by rule,
And the working copy it runs from does not expose the deployed layout, so the check
  cannot reach the parent-id derivation helper it needs to evaluate any of those files,
When the check finishes,
Then its output states that it did not inspect the staged files, names the prerequisite
  it could not reach, and names what was consequently left unverified — for example
  "parent covered_by links were not evaluated for 6 staged files",
And the outcome is emitted in a form a caller can distinguish from a clean run without
  reading prose: a distinct could-not-check result value, not the same success value a
  clean run produces,
And the behaviour observed today — a single stderr line reading "cannot import
  derive_parent_id ...; skipping check (fail-open)" followed by an ordinary success
  result — no longer satisfies the check's contract,
And this criterion does not by itself decide whether the commit is blocked; the
  per-check block-or-announce decision is governed by GE-120a-2.

Coverage note: this criterion is covered only by a test that EXECUTES the check under a
genuine cannot-reach condition and asserts on the observed result value and output text.
A test that searches the check's source for a warning string does not cover it — a
grep-only test passes on dead code (CLAUDE.md, "Gate / Workflow ACs — Verify
Behaviorally, Not by Grep").
```

## Implementation Notes

```yaml
- 'Target is concrete: templates/scripts/commit_guardian/check_ac_parent_covered_by.py.
  The cannot-run branch to replace is its PRIVATE _get_derive_parent_id() fallback
  (~line 377), which today prints ''cannot import derive_parent_id ...; skipping check
  (fail-open)'' and returns an ordinary success. VERIFIED 2026-08-14: this check does
  NOT import the shared templates/scripts/commit_guardian/_resolve_root.py that 27
  other files in the family already use.'
- The could-not-check outcome must be machine-readable INDEPENDENTLY of the exit code.
  GE-120a-2 permits an announce disposition that still exits 0, so exit status alone
  cannot carry the distinction. Callers (pre-commit, the GE-120b-4 sweep, the GE-120c-1
  harness) must tell could-not-check from clean-pass without parsing prose.
- 'Declare the outcome vocabulary ONCE in a shared module under templates/scripts/commit_guardian/
  that every check imports. Do not re-declare the values per check: a per-check copy
  reproduces the 19-instance private-root-walk pattern that GE-120b-2 exists to remove.'
- Any new shared module a hook imports MUST be added to the build deploy manifest
  (deploy_map in scripts/build_phases.py). An undeployed hook dependency raises ModuleNotFoundError
  at hook runtime from the deployed layout and blocks every commit (CLAUDE.md, 'New
  Hook / Gate Dependencies Must Be in the Build Deploy-Manifest').
- 'ADR-001 deployed/template parity: edit templates/scripts/commit_guardian/ (canonical),
  then run ''python scripts/build.py --target-dir .'' so scripts/commit_guardian/
  and .leafcutter/scripts/commit_guardian/ match. check_hook_parity enforces all four
  locations (config section hook_parity: runtime_dir scripts/commit_guardian, canonical_template_dir
  templates/scripts/commit_guardian, legacy_template_dir templates/commit-guardian,
  deployed_output_dir .leafcutter/scripts/commit_guardian). A template-only fix is
  a NO-OP in the deployed layout, which is the exact defect class this tree closes.'
- The message must name BOTH the unreachable prerequisite AND the unverified scope
  (for example '6 staged files not evaluated'). Naming only the failed import is insufficient;
  GE-120b-1-i requires reader-actionable wording.
- 'Main-checkout behaviour must be unchanged: with the prerequisite reachable, the
  same staged set still blocks with the same 6 violations (the GE-118a-1 backward-compatibility
  precedent).'
- 'Error-handling policy: the cannot-run branch catches a SPECIFIC exception (ImportError
  / OSError), logs at WARNING, and converts to the could-not-check outcome. No bare
  except, no silent swallow (CLAUDE.md Error Handling Rules 1-3).'
```
