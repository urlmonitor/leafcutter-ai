## Implementation Notes

```yaml
- ADD `declared_by` AND `pinned_by` TO config/ac_store_schema.json. Both are arrays
  of strings, both optional, both defaulting to []. `declared_by` holds FrontendComponent
  paths; `pinned_by` holds AcDeclaration pin slugs (GE-124b-1's deterministic slug
  — this is why that slug must be stable). Document both in docs/reference/ac-schema.md
  alongside covered_by and implemented_by, stating explicitly what each does and does
  NOT establish. This schema change is real work that must land before anything can
  write the fields; scripts/ac_store/validate_ac_schema.py and scripts/commit_guardian/check_ac_schema.py
  validate against that one file, so both validators pick it up together.
- THE REJECTION MUST BE ENFORCED ON THE GATE THAT ACTUALLY RUNS. Adding the fields
  to the JSON schema does NOT by itself reject a bad covered_by entry — a front-end
  path is a valid string and passes a type check. The rejection needs an explicit
  rule in the AC-schema validation path (the _ac_schema_validators surface that check_ac_schema.py
  already calls per file, and which validate_ac_schema.py shares), so it fires on
  the staged commit. A rule added only to the JSON schema is a no-op here.
- 'THE DETECTION RULE MUST BE STATED, NOT LEFT TO INTUITION. A covered_by entry that
  names a front-end source path (an in-scope extension per GE-124a-2''s map) or matches
  a pin-slug shape is rejected. Note the honest limit: covered_by legitimately holds
  test references, and a front-end TEST file also has an in-scope extension — so the
  rule must exclude the named test/story exclusions (GE-124a-3-ii) before rejecting,
  or every legitimate front-end test reference is refused. Get this boundary right
  or the rule is unusable.'
- THE REJECTION MESSAGE NAMES THE FIELD THE VALUE BELONGS IN — declared_by for a component-level
  declaration, pinned_by for a pin — so the fix is one move rather than a puzzle.
- NO OPT-OUT, AND NO CONFIGURATION KEY THAT PERMITS ONE. GE-124d's escapes govern
  whether a FILE MUST DECLARE; they have no application here. A configurable version
  of this rule is not a rule. The configuration surface itself is GE-124g-1-i.
- WRITING declared_by / pinned_by IS THIS AC'S BUSINESS; READING THEM AS EVIDENCE
  IS NOT ANYONE'S. GE-124e-2 must scan front-end source rather than consult these
  fields — they are the recorded projection of that scan, and a gate reading them
  would check the store against itself.
- '`implemented_by` IS EXPLICITLY RULED OUT AND THE REASON MUST SURVIVE IN THE SCHEMA
  DOCUMENTATION: it records a link established by completed work, whereas a declaration
  is an unverified claim a file makes about itself. Folding them would make implemented_by
  mean two things.'
```
