## Implementation Notes

```yaml
- 'PREREQUISITE THAT DOES NOT EXIST YET — READ THIS FIRST. The criteria assume ''the
  design''s own rendered markup carries element pins''. It does not. Verified 2026-08-25:
  docs/product-truth/mockups/fern-and-fig/ contains five rendered .html files (plant-listing,
  plant-detail, cart, checkout, order-confirmation) and NONE of them contains a single
  `data-ac` attribute; the .mockup.json records carry `screen`, `renders` (the html
  filename) and `entities`, but no per-criterion element mapping. This AC therefore
  has an unbuilt prerequisite: mockup markup must start carrying data-ac pins, which
  is mockup-author''s surface and is NOT covered by any AC in the GE-124 family. Either
  land that prerequisite first or this AC compares against an empty set and reports
  every criterion as missing from every built page. Flagged to the user rather than
  absorbed.'
- THE COMPARISON IS OVER ELEMENT PINS, NOT PIXELS, and is read from both sides with
  the SAME shared reader (GE-124b-1). Comparing rendered appearance is a different
  and much larger problem with a far worse signal-to-noise ratio; comparing which
  criteria each side claims to render is mechanical, stable, and answers the question
  the realisation label actually makes. Using one reader for both sides is what makes
  the two pin sets commensurable.
- THE DERIVED LABEL TAKES PRECEDENCE, AND PRECEDENCE MEANS THE HAND-WRITTEN VALUE
  IS NOT CONSULTED WHEN A COMPARISON IS AVAILABLE. Resolve the label in one place,
  comparison-first. Without precedence the derived result is advice and the hand-written
  label still governs, which leaves the phantom-done pattern exactly where it was
  — the PO's whole reason for this AC.
- A PAGE OUTSIDE THE CHAIN HAS NO COMPARISON AND MUST KEEP ITS HAND-WRITTEN LABEL
  WITHOUT PENALTY (GE-124f-1-ii). Precedence applies when a comparison exists; absence
  of a design is not evidence of a mismatch. Conflating the two would report every
  unmodelled page as unbuilt.
- 'THE DIFFERENCE IS DIRECTIONAL AND BOTH DIRECTIONS ARE REPORTED SEPARATELY: in the
  design and absent from the page (the criteria''s case, an incomplete build), and
  on the page and absent from the design (a page claiming a criterion the design never
  had — either an undocumented addition or a stale design). A symmetric set-difference
  collapses two different conversations into one number.'
- THIS IS A REPORTING/DERIVATION SURFACE, NOT A COMMIT GATE. It produces a comparison
  and a label; it must not block a commit, and its output feeds GE-124g-3's reporting,
  where it is counted on its own axis and never folded into a coverage figure. A matching
  comparison proves the built page CLAIMS what the design claims — it does not prove
  the behaviour behind it works.
- Must handle errors gracefully per the project error handling policy; an unreadable
  mockup file must be named rather than silently producing an empty design-side pin
  set, which would report every criterion as missing from the built page.
```
