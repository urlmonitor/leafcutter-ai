## Implementation Notes

```yaml
- 'Author under docs/how-to/ with check_doc_frontmatter-compliant frontmatter for
  docs/** (title, type: how-to, status, created, last_updated, components, description)
  and stay within the check_doc_length budget.'
- THE FIVE MARKUP EXAMPLES MUST BE EXECUTABLE. Each is a complete opening tag in its
  file shape, written so the test contract can extract it verbatim and feed it to
  the real pin reader. An example the reader would not accept teaches the author a
  form that fails, which is worse than no example.
- THE BLOCK REPORT SHOWN MUST BE THE REAL ONE. Reproduce the message the commit-tier
  check actually emits for an undeclared-but-pinned file (GE-124c-1-i), captured from
  the check rather than paraphrased. A paraphrased report drifts from the printed
  text and stops matching what the author is staring at.
- TASK GUIDANCE ONLY — DO NOT DUPLICATE THE CONTRACT. GE-124b-5 is the authoritative
  reference for the attribute name, value grammar, resolution rule, production stripping
  and what the pin does not prove. This page links to it; two documents describing
  one contract drift, and the reference is the one the four consumers are written
  against.
- THE 'WHEN NOT TO PIN' CLAUSES ARE REQUIRED CONTENT, not softening. An author told
  only how to add a pin will add one to every element, and a pin on every element
  makes the marker meaningless — that is the failure this page is most able to cause.
- change_target stays `code` under the L0's tree-wide instruction; the deliverable
  is the how-to document (see GE-124a-4's notes on the mechanical consequence for
  the test contract).
```
