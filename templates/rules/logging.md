# Logging and Debugging Rules

## 1. Logging Levels & Usage
- **`logger.debug()`**: Use for granular, step-by-step variable states and loop iterations.
- **`logger.info()`**: Use for significant milestones, like starting a process, fetching data, or completing a batch.
- **`logger.warning()`**: Use for recoverable issues, missing non-critical data, or unexpected state that doesn't halt execution.
- **`logger.error()` / `logger.exception()`**: Use for failures, stack traces, and issues requiring developer attention.

## 2. Visibility for Final Outputs
When a long-running process (like model training, aggregation, or strategy mining) completes, the final result **MUST** be highly visible to the user at first glance:
- **Use Emojis:** Wrap the final conclusion statement with relevant emojis (e.g., `✨`, `✅`, `🚀`, `⚠️`).
- **Use Terminal Colors:** Wrap the important text or numbers in standard ANSI color codes.
  - *Green (Success)*: `\033[92m[Text]\033[0m`
  - *Yellow (Warning)*: `\033[93m[Text]\033[0m`
  - *Red (Error)*: `\033[91m[Text]\033[0m`
  - *Cyan (Info)*: `\033[96m[Text]\033[0m`
- **Example:**
  ```python
  logger.info(f"✨ \033[92mFound {len(rules)} promising rule combinations!\033[0m ✨")
  ```

## 3. Contextual Information in Logs
Always provide boundaries and context so the user doesn't have to guess what data was processed:
- **Include Date Ranges:** When fetching or processing data, always log the exact `start_time` and `end_time` bounds.
- **Include Sizes:** Log exact row counts, matrix shapes, or batch progress (e.g., "Processed 500/1000 items").
- **Include Key Parameters:** If a function runs with specific target/stop percentages or symbol names, log them in the initial `logger.info()` statement.

## 4. Debugging Scripts
- **Location:** Any one-off or repeatable scripts designed purely for debugging must be placed in `debugging/scripts/`.
- **Logs:** Any file output generated by debugging should be placed in `debugging/logs/`.
- **Reuse:** Before writing a new debug script, check `debugging/scripts/` to see if an existing script can be repurposed. This prevents the main project folders from becoming cluttered.
