## Actor / Goal

## Context

## Acceptance Criteria

```gherkin
Given a set of staged AC YAML files that violate the parent covered_by rule in 6 places,
And two working copies of the same repository at the same commit — one that exposes the
  deployed layout and one that does not,
When the AC-parent-covered-by pre-commit check is executed against those identical staged
  files from each working copy in turn,
Then both runs report the same verdict: blocked, naming the same 6 violations,
And neither run reproduces the observed asymmetry, in which the copy without the deployed
  layout printed "cannot import derive_parent_id: ac_parent_id.py not found via package
  import, script-relative, or project-root walk.; skipping check (fail-open)" and exited
  successfully,
And the verdict is determined by the staged content alone — the identity of the working
  copy the check was run from does not appear in the result.

Coverage note: covered only by a test that executes the check as a separate process from a
real second working copy that does not have the source tree on its import path — the
harness of GE-120c-1. A test that imports the check module from the source tree runs in the
one layout in which the defect cannot reproduce, and so cannot fail on it; that is exactly
what masked this class of defect until now. Grep-only coverage does not satisfy this
criterion (CLAUDE.md, "Gate / Workflow ACs — Verify Behaviorally, Not by Grep").
```
