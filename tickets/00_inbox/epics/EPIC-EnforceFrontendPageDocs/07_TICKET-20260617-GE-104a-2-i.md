# DSL trigger expresses a new-page-without-matching-doc condition (negation feasibility open question)

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-104a-2-i` — DSL trigger expresses a new-page-without-matching-doc condition (negation feasibility open question) — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-104a-2-i`. Component: `guardrail-engine`. Assigned agent: `llm-expert`. Estimated complexity: `S`.

## Acceptance Criteria

```gherkin
Given the documentation-expert agent has a trigger condition intended to fire
  when files_touched contains a new site/app/**/page.tsx WITHOUT a matching
  docs/reference/frontend/<name>.md
And the existing trigger DSL grammar supports only positive "contains" terms
  combined with AND / OR (for example "files_touched contains *.tsx")
When the trigger condition is evaluated against a ticket whose files_touched
  has a new page and no matching reference doc
Then the documentation-expert status resolves to "needed"
And when evaluated against a ticket whose files_touched has the new page AND
  its matching reference doc, the condition does NOT fire on that basis

---

Given the existing DSL evaluator may not support a "without matching" / negation
  relationship between a page path and its derived doc path
When the trigger condition for documentation-expert is authored
Then it is flagged as an OPEN QUESTION for the IT PO whether the existing DSL
  evaluator can express this negated / derived-path condition as a dsl-type
  expression, or whether it must instead be expressed as an llm-type condition
  (per ADR-018) or the DSL grammar must be extended
And the chosen mechanism resolves the same observable outcomes: needed when a new
  page lacks its doc, and not-fired when the page and its doc are both present
```
