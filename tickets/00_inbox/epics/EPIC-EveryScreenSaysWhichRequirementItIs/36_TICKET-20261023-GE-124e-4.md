## Implementation Notes

```yaml
- 'TWO ROUTES INTO THE DIFF, BOTH MANDATORY — THIS IS THE ONE REQUIREMENT THAT MUST
  NOT BE SIMPLIFIED. The evaluated set is the UNION of: (route A) selected criteria
  whose OWN AC YAML record is among the changed files, and (route B) selected criteria
  that are declared or pinned by any changed FRONT-END file. Every diff-scoping precedent
  in this repo scopes by file path, so ''diff-scoped'' reads naturally as route A
  alone — and route A alone makes this gate close to inert, because the common case
  is a criterion whose record is stable while its screen churns. An implementation
  with route A only will pass a casual review, will pass any test written from route
  A''s scenario, and will almost never evaluate anything. Route B is the reason this
  AC exists.'
- 'ROUTE B IS COMPUTED BY RUNNING THE SHARED READER OVER THE CHANGED FRONT-END FILES
  and taking the union of their declares[] and pin ac_ids[]. It is the diff-scoped
  counterpart of GE-124e-2''s full inversion: same reader, same in-scope rule (GE-124a-3),
  restricted to the changed set. Do not approximate route B by grepping the diff text
  — a criterion declared on an unchanged line of a changed file is still route-B in
  scope, because the file is what changed.'
- THE CHANGED SET IS `git diff --name-only <base>...HEAD` AGAINST THE TARGET BRANCH,
  matching the existing done-proof job's `--mode ci-changed --base origin/${{ github.base_ref
  }}`. Include renames and additions; a renamed front-end file's criteria are in route-B
  scope under its new path.
- 'NOT EVALUATED IS NOT A STATE. An untouched criterion must be absent from every
  collection the run produces — not exempt, not deferred, not pre-convention, not
  skipped, not passed, and in no count. If the run emits a structured report, the
  criterion''s id must not appear in it at all. This is the difference between diff-scoping
  and the dated cutoff it replaced: there is no exempt population, nothing to size,
  and nothing to retire.'
- NO CUTOFF, NO EXEMPT LIST, NO BACKFILL COUNTER anywhere in this gate. The user decision
  of 2026-08-25 replaced the dated-cutoff proposal with diff-scoping precisely so
  that no dated population is created. Adding a counter 'for visibility' recreates
  the population the decision removed.
- THE TWO ROUTES ARE ONE UNION, DEDUPLICATED. A criterion reachable by both routes
  is evaluated once and can produce at most one finding (GE-124e-3's per-(subject,
  code) rule).
- 'MATCH THE HOUSE PRECEDENT RATHER THAN INVENTING A SECOND IDIOM: check_done_proof
  --mode ci-changed --base origin/main (whose docstring gives this exact promotability
  rationale), the diff-scoped component-vocabulary CI job (diff-scoped on PRs, whole-tree
  on push to main), GE-111c-1, and the presence-only-assertion staged-hunks ratchet.
  If a whole-tree mode is added for push-to-main, it must be an explicit separate
  mode, never the default.'
```
