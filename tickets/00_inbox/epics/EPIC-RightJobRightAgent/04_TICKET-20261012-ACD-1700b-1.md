## Acceptance Criteria

```gherkin
Given an AC with a deliverable surface (file path + extension) and an assigned_agent,
  and a surface->craft map that resolves each surface to the craft that owns it
  (path-aware, not extension-alone),
When the assignment-quality check evaluates the AC,
Then the assignment is flagged as a mismatch ONLY when assigned_agent differs from the
  craft the surface->craft map resolves for that deliverable surface,
And a legitimate mapping is NOT flagged — in particular a .js/.mjs WORKFLOW body under
  templates/workflows-js/ assigned to python-coder passes (Node orchestration is
  python-coder's craft per project convention),
And a genuine mismatch (e.g. a frontend .jsx/.tsx/.vue/.svelte deliverable assigned to
  python-coder, or a .sql deliverable assigned to python-coder) IS flagged,
And the flag names the deliverable surface, the craft the map resolved, and the
  mismatched agent,
And the AC is held for reassignment before dispatch.
```

## Implementation Notes

```yaml
- 'CONFIG HOME (IT-PO decision, 2026-08-12): the surface->craft map lives in a dedicated
  ordered config file, config/surface_craft_map.yaml, as a path-aware, FIRST-MATCH-WINS
  list of {glob -> craft} entries. It is NOT expressed as per-agent surface globs
  on config/agent_registry.json, because per-agent extension lists cannot encode first-match
  path precedence (e.g. templates/workflows-js/**/*.js -> python-coder must override
  a generic web *.js -> frontend-coder).'
- config/surface_craft_map.yaml is the SINGLE source of truth read by the check AND
  by any generator/assignment tooling; the check must not inline or duplicate any
  glob->craft rule, and a duplicated rule is a defect to delete.
- A mismatch is flagged ONLY when assigned_agent differs from the craft the map resolves
  for the deliverable surface; the flag payload names the deliverable surface, the
  resolved craft, and the mismatched agent.
- config/surface_craft_map.yaml must be added to the build deploy manifest (deploy_map
  in scripts/build_phases.py) so the check reads it from the DEPLOYED layout, not
  only the source tree (done_proof.py ModuleNotFoundError precedent).
- A deliverable surface that matches no glob must produce an explicit unresolved/advisory
  outcome, never a silent pass and never a false mismatch.
- 'Holding for reassignment is advisory-then-blocking per ADR-026 warn-before-required
  rollout: ship enabled/non-strict, promote to blocking only after the green self-host
  window.'
```
