  remains,

  workspace exists for it.

- 'BUILD ON WHAT SHIPPED (BO-4300e-2-ix, done): remove already accepts --kind/--slug,
  resolved to the work''s position by the landing rule. This record adds the line-of-work
  name form and the rule that a name-based request is answered exactly like a request
  by location. It does not re-implement the kind/slug form, the half-cleared finishing
  of BO-4300e-2-ix..xii, or any refusal of the door.'
- 'ONE RESOLVER: every name form remove accepts (kind and short name, line-of-work
  name, and each older spelling ensure and locate accept under BO-4300a-2) resolves
  through the same identity resolution that ensure and locate use, never a second
  copy. The named work must match exactly, never by prefix, substring or similarity,
  so "alpha" never reaches "alpha-v2".'
- 'LINE-OF-WORK NAME: remove accepts the line-of-work name under the option spelling
  locate already uses (--branch), added to the remove sub-parser in templates/scripts/worktree.py
  (wiring only). The name is resolved to the work''s identity and position by the
  identity and landing rules, not only by scanning workspace records, so it reaches
  the same folder that --path and --kind/--slug reach, a leftover whose record is
  gone included. This removes the reason BO-4300e-2-ix gave for leaving --branch off
  remove (record lookup fails once the record is gone). An alias that matches two
  workspaces is refused AMBIGUOUS_LINE, as locate refuses it.'
- 'SAME DOOR, SAME ANSWER: once resolved, a name-based request runs exactly the path
  that a --path request for that location runs (program check, unsent-work check,
  own-project scope check, deletion and the post-check that nothing is left). Its
  answer, every refusal included, is the answer that --path request would give, and
  an ok answer''s removed_path equals the workspace_path that locate answers for the
  same name.'
- The door still never reads stdin and never prompts (BO-4300e-2), and it answers
  with exactly one JSON object under the BO-4300c-2 contract. Any new answer field
  or code is additive; the schema version and every existing code stay unchanged.
- 'FILE SIZES: worktree.py (425 lines) and worktree_remove.py (485 lines) are over
  the 400-line limit, so the ratchet allows them wiring only, with a net line count
