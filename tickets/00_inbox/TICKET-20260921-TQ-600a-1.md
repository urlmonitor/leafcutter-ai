# The reference layout is produced once for the whole run, and shared across workers rather than rebuilt by each

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `TQ-600a-1` — The reference layout is produced once for the whole run, and shared across workers rather than rebuilt by each — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `TQ-600a-1`. Component: `testing-quality`. Assigned agent: `python-coder`. Estimated complexity: `L`. Complexity: `high`.

## Acceptance Criteria

```gherkin
Given a selection of tests that need a deployed copy of the package only in order
  to read it — they inspect what the deploy produced and never alter the package
  beforehand nor the result afterwards,
When that selection is run,
Then the package is really deployed exactly once for the whole run, however many
  of those tests there are,
  And that stays one deploy for the whole run when the run is spread across several
    workers — the first worker to ask for the layout produces it while the others
    wait for that same one, rather than each worker producing a copy of its own, so
    "once per run" does not quietly come to mean "once per worker",
  And every one of those tests is handed the same layout root path, including tests
    running on different workers, so two of them asked for the root receive the
    identical answer,
  And no test is handed the root before the layout behind it is complete: a test
    that starts reading a layout another worker is still producing is not a case
    that can arise.
```

- [ ] AC-1: the package is really deployed exactly once for the whole run, however many
- [ ] AC-2: that stays one deploy for the whole run when the run is spread across several
- [ ] AC-3: every one of those tests is handed the same layout root path, including tests
- [ ] AC-4: no test is handed the root before the layout behind it is complete: a test

## Implementation Notes

```yaml
- 'THE FIXTURE MUST BE REGISTERED WHERE A WHOLE-SUITE RUN LOADS IT, AND THE LOAD-BEARING
  REGISTRATION MUST BE NAMED. Verified at enrichment: this repo has NO root conftest.py
  and no unit_tests/conftest.py — the only conftest files are per-directory (e.g.
  unit_tests/portability/conftest.py). A fixture defined in a per-directory conftest
  is invisible to the other test files holding the 77 measured sites, so it would
  be shared across a fraction of the run while reading as shared across all of it.
  Register the fixture and its deploy signal in a surface the whole run loads (a plugin
  named in pytest.ini, or a root conftest), enumerate every place it is registered,
  and state which one actually gates.'
- 'ONE PRODUCTION PER RUN ACROSS WORKERS IS NOW A CRITERION, NOT AN OPEN DECISION.
  The first enrichment pass left this as a choice between sharing across workers and
  reporting N honestly; the rewritten criteria took the first branch, so only the
  mechanism is open. A pytest session-scoped fixture runs once PER WORKER under pytest-xdist,
  so the plain session fixture does NOT satisfy these criteria once TQ-600b-5 makes
  parallel the default: production must be serialised on a cross-process lock, and
  the layout must live in a run-scoped directory derived from the workers'' COMMON
  base temporary directory rather than from each worker''s own. TQ-600b-5 carries
  the same decision; neither AC may assume the other resolved it.'
- THE ROOT IS PUBLISHED ONLY AFTER THE LAYOUT BEHIND IT IS COMPLETE. A waiting consumer
  must be unable to observe a root whose layout is still being written — produce into
  a private location and publish atomically, or gate the handout on a completion marker
  consulted under the same lock. A path that exists is not evidence that the deploy
  behind it finished, and a half-read layout surfaces as a mysterious assertion failure
  in an unrelated test on another worker.
- THE DEPLOY SIGNAL FIRES ON EXECUTION, NOT ON HANDOUT. This AC owns the single point
  at which a `python scripts/build.py --target-dir <path>` subprocess is really executed
  (measured 59.8s) and the signal emitted there; TQ-600a-6 owns the figure derived
  from it. Emit on execution only, and make the signal reachable from the whole run
  rather than from the producing worker alone — a signal visible only inside the worker
  that produced the layout leaves TQ-600a-6's whole-run clause unsatisfiable from
  here.
- Production must be lazy, on first demand — see TQ-600a-1-i. An eagerly created shared
  layout satisfies every other clause here and taxes every single-test debugging run
  by the full 59.8s.
- 'Deploy failure must not be swallowed. The deploy is a subprocess, so it is external
  I/O under the project error handling policy: wrap it, log at WARNING or above, and
  raise a typed error. Never hand out an empty or half-written layout (TQ-600a-1-ii).'
- The new test directory `unit_tests/suite_performance/` needs an `__init__.py` to
  match every other directory under unit_tests/; omitting it changes collection behaviour
  relative to its siblings.
- 'THE STANDING RULE IN CLAUDE.md GOES STALE THE MOMENT THIS LANDS. Verified at enrichment:
  the sentence "Until that fixture exists, the prohibition alone applies" sits at
  CLAUDE.md line 416, inside the rule authors actually read. The reconciliation is
  TQ-600a-7''s to make — it was a caveat at the first enrichment pass and the BA has
  since authored the AC — so this record''s obligation is only sequencing: this must
  not reach main in a state that leaves the rule teaching authors to do nothing rather
  than to declare.'
```
