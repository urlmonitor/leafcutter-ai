# The document that lists the accepted suppression forms also says what is rejected and why

## Actor / Goal

## Acceptance Criteria

```gherkin
Given the reference document that describes the secrets check and lists the
  forms a suppression may take,
When a reader looks up whether a form they have written is accepted,
Then the document states, for each of the three parts of an entry, what makes
  that part unusable — a check name that is not one the scanner reports, a file
  path carrying text that is not part of the path, and a third part that is
  neither a line number nor the marker meaning every line,
And it states that an entry with any of those is reported and ignored rather
  than silently loaded,
Because the document currently lists only what works, so every mistake in it is
  something the reader has to discover from the check's behaviour — and this
  class of mistake has no behaviour to discover.

Given the same document,
When the reader looks for whether a suppression that has stopped being needed
  is a problem,
Then the document states that an entry which cannot match anything is reported,
  that an entry which simply matched nothing during a run is not, and why the
  two are treated differently,
Because the distinction is the whole design decision behind this behaviour, and
  without it in writing the next change to this area is likely to erase it.

Given the same document,
When the reader compares it against the check as it behaves,
Then every rejected form the document lists is one the check actually rejects,
  and every form the document presents as accepted is one the check actually
  accepts,
Because a reference that is wrong in either direction produces the same outcome
  as the defect this L1 removes — an author confident in a suppression that does
  not do what they believe.
```
