## Acceptance Criteria

```gherkin
Given the flows How a flow renders in the Atlas and Deliver a feature end-to-end exist and
  no flow has the id leafcutter/flow-render-pipline,
When a person opens /flows/leafcutter/flow-render-pipeline,
  /flows/leafcutter/flow-render-pipeline?step=resolve, /flows and
  /flows/leafcutter/flow-render-pipline,
Then the tab title reads 'How a flow renders in the Atlas · Flows · Leafcutter Atlas' for
  both flow addresses,
And it reads 'Flows · Leafcutter Atlas' for the finder,
And it reads 'Flow not found · Flows · Leafcutter Atlas' for the unknown id,
And after drilling from /flows/leafcutter/deliver-a-feature into 'Build' the title becomes
  'How a ticket is built (the phase chain) · Flows · Leafcutter Atlas',
And Back restores 'Deliver a feature end-to-end · Flows · Leafcutter Atlas'.
```

## Implementation Notes

```yaml
- One title builder produces '<flow name> · Flows · Leafcutter Atlas', 'Flows · Leafcutter
  Atlas' and 'Flow not found · Flows · Leafcutter Atlas'; the server metadata and
  the client updates both use it.
- The title is correct in the server HTML for a flow address, a step address, the
  finder and an unknown flow id. Next.js 14 handles not-found metadata differently
  from page metadata, so the unknown-id title must be proven on the server output,
  not assumed.
- Client-side pushes, finder/flow mode switches and pops set document.title to what
  is shown; a drawer replace does not change it.
```
