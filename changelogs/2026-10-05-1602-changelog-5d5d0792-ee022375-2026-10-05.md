## Entry

Nine acceptance criteria record two speed levers from the slowest-tests analysis. Both
are measured, not estimated. They are independent of each other and of the TQ-600a
migration. Nothing is implemented yet.

**TQ-600a-11 — the C YAML loader.** In one process over the real 4,635-file store,
reading took 0.17s, `yaml.safe_load` 24.68s and `yaml.CSafeLoader` 1.86s. libyaml is
installed but unused. 76 source files use the slow loader. One file,
`scripts/render_effective_prompt.py`, already uses the fast idiom, so the lever follows an
in-repo precedent. `validate_ac_schema.py` runs in a required CI gate and in pre-commit on
every commit. The children add three things:

- **-i:** a guarded fallback, so the package still installs where PyYAML lacks libyaml.
  The test simulates that absence.
- **-ii:** a differential proof that compares both parsers' objects over the real store.
  It must include the four known divergence classes.
- **-iii:** a can-fail check. Given a divergent record, it must exit non-zero and name the
  record and the differing path.

**TQ-600a-12 — the fixture defeats its own cache.** `run_key()` caches a UUID per OS
process. Each of the 27 tests under `unit_tests/suite_performance/` starts a child pytest
session, so each child rebuilds the deployed package. The rebuild costs 48.94s; copying the
built layout costs 2.07s. Over about 23 rebuilds that is worth about 950s. The children add
four things:

- **-i:** a seed that is missing, incomplete or built under a different configuration is
  refused out loud.
- **-ii:** seeding is asked for per test. Only the 17 seedable tests may get a pre-warmed
  layout. The 10 tests that assert the deploy count would pass vacuously on one, so their
  three files are forbidden by path.
- **-iii:** a deploy-count test handed a pre-warmed layout is caught, not quietly green. The
  proof is built around `test_tq_600a_1_i.py`.
- **-iv:** no test gets slower by moving onto the private-copy route. Routing the Shape-A
  tests (14.81s) onto the Shape-B path (48.94s) would make the suite about 680s slower.

TQ-600a's `child_limit_override` goes from 8 to 12, so it stays correct after the
copy-fixture branch (TQ-600a-9/-10) also merges. Lever 1 is filed under TQ-600a for delivery
speed. Its notes record that it fits a new TQ-600d better, with the steps to re-parent it.

The same pull request also carried deb626b44, which corrected TQ-600a-11's end-to-end
threshold. That commit is outside this entry's range.
