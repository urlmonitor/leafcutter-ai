# Mock decision: production lock > runtime override > env default

## Actor / Goal

As the Atlas deployment, I want the mock-mode decision to follow a fixed resolution
order — production lock > runtime override > env default — so a real deployment can
never accidentally serve fixture data.

## Acceptance Criteria

- Given `LEAFCUTTER_MOCK_LOCK=real`, when a request arrives with a mock cookie,
  then the seam returns real data regardless of the cookie value.
- Given no lock and `LEAFCUTTER_MOCK=1`, when no cookie override is present,
  then the seam returns fixture data (env default).
- Given no lock and `LEAFCUTTER_MOCK=0`, when a cookie `mock=1` is present,
  then the seam returns fixture data (runtime override wins over env default).
