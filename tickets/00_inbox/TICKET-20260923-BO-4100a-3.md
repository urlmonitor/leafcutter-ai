## Implementation Notes

```yaml
- '_fetch_origin currently degrades a failed fetch to a WARNING and proceeds with
  the cached remote-tracking ref. That warn-and-continue branch IS the silent fallback
  this record removes: an unestablished shared tip must end the run, not soften into
  a note on stderr.'
- A cached remote-tracking ref that could not be refreshed must not be treated as
  the shared tip. 'Could not read the shared line' and 'the shared line is empty'
  are different outcomes and must be reported as different outcomes.
- The refusal must be emitted as a discriminated structured outcome on the same channel
  the success payload uses, following the shape ADR-039 already established for the
  fast-lane occupied-workspace refusal -- never a relayed git diagnostic on stderr
  with no structured output, which is the pre-ADR-039 behaviour.
- Applies to all three creation paths. A refusal implemented on one path leaves the
  other two falling back silently.
- Both the canonical template and its scripts/ build output must carry the change
  (ADR-001).
- 'Error handling follows the project error handling policy: the underlying read failure
  must be logged at WARNING or higher and either re-raised or wrapped in a typed error,
  never swallowed.'
```
