description: "Wires assemble_context_bundle into the live fast lane, closing BO-2400c-1 and KI-BO-005. The prompt-caching layer orders agent context most-stable-first (architecture, conventions, parent acceptance criteria), inserts one cache breakpoint marker, then appends the volatile layers (this batch's criteria, prior tests, prior outputs, working diff), so an LLM key-value cache can anchor on a byte-identical prefix across dispatches. It was fully implemented with roughly 25 passing tests and a reference doc, and it had never executed once: the module defined no argparse and no __main__ so it could not be invoked as a command, and its only production reference was inside templates/workflows-js/fast-lane-build.js, an orphaned runner nothing invokes. The parent criterion was nonetheless marked done; it is reset to in_progress in the same change, since its wording describes a real dispatched prompt and no such prompt existed. scripts/injection_builders.py gains an assemble-bundle CLI subcommand around the unchanged pure function. It reads each layer from a file path, writes only the bundle to stdout with every diagnostic on stderr, and exits non-zero naming the layer when one is missing or unreadable rather than emitting a partial bundle. Keeping stdout clean is load-bearing rather than tidiness: a banner or log line would inject run-varying bytes into the stable side of the breakpoint and destroy the byte-identity the whole feature depends on. templates/workflows-js/fast-lane-ship.js gains a context-bundle dispatch after the claim step and before the test-writer phase. It runs exactly once per run and the resulting string is reused verbatim at the head of both the test-writer and coder prompts; reassembling per dispatch would look correct and quietly guarantee a cache miss every time. The gate fails closed on the same plain-falsy read the other gates use, and additionally rejects a bundle that is empty or missing the breakpoint marker, since an assembly that silently dropped a stable layer would still look non-empty. A failed bundle releases the run's claimed criteria and halts rather than falling back to unbundled prompts, because a lane quietly running without its context is indistinguishable from the broken state being fixed. The covering tests execute real behaviour: the CLI tests run the command as an actual subprocess rather than importing the function, since the criterion is that the module answers a command, and one of them runs build.py into a temporary directory and executes the deployed copy, guarding the documented failure class where a module works from the source tree and no-ops once deployed. The workflow tests run the lane under the engine harness and compare the recorded dispatch prompts, asserting the stable prefixes are byte-identical across dispatches and that the volatile suffixes differ, so the equality check cannot be satisfied by sending every agent the same prompt. Also re-points the deploy-manifest justification in scripts/build_phases.py, which had cited the orphaned runner as the reason injection_builders.py is shipped to consumers; without that correction, retiring the orphan would remove the module's only recorded reason to be deployed and a later cleanup would drop it, breaking the CLI this change adds. Records KI-BO-008: the test harness answers an unstubbed agent label with a generically positive reply, so every fixture written before a new mandatory gate breaks when that gate lands, and the cheapest-looking repair is to widen the gate to accept the default's shape. That happened once during this work and was reverted in favour of correcting the fixtures."
