## Acceptance Criteria

```gherkin
Given a Windows machine with a Linux shell running on it that can reach the
  same project,
When a workspace for "alpha" is requested from a Windows shell,
Then the ready answer gives the workspace's location in a form usable from the
  Windows shell and in a form usable from the Linux shell, both naming the same
  folder,
And a request for "alpha" started from the Linux shell is answered with that
  same workspace, not a second one,
And version-control commands run inside the workspace succeed from both shells.
```

## Implementation Notes

```yaml
- Every emitted path appears in native form and in a POSIX alias (workspace_path /
  workspace_path_posix, repo_root / repo_root_posix); on a Windows host the alias
  is the form a WSL shell can use (/mnt/<drive>/...), and --repo-root/--path accept
  Git Bash, PowerShell and WSL spellings of the same folder.
- 'The marker and every stored value hold no absolute path in only one platform''s
  spelling, so a request from either shell recognises the same workspace (decision
  1: clones embed no absolute path).'
- The real two-shell arm runs where wsl.exe is available and is reported as not run
  otherwise; the spelling-equivalence arm (the same --repo-root given in each of the
  three spellings) runs everywhere.
- Answers conform to the result contract delivered by BO-4300c-2 (one JSON object
  on stdout, status/code/exit mapping, workspace_path absent on every non-ok answer).
- Proof runs the DEPLOYED maker -- the copy an install delivers, resolved through
  the shared test locator delivered by BO-4300f-4 -- as a separate process against
  real temporary git repositories with a real bare hub. No mock of git, no import
  of the maker module, no grep of its source (CLAUDE.md 'Gate / Workflow ACs -- Verify
  Behaviorally, Not by Grep'); a test never falls back to the templates/ source copy.
- 'Tests must not spawn the package''s own scripts/build.py (CLAUDE.md ''Tests must
  not spawn their own build.py''): the deployed maker comes from the shared deployed
  layout, and fixture projects carry a minimal stub build entry point that installs
  a real, rejecting hook in well under a second. A test that must mutate the package
  and build its own copy says so and justifies it in its ticket.'
- All temporary projects, hubs and workspaces live under the test's temp directory
  and run git with an isolated global and system config; afterwards the developer's
  own repository's branches, registered worktrees and local git config are unchanged
  (BO-4300f-4-i, F14, KI-TQ-012).
```
