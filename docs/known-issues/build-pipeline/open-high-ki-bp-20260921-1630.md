# KI-BP-20260921-1630 — the clean-mode provenance ledger can only ever learn about artifacts the build still produces, so every orphan that predates it is permanently unremovable

> Filed 2026-09-21 while merging BP-1500g-1 onto a main that had moved 115 commits.
> Index: [build-pipeline.md](../build-pipeline.md).

- **Severity:** high — it silently removes the remedy from two other open entries in this register
- **Status:** open
- **Occurrences:** 1 (found by analysis during the BP-1500g-1 merge, before the branch landed)
- **Where:** `scripts/build_phases_clean.py` — `clean_stale_artifacts`, the
  `updated_ledger[artifact_type] = ... | expected_names` line and the
  `if item.name not in known_before: continue` guard

**The rule BP-1500g-1-i introduced.** `--clean` removes an item only when it is absent from
the CURRENT manifest **and** the ledger records an earlier run having produced it. Anything
the build cannot attribute to itself is kept and reported. That is deliberate and correct —
it is what stops the sweep deleting an adopter's own work, which is the defect KI-BP-009 was
reported for.

**The gap.** The ledger is only ever updated from the current manifest:

```python
expected_names: set[str] = source_manifests.get(artifact_type, set())
updated_ledger[artifact_type] = updated_ledger.get(artifact_type, set()) | expected_names
```

So the only way into `known_before` is to be something the build **currently produces**. An
artifact the package retired *before* the ledger's first run can therefore never be recorded,
and never becomes removable. Not "survives longer" — never removed, on any future run.

**What that costs, concretely.** Every orphan that exists in an installed tree today predates
the ledger by definition, so `--clean` will not remove any of them, ever. That includes:

- **`KI-BP-005`** — a deleted template's deployed copy left behind. The copy is exactly a
  pre-ledger orphan, so the entry's remedy no longer works.
- **`KI-BP-010`** — the doubled `.claude/.claude/workflows` path. Its fix is intact and the
  sweep now looks at the right directory, but the orphan it was written to clear is
  pre-ledger and is retained. `unit_tests/build_guards/test_ki_bp_010_clean_workflows.py`
  had to be amended on 2026-09-21 to seed provenance with a real prior run before asserting
  removal; the amendment is honest about the semantics, but a reader should not take the
  green test as evidence that a real installed tree gets cleaned.

Neither of those entries can be closed by BP-1500g-1-i, and anyone reading them should know
that before picking one up.

**ADR-041 understated this.** Its Consequences/Negative says "Genuine orphans will survive
longer... the accepted cost of the safe direction." The accepted cost is larger than that
sentence describes, and the ADR should be amended rather than left to imply a delay.

**Fix direction.** The build already writes a record of what it deployed —
`.build_manifest.json`. That is the natural provenance source, and it would make an orphan
"present in a previous build's manifest, absent from this one" without any ledger warm-up.
It is not usable as-is: `KI-BP-011` records that the manifest is written to the package that
ran the build rather than the target it describes, so a consumer install has no local copy.
Fixing KI-BP-011 and reading provenance from the target's own build manifest would close this
entry and restore KI-BP-005's and KI-BP-010's remedies at the same time.

A weaker alternative — seeding the ledger from the deployed tree on first run — does NOT work
and should not be reached for: an orphan is by definition not in the current manifest, so a
first-run seed either misses it (no help) or records everything present including the
adopter's own files (reintroducing KI-BP-009).

**Related.** `KI-BP-005`, `KI-BP-010`, `KI-BP-011` (the blocker on the fix direction),
`KI-BP-009` (the defect the ledger exists to prevent), `BP-1500g-1-i` and
`docs/architecture/adrs/ADR-041-recomputed-attribution-at-item-granularity.md`.

**Pattern:** a safety rule whose evidence source can only be populated going forward, applied
to a problem that is entirely historical — so the rule is correct about every future case and
powerless over every existing one.
