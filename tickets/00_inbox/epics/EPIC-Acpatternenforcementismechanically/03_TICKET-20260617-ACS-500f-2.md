# Pattern-first inventory recognizes a pattern AC by the same definition the hook uses

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `ACS-500f-2` — Pattern-first inventory recognizes a pattern AC by the same definition the hook uses — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `ACS-500f-2`. Component: `ac-store`. Assigned agent: `workflow-architect`. Estimated complexity: `S`.

## Acceptance Criteria

```gherkin
Given an AC store contains a pattern AC that declares its parameterized slots
  ONLY via {word} placeholders in its criteria field, with no pattern_slots
  field present (or pattern_slots empty),
And another AC could reuse that pattern's behavior,
When the business-analyst pattern-first inventory scan runs before authoring a
  new L2 AC,
Then the scan includes that pattern AC in its pattern inventory,
And the new AC is offered the chance to reuse it via implements_pattern +
  pattern_bindings rather than restating the behavior inline.

Given the pattern-detection predicate the business-analyst applies during the
  inventory scan,
When it is compared to the predicate the deployed pattern-reference hook uses
  to recognize a pattern AC,
Then the two predicates recognize the same set of pattern ACs,
And both treat an AC as a pattern when EITHER its pattern_slots field is
  non-empty OR its criteria contains at least one {word} placeholder.

Given a pattern AC that declares a non-empty pattern_slots field and no
  {word} placeholder in criteria,
When the inventory scan runs,
Then that pattern AC is still recognized (no regression for the
  pattern_slots-only form).
```
