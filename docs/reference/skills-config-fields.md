# Reference: `skills_config.json` Fields

`skills_config.json` is the single configuration file that controls how
leafcutter's `build.py` generates artifacts and how agents behave at runtime.
The schema is defined in `config/skills_config.schema.json`; the shipped
defaults live in `config/skills_config.default.json`.

**To adopt**: copy `config/skills_config.default.json` to `.claude/skills_config.json`
in your project and edit only the values that differ from the defaults.

**Runtime lookup**: agents read keys via a `_get(key, default)` helper. If the
key or the file is absent, the built-in default is used, preserving backwards
compatibility.

---

## Output Layout

These two fields control where `build.py` writes its artifacts and how it
bridges tool discovery paths. They are the newest top-level fields; both are
required to understand the consolidated output root design (see
[ADR-004](../architecture/adrs/ADR-004-consolidated-output-root.md) and
[Why leafcutter puts all files in .leafcutter/](../explanation/consolidated-output-root.md)).

| Field | Type | Default | Valid values | Description |
|---|---|---|---|---|
| `output_root` | string | `.leafcutter` | any valid folder name | Folder name at the project root where `build.py` writes all artifacts. Dot-prefix is conventional (matches `.claude/`, `.gemini/`). Change this only when the default name conflicts with another tool in your project. |
| `shim_strategy` | enum | `auto` | `symlink`, `copy`, `auto` | How `build.py` bridges canonical tool-discovery paths (`.claude/agents/`, `.gemini/`, `.pre-commit-config.yaml`, etc.) to `output_root`. `symlink` — creates OS symlinks; fails on Windows without Developer Mode. `copy` — physical file copies; always works but doubles disk usage. `auto` — attempts `symlink`, falls back to `copy` on `PermissionError`. |

### Shim targets

When `install_shims()` runs, it creates the following pointers at canonical paths
regardless of `shim_strategy`:

| Canonical path | Points into `output_root` |
|---|---|
| `.claude/agents/` | `<output_root>/agents/` |
| `.claude/skills/` | `<output_root>/skills/` |
| `.claude/commands/` | `<output_root>/commands/` |
| `.claude/hooks/` | `<output_root>/hooks/` |
| `.claude/settings.json` | `<output_root>/settings.json` |
| `.gemini/` | `<output_root>/gemini/` |
| `.antigravity/` | `<output_root>/antigravity/` |
| `.pre-commit-config.yaml` | `<output_root>/pre-commit-config.yaml` |

## Project Identity

Free-text fields read by agents to understand the consumer project's context.
None of these have enforced formats — they are passed verbatim into agent prompts.

| Field | Type | Default | Description |
|---|---|---|---|
| `project_description` | string | `""` | Short prose description of what this project does. Injected into agent system prompts as project context. |
| `common_commands` | string | `""` | Frequently used shell commands (run server, run migrations, etc.). Surfaced to agents that need to run project commands. |
| `architecture_overview` | string | `""` | High-level description of the codebase architecture. Read by architect-review and research-agent. |
| `test_commands` | string | `""` | Human-readable test command summary. Supplements the structured `testing_context` block below. |

## Ticket Paths

These paths locate the lifecycle folders for the ticket workflow. All values are
relative to the project root.

| Field | Type | Default | Description |
|---|---|---|---|
| `tickets_inbox_path` | string | `tickets/00_inbox` | Root folder for standalone ticket files awaiting triage. |
| `tickets_inbox_epics_path` | string | `tickets/00_inbox/epics` | Root folder for proposed epics not yet accepted into `01_todo`. |
| `tickets_todo_path` | string | `tickets/01_todo` | Root folder for in-flight tickets and epics. |
| `tickets_done_path` | string | `tickets/99_done` | Root folder for completed tickets. |
| `tickets_rejected_path` | string | `tickets/99_rejected` | Root folder for rejected tickets kept for historical reference. |
| `ticket_lifecycle_path` | string | `tickets/ticket_lifecycle.json` | Path to the `ticket_lifecycle.json` manifest generated by `build.py` into the target project. |

## Test Commands

Shell commands used by commit-agent pre-flight checks and the `test-runner`
agent. Values here are project-specific; the shipped defaults are placeholders
and must be overridden for any real project.

| Field | Type | Default | Description |
|---|---|---|---|
| `test_command_live_trader` | string | `poetry run python -m unittest discover -s unit_tests/live_trader -t . -p "test_*.py"` | Command to run the fast unit test suite. Must complete in under 5 seconds to pass commit-agent pre-flight. |
| `test_command_sql` | string | `poetry run python -m pytest unit_tests/sql_functions -v` | Command to run SQL/database integration tests. Slow; requires a running database. Not run automatically on commit. |
| `test_command_single_file_pattern` | string | `python unit_tests/live_trader/<file>.py` | Shell pattern for running a single test file. Use `<file>` as the placeholder; agents substitute the actual filename. |

## Build Behavior

Controls how `build.py` and agents locate project-wide resources.

| Field | Type | Default | Description |
|---|---|---|---|
| `default_branch` | string | `main` | Name of the default/main branch. Used for PR targets and merge operations. |
| `docs_root` | string | `docs/` | Root directory for project documentation, relative to project root with trailing slash. All docs-related paths in `paths.json`, commit-guardian, and doc-compliance derive from this value. |
| `changelog_folder` | string | `changelogs/` | Folder where per-entry changelog Markdown files are written. |
| `changelog_categories_path` | string | `.claude/changelog_categories.md` | Path to a Markdown file containing project-specific commit categorization rules. Read by changelog-agent at runtime. If absent, changelog-agent falls back to conventional-commit prefix heuristics only. |
| `precommit_autofix_config_path` | string | `.claude/precommit-autofix.json` | Path to the precommit-autofix routing config JSON used by the pre-commit autofix hook. |
| `test_output_dir` | string | `%TEMP%/leafcutter-tests/` | Directory for test output files. Must be outside the project root. The `%TEMP%` placeholder is expanded at runtime on Windows; use `/tmp/` on Linux/macOS. |

## Worktree Management

Controls the epic worktree workflow and the close-worktree cleanup procedure.

| Field | Type | Default | Description |
|---|---|---|---|
| `worktree_base_path` | string | `../` | Parent directory for epic worktrees, relative to the repo root or absolute. The default places worktrees as siblings of the project root. |
| `settings_module` | string | `settings` | Python module to verify after worktree bootstrap. Set to a module that exists in your project; the bootstrap step imports it to confirm the environment is functional. |

### `worktree_cleanup` (object)

Controls the pre-removal process and log cleanup in the `close-worktree` flow.

| Field | Type | Default | Description |
|---|---|---|---|
| `worktree_cleanup.kill_residual_processes` | boolean | `true` | When `true`, background processes whose `cmdline` matches the worktree path are terminated before `git worktree remove`. When `false`, a summary is printed and the user must act manually. |
| `worktree_cleanup.log_globs` | string[] | `["*.log", "precommit-autofix*.log", ".sql_test_results.json"]` | Glob patterns for files to delete from the worktree directory before removal. |
| `worktree_cleanup.protected_paths` | string[] | `[]` | Path substrings — any process whose `cmdline` contains any listed entry aborts the cleanup instead of being killed. Use to protect production processes (e.g. a live trading daemon). |

## Code Structure

Paths and identifiers that describe the consumer project's Python package
structure. Used by import-scanner, blast-radius analysis, and the
collector-enforcer skill.

| Field | Type | Default | Description |
|---|---|---|---|
| `collector_enforcer_paths` | string[] | `["collector/"]` | List of path prefixes that activate the collector-enforcer skill on commit. Paths are matched against changed files. |
| `top_level_packages` | string[] | `["live_trader", "collector", "dashboards", "api", "model_trainer", "trades_aggregator", "sql_functions", "models", "scripts"]` | List of top-level Python packages in the project. Used by import-scanner and blast-radius analysis to scope cross-module impact detection. |

## Platforms

Toggles which AI platform targets `build.py` generates outputs for. Setting a
platform to `false` suppresses generation of that platform's agent/instruction
files, reducing build time and output size.

| Field | Type | Default | Description |
|---|---|---|---|
| `platforms.claude` | boolean | `true` | Generate outputs for Claude Code (`.claude/agents/`, `.claude/skills/`, etc.). Disable only if the project uses no Claude tooling. |
| `platforms.antigravity` | boolean | `true` | Generate outputs for Gemini/Antigravity (`.gemini/`, `.antigravity/`). |
| `platforms.cursor` | boolean | `false` | Generate outputs for Cursor. |
| `platforms.copilot` | boolean | `false` | Generate outputs for GitHub Copilot. |
| `platforms.cline` | boolean | `false` | Generate outputs for Cline. |

No additional keys are allowed under `platforms` (`additionalProperties: false`).

## Testing Context (`testing_context` object)

A structured block shared by the `test-writer` and `test-runner` agents.
Adopters customize this block to match their project's test layout; the
shipped defaults are placeholders.

The block is read at agent runtime, not at build time. Required sub-fields are
marked below.

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `testing_context.test_root` | string | yes | `unit_tests/` | Root directory containing all test subdirectories. |
| `testing_context.readme_path` | string | yes | `unit_tests/README.md` | Path to the primary test README. Read by `test-writer` at runtime for directory layout, naming conventions, and performance constraints. |
| `testing_context.directories` | object | yes | (see below) | Maps each test subdirectory name to its framework and DB-dependency flag. Used by `test-writer` to produce valid `target_dir` values and to pick the correct `setUp`/`tearDown` pattern. |
| `testing_context.max_test_duration_seconds` | integer | yes | `5` | Maximum allowed wall-clock duration for any auto-running test. Tests that exceed this limit must use `manual_test_suffix`. |
| `testing_context.manual_test_suffix` | string | no | `_MANUAL` | Suffix appended to test function names excluded from the standard pre-commit suite (slow or DB-requiring tests). |
| `testing_context.db_connection_test` | string | no | `postgresql://trader:trader@localhost:5403/LIVE` | Connection string for the test database environment. Used in `setUp` for DB-requiring tests. |
| `testing_context.naming_pattern` | string | no | `test_*.py` | Glob pattern that test files must match. Enforced by the pre-commit hook and `test-runner`. |
| `testing_context.test_output_rules` | string | no | `"Never write to project dirs; use tmp_path or %TEMP%"` | Human-readable constraint injected into `test-writer` prompts to prevent tests from writing to project directories. |

### `testing_context.directories` entry shape

Each key under `directories` is a subdirectory name (relative to `test_root`).
Each value is an object with two required fields:

| Sub-field | Type | Allowed values | Description |
|---|---|---|---|
| `framework` | enum | `unittest`, `pytest` | Test framework used in this subdirectory. Determines how `test-writer` generates `setUp`/`tearDown` boilerplate. |
| `db_required` | boolean | `true`, `false` | Whether tests in this subdirectory require a running database. When `true`, the pre-commit hook skips these tests; `test-writer` routes them to the manual/slow suite. |

**Example `directories` block:**

```json
"directories": {
  "live_trader":    { "framework": "unittest", "db_required": false },
  "sql_functions":  { "framework": "pytest",   "db_required": true  },
  "model_retriever":{ "framework": "unittest", "db_required": false }
}
```

## Live Surface Testing

Controls the `live-surface-tester` phase agent (priority 11.8), which starts the
project's HTTP server in a subprocess during the ticket lifecycle and runs
structured HTTP assertions against it. This block is **optional** and defaults to
disabled — pure library or CLI projects must not accidentally spin up servers
during commits or CI runs.

See [ADR-020: Live Surface Tester](../architecture/adrs/ADR-020-live-surface-tester.md)
for the architectural decision.

> **Wiring status (2026-07-10):** the config block, validation, port registry, startup
> helper, and agent template are in place, but the dispatch wiring that actually spawns
> `live-surface-tester` is delivered by the EPIC-LiveSurfaceTesting revival tickets. Until
> those land, setting `enabled: true` has no effect on ticket dispatch.

| Field | Type | Default | Validation | Description |
|---|---|---|---|---|
| `live_surface_testing.enabled` | boolean | `false` | Must be a bool when present. | Master on/off switch. Set to `true` only for projects with a running HTTP server. `false` is the safe default. |
| `live_surface_testing.startup_command` | string | `"python -m uvicorn app.main:app --host 0.0.0.0 --port {port}"` | Required (non-empty) when `enabled: true`. | Shell command to start the server. Use `{port}` as a placeholder; the port registry substitutes the actual port at runtime, enabling concurrent worktrees to use separate ports. |
| `live_surface_testing.health_check_path` | string | `"/health"` | — | HTTP path the startup helper polls to confirm readiness. The request is `GET http://127.0.0.1:{port}{health_check_path}`. |
| `live_surface_testing.startup_timeout_seconds` | integer | `30` | — | Maximum seconds to wait for the health check to return 200 before declaring the startup failed. |
| `live_surface_testing.port_range_start` | integer | `8200` | Must be less than `port_range_end` when both are present. | Lower bound of the port band. The port registry draws from `[port_range_start, port_range_end]`. |
| `live_surface_testing.port_range_end` | integer | `8299` | Must be greater than `port_range_start` when both are present. | Upper bound of the port band. Default gives ports 8200–8299, above the common dev range of 8000–8199. |

### Validation rules enforced by `config_loader.py`

1. `enabled` must be a boolean (`true` or `false`) when present.
2. When `enabled: true`, `startup_command` must be a non-empty string. Omitting or leaving it blank raises `ConfigValidationError`.
3. When both `port_range_start` and `port_range_end` are present, `port_range_start` must be strictly less than `port_range_end`. Violating this raises `ConfigValidationError`.
4. Absence of the entire `live_surface_testing` block is valid — it is treated as `enabled: false`. Existing `skills_config.json` files that do not include this block continue to work unchanged.

### Example configuration (enabled)

```json
{
  "live_surface_testing": {
    "enabled": true,
    "startup_command": "python -m uvicorn app.main:app --host 0.0.0.0 --port {port}",
    "health_check_path": "/health",
    "startup_timeout_seconds": 30,
    "port_range_start": 8200,
    "port_range_end": 8299
  }
}
```
