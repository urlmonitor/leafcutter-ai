description: "No agent in the registry claimed the .js extension. python-coder owns .py, sql-coder .sql, and frontend-coder owns .tsx/.jsx/.vue/.svelte/.html/.css/.scss but not plain .js. Meanwhile leafcutter's own orchestration layer is roughly 8800 lines of workflow JavaScript across nine files in templates/workflows-js/, including build-feature, finalize-feature, plan-feature and fast-lane-ship. Every acceptance criterion touching those files had assigned python-coder purely by imitation. Two costs followed: the intent-vs-surface check flagged every such criterion as a technology contradiction, making a real signal permanently noisy; and an agent with no precedent to copy had nothing to route on, most plausibly guessing frontend-coder, which would bring jest or vitest and no way to run the Python-driven Node harness those tests actually use. As an expedient, .js is added to python-coder alongside a new owns_file_extensions_rationale field stating plainly that this is not a judgement that a Python agent should own JavaScript, naming the consumer limitation (an installed project whose own application code is JavaScript would be assigned here too, which is wrong for it), and naming the condition under which the entry should be removed. The blast radius is advisory only: the two commit-guardian hooks that read this field, check_complexity.py and check_exception_handling.py, both look up .py explicitly, so nothing mechanical routes on .js. Alongside the expedient, a new AR-100 criteria tree records what closing the gap properly means, keeping two genuinely different needs separate rather than collapsing them into one muddled agent: AR-100a, that leafcutter's own orchestration deserves a dedicated owner who knows its authoring rules and test harness; and AR-100b, that an installed project whose product is written in JavaScript should get a JavaScript specialist on its own terms. AR-100c requires every kind of work to be claimed by exactly one specialist, which is what will mechanically force this expedient's removal once a workflow owner exists, since two agents could not both claim .js. AR-100d states that the mis-assignment warning must stop firing on correctly routed work. Making ownership configurable per installed project, and splitting specialists along frontend and backend lines, are recorded in AR-100's notes as deliberately out of scope. The agent-registry component is also registered in the acceptance-criteria index with the previously unused AR prefix; without it the new criteria are unreachable to the tooling that resolves components through that index."
