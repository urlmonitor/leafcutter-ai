# A test linked to a not-done AC runs informationally and never fails the run

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `TQ-100b-1` — A test linked to a not-done AC runs informationally and never fails the run — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `TQ-100b-1`. Component: `testing-quality`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given a test function that declares the acceptance-criterion it covers via the
  established tag convention (a "# covers: <AC-ID>" comment), and that AC's
  work_status in the AC store is anything other than done,
When the suite is run and that test fails,
Then the test's failure is reported informationally (the result is visible,
  e.g. surfaced as an expected/non-blocking outcome) and does not count as a
  run failure
And the overall run outcome is not driven to non-passing by that test alone
And a session-level component reads each tagged test's covering AC's
  work_status from the AC store to decide that the test is informational.
```

## Test Requirements

- `test_not_done_ac_test_is_informational`: A failing test tagged '# covers: <AC>' whose AC work_status is not done is reported informationally and does not fail the run.
- `test_classifier_reads_work_status_from_store`: The session-scoped classifier reads each tagged test's covering-AC work_status from the AC store to decide informational vs enforced.
