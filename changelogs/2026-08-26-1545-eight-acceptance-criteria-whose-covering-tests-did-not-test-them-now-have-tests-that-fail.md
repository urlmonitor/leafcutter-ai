description: "The known-issue review that prompted this found eight acceptance criteria still falsified against source, and found that five of the eight carried an empty covered-by list while standing at a finished work status — the field the store reads was empty while the claim was green. Where a covering test did exist, it mostly did not test the criterion, and the ways it failed to are worth recording because they are distinct. For the quick-fix divergence gate, all four covering tests read the workflow file as text and assert that the word divergence appears in it; every one passes on a divergence check that does nothing. For the fulfillment gate's auto-fix, the eighteen covering tests are all frontmatter and registry assertions — that the agent is pinned to a particular model, that its priority is a particular number — and not one exercises the auto-fix behaviour at all. For the fast-lane worktree reconnect, the single test touching the origin-main path stubs the branch-existence check to return nothing, with a comment saying the branch does not exist, so the defective reconnect arm is never entered. For the byte-preservation criterion, the fourteen tests said to cover it contain zero occurrences of the words that name the axis the defect lives on, because they assert values and the defect is in line endings. The most instructive two are the ones that look sound. One is genuinely behavioural, runs the real workflow, and still passes on the bug: it asserts that pause-persistence is not dispatched on cancel and never asserts the status string, so it is satisfied by a run that reports success. Behavioural is necessary and not sufficient; the assertion has to be on the thing the criterion is about. The other feeds the agent registry's contents into the workflow through the test harness, which means the one operation that fails in production — reading a file from a working directory where it does not resolve — is the operation the test never performs. Eight new test files replace that. All are behavioural: the real Node subprocess harness for the JavaScript workflows, a real temporary git repository with a genuinely pruned worktree for the reconnect case, real store records copied byte for byte for the ticket generator, and binary reads for the line-ending case, because reading in text mode re-applies the very translation under test and makes a broken implementation look correct. One target has no executable form at all — its mechanism exists only as prose in an agent template — and rather than fall back to a source-text assertion, that test extracts the literal command the template specifies, by pattern rather than by retyping it, and executes it against a constructed tree; retyping would have produced a test that drifts from the template and then tests itself. The four passing controls are load-bearing rather than filler. One supplies a genuinely convergent case so a future fix cannot degrade into warning on every run. One passes today and is evidence that an existing partial mitigation works, not a broken test. One proves a scope interpreter is not simply always negative. One proves the real-subprocess technique is itself sound and not the cause of the failures beside it. Every test carries a covers tag naming its criterion. All eight criteria are unfinished, so the enforcement plugin downgrades these failures to expected failures in a normal run and surfaces them as real failures under the strict environment variable. Both were verified across all eight files together: eighteen failed and four passed under strict, eighteen expected-failures and a zero exit without it. A full-suite run reported one hundred and twenty-eight failures, none of them in these eight files; all sit in the commit-guardian and feedback directories, the deploy-dependent set that fails in any worktree where the build has not been run. That was verified rather than assumed by running the same files in a pristine worktree carrying none of these changes, where they fail identically. No source file is modified. These tests document live defects; the fixes come later through the criteria that now specify them."
