## Implementation Notes

```yaml
- 'The 308 is issued from the existing leafcutter-web/middleware.ts with NextResponse.redirect(url,
  308) (owner decision 2026-10-09), building the path with flowHref. Not leafcutter-web/next.config.mjs
  redirects(): a config redirect passes the original query through unchanged (the
  old ''flow'' parameter would ride along), and a captured value placed in the destination
  path can be re-encoded as ''%2F''.'
- Fire only on the bare /flows path when a 'flow' query parameter is present; /flows
  without it passes through untouched (UXP-591-1-i).
- 'The Location is same-origin and always under /flows/, with the ''/'' in the decoded
  flow id literal. Its query is the original query with only the ''flow'' parameter
  removed: step and every other parameter (e.g. UXP-608''s mock=1) are carried over
  verbatim and in their original order (owner decision 2026-10-09). For any ''flow''
  value, including ''.'', ''..'', empty segments, a leading ''//'' or a scheme, the
  redirect must not leave /flows/ (open-redirect and path-normalisation guard); such
  values land on the UXP-591-1-ii 404.'
- The redirect is a pure function of the query with no flow-existence check (Edge
  runtime, no flow store; UXP-591-2-v).
- '308, not 301/302/307: it is permanent, and the browser replaces the legacy URL
  in the tab''s history, which meets ''Back does not return to it'' without client
  code.'
- 'leafcutter-web/middleware.ts already holds the UXP-608 mock-mode gate and Next.js
  allows one middleware file: extend it without changing that gate''s behaviour; leafcutter-web/__tests__/route-gating.test.ts
  stays green.'
```
