## Acceptance Criteria

```gherkin
Given a workspace in which the package has never been built, so there is no deployed layout
  for a fresh working copy to be given,
When set-up runs there,
Then it reports that specific cause — the workspace has not been built — and the single
  action that resolves it,
And it does not report the generic not-found message, which leaves the reader unable to tell
  a missing build from a missing file,
And it still fails the set-up rather than proceeding,
And a workspace that has been built, but in which one expected artifact is genuinely absent,
  produces a different message naming that artifact.

Coverage note: both conditions must be exercised — never-built, and built-but-incomplete —
because the criterion is that they are told apart. A single run against one of them cannot
show a distinction.
```

## Implementation Notes

```yaml
- 'DEFINE THE TWO CAUSES PRECISELY. NEVER-BUILT: no .leafcutter/ directory and no
  scripts/ build outputs in the workspace — only templates/. BUILT-BUT-INCOMPLETE:
  the layout exists and one expected artifact is genuinely absent. DISCRIMINATE ON
  THE PRESENCE OF THE LAYOUT, not on the absence of whichever single file happened
  to be looked up first — that is the mistake that produces one generic message for
  two causes.'
- The never-built message names the SINGLE resolving action — 'python scripts/build.py
  --target-dir <workspace>', or ./build-self.sh in the package's own workspace. The
  built-but-incomplete message names the ABSENT ARTIFACT by path. The two messages
  must not share a template string, or they will converge again the next time someone
  edits one.
- BOTH CONDITIONS STILL FAIL THE SET-UP. The distinction is in the message and the
  remedy, never in whether set-up proceeds — a refusal the reader cannot act on gets
  worked around, and the workaround is what re-creates the unprotected copy by hand.
- SHARE THE CLASSIFIER WITH GE-120b-1-i, which draws the identical never-built vs
  built-but-incomplete line on the check side. Two independent classifiers for one
  distinction will drift, and they will drift in the direction of whichever surface
  is edited more often.
- 'ADR-001 deployed/template parity across all three copies of setup_ticket_worktree.py:
  edit templates/scripts/, run ''python scripts/build.py --target-dir .'', confirm
  scripts/ and .leafcutter/scripts/ match.'
```
