# A real deployment cannot be flipped to fake data by a visitor

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `UXP-608` — A real deployment cannot be flipped to fake data by a visitor — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `UXP-608`. Component: `ux-prototyping`. Assigned agent: `frontend-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a production deployment that has NOT explicitly opted in to allowing runtime mock
  overrides (default-deny is the safe default, independent of the production lock),
When an anonymous visitor sends a request carrying a runtime override such as ?mock=1
  (or a leftover mock cookie),
Then the override is ignored and the deployment serves real data with the live badge,
So a production Atlas meant to show real data keeps showing real data no matter what an
  untrusted visitor tries.
```

- [ ] AC-1: the override is ignored and the deployment serves real data with the live badge

## Implementation Notes

```yaml
- 'In production, the override allow/deny decision must default to DENY: unless an
  explicit opt-in flag is set, the request-time override in leafcutter-web/middleware.ts
  and the seam in leafcutter-web/lib/data/mock.ts must ignore ?mock=1 and any mock
  cookie and resolve to live.'
- 'Default-deny must hold for untrusted input: a query param or cookie supplied by
  an anonymous visitor must not be able to flip a production deployment to fixtures
  (treat override input as untrusted, fail safe to real data).'
- The resolved decision under default-deny must be 'live' and drive the live badge,
  so the badge and served data stay consistent (per UXP-607).
- The default-deny gate must be enforced on the request-handling seam that actually
  resolves the data source (middleware.ts / mock.ts), not only in UI presentation,
  so no view can be served fixtures while the badge reads live.
```
