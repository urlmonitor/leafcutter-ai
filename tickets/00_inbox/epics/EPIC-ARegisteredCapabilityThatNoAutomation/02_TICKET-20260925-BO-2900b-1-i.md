## Acceptance Criteria

```gherkin
Given a change that registers a new capability `verify` on the command surface and,
  in the same change, adds an automation invocation of `verify`,
When the connection from registered capabilities to the automation that runs them
  is checked,
Then `verify` is not reported and the change is not refused.

Given a change that registers `verify` and adds no automation invocation of it,
When the same check runs,
Then `verify` is reported and the change is refused,
  And the report names both ways forward — adding the automation invocation in this
    change, or recording an exemption for `verify` with a stated reason —
  And the report does not suggest disabling the check.
```

- [ ] AC-1: `verify` is not reported and the change is not refused.
- [ ] AC-2: `verify` is reported and the change is refused
- [ ] AC-3: the report names both ways forward — adding the automation invocation in this
- [ ] AC-4: the report does not suggest disabling the check.
