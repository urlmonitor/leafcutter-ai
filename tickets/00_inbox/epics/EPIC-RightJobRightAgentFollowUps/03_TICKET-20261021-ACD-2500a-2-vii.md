## Implementation Notes

```yaml
- 'IT PO decision (the BA''s open call): the hand-back pass is named to the check
  as its own --stage value, itpo-handback. The CLI stage list, the owner map and the
  reference doc use that one spelling.'
- The owner map is held in exactly one place and read only by the protected-fields
  family; no other code branches on a stage name to allow a field.
- For itpo-handback the protected set also covers the test designer's outputs (file_findings
  verdict, reason, line_range, found_in, file_findings_opened_files, test_spec, test_design_*
  marks), and of all protected fields it allows only assigned_agent, each file finding's
  decision (it-po S3b) and the planner's own enrichment fields it_requirements, declared_files,
  delivers_to and expects_from. It never allows criteria, test_intent, test_spec,
  a file finding's fields other than its decision, or a test_design_* mark.
- Wiring /plan-feature to run the check with --stage itpo-handback after the hand-back
  pass is not in this record's scope (logged as a caveat).
- The itpo-handback before-state is the post-design batch (provided by ACD-2500a-2-ix's
  stage commit). Run against a pre-design before-state, the map would report every
  test_spec and file_findings entry as a hand-back edit; that is a wiring error, not
  a finding to tune away in the map.
```
