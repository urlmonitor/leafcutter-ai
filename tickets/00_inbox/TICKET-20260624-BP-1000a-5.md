# The build reads the feedback deployable-script source from the tracked templates mirror, not the gitignored working copy

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BP-1000a-5` — The build reads the feedback deployable-script source from the tracked templates mirror, not the gitignored working copy — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BP-1000a-5`. Component: `build-pipeline`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given a fresh checkout in which the only feedback deployable-script source that
  is committed to version control lives under the tracked templates mirror
  directory templates/scripts/feedback/ (mirroring the existing
  templates/scripts/commit_guardian/ pattern)
And the gitignored working-tree directory scripts/feedback/ is empty or absent
  (it holds no committed source on a fresh checkout)
When the build resolves the set of feedback scripts it will deploy (the step
  that today is performed by the feedback manifest builder and the feedback
  deploy phase)
Then the build sources every feedback script from templates/scripts/feedback/
And the set of feedback scripts the build deploys is non-empty and matches the
  files present under templates/scripts/feedback/
And the build does not require any file under the gitignored scripts/feedback/
  directory to be present in order to determine what to deploy
```
