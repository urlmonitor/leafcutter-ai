# The reference gate still refuses from a fresh consumer install, not only from the package's own checkout

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `INF-700b-2-i` — The reference gate still refuses from a fresh consumer install, not only from the package's own checkout — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `INF-700b-2-i`. Component: `infrastructure`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

**Scope corrected by architect-review 2026-10-23 (the generated ticket is stale).** The gate this AC protects is the existing `check-agent-registry` hook (`templates/scripts/commit_guardian/check_agent_registry.py`), widened to every package `templates/**/*.md` by INF-700b-2 (#1319). There is no `check_skill_refs.py` hook to relocate or deploy, `_resolve_root.find_project_root()` already prefers `git rev-parse --show-toplevel`, and the verdict (`ability_reference_verdict`) already fails closed on an unreadable skills directory. The original Implementation Notes described a design that no longer applies; see the Comments entry for the reconciliation. Remaining work is behavioural proof from a REAL built layout, tests only.

**No private build.py in tests (project CLAUDE.md, TQ-600a).** Every test here requests the session-scoped `shared_reference_layout` fixture and is marked `@pytest.mark.shared_layout_reader`. That layout is a directed build into an EMPTY `--target-dir`. Tests COPY the deployed hook directory and the layout's own `.leafcutter/pre-commit-config.yaml` entry OUT of it into a private temporary consumer project, and plant the dangling reference there. Nothing is written into the shared layout, and no test spawns `build.py`. Isolation hazard (ticket 04, INF-700b-2): never build with `--target-dir` set to a `H.make_build_package` copy; that copy symlinks the repository's root entries (`.leafcutter`, `.claude`, `tickets`), so a build through it rewrote the shared install (a dangling sentence landed in the shared `signoff` skill and `knowledge_sink.json` was repointed at a deleted path). If a fresh build is ever unavoidable, build into a new empty directory with the package OUTSIDE it.

**Deploy manifest.** `build_commit_guardian` copies the whole `templates/scripts/commit_guardian/` directory, so no allowlist edit is needed; the deploy proof is test 5 below, run against the real built layout.

## Acceptance Criteria

```gherkin
Given a consumer project that has installed the package and run its build,

  run from,
When a template in that deployed tree names a skill directory that was not
  deployed,
And the consumer commits that change,
Then the gate runs from the deployed layout and refuses the commit,
And it does not exit zero because a module it imports, a configuration file

  deployed layout,

And the difference between the two runs is observed in the consumer project,
  not in the package's own working tree.
```

## Superseded original Implementation Notes (do NOT implement)

```yaml
- THE CHECKER IS NOT DEPLOYED TODAY. scripts/check_skill_refs.py lives outside templates/,
  so no consumer install receives it, while every guardian hook the manifest invokes
  resolves under {{config.output_root}}/scripts/commit_guardian/. The script must
  be relocated or mirrored into templates/scripts/commit_guardian/ and added to the
  build deploy manifest in the same change that registers the hook, per the standing
  rule 'New Hook / Gate Dependencies Must Be in the Build Deploy-Manifest' — a hook
  whose target is absent from the deployed layout raises ModuleNotFoundError at hook
  runtime while its source-tree unit tests stay green.
- ROOT RESOLUTION. The script currently computes its root as Path(__file__).resolve().parent.parent,
  which in a symlinked .leafcutter deployment resolves into the PACKAGE checkout rather
  than the consumer project — so it would scan the package's own templates and pass
  while the consumer's tree is broken. It must resolve the root through the shared
  helper templates/scripts/commit_guardian/_resolve_root.py find_project_root(), which
  prefers `git rev-parse --show-toplevel` for exactly this reason.
- 'LAYOUT-AWARE SKILL RESOLUTION — the largest gap, and the one most likely to produce
  a false green. load_skill_names() reads <root>/templates/skills/. A consumer install
  HAS NO templates/ directory: build.py deploys skills to .claude/skills/ and the
  package tree to .leafcutter/. Verified on this workspace''s own deployed layout,
  where .claude/skills/ holds the deployed bundles and no templates/ exists beside
  them. The known-skill set and the scanned template set must both be resolved from
  whichever layout is present.'
- SILENCE IS NOT A PASS. A run that resolves no skills directory, or that scans zero
  Markdown files, must FAIL (the script's existing exit 2 for an unreadable skills
  dir is the right shape) and must never print the OK line. Today a consumer run would
  find no templates/skills/, return None from load_skill_names and exit 2 — which
  is accidentally correct; make it deliberate and test it, because the tempting 'fix'
  is to treat a missing directory as an empty known-set, which turns every reference
  into a violation, and the next tempting fix after that is to treat it as a pass.
- The scanned surface in a deployed layout is .claude/agents/*.md and .claude/skills/**/*.md,
  matching the surfaces the package deploys. A reference written as `.claude/skills/<name>`
  must resolve against the deployed skills directory, and a reference written as `templates/skills/<name>`
  must still resolve in the package checkout — the existing regex already accepts
  both spellings and must keep doing so.
- PROOF MUST BE OBSERVED IN A CONSUMER-SIMULATION TREE, not in this repository's working
  tree. Build into a temporary target directory with `python scripts/build.py --target-dir
  <tmp>` and exercise the gate there. A test that runs from the package checkout cannot
  distinguish a layout-aware gate from a layout-blind one, because in the package
  checkout both layouts happen to resolve.
- This AC must not change what the gate considers a violation. It changes only where
  the gate can run. If deployed-layout support changes the set of reported references
  in the package checkout, that is a regression in INF-700b-2, not a feature of this
  AC.
```
