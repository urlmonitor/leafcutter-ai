# The started server's PID is recorded in the port registry

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-2100c-1` — The started server's PID is recorded in the port registry — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-2100c-1`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `S`. Complexity: `low`.

## Acceptance Criteria

```gherkin
Given live_surface_startup.py has allocated a port and spawned the development
  server subprocess for a worktree
When the start command completes and reports the server ready
Then the server's PID has been written into the port registry for that worktree
  via `python scripts/port_registry.py set-pid <worktree> <pid>`
  And a subsequent `port_registry.py list` shows a non-null `pid` for that
  worktree entry
  And the recorded PID is the identifier later used to stop the server.
```

## Test Requirements

```yaml
tests:
- name: test_bo_2100c_1_the_server_s_pid_has_been_written_into
  file: unit_tests/test_bo_2100c_1.py
  covers:

  asserts: the server's PID has been written into the port registry for that worktree
```

## Implementation Notes

```yaml
- The PID must be recorded before the start command reports the server ready, so teardown
  always has a PID to act on.
- The recorded PID must be the process-group-leader PID that teardown signals (consistent
  with the group-kill behavior in BO-2100c-3).
- Registry writes must follow the project error-handling policy for file I/O and must
  not corrupt or lose other worktrees' entries on concurrent access.
```
