## Acceptance Criteria

```gherkin
Given a ticket whose changed surface includes one or more Python files,
When the ruff-runner is invoked against that ticket's new and changed
  Python files,
Then it runs the repository's own ruff configuration against exactly those
  files (so the result matches what CI enforces, with no divergent local
  ruleset),
And it returns a deterministic verdict that classifies the outcome as one of:
  clean (no violations), violations (one or more ruff violations found —
  e.g. a violation that the project's error-handling Ruff rules forbid), or
  tooling-unavailable (ruff is not installed, or the repository ruff
  configuration cannot be located from the worktree root),
And on violations the verdict carries the violation detail so the sign-off
  gate that consumes it can record the lint violations as the blocking reason,
And on tooling-unavailable the verdict is reported as a distinct third state
  naming the reason (never collapsed into clean),
And the verdict carries the file set it was run against so the consuming
  sign-off gate can record auditable evidence of what was checked.
```

## Implementation Notes

```yaml
- THIN ADAPTER, NO RUFF ARGV OF ITS OWN (amended 2026-10-09, replaces 'invoke ruff
  with the repository's own ruff configuration'). The runner must not build a ruff
  command line, hold a tree list, hold a rule list, locate ruff, or read a ruff version
  itself. It invokes the DEPLOYED commit-guardian lint runner delivered by BP-1300e-1-i
  -- `python <output_root>/scripts/commit_guardian/check_lint_gate.py --mode files
  --files <the ticket's new/changed .py files> --json` -- with cwd at the worktree
  root, and maps its JSON. That runner reads the project's one lint declaration (leafcutter-lint.json,
  BP-1300e-1-i) and applies every declared step, so a changed file under kernel/ is
  also judged by CI's second step (E722, BLE001, TRY over kernel/ only) -- which the
  previous wording ('the repository's own ruff configuration') silently omitted --
  and a file the declaration or the ruff configuration's excludes leave out is not
  judged, exactly as CI.
- 'LINTER VERSION CHECK IS INHERITED, NOT RE-IMPLEMENTED (amended 2026-10-09). Through
  files mode the runner applies BP-1300e-1-v''s check: a local ruff whose version
  differs from the exact pin in the file CI installs from (this repository: requirements-dev.txt,
  ruff==0.15.15) yields outcome could_not_check, reason linter_version_mismatch, with
  no findings. The adapter maps it to tooling-unavailable carrying that reason, so
  a verdict from a different linter is never recorded as clean.'
- 'OUTCOME MAPPING, EXACTLY (amended 2026-10-09). ok -> clean; refused -> violations
  (reason = the findings, one per line as path:line:col: CODE message [step]); could_not_check
  -> tooling-unavailable (reason = the runner''s reason code plus its human-readable
  reason line; covers every reason in BP-1300e-1-iii''s vocabulary, including ruff_not_installed,
  ruff_config_unreadable, declaration_unreadable, linter_version_mismatch and no_repository);
  nothing_to_inspect -> clean with files = [] and a reason stating that no changed
  file was in the declared lint scope; files = the runner''s files_inspected. Distinguish
  outcomes by the JSON ''outcome'' field, never by exit code (refused and could_not_check
  both exit non-zero). An unparseable or absent JSON payload, or a runner that cannot
  be launched, is tooling-unavailable naming the cause -- never clean.'
- The verdict must be a deterministic, machine-readable three-state outcome (clean
  | violations | tooling-unavailable); tooling-unavailable must NEVER be reported
  as clean.
- The runner must not depend on the worktree pre-commit hooks having fired (worktrees
  historically lack the .pre-commit-config wiring) — it invokes check_lint_gate.py
  directly as a subprocess, independent of pre-commit.
- 'The runner must follow the project error-handling policy (CLAUDE.md Rules 1-4):
  wrap the check_lint_gate.py subprocess I/O and the JSON decode in specific excepts
  (OSError, subprocess.SubprocessError, json.JSONDecodeError), log at WARNING or higher,
  and classify the failure as tooling-unavailable rather than swallowing it.'
- The verdict must include the changed-Python file set checked and a human-readable
  reason on the non-clean states, so the consuming sign-off gate can record auditable
  evidence.
- BUILD ORDER (amended 2026-10-09). This runner cannot be built before BP-1300e-1-i
  delivers check_lint_gate.py's files mode and --json payload, and BP-1300e-1-v its
  version check; implementing a private ruff invocation as a stopgap is forbidden
  (it is the fourth hand-kept copy BP-1300e-1-i exists to remove). Verify against
  the deployed runner in the shared reference layout, not the template source. This
  ordering is now ALSO encoded in depends_on (BP-1300e-1-i, BP-1300e-1-v; user-approved
  2026-10-09); this prose stays because it explains why.
```
