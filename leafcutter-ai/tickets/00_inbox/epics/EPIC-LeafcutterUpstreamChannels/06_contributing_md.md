## Goal

In order to communicate the contribution model to external consumers and potential contributors, we need a `CONTRIBUTING.md` that clearly explains how to report bugs (Issues), propose features (Discussions), and submit PRs — including the maintainer's triage process.

## Context

Key message (from CANDIDATE spec):

> Bug reports go to GitHub Issues. Feature proposals and questions go to GitHub Discussions. The maintainer triages open items periodically and converts accepted proposals into internal tickets. External contributors are welcome to open PRs against open Issues once they are triaged and accepted.

Sections to cover: reporting bugs, proposing features, PR workflow (fork → branch → PR against main), code style expectations, running tests, how the maintainer triages.
