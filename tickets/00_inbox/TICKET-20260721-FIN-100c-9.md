## Acceptance Criteria

```gherkin
Given baseline_failures is null and the post-merge run reports failing tests
And the targeted main-HEAD rerun cannot be performed
  (for example the main-HEAD checkout fails, or the build/deploy step errors)
When the workflow cannot determine which failures are pre-existing
Then it falls back to the conservative classification: all post-merge failures
  are treated as regression and blocks_finalization is set to true
And the halt message lists each failing test together with its modified_by_branch flag
  so a human can adjudicate which failures the branch actually touched
```

- [ ] AC-1: the targeted main-HEAD rerun cannot be performed
- [ ] AC-2: it falls back to the conservative classification: all post-merge failures
- [ ] AC-3: the halt message lists each failing test together with its modified_by_branch flag
