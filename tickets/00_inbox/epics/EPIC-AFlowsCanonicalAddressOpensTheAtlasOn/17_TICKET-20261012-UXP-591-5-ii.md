## Implementation Notes

```yaml
- 'One popstate listener in leafcutter-web/components/flows/flows-view.tsx restores
  the view: the entry''s URL is the authority for the flow and the drawer (?step=),
  the entry''s {crumbs, filters} in history.state (owner decision 2026-10-09) for
  crumbs and filters; an entry with no stored state falls back as UXP-591-5''s contract
  states.'
- 'Restoring an entry writes no history: no replace or push in reaction to a pop,
  including when the restored filters differ from the current ones.'
- Back onto an entry whose flow id is unknown restores the not-found state (notice,
  empty breadcrumb, no flow) with no fallback flow.
- The listener is registered once and removed on unmount; a pop to an entry outside
  the Flows view is left to the App Router.
- jsdom does not run the App Router's history integration, so the real-browser behaviour
  (history length under the App Router, Back/Forward without a page reload) is proven
  by this AC's Playwright spec in leafcutter-web/e2e/, run in CI against `next build`
  + `next start` (owner decision 2026-10-09; harness set up under UXP-591-1).
```
