description: "When a set of requirements is assembled into a group of work items, each item is renamed with a number recording where it falls in the build order. The prerequisites each item declares were left pointing at the names the items had before they were renamed — so every one of those references named a file that does not exist. The safety check that reads work-item metadata refused to save the group, which means every group produced through the ordinary route has needed hand correction before it could be kept at all. The loudness of that check is the only reason this never shipped quietly. The translation this needs already existed and already worked; it simply was not reached from this route. There are two ways to assemble a group: walking down from a goal, or handing over an explicit list. A change some weeks ago added two pieces of hygiene — this prerequisite translation, and recording file references in a portable rather than machine-specific form — and applied both to the newer list-based route while applying neither to the goal-based one. The goal-based route is the default, and it is the one the ordinary command uses, so the rarer path was correct and the well-trodden path was broken in two separate ways. The written history of that earlier change records both fixes as applied, which is precisely why nobody noticed: the note was true of the function being added and read as true of the whole script. The portable-reference half was repaired a few hours before this one, and finding it should have prompted the question of whether anything else from the same batch was also missing. It did not; the safety check asked instead. When a fix turns out to be a missing back-port, the rest of that batch is worth checking in the same pass. The regression test covers both routes on purpose. Before the change the goal-based route failed and the list-based route passed, and that contrast is the evidence the fault was specific to one entry point rather than general — a test exercising only the working route would have reported this entire class of problem as absent, which is exactly how the gap survived. The test asserts that each declared prerequisite names a file that is really there, rather than that the name looks correctly formatted: a formatting check would accept a well-formed name for a file that does not exist, and would break if the numbering scheme ever changed. Existence is also the precise thing the safety check enforces, so the test and the check now agree on one fact instead of two approximations of it."
