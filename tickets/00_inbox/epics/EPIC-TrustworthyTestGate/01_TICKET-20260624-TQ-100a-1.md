# The suite runs every loadable test even when one file fails to load

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `TQ-100a-1` — The suite runs every loadable test even when one file fails to load — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `TQ-100a-1`. Component: `testing-quality`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given a test suite that contains many test files, exactly one of which cannot
  be loaded during the collection phase (for example because it imports a
  module that does not exist in the checkout),
When the suite is run with collection-error isolation enabled (pytest invoked
  with --continue-on-collection-errors),
Then the run does not abort at the point the unloadable file is encountered
And every other test file is collected and executed to completion
And the run reports an individual result for each test in every loadable file
And the one unloadable file is reported as a single collection error rather
  than terminating the session before the other files run.
```

## Test Requirements

- `test_collection_error_does_not_abort_other_files`: A suite with one unloadable test file still collects and runs every other test file to completion under --continue-on-collection-errors.
- `test_unloadable_file_reported_as_single_collection_error`: The single unloadable file surfaces as one collection error rather than terminating the session before the other files run.
