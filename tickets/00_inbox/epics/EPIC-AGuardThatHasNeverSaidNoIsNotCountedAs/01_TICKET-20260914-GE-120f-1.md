# A check's refusal is established by putting its declared known-bad input through the entry point the protected surface uses, and the record says what was observed rather than what was declared

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-120f-1` — A check's refusal is established by putting its declared known-bad input through the entry point the protected surface uses, and the record says what was observed rather than what was declared — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-120f-1`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `L`. Complexity: `high`.

## Acceptance Criteria

```gherkin
Given every protective check declares one known-bad input it must reject together
  with the observable rejection that input must produce, held where the check is
  registered and read by machine rather than by a person reading prose,
And the record of what happened when that input was last put through the check can
  say that the rejection was observed, that it was not observed, that the attempt
  could not be run to a verdict, or that the attempt has never been made,
When the liveness run examines a check,
Then it puts the declared input through the entry point the surface that check
  protects uses to invoke it, observes what the check then does, and writes that
  check's record from that observation,
And no part of the record is taken from the declaration: a check whose declared input
  has not been put through it carries the value that the attempt has never been made,
  however completely and however well-formed its declaration is written,
And given a check whose record says the rejection was observed is altered so that the
  declared input no longer produces the declared rejection, while its declaration is
  left exactly as written,
When the run repeats,
Then that check's record says the rejection was not observed,
And given the alteration is reverted and nothing else in the repository changes,
When the run repeats again,
Then that check's record says the rejection was observed.
```
