# A changed screen component with no declaration blocks the commit by default

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-124c-1` — A changed screen component with no declaration blocks the commit by default — so that the acceptance criterion is satisfied.

## Context

## Acceptance Criteria

```gherkin
Given the staged set contains `components/coverage/gaps-callout.tsx`, an
  in-scope screen component with no component-level declaration
And the path is not on the warn list and carries no opt-out reason
When the commit-tier declaration check runs
Then the commit is rejected
And one finding is reported with the verdict "block" and the code
  "missing-component-declaration"
And the finding names the file path, names the surface as the component-level
  declaration, and states the two ways out — add the declaration, or record a
  visible per-item opt-out reason

Given the staged set contains three in-scope screen components, all three
  with no component-level declaration
When the commit-tier declaration check runs
Then the commit is rejected
And all three files are named in the report, rather than the report stopping
  at the first
```

- [ ] AC-2: the commit is rejected
- [ ] AC-3: one finding is reported with the verdict "block" and the code
- [ ] AC-4: the finding names the file path, names the surface as the component-level
- [ ] AC-5: the commit is rejected
- [ ] AC-6: all three files are named in the report, rather than the report stopping

  config section plus one hooks_manifest.hooks entry with tier `judgment`, entry `python
  .leafcutter/scripts/commit_guardian/run_hook.py .leafcutter/scripts/commit_guardian/check_frontend_ac_declaration.py`,
  matching the shape of the existing judgment-tier hooks. Add its row to the hook
  documentation index.'
- DEPLOY-MANIFEST OBLIGATION FOR THE SHARED READER. The hook imports _frontend_declaration_reader
  (GE-124a-1); that module MUST be in the commit-guardian deploy_map in scripts/build_phases.py
  in the same change. Verify by running the DEPLOYED hook after a build.py round-trip,
  not only the source-tree unit tests — done_proof.py shipped with exactly this gap
  on 2026-07-22 and crashed with ModuleNotFoundError in the deployed layout while
  every source-tree test stayed green.
- BLOCK IS THE DEFAULT AND IS NOT CONFIGURABLE AWAY. Every in-scope missing declaration
  blocks unless the path is on the warn list (GE-124d-1) or the file carries an accepted
  opt-out reason (GE-124d-2). Do NOT add a global enforcement-mode key, an advisory-first
  rollout, or an environment-variable override; the per-path opt-in already covers
  staged adoption. This mirrors GE-117d-1's fail-closed default deliberately — do
  not invent a second enforcement idiom.
- ENUMERATE ALL OFFENDERS, NEVER STOP AT THE FIRST. A branch adding six components
  would otherwise produce six sequential blocked commits, and six blocked commits
  in a row is how a guardrail gets turned off. Collect every finding, then decide
  the exit code once.
- 'THE FINDING RECORD SHAPE IS {subject, subject_type: ''frontend_component'', tier:
  ''commit'', check, code, verdict, surfaces[], message, suppression_reason, ac_ids[],
  resolver} — matching the mock-data GuardrailFinding entity so the escapes in GE-124d
  downgrade a field rather than emit a parallel record, and so GE-124c-1-i can enforce
  at-most-one per (subject, code).'
- THE MESSAGE MUST NAME BOTH WAYS OUT — add the declaration, or record a visible per-item
  opt-out reason — and point at the GE-124c-4 how-to by its verdict code. A bare 'missing
  declaration' leaves the author guessing, and the GE-117 house shape is that the
  verdict carries the remediation.
- 'FAIL-OPEN ON INTERNAL ERROR ONLY: an unexpected exception exits 0 with a stderr-prefixed
  advisory and clean stdout, so a hook bug never masquerades as a declaration violation.
  A real missing declaration must still fail closed. The store-unreachable case is
  GE-124c-2-ii''s, and the single-unreadable-file case is GE-124c-3-i''s; neither
  is this fallback.'
- Must handle errors gracefully per the project error handling policy (CLAUDE.md Rules
