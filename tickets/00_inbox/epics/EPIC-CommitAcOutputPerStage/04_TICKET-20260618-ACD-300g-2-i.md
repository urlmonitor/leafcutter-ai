# Partial-run recovery: uncommitted AC files from a prior crashed session are detected

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `ACD-300g-2-i` — Partial-run recovery: uncommitted AC files from a prior crashed session are detected — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `ACD-300g-2-i`. Component: `ac-driven-dev`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given a prior /create-ac session wrote AC YAML files to disk but the session
  ended before the stage commit occurred (e.g. the user's terminal closed,
  the agent timed out, or a network interruption killed the process),
And the uncommitted AC files remain in the working tree with
  origin_agent set to one of the AC-authoring agents (product-owner-v3,
  business-analyst-v3, or it-po-v3) and readiness: draft,
When the user invokes /create-ac again,
Then the workflow detects the uncommitted AC files in the working tree
  by scanning the AC store directory for files with unstaged or staged
  but uncommitted changes,
And it warns the user: "Found N uncommitted AC files from a prior session:
  [list of AC IDs]. Commit them before starting new work? (yes/no/discard)",
And if the user chooses "yes", the workflow commits the orphaned files
  before beginning the new triage,
And if the user chooses "discard", the workflow reverts the uncommitted files
  and proceeds with a clean working tree,
And if the user chooses "no", the workflow aborts with a message explaining
  that uncommitted AC files must be resolved before a new run can begin.
```
