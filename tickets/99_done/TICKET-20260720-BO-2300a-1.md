# A gate pauses and persists resumable state instead of cancelling

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-2300a-1` — A gate pauses and persists resumable state instead of cancelling — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-2300a-1`. Component: `build-orchestration`. Assigned agent: `llm-expert`. Estimated complexity: `L`. Complexity: `high`.

> **CORRECTED SPEC (2026-07-20) — read before implementing.** A prior build of this ticket produced a standalone Python module (`scripts/pause_resume_substrate.py`) and edited ZERO JavaScript — leaving every defective gate untouched. That was the wrong surface.
>
> - **SURFACE:** the defect lives in the interactive gates of the E2 workflow ENGINE, which is **JavaScript** — `templates/workflows-js/plan-feature.js` (4 gates) and `templates/workflows-js/finalize-feature.js` (1 merge gate). `build-feature.js` has no gates (relevant only to the "gateless run completes normally" behavior). The fix migrates those JS gates to PAUSE-and-persist. **Do NOT implement this as a standalone Python module** — a Python module in isolation touches none of the gates.
> - **FEASIBILITY:** the E2 workflow body has **no filesystem or Node.js access** (docs/reference/workflow-constraints.md). The pending-question record at `.leafcutter/paused_runs/<run_id>.json` is therefore persisted and read **via an `agent()` dispatch** (agents carry Bash/Write tools), never by `fs` calls in the body. On resume the human's answer is supplied via `args`. Engine integration (gate migration, `resolveGate`, returning `paused_awaiting_input`) is JavaScript.
> - **TEST STRATEGY:** every test drives the **real JS engine** via `unit_tests/_workflow_engine_harness.py` `run_workflow_under_e2(<script>.js, label_responses={...})` and asserts on observable JS behavior (status `paused_awaiting_input`; a persist `agent()` dispatch present in captured `agent_calls`; resume via `args` proceeds past the gate without re-running committed stages). Do NOT pytest a standalone Python module in isolation.
> - **CORRECTNESS INVARIANT (ADR-024 rule 4):** `resolveGate()` MUST consult the record's answer (via resume `args`, or a resume `agent()` dispatch) BEFORE the gate's live `agent()` call, or resume replays the cached headless-default and re-cancels.
>
> Full design: `docs/architecture/adrs/ADR-024-interactive-pause-resume.md`. The corrected per-AC technical specs live in the AC store (`docs/acceptance-criteria/build-orchestration/BO-2300-interactive-pause-resume/`).

## Acceptance Criteria

```gherkin
Given a background run is executing with no human attached to answer questions,
And the run reaches an interactive decision point (a gate that would ask
  "approve, edit, or cancel?"),
When the run cannot obtain an immediate answer,
Then the run does NOT cancel and does NOT discard the work completed so far,
And the run enters a paused state that records a pending question tied to the
  run so the run can be resumed from that exact point later.
```
