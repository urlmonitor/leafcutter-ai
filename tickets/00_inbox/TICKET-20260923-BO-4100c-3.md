# A workspace nobody could reach a verdict on is never disposed of

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-4100c-3` — A workspace nobody could reach a verdict on is never disposed of — so that the acceptance criterion is satisfied.

## Acceptance Criteria

```gherkin
Given a workspace whose assessment cannot reach either verdict -- its version
  control data is absent, or the attempt to read it fails,
When its disposal is requested,
Then the disposal is refused,
And the workspace is still listed in the live set afterwards and its files are
  byte-identical to what they were before the request,
And the refusal states that no verdict could be reached, and is distinguishable
  in its report from a refusal issued because the workspace holds work.
```

- [ ] AC-1: the disposal is refused
- [ ] AC-2: the workspace is still listed in the live set afterwards and its files are
- [ ] AC-3: the refusal states that no verdict could be reached, and is distinguishable

## Implementation Notes

```yaml
- An assessment that raises, times out, or finds the version-control data absent must
  yield the no-verdict outcome -- never holds-nothing. The natural implementation
  reads an unanswerable question as an empty finding set, lands on holds-nothing,
  and disposes of the workspace. That path must be closed explicitly rather than assumed
  absent.
- The two refusals must be distinguishable by a MACHINE, through the closed verdict
  discriminator, not only by the wording of their messages. They call for opposite
  follow-ups -- deliver the work, versus repair the workspace -- so a caller that
  cannot tell them apart without matching on prose will eventually match wrong.
- 'The refusal path must be inert: no attempt to repair, re-initialise or prune the
  unreadable workspace while refusing. The unreadable workspace is the one most likely
  to be worth keeping intact.'
- 'Both failure modes named in the Given must be covered: version-control data ABSENT,
  and an attempt to read it that FAILS. They arrive by different code paths and an
  implementation can easily handle one and crash on the other.'
- 'Error handling follows the project error handling policy: the underlying read failure
  is logged at WARNING or higher and carried into the refusal''s reason, never swallowed
  into a default verdict.'
```
