Amended ADR-042 ("The Product-Truth Checker Reports a Closed Outcome Vocabulary on a
Structured Channel") with **Amendment 1 — `checked-and-sound` is withheld when any
pointer is unresolvable**, which is the ADR-contract change architect-review's LARGE
classification was blocking on.

What the amendment binds (six sub-decisions, all in MUST language):

- **§A1** — `_check_pointers` MUST classify every pointer into exactly one of three
  *pointer* verdicts (`resolved` / `broken` / `unresolvable`). The *run-outcome*
  vocabulary stays closed at four values and MUST NOT gain a fifth; `degraded` already
  means "ran, no errors, but soundness not established".
- **§A2** — `checked-and-sound` MUST additionally be withheld when one or more pointers
  are unresolvable; such a run MUST report `degraded` (AC-4). A fixed precedence order is
  pinned: errors → `failed`; all types empty → `nothing-examined`; some type empty **or**
  any unresolvable pointer → `degraded`; otherwise `checked-and-sound`. `_compute_outcome`
  MUST take the unresolvable count as an explicit third argument and MUST NOT have the
  condition pre-folded into `errors`/`empty_types` by a caller.
- **§A3** — an unresolvable pointer MUST NOT be appended to `errors` (AC-3, exit code stays
  0 under §6 fail-open), MUST NOT be counted as resolved (AC-2), and MUST NOT affect
  `empty_types`.
- **§A4** — classification MUST be by a single named recognised-target-kind predicate
  evaluated *before* any lookup, and MUST NOT be inferred from a lookup miss (a miss on a
  recognised kind is `broken`). Exactly one such predicate may exist — this is the clause
  architect-review asked for to stop a fourth ad hoc vocabulary drifting in.
- **§A5** — the report MUST name holder, position, target and reason on the existing
  logger/stderr channel at WARNING level (survives `--quiet`), with the distinct
  `[pointer-unresolvable]` prefix so it is separable from broken pointers' `[pointer]`
  (AC-1).
- **§A6** — the stdout payload gains two additive integer keys, `resolved_pointers` and
  `unresolvable_pointers`, emitted on every run including zeros, so AC-2's "excluded from
  the stated count" is observable on the structured channel rather than only in prose that
  §3 forbids consumers from parsing. Payload keys are declared **additive-only** and
  consumers MUST NOT assert an exact key set — that rule is what keeps
  `unit_tests/product_truth/test_uxp_700b_1.py` (ADR-042's pinned suite, which reads keys
  via `.get()` and only asserts a single JSON-parseable stdout line) green across this
  amendment. I verified that suite's assertion style before binding the rule.

Six alternatives are recorded as explicitly rejected with concrete failure mechanisms,
including the two the AC names as mutations (fold unresolvable into `resolved`; report it
through `errors`), a fifth vocabulary value, heuristic inference from a lookup miss,
deferring the whole thing to `UXP-700c-3`'s gate, and carrying the full per-pointer detail
list in the payload. Consequences are split Positive / Negative / Operational; the Negative
section states honestly that `degraded` now carries two distinct meanings and that §A4's
predicate is a new place a mistake can be silent.
