# Every log a drive writes lands in the enduring location, not in the workspace that is about to be deleted

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `INF-500d-4-iv` — Every log a drive writes lands in the enduring location, not in the workspace that is about to be deleted — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `INF-500d-4-iv`. Component: `infrastructure`. Assigned agent: `python-coder`. Estimated complexity: `L`. Complexity: `high`.

## Acceptance Criteria

```gherkin
Given a drive is running inside a temporary per-drive workspace that will be
  deleted when the drive finishes,
When an agent in that drive files a report and the write succeeds,
And the temporary workspace is subsequently removed,
Then the report is still readable afterwards from the durable location that
  outlives the workspace,
And the record identifier cited in the drive's ticket resolves to that stored
  record.

Given the operational log directory also holds the agent-telemetry log and the
  knowledge-emission log, which are written by the same drives with the same
  workspace-relative lifetime and are destroyed the same way,
When the durable location is adopted for the report sink,
Then the same durable location is adopted for every log in that directory, so the
  directory is not split across a disposable root and an enduring one.
```

## Implementation Notes

```yaml
- EACH WRITER'S DEFAULT IS THE DECLARED VALUE, READ FROM ITS OWN WORKSPACE'S DEPLOYED
  DECLARATION. submit_feedback.py with no --jsonl uses feedback_sink. emit_event.py
  with no --log uses operational_telemetry_stream. inline_work_guard.py uses <operational_log_root>/inline_work_guard.jsonl.
  Reading the declaration file from the workspace's own deployed config is rule (a),
  and the value it holds is rule (c). No writer may compute a root independently,
  invoke git, or reach into another install.
- REACH THE DECLARATION IN THE REAL DEPLOYED LAYOUT, FROM ANY CURRENT DIRECTORY. It
  lives at <output_root>/config/knowledge_sink.json. The writers deploy to <output_root>/scripts/feedback/,
  <output_root>/skills/agent-telemetry/scripts/ (reached through the .claude/skills
  symlink) and <output_root>/hooks/. emit_event.py's current ancestor search for <dir>/config/knowledge_sink.json
  never matches that layout — from the project root and from a worktree it returns
  the bare relative debugging/logs/agent_telemetry.jsonl (verified 2026-10-09) — and
  must be fixed. Prove it against the deployed copy, not the source tree.
- REMOVE THE KI-FC-001 ROOT CAUSE. submit_feedback.py's sink must no longer derive
  from the _find_project_root upward walk for .claude/. Configuration-root resolution
  (_find_config_root, rule (a), INF-100c-1-i) is unchanged and must stay unchanged.
- plan-feature.js emitPtTelemetry currently prefixes the authoring worktree path onto
  debugging/logs/agent_telemetry.jsonl, so the product-truth telemetry it dispatches
  is written into the disposable worktree. It must append to the declared operational_telemetry_stream,
  obtained through INF-500d-4-iii's location query in the dispatched instruction,
  never a path the workflow composes itself. It stays best-effort and non-blocking
  as it is today.
- 'NO SILENT FALLBACK WHEN THE DECLARATION IS MISSING. submit_feedback.py takes INF-500d-4-i''s
  refusal. emit_event.py stays non-fatal by design (BP-400a-1-i: exit 0, callers append
  || true), so it must print a stderr warning naming the missing declaration and drop
  the event rather than write to the CWD-relative default. inline_work_guard.py must
  not block any tool call because of this (hooks fail open on logging) and must likewise
  warn rather than write workspace-relative.'
- 'INF-500d-4-ii''s ''[submit_feedback] sink: <path>'' stderr line must be preserved
  unchanged in form. It now names the declared path.'
- emit_event.py is deliberately self-contained (standard library only, no package
  imports) to avoid the deployed-dependency failure class. Keep that by reading the
  declaration with the standard library, or retire it explicitly in its DECISION HISTORY
  and add the shared reader to the deploy manifest of every deployed copy. Do not
  break it silently.
- Concurrent appends from simultaneous drives into the shared files must lose, truncate
  or interleave no record. submit_feedback.py's existing exclusive lock must be kept,
  and emit_event.py and inline_work_guard.py must write each record as one atomic
  append.
- emit_hook_finding.py reaches the sink through submit_feedback.py and must inherit
  the change with no edit of its own. If it needs an edit, add it to declared_files
  and state why.
- 'File-size ratchet: submit_feedback.py is 637 lines, over the 400-line limit. Extract
  rather than grow, and never SKIP check-file-size.'
- 'Deployed/template parity (ADR-001): edit the templates and verify the deployed
  copies through the build round-trip.'
- Must handle errors gracefully per the project error handling policy.
```
