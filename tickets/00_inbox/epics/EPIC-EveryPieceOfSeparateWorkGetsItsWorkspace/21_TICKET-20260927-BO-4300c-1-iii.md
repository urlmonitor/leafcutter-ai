# Setting up a workspace never leaves stray changes in the project's own files

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-4300c-1-iii` — Setting up a workspace never leaves stray changes in the project's own files — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-4300c-1-iii`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given building the tools inside a new workspace alters 61 files that the
  project keeps under version control,
When the workspace maker answers,
Then either those 61 files have been put back to their committed content and
  the answer lists them as restored, or the answer is a refusal naming them,
And a ready workspace never starts with changes to version-controlled files
  that the work itself did not make.
```

- [ ] AC-1: either those 61 files have been put back to their committed content and
- [ ] AC-2: a ready workspace never starts with changes to version-controlled files

## Implementation Notes

```yaml
- Before the build, snapshot the tracked-file state; after it, every tracked path
  the build changed is either restored to its committed content and listed in bootstrap.restored_tracked,
  or the answer is BOOTSTRAP_DIRTIED_TRACKED naming them (the memo's two mitigations).
  Only paths the build changed are touched -- the work's own changes are never restored
  away (BO-4300d-1-i).
- 'ok requires tree_clean: `git status --porcelain` shows no tracked change the work
  did not make.'
- Proof runs the DEPLOYED maker -- the copy an install delivers, resolved through
  the shared test locator delivered by BO-4300f-4 -- as a separate process against
  real temporary git repositories with a real bare hub. No mock of git, no import
  of the maker module, no grep of its source (CLAUDE.md 'Gate / Workflow ACs -- Verify
  Behaviorally, Not by Grep'); a test never falls back to the templates/ source copy.
- 'Tests must not spawn the package''s own scripts/build.py (CLAUDE.md ''Tests must
  not spawn their own build.py''): the deployed maker comes from the shared deployed
  layout, and fixture projects carry a minimal stub build entry point that installs
  a real, rejecting hook in well under a second. A test that must mutate the package
  and build its own copy says so and justifies it in its ticket.'
- All temporary projects, hubs and workspaces live under the test's temp directory
  and run git with an isolated global and system config; afterwards the developer's
  own repository's branches, registered worktrees and local git config are unchanged
  (BO-4300f-4-i, F14, KI-TQ-012).
```
