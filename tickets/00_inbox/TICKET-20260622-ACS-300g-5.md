# Component integrity hook skips the new-component check during a merge

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `ACS-300g-5` — Component integrity hook skips the new-component check during a merge — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `ACS-300g-5`. Component: `ac-store`. Assigned agent: `python-coder`. Estimated complexity: `S`.

## Acceptance Criteria

```gherkin
Given a git merge is in progress
  (MERGE_HEAD is present and verifiable via
   `git rev-parse -q --verify MERGE_HEAD`),
And docs/components.json in the merge index contains component entries
  that arrived from the merged-in parent and are therefore absent from
  the current HEAD's components.json,
When check_components_integrity.py runs as a pre-commit hook for the
  merge commit,
Then it must NOT flag those merged-in component entries as
  "newly added",
And it must exit 0 (skipping the new-component existence check) for the
  merge commit so the merge can be committed without --no-verify.
And as a regression guard, a normal (non-merge) commit where MERGE_HEAD
  does not exist still runs the full new-component existence check
  unchanged, flagging genuinely new components whose detail_ref does
  not exist on disk.
```
