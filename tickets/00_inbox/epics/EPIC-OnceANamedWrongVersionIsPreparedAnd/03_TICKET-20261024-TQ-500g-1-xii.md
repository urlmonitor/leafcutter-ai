## Implementation Notes

```yaml
- The decision lives in one place, _wvp_plan (created by TQ-500g-1-xi), called by
  the list step and by the write step alike, so the list's to_prepare, the manifest's
  source values and the names sent to the preparer can never disagree. No route, prompt
  or second module re-derives it.
- 'Lookup: an owed name finds its pin only through _wvr_scope.norm_name (strip, then
  casefold), the same normalisation as the alias rule; nothing else is normalised
  (inner spaces, punctuation and any other character count). A name with no pin under
  its key is "prepared: not pinned". The writer''s reply matching stays exact (TQ-500g-1-ix
  decision 2c); only the pin lookup is normalised.'
- 'Retarget trigger: a pinned replacement whose old text no longer occurs exactly
  once in its file as it now stands is never applied. Wording, exactly: "re-prepared:
  target changed" when it occurs 0 times; "re-prepared: old text found N times" when
  it occurs N >= 2 times (TQ-500g-1-xiii''s check a). The count uses _wvw_prepare''s
  own counting and CRLF rule, never a second matcher. A pin with several replacements
  is judged in order, each against the result of the one before, as the writer applies
  them; the first failing one names the reason.'
- 'Spelling: a name applied from the pin keeps the pin''s replacements but its manifest
  entry and every verdict row carry the name as the CURRENT entry spells it (owed
  spelling), never the spelling stored with the pin.'
- 'Unowed pins: the plan iterates owed names only, so a pin whose name is not owed
  is neither applied, nor reported, nor removed; it is used again, after the checks,
  when an entry names it again. No step except the reset (TQ-500g-1-xvi) removes it.'
- to_prepare items are the owed items byte for byte (name, files, scope, and the additive
  blocking and origin keys of a to-run-later extra), in owed order. A to-run-later
  extra (TQ-500g-2-ii) follows the same three triggers.
- 'Deterministic: the same owed list, pin file and code give byte-identical list output
  and plan.json. The plan reads only the pin file, the AC store (through the shared
  reader) and the files the pinned replacements name; it never scans the repository.
  50 owed names are planned within 1 s on a typical work when no pytest run is needed.'
- Every new or changed Python file stays at or under 400 counted lines; no new module
  is needed beyond _wvp_plan (deployed by the build_orchestration directory glob,
  no deploy-list edit).
```
