# Everything needed to choose arrives with the refusal, the division is offered as a starting point, and declining it costs nothing

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-127e-4` — Everything needed to choose arrives with the refusal, the division is offered as a starting point, and declining it costs nothing — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-127e-4`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a tracked file of a kind the size standard covers is refused for its
  length,
When the author reads the refusal and nothing else — running no further
  command, opening no produced report and waiting for no later review,
Then what is in that file and where it divides is already in front of them,
And the refusal states that the division it names is a starting point taken
  from the file as it currently stands,
And the refusal asserts nothing about the division beyond that: not that it
  preserves what the file does, not that the things depending on the file were
  examined, not that it is the only division available, and not that it is the
  best one,
And given the author declines the division that was named and instead makes a
  change that brings the same file below its permitted length by some entirely
  different division,
When the author performs an ordinary commit,
Then the commit completes, and nothing about that file's length and nothing
  about the division that was declined is reported at all — no warning, no
  note, and no line naming the file.
```

- [ ] AC-2: the refusal states that the division it names is a starting point taken
- [ ] AC-3: the refusal asserts nothing about the division beyond that: not that it
- [ ] AC-4: given the author declines the division that was named and instead makes a
- [ ] AC-5: the commit completes, and nothing about that file's length and nothing

## Implementation Notes

```yaml
- 'NO PACKAGE SURFACE — MEASURED, NOT ASSUMED, AND THIS RECORD IS THE ONE WHERE A
  NEW SURFACE WOULD BE MOST TEMPTING. WATCHED_REGISTRIES binds two containers on commit_guardian.json:
  hooks_manifest.hooks (by id) and the document''s own top level (by mapping key).
  This record adds neither; both were read in this worktree, and `check-file-size`
  and `file_size` already exist. Note the direction of travel: the natural shape of
  a good implementation here — a report path, an output directory, a "write the analysis
  to X" setting — WOULD be a new top-level key and would be caught by check-package-surface-declaration.
  That the correct implementation registers nothing is a consequence of the first
  arm, not a coincidence. No config_schema_fragment invented to satisfy the structured-spec
  validator.'
- THE GUIDANCE ARRIVES ON THE ONE OUTCOME STREAM AND NOWHERE ELSE, AND THE PROHIBITION
  IS ON THE ARTIFACT, NOT ON THE POINTER. It is not enough that the refusal avoids
  saying "see the report"; the run must not PRODUCE a second artifact at all — no
  report file, no JSON dump, no cache, no log line carrying the parts, no environment-variable
  handoff, no entry appended anywhere. A run that writes an artifact nobody points
  at is one commit away from a refusal that points at it, and it is invisible to every
  other record in this tree. Everything the author needs is in the text of the refusal
  itself.
- NOTHING MAY BE DEFERRED TO A LATER SURFACE THAT ALREADY EXISTS, EITHER. Satisfying
  this record by citing a review to be run, a periodic sweep, or a report produced
  elsewhere hands the obligation to CR-100 without CR-100 accepting it, and returns
  the author to a verdict plus a research task — the exact state this L1 exists to
  end. Reuse whatever CR-100's work produces as VOCABULARY inside the refusal; never
  as a destination.
- 'THE FRAMING SENTENCE IS PART OF THE OUTPUT AND HAS A CEILING. The refusal must
  state that the division it names is a starting point taken from the file as it currently
  stands. It must assert nothing further: not that the division preserves what the
  file does, not that consumers or dependents were examined, not that it is the only
  division available, not that it is the best one, not that it is safe. Those are
  INF-800''s claims and this gate has done none of that work. The wording must be
  provably weaker than the claim, so an implementer who wants to sound helpful cannot
  reach for "safely split here" — a phrase that is one word away from claiming an
  analysis that never ran.'
- 'THE VERDICT REMAINS A FUNCTION OF LENGTH ALONE, AND NOTHING MAY REMEMBER WHAT WAS
  ADVISED. No persisted record of which division was named, no comparison of the author''s
  actual change against the suggestion, no second finding, no note that the advice
  was not followed, no repeat refusal because the file was divided differently. The
  moment the gate can tell whether its own advice was taken, it has acquired an opinion
  it was never granted and a hard line has become a design mandate. This also means
  the description must be stateless between runs: computed fresh from the file in
  hand each time, never diffed against a stored previous suggestion.'
- 'COST BUDGET, BECAUSE EVERYTHING MUST BE IN THE MESSAGE. Carrying the whole description
  in the refusal makes message length a real concern for a file with many parts. Bound
  the printed output so it stays readable in a terminal at the moment of refusal —
  a bounded set of named parts, with the remainder accounted for as a stated residual
  rather than enumerated — and never resolve a long message by moving content elsewhere,
  which is the first arm''s mutation. Note the interaction with GE-127e-1''s half
  threshold: the bound must still let the named parts account for at least half the
  quoted length, so it is a bound on enumeration, not on coverage.'
- 'Must follow the repo error-handling policy: specific-exception try/except around
  any file read; log at WARNING or higher or re-raise; no bare or blind excepts. Note
  the specific interaction with GE-127e-3-i: because there is no second artifact to
  fall back to, a failure to produce the description must surface as that record''s
  named line on the unchanged refusal — never as a pointer to somewhere the author
  could go instead.'
- CANONICAL VERSUS BUILD OUTPUT, AND THE BUILD IS PART OF THE CHANGE. Edit templates/scripts/commit_guardian/
  only; scripts/commit_guardian/ and the repo-root .pre-commit-config.yaml are untracked
  build outputs overwritten by build.py, and templates/commit-guardian/commit_guardian.json
  is a decoy. Re-run `python scripts/build.py --target-dir .`, because the message
  the author actually reads is printed by the deployed copy.
```
