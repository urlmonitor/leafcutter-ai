## Acceptance Criteria

```gherkin
Given a worktree with a live_surface_testing registry entry that holds an
  allocated port and a recorded server PID
When /finalize-feature runs its teardown step for that worktree
Then the recorded server PID is terminated
  And the port allocation for that worktree is released from the registry
  And after finalize a `port_registry.py list` shows no allocation for that
  worktree and the port is free for reuse.
```

## Implementation Notes

```yaml
- 'Teardown must be idempotent: re-running finalize on an already-torn-down worktree
  must not error and must leave no allocation.'
- Must both terminate the recorded PID and release the port allocation; a failure
  to kill the PID must not leave the port stuck as allocated.
- Must only act on the target worktree's entry — it must never terminate processes
  or release ports belonging to other worktrees.
- Signal/kill and registry I/O must follow the project error-handling policy (log
  at appropriate severity or raise typed errors, no silent swallow).
```
