## Acceptance Criteria

```gherkin
Given the rule "is this declared log stream usable, and is the enduring root that
  holds it still live" exists once as the canonical rule and five more times as
  copies of it:
    - the canonical rule in the shared sink-resolution module,
    - the inline copy carried by the agent-telemetry event writer,
    - the inline copy carried by the inline-work guard hook,
    - the telemetry command the plan-feature workflow dispatches for its
      product-truth events,
    - the pre-drive reachability probe in the epic-building runbook,
    - the same probe in the epic supervisor's pre-flight checklist,
And each copy is taken from a deployed install, in the form an agent, hook or
  workflow actually runs it,
And for a copy that keeps a log file of its own rather than reading a declared
  stream, the canonical verdict it is compared against is the verdict the rule
  gives for that file placed directly under the declared root,
And a table of installs with one declaration and filesystem layout per row:
    - no declaration file,
    - a declaration that is an empty object, which is what a build with no log
      root records,
    - a declaration that cannot be parsed,
    - a declaration with no operational log root,
    - a declaration whose operational log root is a relative path,
    - a declaration whose stream is missing, or is a relative path,
    - a declaration whose stream sits outside the operational log root,
    - a declaration whose stream sits two levels under the operational log root,
    - a valid declaration whose log directory exists,
    - a valid declaration whose log directory is missing under a live enduring
      root (a fresh install), once in the conventional project/debugging/logs
      layout and once with a log root that is not under a debugging directory,
    - a valid declaration whose enduring root has vanished, in both of those
      layouts,
When the parity check feeds every row to every copy,
Then every copy returns the same usable-or-unusable verdict as the canonical rule
  on every row,
And on every row the canonical rule finds usable, every copy that reports a
  location reports the same absolute location the canonical rule returns,
And exactly the valid rows whose enduring root is live are usable, so a table on
  which every copy agrees that everything is unusable, or that everything is
  usable, fails the check instead of passing it,
And on every unusable row no copy brings the log directory or the enduring root
  into existence, and no copy leaves any new file behind.

Given the plan-feature telemetry command and the two pre-drive probes are workflow
  and prompt text rather than importable code,
When the parity check compares them,
Then each one is executed in a shell exactly as the deployed text states it,
  against the same row layouts as every other copy,
And its verdict is read from what it observably does: the probe's
  reachable-or-unreachable outcome, and the telemetry command's exit status
  together with whether the declared stream gained exactly one line,
And a check that only searches the text for expected words or fragments does not
  satisfy this criterion.

Given the canonical rule is changed so its verdict flips on one row, for example
  a stream two levels under the root becomes usable, or a missing log directory
  under a live enduring root is treated as stale,
And one of the five copies is left as it was,
When the parity check runs in the test suite that guards a merge,
Then the check fails,
And the failure names the copy that disagrees, the row it disagrees on, and the
  two verdicts,
So that the drift is caught before the change merges, not discovered later when a
  drive's logs are lost or its writers refuse.

Given one of the five copies can no longer be found in the deployed install, or
  its command can no longer be extracted and run as written,
When the parity check runs,
Then the check fails and names the copy it could not find or run,
And every run reports how many copies and how many rows it compared, so a run that
  compared nothing cannot report agreement.
```
