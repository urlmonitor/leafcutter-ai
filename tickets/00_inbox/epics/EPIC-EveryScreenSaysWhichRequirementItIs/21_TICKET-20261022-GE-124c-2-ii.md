## Implementation Notes

```yaml
- 'THE UNREACHABLE-STORE STATE MUST BE CARRIED, NOT INFERRED. Consume the third answer
  GE-124c-2-i''s entry point returns (resolved | not-found | store-unreachable). A
  check that only sees not-found cannot implement this AC at all: it would resolve
  nothing, find no unresolved ids, and print a pass — ''green'' indistinguishable
  from ''did not run'', the exact defect class GE-120 exists to close.'
- THE FLOOR IS ANNOUNCE, AND IT IS UNCONDITIONAL. The check must emit an explicit
  could-not-resolve report naming the reason (store path absent, unreadable, or unparseable)
  and must NOT emit its normal success line. Silence plus exit 0 is forbidden even
  under the internal-error fail-open path, because the whole point is that the run
  is visible.
- OPEN DECISION FOR THE USER — BLOCK OR ANNOUNCE. This AC deliberately does not settle
  whether an unreachable store should also REJECT the commit. GE-120 fixes the unit
  of the rule at VISIBILITY, and this component's standing note is explicit that block-versus-announce
  is a per-check decision with no blanket default. The IT-PO recommendation is ANNOUNCE-ONLY
  at the commit tier and BLOCK at the CI tier (GE-124e), on the grounds that a developer
  whose store is unreadable is usually mid-rebase and blocking them helps nobody,
  whereas a CI run that cannot read the store has produced no evidence and must not
  be merged on. Confirm before implementing; whichever is chosen, record it in the
  frontend_ac_declaration config section as a named value rather than as an unlabelled
  constant.
- 'DISTINCT FROM THE OTHER TWO DEGRADE PATHS AND MUST NOT BE MERGED WITH THEM: GE-124c-3-i
  is ONE file unreadable while the run is otherwise sound; GE-124c-1''s internal-error
  fail-open is an unexpected exception in the hook itself. Here the RESOLVER is unavailable
  and no file can be judged. Three different conditions, three different messages.'
- The declaration and pin PARSE results are still valid when the store is unreachable
  — only resolution is impossible. Missing-declaration findings (GE-124c-1) must still
  be produced and must still block, because they need no store access.
```
