## Implementation Notes

```yaml
- PER-FILE ERROR CONTAINMENT. Wrap each file's read-and-parse individually so one
  failure cannot abort the loop; the component's deliberate fail-open convention (approved
  as GE-116a-1-iii) is that one unparseable input must not block an unrelated commit.
  Catch specific exception types per the project error handling policy — never a bare
  except — and log at WARNING or higher.
- SKIPPED-AND-NAMED IS A RECORDED OUTCOME, NOT A LOG LINE THAT SCROLLS PAST. The unreadable
  file appears in the check's output with the reason (decode error, unterminated construct,
  whatever the read actually failed on). A file skipped quietly is a permanent hole
  the author never learns about, and is the shape of a check that passes because it
  did nothing — GE-120's line.
- SKIPPED IS NOT PASSED AND NOT EXAMINED. The unreadable file must not receive a pass
  record and must not be counted as declared anywhere. It occupies its own outcome,
  distinct from GE-124c-3's not-examined (never in the staged set) and from a genuine
  pass.
- 'DISTINCT FROM GE-124c-2-ii, AND THE TWO MESSAGES MUST DIFFER: there the RESOLVER
  is unavailable and no file can be judged; here one FILE is unreadable and the rest
  of the run is sound. Merging the two messages would tell an author to check their
  AC store when the real problem is their markup.'
- The exit code is decided from the OTHER files' verdicts. An unreadable file contributes
  nothing to the block decision in either direction — it neither blocks nor rescues
  a run that would otherwise block.
```
