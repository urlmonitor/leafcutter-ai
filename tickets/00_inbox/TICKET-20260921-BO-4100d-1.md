# Ask for a fix and you get a fix, not a feature wearing its name

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-4100d-1` — Ask for a fix and you get a fix, not a feature wearing its name — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-4100d-1`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a request for a workspace naming the kind of work it is for, made once
  for each supported kind -- feature, fix, chore and hotfix,
When each workspace is created,
Then the branch that exists afterwards carries the kind that was requested,
And the kind carried by the branch is never a kind other than the one
  requested,
And this holds for all four kinds, with no kind being substituted for another.
```

- [ ] AC-1: the branch that exists afterwards carries the kind that was requested
- [ ] AC-2: the kind carried by the branch is never a kind other than the one
- [ ] AC-3: this holds for all four kinds, with no kind being substituted for another.

## Implementation Notes

```yaml
- No creation path accepts a kind today. cmd_setup_ticket and cmd_create_only hard-code
  feature/ in both the branch they cut (_create_worktree, git worktree add -b feature/<slug>)
  and the payload they report. Accepting the kind is part of this work, not a precondition
  of it.
- The supported-kind set must be DECLARED ONCE and read by every site that depends
  on it -- branch construction, refusal (BO-4100d-2), reporting (BO-4100d-3), and
  the reconnect/reuse lookup. _worktree_exists currently recognises prior workspaces
  by a hard-coded prefix list (feature/, ticket/, ac-authoring/, fast-lane/); a kind
  that creation can cut but reuse cannot find silently produces a SECOND workspace
  on the next call, which is a new instance of the accumulation BO-4100c exists to
  end.
- The kind must be readable back off the branch that exists, because BO-4100d-3's
  read-back comparison depends on it. It must not be held only in a side record that
  creation writes.
- Adding kinds must not break the existing prefixes. ac-authoring/ and fast-lane/
  are consumed by _worktree_exists, by the fast-lane occupancy determination, and
  by callers that match on them; they are part of the declared set, not legacy to
  be replaced.
- Template and deployed copies change together and are verified in parity via the
  build.py round-trip (ADR-001).
```
