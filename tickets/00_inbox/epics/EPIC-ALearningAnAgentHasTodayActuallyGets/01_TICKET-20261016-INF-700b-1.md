# An agent that finishes with a learning leaves a durable record of it by following the capture step verbatim

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `INF-700b-1` — An agent that finishes with a learning leaves a durable record of it by following the capture step verbatim — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `INF-700b-1`. Component: `infrastructure`. Assigned agent: `llm-expert`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a fresh install of the package in which nobody has hand-created any
  directory the knowledge-capture step asks for,
And a phase agent has just finished a piece of work and holds one learning
  about this project that it did not hold when it started,
When that agent executes the shared sign-off knowledge-capture step exactly
  as written, taking no initiative beyond the literal instructions,
Then every artefact the step names — each directory, file or helper it tells
  the agent to load or run — is present at the location the step names, so
  no instruction resolves to a missing target,
And the step's "if unavailable, log a warning and proceed" branch is not the
  branch taken,
And a durable knowledge record exists once the agent's process has ended,
And that record carries the learning as the agent wrote it, in prose a reader
  who was not present in that run can understand from the record alone,
And a reader can recover the learning without opening the agent's console
  output and without opening any other file.
```

- [ ] AC-3: the step's "if unavailable, log a warning and proceed" branch is not the

## Implementation Notes

```yaml
- 'SCHEMA CHANGE (resolves the INF-400b-2 contradiction the BA escalated). The knowledge-capture
  record gains one additive field, `text`, carrying the learning body as the agent
  wrote it. The field is REQUIRED OF THE PRODUCER (an emitting agent must populate
  it with non-empty prose) and OPTIONAL TO THE CONSUMER (a reader must accept a record
  without it). This asymmetry is the whole backward-compatibility story: the 28 six-field
  records already in debugging/logs/agent_telemetry.jsonl stay structurally valid
  on read, and a missing `text` is a CLASSIFICATION (ineligible-to-write, per INF-700c-1)
  rather than a parse error or a validation failure.'
- GOVERNANCE — INF-400b-2 requires amendment and must NOT be edited by the implementer
  of this AC. Its enumerated field list (event, timestamp, agent, component, destination,
  entry_kind) becomes incomplete the moment `text` ships. Its separate clause 'structurally
  identical to the events emitted by phase agents via signoff section 7 step 4' does
  NOT need amendment and must keep holding — which is why the field must be added
  to BOTH emission surfaces in one change (see next requirement). Raise the amendment
  to the BA/PO; do not resolve it silently in code or prose.
- 'The `text` field must be added to all four emission surfaces in a single change
  so no install ever runs a mixed contract: templates/skills/signoff/SKILL.md section
  7 step 4, and the S9 knowledge-emission blocks of templates/agents/product-owner.md,
  templates/agents/business-analyst.md and templates/agents/it-po.md.'
- 'PRE-EXISTING DIVERGENCE, flag do not fix here: section 7 step 4 documents a record
  keyed on `ticket`, while the three v3 templates document `agent` + `component`;
  all 28 records on disk carry the v3 shape and none carries `ticket`. The harvester''s
  idempotency hash keys on `ticket` among other fields (scripts/knowledge/harvest_learnings.py
  `_event_hash`), so it hashes an always-empty field. Reconciling the two shapes belongs
  to INF-400b-2, not to this AC; this AC must not pick a winner unilaterally, and
  must not make the divergence worse.'
- 'The record is one JSONL line. `text` must be a JSON string that survives a json.loads
  round trip with embedded newlines escaped — no multi-line pretty-printing, no unescaped
  control characters, no raw markup fragments. Precedent: line 19 of the live sink
  is a bare `</content>` fragment left by a hand-composed append.'
- 'The replacement step must name ONLY artefacts that resolve in BOTH layouts: templates/skills/<name>/
  in the package checkout and .claude/skills/<name>/ in a consumer install. The names
  `route-learning` and `capture-learning` are retired by ADR-034 section 2 item 3
  and must not be reintroduced under any spelling; scripts/check_skill_refs.py currently
  reports 10 dangling imperative references to the two of them across six files, and
  INF-700b-2 turns that report into a refusal.'
- Must not introduce a sink-path literal. Which file the record lands in is INF-400c-4's
  decision and is currently unsettled (the harvester defaults to debugging/logs/knowledge_emissions.jsonl,
  which has never existed; the live records are in debugging/logs/agent_telemetry.jsonl).
  Reference the sink through the single declared path, never a second competing literal.
- Fail-open is retained — a knowledge step must never block an agent's primary output
  or its sign-off — but the proceed-anyway branch must leave a countable artefact.
  That obligation is specified by INF-700b-1-ii and must not be re-specified or contradicted
  here.
```
