## Acceptance Criteria

```gherkin
Given a test written to answer a specific requested kind of proof for a specific
    piece of work,
  And that test already carries the existing tag naming the piece of work it
    covers,
When the test is written and the suite is read,
Then the test also carries a tag naming the kind of proof it was written to give,
  And both tags are collected for the same test by one reader in one pass, so a
    test cannot be present on one axis and absent from the other by accident,
  And a test carrying a kind that is not one of the taught kinds is reported,
    naming the test and the unrecognised kind,
  And the new tag changes nothing about how any failing test is treated: it is a
    statement of what the test was written for, and it feeds no pass, done or
    eligibility decision anywhere.
```

### Scope correction — TWO SURFACES, AND THE PROMPT ONE IS NOT OPTIONAL

The generated `files_touched` named only `scripts/ac_store/done_proof.py`, and the
readiness report passed it on a path count (KI-ACS-002). That is half the work.

This ticket has **two owners and two surfaces**, which is why `change_target` is
`[prompt, code]` and why both `llm-expert` and `python-coder` are in the agents map:

| clause | surface | owner |
|---|---|---|
| 1 — the test *carries* a kind tag | `templates/agents/test-writer.md` | **llm-expert** |
| 2-4 — one scanner collects both axes | `scripts/ac_store/done_proof.py` | **python-coder** |

**Build only the reader and you have built nothing.** The AC's own it-po note says it
outright: *"Until one of those happens, python-coder builds a reader for a tag nothing
is instructed to emit."* The it-po recommended splitting clause 1 into an L3, but
rejected it because `BP-1100g` is at `child_limit_override: 7`. It stays in this ticket,
so it must be built in this ticket. `BP-1100g-1` (merged today, `c042c967`) already
added the `<!-- TAUGHT-TEST-ANGLES:START/END -->` anchor to that same template — the
tag-authoring convention belongs alongside it, in the same file, as one convention.

**Edit `templates/agents/test-writer.md`, never `.claude/agents/test-writer.md`.** The
latter is a symlink into `.leafcutter/` that `build.py` regenerates; an edit there is
lost on the next build and is listed in `out_of_scope` as a hard violation.

`scripts/commit_guardian/check_test_ac_tags.py` is ALSO in `out_of_scope`, but for a
different reason: it is the **second live reader** of this tag surface, with its own
`COVERS_REGEX`, currently in warn mode. The AC requires the two readers to stay in
agreement — that is a constraint to respect, not a file to edit here. If the work
genuinely cannot be done without changing it, stop and say so rather than editing it
quietly.
