## Acceptance Criteria

```gherkin
Given a criterion whose proof is written in the shape this project instructs its
  authors to write it in — driving the unit as a separate program it launches —
  and that shape is one the reachability judgement cannot watch,
  And the reachability rule nevertheless reaches a finding against that proof,
When the criterion is evaluated for eligibility to be marked done,
Then the criterion's eligibility is exactly what it would have been had the
  reachability rule not run at all, so the finding does not stop the criterion
  being marked done,
  And the finding is still announced in full — naming the unit, the way in that
    was not entered, the proof it is about, and which of the rule's reasons it
    would have refused for — so every affected criterion stays countable,
  And the announcement states that the finding does not block and names the
    defect in the judgement that is the reason it does not,
  And a criterion the rule reaches no finding against is likewise unaffected,
    so while the rule is in this state it can move no verdict in either
    direction,
  And the announcement offers no way to switch the rule off.
```

## Implementation Notes

```yaml
- SURFACE. The suspension lives in scripts/ac_store/_done_proof_entry_point_gate.py::_apply_entry_point_reachability_gate,
  which is already report-only in this tree. This AC's work is (a) making the announcement
  countable and complete and (b) proving the pass-through executes. Do NOT relocate
  the rule, do NOT add a second eligibility oracle, and do NOT delete the module's
  DECISION HISTORY block — BO-2900a-1-iii reads its re-arm conditions.
- THE PASS-THROUGH MUST BE TOTAL, NOT PER-BRANCH. On every path — finding, no finding,
  no entry point resolved, internal error — the function must return the verdict mapping
  it received with no key added, removed or changed. 'Same eligibility' is an equality
  property of the whole verdict, not just of verdict['eligible']; a rule that leaves
  eligible alone while writing refusal_cause has still moved the verdict for BO-2900e-1's
  message layer.
- 'EVERY FINDING MUST CARRY FOUR NAMED FACTS: the unit, the entry point that was not
  entered, the proof''s test nodeid, and the refusal_cause the rule would have used.
  A finding missing any one of the four is not countable and does not satisfy this
  AC. The only refusal cause this rule can put on a finding is proof_not_through_entry_point,
  and only from a reach record whose reached_through is the literal ''not_reached''
  (no_entry_point_reaches_code belongs to BO-2900a-3). An unwatched record (BO-2900a-2-ii)
  or an undecidable answer (BO-2900a-2-iii) is announced on the same finding channel,
  naming the unit, the entry point and the proof nodeid together with its unwatchable_cause
  or undecidable_cause, with refusal_cause null and no clearing action. It is never
  given a refusal cause. ''observation_unavailable'' is retired as a cause, and this
  AC must not invent another one.'
- 'THE FINDINGS MUST BE COUNTABLE WITHOUT PARSING PROSE. Emit each finding through
  one named function that produces BOTH the operator-facing line on stderr AND a structured
  finding record ({unit: str, entry_point: str, offending_test: str, refusal_cause:
  ''proof_not_through_entry_point''|null, unwatchable_cause: str|null, undecidable_cause:
  str|null}, where exactly one of the three cause fields is non-null) that an in-process
  caller can collect. BO-2900a-1-iii''s corpus exercise measures this population;
  a population only recoverable by regexing stderr is not a measurement, and a suspension
  that stops announcing removes the only evidence that can end it.'
- 'NO SUPPRESSION SURFACE MAY EXIST. The announcement path must read no environment
  variable, accept no keyword argument, and consult no config key that changes whether
  it announces. This is a property of the code, not only of the emitted text: an emitted
  line that names no bypass while an undocumented env var silences the whole function
  still fails this AC.'
- THE ANNOUNCEMENT MUST REACH THE OPERATOR IN ALL THREE check_done_proof MODES (precommit,
  ci, ci-changed) and from the DEPLOYED layout, not only from the source tree. Write
  to stderr directly; do not route through a logger whose level the calling context
  can lower to silence.
- 'ERROR HANDLING. Per the project error handling policy, a failure inside the rule
  must be logged at WARNING or higher and must not propagate into the eligibility
  decision — a rule that cannot decide must not be able to crash the gate that is
  ignoring it. It must equally not be swallowed silently: an inert rule and a suspended
  rule are indistinguishable without the log line.'
- 'PERFORMANCE. The rule still runs only after the two incumbent conditions have already
  returned eligible: True, and must not add a second pytest or subprocess invocation
  of its own beyond the observation call that is already there. It must not increase
  the per-AC done-proof budget measurably.'
```
