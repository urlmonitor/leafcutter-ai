## Implementation Notes

```yaml
- 'TWO findings must be modelled separately and be separately reportable: ''a local
  remnant exists'' and ''the shared record is damaged''. Collapsing them into one
  message in EITHER direction is what produced the recorded misdiagnosis, and collapsing
  them the other way is the cheapest way to pass this record.'
- The report's statement about the shared record must be DERIVED from an actual check
  of it, never asserted. 'The shared record is intact' printed without checking is
  the same class of untrue report BO-4100d exists to remove, arriving one component
  over.
- No remedy addressed at the shared record may be emitted on the leftover-only path.
  The recorded harm is not just a wrong word -- it sends the operator to repair the
  shared record, which is unnecessary and dangerous, while the actual remnant goes
  untouched.
- The leftover finding must name the location it occupies as a path, so the operator
  can act without searching.
- 'The two findings must be distinguishable by a machine-readable discriminator, not
  by wording, for the same reason BO-4100c-3''s two refusals must be: they call for
  different follow-ups.'
- Error handling follows the project error handling policy. A failure to CHECK the
  shared record is a third outcome -- it must not be reported as 'intact', and it
  must not be reported as 'damaged' either.
```
