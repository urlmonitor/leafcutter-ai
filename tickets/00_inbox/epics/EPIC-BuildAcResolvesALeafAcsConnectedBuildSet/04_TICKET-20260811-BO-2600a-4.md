## Acceptance Criteria

```gherkin
Given /build-ac processing a leaf AC in its single-ticket path (Step 2b),
And the coordinator resolves the connected build set via the select_connected
  CLI with --exclude-structural-parent,
When the resolved set contains more than one AC,
Then the coordinator emits a dependency-ordered epic folder (not a single ticket)
  by reusing the goal_to_epic machinery — one ticket per AC in the set, ordered
  prerequisites-first, with each ticket's depends_on wired to the co-located
  prerequisite tickets (via resolve_leaf_dependencies + topological_sort) so the
  ticket_frontmatter_guard passes,
And every member of the resolved set (the target AC and its baked-in prerequisites
  and un-built children) appears as a ticket in the epic folder,
And the Step 3 confirmation prompt adapts to the epic form
  ("Build this epic now? (yes / review / skip)"),
And dependency cycles are already drained (with a warning) UPSTREAM during
  connected-set resolution (fast_lane.resolve_connected_build_set), so the id list
  handed to goal_to_epic is acyclic; goal_to_epic's CyclicDependencyError is only a
  defensive backstop, and if it fires the coordinator surfaces the non-zero exit as
  an error rather than silently proceeding.
```
