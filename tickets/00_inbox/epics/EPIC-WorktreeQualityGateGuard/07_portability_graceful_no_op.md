# 07: Portability + Graceful No-Op

## Goal
Ensure build.py deploys the three guard scripts to the correct consumer directory structure, detect partial builds, handle non-worktree clones gracefully, support main-tree commits without gates, and establish authoritative "no config" detection.

## Context
Stub generated by create-epic. This ticket ensures the guard system works everywhere leafcutter is installed:
- BO-1700e-1 / e-1-i: build.py deploys 3 guard scripts with correct consumer subdir layout
  - Probe (verify_precommit_active.py) → deployed to consumer/scripts/commit_guardian/
  - Canary (precommit_canary.py) → deployed to consumer/scripts/commit_guardian/
  - Self-heal (ensure_precommit_config.py) → deployed to consumer/scripts/commit_guardian/
  - commit_guardian.json manifest → deployed to consumer/config/commit_guardian/
- BO-1700e-3: Detect and handle partial builds (missing one of the 3 scripts)
  - Gates gracefully no-op if any script is missing
  - Log a warning (not an error) when gates are skipped
- BO-1700e-4: Non-worktree clones (main-tree commits) skip gates gracefully
  - Detect when the code is not in a worktree
  - Allow commits on main tree without invoking gates
  - No error; gates simply do not run
- BO-1700e-5: Authoritative "no config" determination
  - If consumer has never run build.py or leafcutter is not installed, gates are absent
  - Code must not assume gates exist; gates must opt-in via setup
  - Main tree carries no gates by default
- BO-1700f-1 / f-1-i / f-1-ii: Consumer subdirectory layout and deployment strategy
  - All 3 scripts deploy to the same directory for atomicity
  - JSON manifest is the authoritative registry of deployed hooks
  - Idempotent deployment: running build.py twice produces identical state
