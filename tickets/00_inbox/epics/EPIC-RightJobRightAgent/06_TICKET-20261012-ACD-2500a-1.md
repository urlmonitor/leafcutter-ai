
## Implementation Notes

```yaml
- 'IT-PO decision (left open by the BA): the check is a CALLER of the store''s existing
  record check, not a parallel re-implementation. Rules that check already owns (config/ac_store_schema.json,
  the components rule, the parent back-link rule) are evaluated through its code path
  and each violated rule surfaces as exactly one finding.'
- 'Fail-closed on every inconclusive path: zero records checked, an unreadable record,
  or an internal error in any rule family yields verdict failed. The fail-open tail
  of the commit-time circular-dependency hook must not be reused.'
- Must operate directly on the feature-folder path it is given, independent of the
  git index and the staged-file set (check_ac_schema.py and check_ac_parent_covered_by.py
  read the index and are no-ops when pointed at a path by hand).
- The feature-planning workflow (templates/workflows-js/plan-feature.js; python-coder
  craft per ACD-1700b-1) runs the check at the end of each authoring stage (product
  owner, business analyst, technical planner, code-aware step) and reads the outcome
  from the check's exit status and JSON report, never from the stage agent's returned
  text.
- A stage whose check verdict is failed is not reported complete, does not advance
  to the next gate, and its report is shown at that stage's gate.
- 'Deterministic: an identical folder yields a byte-identical report (run-twice-and-diff).'
- Must complete within 5 seconds for a feature folder of up to 100 records.
- Must never modify criteria, title, depends_on, req_status or any field outside the
  three repair families of ACD-2500a-2 (write-locked fields per check_ac_governance.py).
- 'Ships to consumer projects with the plan-feature workflow: canonical source and
  deployed copy kept in parity through the build (ADR-001, ADR-013) and verified from
  the deployed layout after a rebuild.'
- Must log repairs at info and findings/failures at warning or above per the project
  error handling policy.
```
