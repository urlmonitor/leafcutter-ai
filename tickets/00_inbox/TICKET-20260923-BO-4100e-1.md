```gherkin
Given a directory sitting where workspaces are created, carrying a workspace's
  own identifying state, for which the registration record holds no entry,

And it is marked in the listing as having no registration entry, distinguishing
  it from the registered workspaces alongside it,
And the listing reaches it by inspecting the location workspaces occupy, so it
  is found even though nothing in the registration record refers to it.
```

## Implementation Notes

```yaml
- 'The listing must have TWO discovery routes and return their union: the registration
  record, and an inspection of the location workspaces occupy. A listing derived only
  from git worktree list structurally cannot surface a leftover that was never registered
  -- which is the entire defect, so the second route is the substance of this record
  and not an optimisation.'
- The location must be resolved exactly as creation resolves it -- _resolve_installed_layout()
  then <worktrees_base>/worktrees -- so discovery and creation can never disagree
  about where to look. A second, independently-derived location is a new way for a
  leftover to stay invisible.
- The discovered/registered distinction must be a machine-readable field on the entry,
  not a difference in how the entry is rendered. BO-4100e-2 addresses removal by it,
  BO-4100e-3 branches its report on it, and BO-4100e-4 refuses handover on it -- none
  of those can read a rendering.
- Discovery must be a READ. It must not register, repair, prune or write anything
  it finds; registering what is discovered is explicitly forbidden by BO-4100e-4.
- A directory whose own identifying state cannot be read must not be silently skipped
  -- it is the case most likely to be a genuine leftover. It is surfaced with the
  no-verdict outcome BO-4100c-1 defines rather than dropped.
- Listing must stay fast enough for routine use at the recorded scale (~150 entries),
  since every other child of BO-4100e runs on top of it.
- Any new module must be registered in the build deploy manifest, or the deployed
  listing path raises ModuleNotFoundError while the source-tree unit tests pass.
```
