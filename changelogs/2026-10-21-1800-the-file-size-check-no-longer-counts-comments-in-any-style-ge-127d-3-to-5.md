summary: "check-file-size now measures with a per-language tokenizer. A line counts only if it holds code: no comment counts in any style, standalone Python strings (docstrings, bare strings, DECISION HISTORY blocks) do not count, and blank lines never count anywhere. Rewriting // lines as /* */ blocks, or adding and removing blank lines, therefore changes nothing. A comment marker inside a string is code. A file that cannot be tokenized is INDETERMINATE. On a file already over its limit, a change that lowers the measured length while the real line count rises is refused."
description: "GE-127d-3, -3-i..-iv, -4, -5; closes KI-CG-20261013 (the measure can be gamed by comment style) and KI-CG-20261009 (/* inside a string opened a false block comment). New package templates/scripts/commit_guardian/_file_size_measure/ holds the line rules for Python (stdlib tokenize, with standalone-string detection from the token stream), C-family JS/MJS/TS (template literals, regex literals), JSX for .js/.mjs/.tsx (including type arguments on elements), SQL (dollar quotes, nested block comments) and shell (word-start #, here-documents). It also holds the over-limit backstop and the generated rule statement. _file_size_ratchet.py, check_file_size.py and _file_description.py measure through it. Blank lines never count, including inside comments and used strings (BrainCandy, 2026-10-21, after review showed a blank line between two // lines counted while the same blank inside a /* */ block did not). Shell `<<` inside arithmetic or [[ ]] is no longer read as a here-document. A SQL dollar-quoted body the lexer cannot read is counted as a string and logged at WARNING. Previous versions are re-measured with the same rule, so no file is refused just because the rule changed. Restyling comments counts as 0 added lines in the two-for-one repayment. A file that cannot be tokenized gives INDETERMINATE (exit 2). Refusal advice no longer names a free comment style. README.md and commit_guardian.json file_size._comment state the new rule, and check_file_size_rule_parity.py now compares the measurement rule too. The check-file-size hook is verbose, so a completing over-limit commit shows both lengths. A file that moves from over its limit to under it prints no length lines (GE-127e-4). Tests: unit_tests/commit_guardian/test_ge_127d_3*.py, test_ge_127d_4.py and test_ge_127d_5.py, including a TypeScript-compiler oracle over every tracked JS/TS file. Fixtures that copy commit_guardian helpers now copy the new package through _file_size_measure_copy.py. GE-127d-2's old-rule tests were rewritten for the new rule. GE-127d and its new children are marked done."
