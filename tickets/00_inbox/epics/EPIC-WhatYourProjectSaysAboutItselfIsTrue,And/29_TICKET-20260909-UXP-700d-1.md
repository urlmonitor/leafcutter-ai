# Example artifacts live under their own product root and never appear in a project's own record

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `UXP-700d-1` — Example artifacts live under their own product root and never appear in a project's own record — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `UXP-700d-1`. Component: `ux-prototyping`. Assigned agent: `python-coder`. Estimated complexity: `L`. Complexity: `high`.

## Acceptance Criteria

```gherkin
Given the example product's journeys, example datasets and screens,
When the artifacts belonging to the project's own record are enumerated,
Then none of the example product's artifacts is returned,
And the example product's artifacts are still returned when the example product is asked for
  by name,
And which product an artifact belongs to is decided by the product root it lives under rather
  than by anything in its content, so an artifact cannot belong to both and cannot be moved
  between them by an edit.
```

- [ ] AC-1: none of the example product's artifacts is returned
- [ ] AC-2: the example product's artifacts are still returned when the example product is asked for
- [ ] AC-3: which product an artifact belongs to is decided by the product root it lives under rather
