### Scope correction 1 — `reference_file_path` NAMES AN UNTRACKED BUILD OUTPUT. EDIT THE `templates/` COPY.

The AC's `reference_file_path` is `scripts/commit_guardian/commit_guardian.json`, and the
generated `files_touched` copied it verbatim. **That path is not a file. It is a symlink into a
build output, and git does not track it:**

```
scripts/commit_guardian -> ../.leafcutter/scripts/commit_guardian
git ls-files scripts/commit_guardian            ->  (no output — untracked)
git ls-files templates/scripts/commit_guardian/commit_guardian.json
                                                 ->  tracked
```

Editing through the symlink is worse than the usual deployed-copy trap. It is not merely wiped by
the next `build.py` — the file is **untracked, so the edit never reaches the commit or the PR at
all**. The registration would appear to work locally, the hook would run locally, and nothing
would ship. Every edit goes to `templates/scripts/commit_guardian/`.

This is not the AC's fault in the usual sense: its own constraint explains that
`reference_file_path` must resolve to an existing file and that the real work is a new module. It
just names the deployed path while doing so. Do not "fix" the AC — build against `templates/`.

### Scope correction 3 — "the stated behaviour" is not a field that exists

The AC requires the refusal to name three things: *the piece of work, the stated behaviour, and
the kind of proof that was promised and never claimed.* Two of those are directly available. The
third is not.

A `test_spec` descriptor carries `name`, `target_dir`, `framework`, `type`, `angle` and
`description`. **There is no field linking a descriptor to the particular Then-clause it was
promised for.** So "the stated behaviour" cannot be read off the promise side as things stand.

**Decision for this ticket — do not improvise an alternative.** Treat the AC leaf itself as the
stated behaviour: name the AC id and its `criteria` text (truncated for the message), and include
the descriptor's `description` as the specific promise that went unclaimed. For L2/L3 leaves in
this store one leaf is approximately one behaviour, so this satisfies the actionability
requirement the constraint actually cares about — *"the reader has to be able to go and write the
specific missing test."*

Do **not** add a `criterion_ref` field to `test_spec` to make this exact. That is a schema change
to the AC store, it is not in this AC's scope, and it would need its own AC. If the approximation
turns out to be insufficient, stop and say so rather than widening the schema quietly.

### The hard boundary — READING A TEST BODY IS FORBIDDEN ON EVERY PATH TO THE OUTCOME

The AC is unambiguous and this is the one thing that must not be got wrong:

> Reading a test FILE to COLLECT its tag is the scanner's job and is permitted; opening, parsing,
> tokenizing, importing-for-inspection or regexing a test's BODY to judge what it does is
> forbidden on every path to the outcome (BO-2900a-2). **A source scan inside a phantom-done guard
> is itself phantom-done.**

Both inputs are authored declarations and nothing else may be consulted:

- **Promise** — the `## Test Requirements` descriptors' `angle` values (already emitted by the
  generator today).
- **Claim** — `collect_test_tag_records()` from `done_proof.py`, shipped by `BP-1100g-3`
  (`2f740cc4`). **Import it. Do not reimplement a second scanner** — a parallel reader of one
  source is the `EPIC-ComputedQualityGates` layer-3 failure, and `BP-1100g-3` extended the
  existing scanner precisely to avoid it.

`scripts/ac_store/done_proof.py` is therefore in `out_of_scope`: **consume it, never modify it.**

### The denominator rule is the difference between a useful gate and one that gets switched off

The promise set is the denominator. A kind absent from the promise set is absent from the refusal,
always. Without it the check degenerates into demanding all seven kinds on every piece of work,
buries the signal it exists to raise, and gets disabled. A plan promising nothing produces no
refusal at all.

### REGRESSION GATE — `BP-1100g-3-i` MUST STILL PASS

`BP-1100g-3-i` (merged today, `8f55fd25`) asserts the angle axis **feeds no pass, done or
eligibility decision**. This ticket makes the angle axis feed a *refusal*. Those are compatible,
but only for a specific reason, and an implementer who blurs it will silently break the invariant:

- `g-3-i` governs the **run outcome and completion decision** — which *failing* tests block, and
  whether work counts as done. Untouched here.
- `g-4` blocks at commit time on a **missing** test. It never makes work look *more* complete, and
  it must never change which failing tests block (the AC says so explicitly).

So: **run `unit_tests/ac_store/test_bp_1100g_3_i.py` and
`unit_tests/commit_guardian/test_bp_1100g_3_i.py` as a regression gate before sign-off.** If either
goes red, the new gate has leaked into the eligibility path and the design is wrong — surface it,
do not adjust those tests.

One caution learned from `g-3-i`'s own build: its `real_artifact` test was initially unable to
observe the leak it existed to forbid, and was only caught by mutation. Green there is not
self-evidently meaningful. If you change anything those tests read, re-verify by mutation rather
than by re-running.

### Scope correction 4 — two conditional phases were in the map with no condition to read

The generator put `user-surface-smoker` and `documentation-verifier` in the agents map as
`needed`, but wrote neither of the frontmatter fields they key on. Both templates say *"Only
emitted in agents: map when `<field>` != null"* — so as generated, both agents were dispatchable
with their governing field absent. `documentation-verifier` is documented fail-closed
(*"an ambiguous parse or exception emits status: blocker, never status: ok"*), and a phase that
cannot complete leaves itself `needed`, which is exactly the outstanding-phase halt the
`BP-1100g-3` drive hit.

Note the near-miss that caused it: the generator emitted `documentation_required: true` — a
**different field** from the `requires_documentation_verification` the agent actually reads. A
grep for "documentation" in the frontmatter looks satisfied while the condition is unset.

Both fields are now set. `user_facing_surface: pre_commit_hook` is not a formality here — the AC
says so directly: *"the refusal message is exactly the kind of user-facing output
user-surface-smoker's placeholder negative control exists to check ('proof requirements not met'
is the placeholder to fail on)."*
