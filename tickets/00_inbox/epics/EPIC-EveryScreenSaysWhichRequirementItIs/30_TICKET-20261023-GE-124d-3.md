## Acceptance Criteria

```gherkin
Given the staged set contains an in-scope screen component with no
  component-level declaration
And its file header records an accepted opt-out reason
When the commit-tier declaration check runs
Then exactly one verdict is recorded for that file and that code, and it is
  "pass-with-reason"
And no "block" verdict is recorded for the same file and the same code

Given a file that is both on the warn list and carries an accepted opt-out
  reason
When the commit-tier declaration check runs
Then exactly one verdict is recorded for that file and that code
And the recorded verdict is "pass-with-reason", because a stated reason is a
  stronger claim than an area-wide postponement
And the report names the reason, so the file does not read as merely
  postponed

Given a file that is on neither the warn list nor excused by a reason
When the commit-tier declaration check runs and finds no declaration
Then the recorded verdict is "block"
```

## Implementation Notes

```yaml
- 'RESOLVE THE VERDICT ONCE, IN ONE PLACE, BEFORE ANY FINDING IS EMITTED. Implement
  the escapes as a single verdict-resolution step that takes (base verdict, warn-listed?,
  accepted reason?) and returns ONE verdict, rather than as two independent downgrade
  passes over an emitted finding. Two passes can each write, and the mock-data invariant
  is absolute: verdict == ''block'' implies suppression_reason == null.'
- 'PRECEDENCE IS OPT-OUT > WARN > BLOCK, encoded as an explicit ordered rule with
  the reason recorded next to it, not as the incidental result of the order two if-statements
  happen to appear in. USER CONFIRMATION NEEDED: the BA chose opt-out over warn on
  the grounds that a stated reason is more specific and more accountable than an area-wide
  postponement, and that resolving to warn would discard something a reviewer could
  challenge. The alternative (warn wins) is defensible. This is not stated in the
  PO note or in the mock data — confirm at the final gate rather than absorbing it.'
- A REFUSED OPT-OUT (GE-124d-2-i) IS NOT AN OPT-OUT for precedence purposes. The input
  to the precedence rule is 'accepted reason?', not 'marker present?', so a file with
  a refused marker on a warn-listed path resolves to warn, and one on an unlisted
  path resolves to block.
- suppression_reason IS POPULATED EXACTLY WHEN THE RESOLVED VERDICT IS pass-with-reason
  and is null for every other verdict. That biconditional is the mechanical form of
  'never sits beside it' and is the cheapest thing to assert in a test.
- 'THIS AC AND GE-124c-1-i ARE DIFFERENT RULES: that one fixes the COUNT of findings
  at one per (subject, code); this one fixes which single VERDICT that finding carries.
  An implementation can satisfy either while breaking the other — one finding with
  a contradictory verdict, or two findings each with a defensible one.'
```
