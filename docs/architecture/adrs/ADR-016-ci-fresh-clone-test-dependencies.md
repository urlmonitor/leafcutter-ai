# ADR-016: CI Fresh-Clone Test Dependencies — Build Step Required Before Test Suite

## Status

| Field | Value |
|---|---|
| Status | Accepted |
| Date | 2026-06-24 |
| Deciders | leafcutter engineering team |
| Author | leafcutter engineering team |
| Supersedes | — |

## Context

[ADR-004](ADR-004-consolidated-output-root.md) consolidated all `build.py`
output artifacts into a single `.leafcutter/` directory at the consumer project
root, replacing the previous scattered layout. As part of this consolidation,
three script directories that were previously emitted at the project root were
moved into `.leafcutter/scripts/`:

- `scripts/commit_guardian/` → `.leafcutter/scripts/commit_guardian/`
- `scripts/doc_compliance/` → `.leafcutter/scripts/doc_compliance/`
- `scripts/feedback/` → `.leafcutter/scripts/feedback/`

ADR-004's shim layer creates symlinks (or copies on Windows) at the canonical
tool paths for Claude Code (`.claude/agents/`, etc.) and pre-commit
(`.pre-commit-config.yaml`), but did **not** include shims for the
`scripts/commit_guardian/`, `scripts/doc_compliance/`, and `scripts/feedback/`
directories.

The consequence: approximately 36 tests across `tests/` and `unit_tests/` add
the old `scripts/<subdir>/` paths to `sys.path` at import time:

```python
sys.path.insert(0, str(Path(__file__).resolve().parents[1] / "scripts" / "commit_guardian"))
```

On a developer's machine that has run `build.py` at least once, these
directories exist as shims (symlinks to `.leafcutter/scripts/...`) from a prior
build, so the tests pass. On a **fresh clone** — or in a CI environment that
pulls the repo and runs the test suite without first running the build step —
the `scripts/commit_guardian/`, `scripts/doc_compliance/`, and
`scripts/feedback/` directories are absent. The tests fail at import with
`ModuleNotFoundError`, even though the module code is present inside
`.leafcutter/scripts/`.

This is AC `BP-1200a-1`: the full test suite must pass deterministically on a
fresh clone using the documented CI test command.

### Options evaluated

**Approach 1 — Extend shim_map (chosen)**
Add three directory shims to `install_shims()` in `build_helpers.py`:

```python
("scripts/commit_guardian", "scripts/commit_guardian"),
("scripts/doc_compliance", "scripts/doc_compliance"),
("scripts/feedback", "scripts/feedback"),
```

The CI procedure becomes: install dev dependencies, run `build.py`, run the
test suite. All 36+ affected tests resolve their imports through the symlinks
at the old `scripts/` paths.

**Approach 2 — Repoint tests to `.leafcutter/scripts/`**
Change every `sys.path.insert` in the test files to point into `.leafcutter/`
directly. This removes the shim dependency but requires touching ~36 test
files and means the `.leafcutter/` layout is now baked into the tests.

**Approach 3 — Track build outputs in git**
Commit `.leafcutter/scripts/commit_guardian/`, `.leafcutter/scripts/doc_compliance/`,
and `.leafcutter/scripts/feedback/` to the repository. Fresh clones would then
have all files without a build step.

### Why the alternatives were rejected

**Approach 2** couples the test surface to the internal `.leafcutter/scripts/`
path, which is an implementation detail of ADR-004. If the output root is ever
renamed or restructured, every test `sys.path` insertion must change again.
The shim pattern exists precisely to insulate consumers and tests from this
detail. Touching 36 test files also widens the blast radius without resolving
the underlying gap.

**Approach 3** violates the ADR-004 invariant that `.leafcutter/` is a build
artifact (git-ignored, regenerated by `build.py`). Committing build outputs
would cause `git status` noise for every developer and would defeat the
isolation goal of ADR-004. On Windows with Developer Mode disabled, the
tracked symlinks would also break silently.

## Decision

**Approach 1** is accepted. The `install_shims()` function in
`scripts/build_helpers.py` is extended to shim three additional directories:

```python
("scripts/commit_guardian", "scripts/commit_guardian"),
("scripts/doc_compliance", "scripts/doc_compliance"),
("scripts/feedback", "scripts/feedback"),
```

Each entry creates a symlink (or copy on Windows) at the old project-root
location pointing into `.leafcutter/scripts/<name>/`.

The documented CI test command for this repository is:

```bash
# 1. Install development dependencies
pip install -r requirements-dev.txt

# 2. Run the build step to deploy shims and artifacts
python scripts/build.py --target-dir .

# 3. Run the full test suite
python -m pytest tests/ unit_tests/ -x -q
```

This procedure must be followed on every fresh clone. Running only step 3
(without step 2) on a fresh clone will fail with `ModuleNotFoundError` for
the commit-guardian, doc-compliance, and feedback modules.

## Consequences

**Positive:**
- All tests pass deterministically on a fresh clone.
- No test files need to change — the shim layer absorbs the path difference.
- The `.leafcutter/` internal layout remains an implementation detail; tests
  still import from the stable `scripts/<name>/` path.
- Consistent with the ADR-004 principle: shims bridge canonical tool paths to
  the consolidated output root.

**Negative / accepted tradeoffs:**
- CI and fresh-clone operators must run `build.py` before `pytest`. This is a
  new prerequisite that must be documented in the CI workflow configuration.
- Consumer install risk: the three new shim entries are created by
  `install_shims()`, which also runs during consumer-project installs
  (`python leafcutter-ai/scripts/build.py --target-dir .`). The shims at
  `scripts/commit_guardian/`, `scripts/doc_compliance/`, and
  `scripts/feedback/` will be created in **consumer** projects too. This is
  correct behavior — these directories are pre-commit hook scripts that the
  consumer's `.pre-commit-config.yaml` must be able to locate — but it
  means the shim layout is now part of the consumer install contract.
  Any future rename of these directories in `.leafcutter/scripts/` is a
  breaking consumer-facing change and requires a migration step.
- The existing `scripts/` directories in the leafcutter-ai development
  environment (the self-hosted install) are currently deleted from git
  (status: `D`) because the build step has not yet been re-run to recreate
  them as shims. Running `build.py --target-dir .` from the repo root
  after this change will recreate the shims and restore a green test state.

**Operational:**
- `install_shims()` uses the same symlink-first, copy-fallback strategy for
  all three new shims as it does for the existing `.claude/agents/` shims.
  No new failure modes are introduced.
- The `force=True` default in `install_shims()` means re-running `build.py`
  will overwrite stale shims without requiring a manual cleanup step.
