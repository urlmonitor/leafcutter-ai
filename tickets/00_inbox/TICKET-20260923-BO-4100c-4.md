# A workspace holding nothing is disposed of completely, and leaves the live set

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-4100c-4` — A workspace holding nothing is disposed of completely, and leaves the live set — so that the acceptance criterion is satisfied.

## Acceptance Criteria

```gherkin
Given a workspace carrying the holds-nothing verdict,
When its disposal is requested,
Then the disposal completes and reports success,
And the workspace no longer appears in the live set,
And no directory remains at the location it occupied,
And no registration entry for it remains, so a second listing of the live set
  returns the same entries as the first.
```

- [ ] AC-1: the disposal completes and reports success
- [ ] AC-2: the workspace no longer appears in the live set
- [ ] AC-3: no directory remains at the location it occupied
- [ ] AC-4: no registration entry for it remains, so a second listing of the live set

## Implementation Notes

```yaml
- Directory removal, registration removal and branch-reference removal are one operation
  whose PARTIAL completion is itself a failure, not a partial success. A half-disposal
  that removes the directory and leaves the registration produces an entry that can
  never be assessed again, which BO-4100c-3 must then refuse forever -- so the anti-accumulation
  arm would make the accumulation permanent.
- Residual background processes and open file handles inside the workspace must be
  dealt with before removal, or removal fails precisely on the workspaces that were
  most recently in use. scripts/worktree/sweep_processes.py already exists for this
  and must be reused rather than reimplemented; if it is not currently reachable from
  the deployed layout, making it so is part of this work.
- 'Disposal must be idempotent: a second request for an already-disposed workspace
  must not error the run, and repeated listings of the live set must return identical
  entries.'
- The verdict that authorises disposal must come from BO-4100c-1's assessment record,
  not from a check disposal performs itself. A second derivation can authorise what
  the first refused.
- This record says nothing about disposal running while a drive is in progress --
  that constraint is BO-1800d's and must not be restated or implemented here.
- Any new module must be registered in the build deploy manifest, or the deployed
  disposal path raises ModuleNotFoundError while the source-tree unit tests pass.
```
