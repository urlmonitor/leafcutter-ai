# llm-expert flags ambiguous agent trait for human review

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-510-4-i` — llm-expert flags ambiguous agent trait for human review — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-510-4-i`. Component: `build-orchestration`. Assigned agent: `llm-expert`. Estimated complexity: `S`.

## Acceptance Criteria

```gherkin
Given an agent template has a description that does not clearly map to
  a single produces value (e.g. an agent that both writes code AND
  produces documentation, or a utility agent with role: analysis that
  also writes configuration files),
When llm-expert attempts to infer the produces trait from the template,
Then it does NOT silently assign an arbitrary value
And it marks the entry with produces: null in the registry
And it appends a structured comment to its sign-off output listing:
  - The agent ID
  - The conflicting signals (e.g. "description mentions both code and docs")
  - The two most likely enum values
And the validation test (BO-510-3) continues to FAIL for that agent
  until a human resolves the ambiguity

Given a human then sets the correct produces value on the flagged agent,
When the validation test runs,
Then it PASSES for that agent
```
