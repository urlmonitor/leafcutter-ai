# A declarative documentation-gates policy demands docs for user-facing, data, flow, and docs changes

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-2200a-1` — A declarative documentation-gates policy demands docs for user-facing, data, flow, and docs changes — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-2200a-1`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a declarative `documentation_gates` policy section exists in the guardrail
  gates configuration, and the ticket generator builds the agents map for a leaf AC,
When the AC's `change_target` is `ui`,
Then the generated agents map includes `documentation-expert`.
And the same result holds when `change_target` is `schema`, `pipeline`, or `docs`
  (each of these four values, on its own, causes `documentation-expert` to be required).
And the requirement is driven entirely by the declarative policy data, not by a
  value hard-coded in the generator, so adding or removing a triggering value is a
  configuration edit rather than a code change.
```
