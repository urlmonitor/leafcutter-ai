description: "Each of the three acceptance-criteria authoring agents carries a parent covered-by update section, implementing the AC schema's S6b protocol, that the template itself marks mandatory. Each says in so many words to use an Edit call that modifies only the covered_by field and overwrites nothing else. None of the three listed Edit among its tools. Four authoring agents dispatched in sequence on 2026-08-26 hit this, each reported that Edit was unavailable to it, and each fell back to rewriting the entire parent file with Write. That fallback is not an equivalent substitute, which is the reason this is a defect rather than a tidy-up. Edit requires an exact match on the text it replaces and therefore fails closed; Write replaces a file wholesale and cannot fail that way. Acceptance-criteria YAML files are untracked until they are committed, so a truncating Write on a file that has never been committed is unrecoverable, with no earlier version to restore from. The hazard is not theoretical: one of the four leaked stray markup into a file tail on its first Write and caught it only through a manual inspection of the file's end that nothing obliged it to perform. Worse, the natural proof that a whole-file rewrite was surgical, comparing the change statistics against the previous commit, is vacuous for an untracked file, because it reports nothing whether the file survived intact or was emptied. So the check anyone would reach for does not cover the risk actually being run. This is the AR-200 rule, that a specialist's capability must match its obligation, reached through a second and different obligation source. AR-200a derives the obligation from the sign-off protocol, and all of its instances carry a sign-off requirement; these three do not, and were outside that rule's derivation by construction rather than by oversight, which is why this lands as a sibling feature rather than as three more instances of the existing one. The fix grants Edit to all three templates, keeping and extending the scoping comment each already carried. No instruction was changed or removed. All three already declared that they require verification, because they already held Write, so the registry validator rule that would otherwise fail the build's shim-installation step is satisfied; a dry-run build confirms zero errors. The accompanying test derives both sides of the comparison from the templates themselves rather than naming the three known offenders, so the value is the fourth instance nobody has noticed yet. It carries three guards on itself: a synthetic violator, so the rule cannot decay into proving only that its own loop runs once the real instances are fixed; a control case using ordinary English about editing, so the cheapest passing implementation, a bare word match that flags most of the registry, is ruled out; and an assertion that the scan actually reaches the agent registry, closing the third way this class of rule goes quietly vacuous, which this repository has shipped once before in a validator whose bare-directory argument matched nothing and reported success for eight days. The red baseline was verified rather than asserted: with the three template changes set aside the rule fails and names all three violators, and with them restored all four tests pass. The binding constraint is recorded in the acceptance criterion and repeated in the test's own failure message, because it is easy to get backwards here: grant the capability, do not delete the instruction. Removing the line that names Edit would make the rule pass while leaving the agents performing whole-file rewrites on unrecoverable files, trading a caught contradiction for an uncaught hazard."
