## Implementation Notes

```yaml
- 'A new rule family registered as docs/reference/requirement-rule-check.md ''How
  a new family registers'' describes (own module, name constant in the report module,
  entry in the deploy map). It is report-only: it never repairs, and the guarded writer''s
  repairable-field set does not change.'
- The before-state for field comparison is each record as committed at --before-ref.
  A run whose before-state holds no field values (a readiness-only --before-snapshot)
  lists the records 'not evaluated' for this family; it never passes them.
- The fixed protected-field list is held once in code and must equal the list of fields
  templates/agents/test-designer.md tells the test designer not to touch; a parity
  test fails naming the field present on one side only.
- A field counts as changed when its parsed value differs; a re-formatting that leaves
  the value equal is not a finding.
- covered_by entries appended by the back-link family in the same run are told apart
  by the run's own pending repairs, not by exempting covered_by.
- The report stays deterministic (sorted findings, no timestamps), with at most one
  finding per (record, field).
- The family needs each record's committed value of every protected field; today's
  before-state carries readiness only, so the before-state loader in scripts/ac_store/_rc_records.py
  is extended to carry the full committed record (or the protected fields) for each
  id.
- it_requirements in list (or string) form is compared as one protected value; in
  mapping form every key except reference_file_path is compared on its own; a change
  from one form to the other is reported as a change of it_requirements.
```
