# Artifact Numbering

Look here for the shape a numbered artifact's identifier takes, where the
authoritative list of already-claimed numbers lives, how to obtain a free one, and
what actually enforces uniqueness today (as opposed to what a goal in progress
intends to enforce once it ships).

**This document currently covers what the code implements.** A fuller,
three-section version of this same file — a generalized one-number-one-artifact
rule, a formal enrolment/exemption table, and a bypass-consequence table — is
specified by three approved-but-unbuilt acceptance criteria (`GE-122a-3`,
`GE-122b-4`, `GE-122d-5`, all `work_status: todo`, all assigned to
`documentation-expert`). A future pass against those ACs should **extend this
file**, not create a competing one — see [Known Divergences](#known-divergences).

---

## The Shared Rule

Four kinds of artifact in this repository are identified by a number: acceptance
criteria, decision records (ADRs), architecture diagrams, and work items (tickets).
`check_identifier_uniqueness.py` runs a **whole-collection** pass — it walks every
artifact in a namespace in one go, rather than validating one staged file in
isolation — and reports every number claimed by two or more artifacts in the same
namespace. This is the load-bearing difference from the older per-file validators:
a per-file check cannot see that a sibling file elsewhere claims the same number: it
opens one artifact at a time and has no memory of any other.

The scanner and its per-namespace walks live in
`templates/scripts/commit_guardian/check_identifier_uniqueness.py`,
`_uniqueness_scanners.py`, and `_work_items_scanner.py`.

## Namespaces at a Glance

| Namespace | Root | Number shape | Authoritative claimed-number source | How to get a free one |
|---|---|---|---|---|
| Acceptance criteria | `docs/acceptance-criteria/` | `PREFIX-NNN[x[-N[-y]]]`, e.g. `GE-122a-3` (hierarchical; parent derived by stripping the last segment) | Recursive walk of every `*.yaml`'s top-level `id` field (`scan_acceptance_criteria`) | Assigned by the authoring pipeline (business-analyst / it-po) when decomposing a parent AC — not a simple increment. See [ac-schema.md](ac-schema.md) for the full ID format. |
| Decisions (ADRs) | `docs/architecture/adrs/` | `ADR-<integer>-<slug>.md` | Highest existing integer in the directory, cross-checked against `origin/main` and in-flight remote branches by `check_adr_collision.py`; `scripts/adr_refs.py`'s "Unclaimed numbers" line is authoritative for which integers are truly free (see [Never-Reuse Rule](#never-reuse-rule)) | `adr-author` scans for the highest existing integer and increments; `check_adr_collision.py` (registered at commit time, see [ADR-029](../architecture/adrs/ADR-029-adr-number-collision-prevention.md)) prints the next free number on a collision. |
| Architecture diagrams | `docs/architecture/diagrams/` | `c{level}-{seq:03d}-{slug}.md`, `level` ∈ `1-4`, `seq` a zero-padded 3-digit integer, `slug` lowercase hyphen-separated | Flat glob of `c{level}-*.md` per level | `python scripts/next_diagram_seq.py <level>` — prints `max(existing seq at that level) + 1`, `1` if none exist. Never guess the number by hand. |
| Work items (tickets) | `tickets/` (lifecycle folders declared in `tickets/ticket_lifecycle.json`) | `TICKET-YYYYMMDD-<source-AC-ID>.md` basename | The set of `TICKET-*.md` basenames across all declared lifecycle folders (`_work_items_scanner.py`) | Generated by `generate_ticket_from_ac.py` from the source AC's ID — there is no separate ticket-number allocator. The guarded failure here is a stale duplicate basename left in two lifecycle folders after a move, not two unrelated tickets colliding on a fresh name. |

## Diagram Numbering

Because `docs/architecture/diagrams/README.md` defers to this document for the
numbering convention, this section gives the diagram namespace the most detail.

The filename pattern is enforced at commit time by `check_diagram_naming.py`,
whose regex is:

```python
_FILENAME_RE = re.compile(r"^c([1-4])-(\d{3})-([a-z0-9-]+)\.md$")
```

It also cross-checks that the filename's level digit matches the file's
`flight_level` frontmatter (`L1-Context`→`1`, `L2-Container`→`2`,
`L3-Component`→`3`, `L4-Code`→`4`). **This check applies only to staged files whose
frontmatter has `type: architecture`** — a file of any other `type` in the same
directory is never checked, no matter what its filename looks like.

`scripts/next_diagram_seq.py` is the canonical allocator: it recursively globs
`docs/architecture/**/c{level}-*.md`, extracts the 3-digit sequence from each
matching filename, and returns `max(used) + 1` (or `1` if none exist at that
level). It deliberately never reuses a number from a deleted diagram.

## Never-Reuse Rule

[ADR-029](../architecture/adrs/ADR-029-adr-number-collision-prevention.md) states
the rule this document generalizes from, currently written for the decisions
namespace only:

> A number is free only when it has **neither a file nor a citation**. Reusing a
> number that existing text still cites converts a dangling reference into a
> confidently wrong one, which is worse.

`scripts/adr_refs.py`'s "Unclaimed numbers" output is the authoritative free-list
for ADRs under this rule. No equivalent free-list tool exists yet for the other
three namespaces; their scanners currently test only "does a file/record claim this
number right now", which is a weaker test than ADR-029's citation-aware one.

## Whole-Collection Uniqueness Enforcement

The same rule evaluation (`check_identifier_uniqueness.run_uniqueness_pass`) runs
at three stages, imported — never re-implemented — by each:

| Stage | Mechanism | Can it be skipped? | Current status |
|---|---|---|---|
| Authoring time | `check_identifier_uniqueness_authoring.py`, a PostToolUse hook on `Edit\|Write` | Not deliberately, but a hook that crashes, times out, or fails to import emits nothing — indistinguishable from a clean write. | Advisory only; reports in-session. |
| Commit time | Pre-commit hook `check-identifier-uniqueness` (`always_run: true`, `pass_filenames: false`) plus the per-namespace guards (e.g. `check_adr_collision.py`) | Yes — any commit-time bypass (`--no-verify`, or an unconfigured `.pre-commit-config.yaml` in a fresh worktree) skips it entirely. | Blocks the commit only when a finding is **attributed to the currently staged diff**; a pre-existing, unattributed collision is printed as "reported-but-unattributed ... not blocking" and does not block. |
| Shared build | CI job `numbering-guarantee-valid` in `.github/workflows/ci.yml`, running `pre-commit run check-identifier-uniqueness` against the PR/push diff | Runs automatically on every push/PR. | **Not yet a required status check.** The AC that adds it to the branch ruleset's required-check set, `GE-122d-2`, is `work_status: todo` as of this writing — so a red result here is currently visible but does not block a merge. |

## Known Divergences

- **Two different diagram-filename regexes.** The commit-time naming hook
  (`_FILENAME_RE = r"^c([1-4])-(\d{3})-([a-z0-9-]+)\.md$"`, scoped to
  `type: architecture` files) is stricter than the whole-collection uniqueness
  scanner's diagram matcher (`_DIAGRAM_FILENAME_RE = r"^c(\d+)-(\d+)-.*\.md$"`,
  case-insensitive, no digit-count or level-range limit, and applied to **every**
  `*.md` file in the directory regardless of its `type`). A file with an unrelated
  `type` whose name happens to start with `c1-002-` would register a claim in the
  uniqueness scanner's diagrams namespace without ever being checked by the naming
  hook. Not yet reconciled.

- **11 files in `docs/architecture/diagrams/` do not match the enforced
  `c{level}-{seq:03d}-{slug}.md` pattern**, all carrying `type: architecture`
  frontmatter: `c2-fast-lane-build-path-components.md`,
  `c2-fast-vs-heavy-lane-phases.md`, `c3-done-proof-evaluation-sequence.md`,
  `c3-fast-lane-build-loop-sequence.md`,
  `df-001-dual-engine-workflow-build-transform.md` (a `df-` dataflow prefix
  outside the `c{level}-` convention entirely), `finalize-progress-narration-sequence.md`,
  `finalize-progress-relay-sequence.md`, `gates-sequence.md`, `probe-sequence.md`,
  `self-heal-component.md`, and `self-heal-sequence.md`. Each would fail
  `check_diagram_naming.py` if it were ever re-staged; they are dormant only
  because that hook inspects staged files, not the whole directory. **They are not
  renamed here** — a formal enrolment/exemption table recording this population as
  a deliberate, reasoned exemption (not an oversight) is the subject of `GE-122b-4`
  (`work_status: todo`).

- **The "cannot be skipped" goal is not yet true end to end.** `GE-122`'s own
  stated goal is that a clash "surfaces the moment it appears... at a point where
  it cannot be skipped." Today: the commit-time stage is bypassable, and the
  shared-build stage that would be the unbypassable backstop is not yet a required
  check (`GE-122d-2`, `todo`). Treat this document as describing present behavior,
  not the fulfilled goal.
