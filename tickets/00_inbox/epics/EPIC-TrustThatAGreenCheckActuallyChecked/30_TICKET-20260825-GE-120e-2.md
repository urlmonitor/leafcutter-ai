## Acceptance Criteria

```gherkin
Given the guardrail engine's hook manifest, which lists every check it installs,
When the set of checks that work out their own change set is determined,
Then the candidate set is every entry in the manifest, read at the time of the
  determination,
And each entry records where its change set comes from — handed to it by the commit path,
  or taken from the shared authored-change source — as a value on the entry itself,
And membership is decided from that recorded value, never from a list of check names
  written down by hand and never from the two checks observed misattributing,
And every check recorded as taking its own change set takes it from the shared source,
And a check recorded as taking its own change set that obtains it by any other means is
  named and the determination reports a failure.

Coverage note: exercise this against a manifest fixture, not against today's manifest. A
test asserting that the checks registered today all take the shared source passes forever
and cannot fail on the day the next self-deriving check is added, which is the day this AC
exists for. Execute the determination and assert on the names it reported and the result
status it produced.
```

## Implementation Notes

```yaml
- 'WHERE THE FIELD GOES. One new key per entry of hooks_manifest.hooks[] in templates/scripts/commit_guardian/commit_guardian.json.
  build_commit_guardian() deploys that manifest TWICE — to scripts/commit_guardian/commit_guardian.json
  (the runner''s copy) and to config/commit_guardian/commit_guardian.json (the authoritative
  copy). Both are generated from the one template: edit the template only, then run
  build.py and confirm both deployed copies carry the field.'
- 'PASS_FILENAMES IS NOT THE DISCRIMINATOR AND MUST NOT BE USED AS ONE. 52 of the
  54 entries in today''s manifest carry pass_filenames: false while only a handful
  derive a diff at all. A predicate built on it sweeps in dozens of checks with no
  change set to narrow and still misses a check that is handed filenames and derives
  a diff anyway. The source is a declared value, full stop.'
- EVERY ENTRY MUST CARRY THE FIELD; ABSENT IS NOT A DEFAULT. An entry with no recorded
  source is a determination FAILURE, so the next hook added without one is blocked
  when it is added rather than silently classified. Defaulting the field is the same
  decay this AC exists to stop, one release later.
- DO NOT BREAK THE MANIFEST'S EXISTING CONSUMERS. scripts/build_precommit.py generates
  .pre-commit-config.yaml from these entries and templates/scripts/commit_guardian/check_hook_parity.py
  compares the generated config back to the manifest. After adding the key, run build.py
  and confirm .pre-commit-config.yaml is unchanged apart from intended edits, and
  that check-hook-parity still passes.
- THE DETERMINATION MUST ACCEPT AN EXPLICIT MANIFEST PATH AND HONOUR IT. Without that,
  this AC's own coverage note — exercise against a fixture manifest, not today's —
  is untestable. This repository has a recorded history of AC hooks that ignore argv
  and read only the installed artefact, which makes them fail open and impossible
  to exercise; do not repeat it.
- REUSE GE-120c-3'S MANIFEST-READING CALLABLE. Two manifest readers will disagree
  and the disagreement will be settled by whichever is quieter. One reader, two questions.
- DO NOT HARD-CODE THE ENTRY COUNT ANYWHERE — not in the code, not in a test, not
  in a docstring. It was 54 when this AC was written and moves with every addition;
  a pinned number fails for the wrong reason and gets edited to match rather than
  investigated.
- FAILURE OUTPUT NAMES THE OFFENDERS. The determination exits non-zero and names each
  check whose recorded source is missing or contradicted, not just a count.
- LATENCY BUDGET. This runs at commit time. A full manifest pass must complete in
  under 200 ms and must not spawn a subprocess per entry.
```
