# Tuple exception types are rendered in full in the violation message

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-108c` — Tuple exception types are rendered in full in the violation message — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-108c`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `S`.

## Acceptance Criteria

```gherkin
Scenario: A multi-type except clause reports the full tuple in the message
  Given a production Python file with a blind handler written as
    `except (ValueError, Exception):` that neither re-raises nor logs at
    WARNING or higher,
  When the exception-handling guard analyses the file,
  Then it emits a silent-handler (BLE001) violation for that handler,
  And the violation message text contains the full caught tuple
    `(ValueError, Exception)`,
  And the message does not abbreviate the caught type to just `Exception`.

Scenario: Detection outcome and location are unchanged by the message fix
  Given a production Python file containing the blind handler
    `except (ValueError, Exception):`,
  When the exception-handling guard analyses the file,
  Then the same single silent-handler (BLE001) violation is emitted that the
    guard emitted before the message-rendering change,
  And the reported line and column of the violation match the position of the
    `except` clause exactly,
  Because this behaviour changes only the human-readable message, not what is
    detected or where.
```
