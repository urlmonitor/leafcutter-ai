summary: "The plan for re-running slow tests after every merge, and holding pull requests while they fail, was reviewed by a CI/CD expert and a GitHub platform expert. Their recommendations, approved by the owner, change how the hold decides, when the tests run, which failures block merges, and how a pull request is stopped from releasing its own hold."
description: "Revises TQ-600a-13-ii through -xi and adds -xii through -xix, with TQ-600a-13-i amended. The tests excluded from the default pull-request run now run after every merge to main, coalesced to one in progress and one waiting, with a heartbeat schedule, instead of nightly, so a failure surfaces within about an hour and the suspect commits narrow from about ten to one to three. The required check, now named Post-merge suite status, takes its verdict from that workflow's own run history on main rather than from whether an issue is open: the issue becomes a notice for people, so closing it by hand, or GitHub closing it when a fixing pull request merges, cannot release the hold, and a failure to write the issue cannot let a red run through. Only correctness tests hold merges; timing-ratio tests, which produce false failures on shared runners, run in a separate lane that reports but never blocks, an exception now written into TQ-600a-13-i at the owner's direction. Failures are re-run on a fresh machine, a test that passes only on retry is tracked, and passing on retry in two of the last five runs counts as red. The check fails distinctly when results are stale, the workflow is disabled, or no run has ever completed. The escape hatch for a fixing pull request now needs evidence, a passing run of the failing tests, instead of a label any agent could apply. The check runs under pull_request_target so a pull request cannot edit the hold logic to pass its own check, never executing pull-request code, and the rollout requires an explicit Actions policy because GitHub blocks that trigger by default in public repositories from 2 November 2026. A merge-burst defect found during the revision is covered: a cancelled run that a newer run replaced carries no verdict, so a burst of merges does not freeze every pull request. Break-glass is removing the check from the ruleset, and the tunable defaults live in one configuration file. The record moving two default-run timing tests into the timing lane can be built first, on its own."
