## Implementation Notes

```yaml
- The five checks live in one new private module, scripts/build_orchestration/_wvp_checks.py,
  called from _wvp_plan (TQ-500g-1-xi) for every pinned and every declared candidate
  before the list step prints to_prepare, so every pinned replacement is checked before
  the preparer is dispatched and before any wrong version is run. The same module's
  functions are the only implementation of the checks; the write step, the runner
  and the declared path (TQ-500g-1-xvii) never carry a copy.
- 'Order and wording, first failure wins, each reason exactly: (e) paths, before any
  file is read, through _wvw_prepare''s path rule and the name''s CURRENT in-scope
  files from the owed list: "not in scope", or the writer''s own refusal wording for
  a test file, a path outside the repository or inside the version-control folder;
  (a) old text exactly once, each replacement against the result of the one before,
  with _wvw_prepare''s counting and CRLF rule: "old text found N times" (N >= 2),
  or "target changed" when it is not found (TQ-500g-1-xii); (c) the applied result
  differs from the file as now written: "changes nothing"; (b) loads: "did not load";
  (d) reaches a line: "changes no line the tests naming it run". A pinned candidate
  that fails gets decision source "re-prepared: <reason>" and goes into to_prepare.'
- 'Check (b), decided before the run (IT-PO decision on the BA''s open point; confirmed
  by the user, BrainCandy, 2026-10-24: EXECUTE, not compile-only, under the runner''s
  journalled apply/put-back). For a .py file: the altered text compiles, and the altered
  module executes in a child interpreter: the alteration is applied in the worktree
  through the runner''s journalled RunGate (_wvr_gate, under <git-dir>/leafcutter/wrong-version-runs/<run-id>/),
  the file is executed as a module (importlib.util.spec_from_file_location, its own
  directory and the repository root on sys.path, within done_proof''s _resolve_pytest_timeout_seconds
  budget), and the file is ALWAYS put back byte for byte before the check returns;
  a cut-short check is put back by the existing recover step. An ImportError, NameError,
  AttributeError or SyntaxError at that point is "did not load". A file of any other
  language has no pre-run load check; its load is judged by the run as today (TQ-500g-1-ii),
  and a run that reads did_not_load still never counts as caught or survived. After
  the list step returns, git status --porcelain is as before.'
- 'Check (d) uses the traced run of TQ-500g-1-xiv (_wvr_trace, _wvr_effect): one pytest
  run on the code as written of only the tests whose own entry names a candidate that
  passed (e), (a), (c) and (b), traced only for the files those candidates alter.
  The candidate passes when at least one test whose own entry names it ran at least
  one changed line of a traceable file. A candidate whose altered files are all untraceable
  (for example SQL) passes (d), with the decision''s reason saying the check could
  not be made, never failing for that reason alone (TQ-500g-1-xiv). The pre-run is
  made only when at least one candidate reaches (d); with no pin and no declaration
  no pytest run happens in the list step. The runner keeps its own baseline run as
  the gate''s control; this pre-run never replaces it.'
- 'A failure found only by the run. When a manifest entry with source "pinned" reads
  did_not_load, not_applied or not_executed in the runner''s verdict, the pin step
  (_wvp_store) leaves the pin''s replacements untouched and records failed_check {check,
  files_sha256} over the bytes of the pin''s files as written in that run. The next
  plan treats a pin whose failed_check matches the files'' current hash as failing
  that check (decision "re-prepared: <check>"); once the files change, the pin is
  checked afresh. This is how a pin that only fails at run time is never silently
  used again and never dropped.'
- 'Re-preparation outcome. A re-prepared or newly prepared replacement is held to
  the same checks: (e), (a) and (c) by the write step through _wvw_prepare and _wvp_checks,
  (b) and (d) by the runner''s run (did_not_load from the kind rule, not_executed
  from TQ-500g-1-xiv). It becomes the name''s pin only through the pin step''s promotion
  rule (TQ-500g-1-xi). When the preparer cannot prepare the name again, or the fresh
  replacement fails a check, the manifest entry is could_not_prepare (or the runner''s
  unfinished result) with a reason that starts "re-prepared: <failed pin check>" and
  then gives the second failure; the verdict reason is unfinished, the name is never
  caught or survived, and the earlier pin is left byte for byte as it was.'
- 'Completeness: every owed name of the entry appears in the manifest exactly once
  and has at least one verdict row: run, or unfinished with its reason. No check failure
  removes a name from owed.'
- 'Cost: checks (e), (a) and (c) for 50 candidates finish within 1 s; (b) costs one
  child interpreter per Python candidate; (d) at most one traced pytest run of the
  holder tests per gate run. Logging to stderr only. Every new or changed Python file
  stays at or under 400 counted lines. _wvp_checks.py is in scripts/build_orchestration/
  and is deployed by that directory''s glob (no deploy-list edit).'
```
