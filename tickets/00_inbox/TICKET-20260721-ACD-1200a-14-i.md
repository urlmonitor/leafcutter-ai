## Acceptance Criteria

```gherkin
This edge case bounds ACD-1200a-14 for the case where canonical git-based
repo-root derivation is unavailable.

Given the generator runs where git rev-parse --show-toplevel cannot resolve a
  repo root — for example the tickets tree is not inside a git repository or the
  git command is unavailable,
When the back-reference is written into the AC's implemented_by list by
  _write_implemented_by,
Then the write does not crash: it falls back to a documented repo-root derivation
  (the existing repo-root helper's non-git path) and emits a WARNING that the git
  top-level could not be resolved,
And the recorded value is still made repo-relative against that fallback root — it
  never records a raw absolute filesystem path with a leading "/",
And when git rev-parse does resolve a repo root the fallback is not used (no
  regression of ACD-1200a-14).
```
