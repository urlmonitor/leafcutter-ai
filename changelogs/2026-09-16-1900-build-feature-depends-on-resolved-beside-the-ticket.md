## Entry

/build-feature's run-set membership check and per-ticket release gate now resolve every `depends_on` entry through one shared resolver, `resolveDependsOnPath()`, that mirrors the ticket frontmatter hook's own documented order (`templates/skills/ticket-authoring/SKILL.md`, "depends_on Resolution"): beside the dependant ticket's own folder, then that folder's `done/`, then — only for a ticket that is itself inside `done/` — the folder above. An entry beginning `tickets/` still resolves against the worktree root, and an absolute entry is used as written. Both readers now share this one function, so they can never resolve the same entry to two different places again. This fixes the 2026-09-16 incident (run wf_3d2879c1-2ae) in which a bare-filename sibling dependency, already `status: done`, was joined onto the worktree root instead of read beside the dependant ticket, withholding 7 of 9 eligible tickets on a resumed epic drive. When a prerequisite resolves to no file anywhere in that search, the reported path is now the first candidate beside the ticket — never the worktree-root join the old code produced. Proven with five behavioral tests: a real-artifact extraction of the resolver (per-path-controllable, since the harness's `agent()` mock gives one static reply per label and cannot itself distinguish candidates) for the criterion, boundary, seam and failure angles, and a full run of build-feature.js's own top-level body through `unit_tests/_workflow_engine_harness.py` for reachability — confirmed red on the unmodified script and green after the fix, and confirmed to turn red again under each of three targeted mutations (root-join reversion, membership-check-only reversion, done/ fallback removal).
