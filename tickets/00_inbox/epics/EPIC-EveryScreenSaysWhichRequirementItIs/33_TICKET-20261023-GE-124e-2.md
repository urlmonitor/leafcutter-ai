## Acceptance Criteria

```gherkin
Given a selected criterion is named in the component-level declaration of at
  least one front-end file and is pinned on no element
When the reverse-direction gate evaluates it
Then the criterion satisfies the gate
And the recorded outcome names the file that declares it

Given a selected criterion is pinned on at least one rendered element and is
  named in no component-level declaration
When the reverse-direction gate evaluates it
Then the criterion satisfies the gate
And the recorded outcome names the file and line of the pinned element

Given a selected criterion is both declared at component level and pinned on
  an element
When the reverse-direction gate evaluates it
Then the criterion satisfies the gate
And the recorded outcome names both surfaces
```

## Implementation Notes

```yaml
- THE ANSWER COMES FROM SCANNING FRONT-END SOURCE, NOT FROM READING declared_by /
  pinned_by. This is the load-bearing implementation decision of the CI tier. Those
  store fields (GE-124g-1) are the RECORDED PROJECTION of a scan; a gate that reads
  them asks the store whether the store is right, and goes vacuous the moment they
  are stale — which is exactly the class of defect GE-111 exists to catch. Build the
  criterion-to-surfaces index by running the SHARED reader (GE-124a-1 / GE-124b-1)
  over the front-end source tree and inverting it. Writing declared_by / pinned_by
  from that same scan is fine and is GE-124g-1's business; reading them as evidence
  is not.
- ONE INVERTED INDEX BUILT ONCE PER RUN — criterion id -> {declaring files[], pinning
  (file, line, pin id)[]} — not a per-criterion re-scan. The gate may evaluate many
  criteria and the front-end tree is scanned once.
- 'EITHER SURFACE SUFFICES: the predicate is `declared_by_files OR pinned_locations`
  non-empty. There must be no code path and no configuration key that requires both.
  Requiring both would make the optional pin compulsory by the back door and contradict
  GE-124b-1 and GE-124b-2; the FLOOR is enforced at commit time by GE-124c, which
  is where it belongs.'
- 'THE FOUR DECLARATION-STATUS VALUES ARE RECORDED, matching the mock-data Ac entity:
  ''component'' (declared only), ''element'' (pinned only), ''both'', ''undeclared''.
  GE-124e-3 turns the fourth into a failing finding and GE-124g-3 counts them on the
  declared axis; a boolean satisfies/does-not would destroy both.'
- 'THE OUTCOME NAMES THE EVIDENCE, per surface: the declaring file path for a component-level
  declaration, and the file AND line for a pin. A reviewer told only ''satisfied''
  cannot check the claim, and the line number is already on the pin record (GE-124b-1).'
- SCANNING THE FRONT-END TREE MUST STAY WITHIN THE CI JOB'S BUDGET. Restrict the scan
  to the in-scope extensions (GE-124a-2's map) before reading any file, and reuse
  the in-scope decision from GE-124a-3 so the CI tier and the commit tier agree about
  which files can carry a declaration at all.
- Must handle errors gracefully per the project error handling policy; an unreadable
  front-end file must be named rather than silently reducing the evidence set — a
  silently skipped file makes a declared criterion look undeclared.
```
