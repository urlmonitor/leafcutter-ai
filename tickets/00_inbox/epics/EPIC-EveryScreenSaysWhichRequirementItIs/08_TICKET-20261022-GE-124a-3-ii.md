## Implementation Notes

```yaml
- EXCLUSIONS ARE PER-FILE, NEVER PER-DIRECTORY. Match on the file's own name suffix
  (`.stories.<ext>`, `.test.<ext>`, `.spec.<ext>`) or on the generated-file marker
  in its own first line. A directory-level exclusion silently exempts real components
  sitting beside a story, and a silent exemption is indistinguishable from the check
  not running — GE-120's standing rule for this component.
- THE THREE EXCLUSIONS ARE THREE DISTINCT REASON CODES ('story-file', 'test-file',
  'generated-file'), matching the enum GE-124a-3 defines. Collapsing them into one
  'excluded' code destroys the clustering signal the PO requires for judging whether
  the scope rule needs narrowing.
- The generated-file marker must be the marker convention the repo's generators already
  emit; adopt the existing one rather than minting a new string, and record which
  one was adopted. Two competing markers would leave one generator's output permanently
  in scope.
- 'Test-directory conventions must be covered as well as suffixes: files under a `__tests__/`
  directory (the convention leafcutter-web/__tests__ already uses) are test files.
  This is the one place a path segment is legitimate, because the segment IS the file''s
  own test identity rather than a neighbouring file''s.'
```
