description: "Two things, both consequences of an INF-400 consultation with the product-owner and business-analyst. FIRST, ADR-034 resolves a contradiction the repo has carried since 2026-06-05: three mutually incompatible answers to who writes a captured learning to disk. The agent inline via capture-learning (INF-400b-1 plus the three v3 agent templates), the harvester deferred (ADR-011's actual Decision, plus harvest_learnings.py), or the user per-item (retrospective-agent). ADR-011 had recorded inline capture as 'deferred, not rejected', so the architecture of record chose the harvester while the templates went on describing the inline design. ADR-034 confirms the deferred-harvest model as authoritative, demotes inline capture from deferred to REJECTED, and retires route-learning and capture-learning as concepts rather than leaving them to be authored. It also records the consequences that follow mechanically, so they are not rediscovered: the emit target must move to knowledge_emissions.jsonl in four places, the harvester needs a caller, and route-knowledge's 16-value taxonomy overlaps the harvester's 11 accepted entry_kinds on only four values -- so a naive repoint would silently discard 12 of 16 routing outcomes, since an unrecognised kind is marked processed and never retried. SECOND, reconciles five ACs against work that already exists, each verified behaviourally rather than by inspection. INF-400g-1 (emit_event.py at the deployed path) was left todo by PR #528, which built the artifact and closed only its BP-400a-1 duplicates; its criteria also require the file to be executable, and it shipped 644 while carrying a shebang, so the bit is set and a test now asserts it. INF-400c-1 is satisfied by ADR-011, which was missing the INF-400b/INF-400c references its criteria require -- those are added here. INF-400c-2, c-2-i and c-3 are satisfied by harvest_learnings.py, confirmed by running it against each AC's own scenario: three events routed with a per-kind summary, a second run reporting all three previously processed with no duplicate writes, and an unrecognised entry_kind warned about, marked processed, not written, and not blocking the events after it. INF-400d-1, d-2 and d-3 are deliberately left todo: the probe output shows _default_capture appends bare text with none of the headers or sections those ACs require, so the file-format contract is genuinely unimplemented. Two child_limit_override waivers on INF-400g (9 L2s, cap 5) and INF-400 (8 L1s, cap 7) record existing counts and admit no new child; both caps had gone untripped for three months because no commit had ever staged one of these files, so the hook's ancestor walk had never run."
