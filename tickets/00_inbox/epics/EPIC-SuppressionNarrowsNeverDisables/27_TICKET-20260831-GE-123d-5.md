# Every exemption granted is announced, and the announcement never echoes the value

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-123d-5` — Every exemption granted is announced, and the announcement never echoes the value — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-123d-5`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `S`. Complexity: `low`.

## Acceptance Criteria

```gherkin
Given a file in the acceptance-criteria store staged for commit contains two
  credential-shaped lines that this feature exempts, on its 12th and 40th
  lines,
When the staged file is checked by the pre-commit secrets check,
Then a notice is written to the error stream that names the check, states the
  number of exempted findings as 2, and for each one gives the file path, the
  1-based line number (12 and 40), and which recognised non-credential shape
  granted the exemption,
And the notice does not reproduce the matched value or the matched line,
And the commit still succeeds — the notice leaves the exit status unchanged,
Because a widening that leaves no trace cannot be reviewed, while a notice
  that echoed the value into a build log would recreate the exposure it
  exists to guard against.

Given a file staged for commit produces no exempted findings,
When the staged file is checked by the pre-commit secrets check,
Then no notice is written to the error stream,
Because a line printed on every commit becomes the same noise this goal
  exists to remove.

Given a file staged for commit produces one exempted finding and one reported
  finding,
When the staged file is checked by the pre-commit secrets check,
Then the reported finding appears on the output stream as findings always
  have,
And the exemption notice appears on the error stream,
And the commit is blocked by the reported finding,
Because the notice is an audit trail and never an input to the verdict.
```

## Implementation Notes

```yaml
- Stream discipline is a hard boundary, not a preference. The notice goes to the error
  stream only. The output stream carries the findings report in its existing format,
  which the hook's own summary text and any log scraper read; a single line of notice
  text on the output stream corrupts that report. This is the same stream split the
  allowlist warnings already observe.
- 'The notice must not change the exit status under any circumstances. It is an audit
  trail, never an input to the verdict, and that must hold in both directions: it
  appears when the run succeeds, and it appears unchanged when the run is blocked
  by an unrelated finding.'
- 'The notice must never contain the matched value, the matched line, or the finding
  excerpt. This is the deliberate departure from the GE-113c-3-v warning contract
  and it must not be harmonised back: the notice concerns a value the check has just
  decided NOT to report, so echoing it into a stream that lands in build logs would
  turn each wrong decision into an exposure. File path, 1-based line number and the
  granting shape name are the whole payload. Everything else in the -v contract —
  the error stream, the file path, the 1-based line number — is reused as-is.'
- 'One notice per run: a header naming the check and the count, then one short line
  per exempted finding. Not one paragraph per finding — the acceptance-criteria store
  holds thousands of files whose text discusses these rules, and a verbose per-finding
  report would reproduce on the error stream exactly the noise this L1 exists to remove.'
- The count must include only findings exempted by THIS feature. Findings removed
  by a .security-allowlist entry are suppressed earlier, before the post-filter ever
  sees them, and findings dropped by the pre-existing file-level high-entropy prose
  exemption are a different mechanism (KI-CG-004). Folding either into the count makes
  the number unreviewable, which defeats the purpose of announcing it.
- The granting shape must be reported by a stable name drawn from the shape vocabulary,
  not by a rendering of the value or a description generated per finding, so that
  the notices can be compared across runs.
- Silence when nothing is exempted must be genuine silence on the error stream — no
  header, no zero count.
- 'Anti-precedent, load-bearing: a guard in this component is documented as dispatching
  a specialist and does not, because its remediation path is a placeholder that always
  reports success. A test that asserts the message string exists in the source would
  repeat that failure exactly. The notice must be observed arriving on the error stream
  of a real run.'
- 'ADR-001 parity: edit the canonical copy under templates/ and verify through the
  build.py round-trip.'
```
