description: "Driving a thirty-seven piece body of work built seventeen pieces and silently left twenty, and the twenty were exactly those carrying a prerequisite: eligibility is decided once, at the start, when nothing is yet finished, so only prerequisite-free work can ever qualify. Criteria covering this were authored five days ago and were thorough, but nothing had been added to say who would build them, against what surface, or how anyone would know the result was right — no assigned agent, no complexity, no requirements mapping, and no test contract on any of the eight records. That layer is now written, and it is what turns a specification into work someone can pick up. The contracts are constrained hardest where this repository has been fooled before. Ordering is asserted on named pieces of work being dispatched, never on counts of groups, because the groups in the observed failure were a parallelism split and seven of the eight held a single item, which reads like a sequence and is not one. The load-bearing contract requires the second planning reply's work to actually receive dispatches rather than merely to have been requested, because the defect is precisely a correct answer that nothing consumes. The widening has a hazard of its own — a run that keeps looking can circle forever on work that can never become eligible — so the bound on how many times it looks, and the requirement that reaching that bound is stated as its own cause rather than passing quietly, are held at the same priority as the widening itself, on the reasoning that shipping the widening without them is worse than the current defect, which at least terminates. Two findings came out of writing this and both are recorded rather than left in the specification. The first is that the run holds no record of what the body of work contained when the plan was fixed that is separate from the plan itself: the baseline the completion check compares against is built by walking the planned groups, so under this defect the baseline is seventeen and not thirty-seven, and the twenty dropped pieces can only appear to the completion check as things that arrived later. That makes this defect and its companion one defect seen from two ends, and it means separating the run's set of work from the run's schedule is a precondition for fixing either rather than a refinement — and because it changes what an already-completed criterion reports, it cannot be done quietly. The second is that the test harness maps each dispatch label to a single response object returned on every call, so the planning label cannot express one wave followed by a different second wave; until that is extended, not one behavioural test for this fix can be written and the work would collapse to the source-scanning proof the conventions forbid. Both are now in the register entry, along with a pointer from the entry to the criteria that cover it — which was missing, and is why the criteria took a search to find rather than a click."
