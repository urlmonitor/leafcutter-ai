# The code-aware step turns test intent into a test design grounded in files it opened

## Actor / Goal

## Context

This ticket was generated from AC store entry `ACD-2500c-1`. Component: `ac-driven-dev`. Assigned agent: `llm-expert`. Estimated complexity: `L`. Complexity: `high`.

## Acceptance Criteria

```gherkin
Given a leaf code requirement whose test intent marks clauses (1) and (2) needs-test and
  clause (3) not needed, and whose declared files exist in the repository,
When the code-aware test-design step runs on it,
Then the record carries a test design with at least one test entry per needs-test clause,
  and each entry names the outcome clause it proves,
And no entry names clause (3),
And each entry names a target test directory that exists and the code file it exercises,
  and that file exists at the time of design,
And for a clause about code that does not exist yet, the entry names the file as
  to-be-created and cites an existing neighbouring test file it read as the convention
  the new test follows,
And the design carries the step's authorship mark and the list of repository files the
  step opened,
And criteria, test intent, assigned specialist, pattern reference and pattern bindings
  are byte-identical before and after the step.
```
