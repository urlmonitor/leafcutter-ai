## Acceptance Criteria

```gherkin
Given the collection contains two acceptance-criterion records that both declare the
  identifier "GE-119",
And the current change set contains ONLY ONE of the two — the other has sat unmodified on
  the shared branch for weeks and appears in no diff,
When the uniqueness pass runs,
Then it reports the contested identifier and names BOTH claimant paths, including the one
  absent from the change set.

And Given a change set that touches NEITHER claimant while the collision is still present in
  the collection,
When the pass runs,
Then it still reports the contested identifier and both claimant paths.

And Given a change set that adds a record claiming an identifier no other record claims,
When the pass runs,
Then it reports nothing for that record.

The property this criterion pins: the change set may be used to decide which findings are
ATTRIBUTED to the current author, but it must never bound WHAT IS INSPECTED. A check whose
input set is the changed files cannot observe a collision whose second claimant is not in the
diff — and in the collision actually observed in this repository, the two claimants were
authored weeks apart from different working copies, so they were never in one diff together.

Coverage note: covered only by a test that stages exactly one claimant, executes the pass, and
asserts the absent claimant's path appears in the output. A test that stages both claimants
cannot distinguish a whole-collection pass from a changed-files pass and therefore does not
cover this criterion.
```
