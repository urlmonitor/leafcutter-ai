## Implementation Notes

```yaml
- 'One tokenizer is shared by the query and every target: case-insensitive, splitting
  at every character that is not a letter or a digit (Unicode-aware), so snake_case,
  kebab-case, dotted field keys and AC ids split.'
- 'The one-target rule is enforced per target: a node matches only when every query
  word starts a word of one single target. Targets are never pooled or concatenated
  per node.'
- 'Targets are exactly the dataset''s list: label; text with condition; each AC id;
  each used and each produced field key; screen id with screen title; each entity
  read or written. A flow''s own targets are its name with its id, and each declared
  entity.'
- Used/produced field keys and their labels come from the same derivation the drawer's
  Inputs/Outputs tables use (<contract>.<JSON-pointer segments joined by '.'>); one
  implementation, moved into a pure shared module if it currently lives inside a component.
- Results recompute on each edit of the search box without a server request; the search
  text is trimmed and an empty search shows the overview.
- Each new summary is written into the existing polite live region; the region is
  not re-created per change.
- Expected values come from the leafcutter/atlas-flows v4 dataset records, replayed
  against a frozen finder-index fixture in leafcutter-web/fixtures/flow-finder/ produced
  by the finder's own index builder from docs/product-truth/flows/ at the dataset's
  measurement commit (provenance recorded in the fixture); tests never pin counts
  against the live store, which grows. fixtures/** is already excluded from vitest
  collection.
```
