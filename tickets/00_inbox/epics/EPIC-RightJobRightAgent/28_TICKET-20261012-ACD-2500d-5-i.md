# The mechanical file facts the code-aware agent needs come from a deterministic pre-pass script

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `ACD-2500d-5-i` — The mechanical file facts the code-aware agent needs come from a deterministic pre-pass script — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `ACD-2500d-5-i`. Component: `ac-driven-dev`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a batch of 3 requirements handed to the code-aware step:
    R1 declares the existing file scripts/a.py and names the existing test directory unit_tests/ac_store/,
    R2 declares a file marked to-be-created and a reference file of the same file type in the same area,
    R3 declares scripts/missing.py, which neither exists nor is marked to-be-created, and a reference
    file of a different file type,
When the pre-pass script runs before the code-aware agent,
Then its report lists, per requirement and per declared file, whether the file exists, is marked
  to-be-created, or is neither,
And it reports whether each named test directory exists,
And it reports, for each reference file, whether it exists and whether it has the same file type
  and area as the deliverable,
And for R3 it reports scripts/missing.py as neither and the reference file as a different file type,
And two runs on the same batch and repository state produce byte-identical reports,
And the code-aware agent is not dispatched for the batch when the script produces no report.
```

- [ ] AC-1: its report lists, per requirement and per declared file, whether the file exists, is marked
- [ ] AC-2: it reports whether each named test directory exists
- [ ] AC-3: it reports, for each reference file, whether it exists and whether it has the same file type
- [ ] AC-4: area as the deliverable
- [ ] AC-5: for R3 it reports scripts/missing.py as neither and the reference file as a different file type
- [ ] AC-6: two runs on the same batch and repository state produce byte-identical reports
- [ ] AC-7: the code-aware agent is not dispatched for the batch when the script produces no report.

## Implementation Notes

```yaml
- 'Read-only and deterministic: never edits a record or file; output depends only
  on the batch and the repository tree.'
- 'Declared files and their existing / to-be-created markers are read only through
  the declared-files seam of ACD-1600c-4 (AC field declared_files; scripts/ac_store/declared_files.py)
  -- the store''s single answer, the same one the ticket generator reads (TKT-600a-3).
  No doc_links -> files_touched derivation (ADR-010) and no second derivation. A record
  in the ''no declared files'' state is reported ''not evaluated: no declared files''
  and is never counted as passed.'
- 'Within the unchanged report shape, a record in the ''no declared files'' state
  appears with declared_files: [] -- unambiguous only because the store refuses an
  empty declared list (ACD-1600c-4-ii). The script must never emit [] for any other
  reason, and consumers must read [] as ''not evaluated: no declared files'', never
  as ''nothing to check''.'
- The 'same area' rule is defined once (in the ACD-2500a-5 / ACD-2500b-4 reference)
  and applied only here; the agent does not re-derive it.
- 'Report shape: Pre-pass report (JSON, deterministic, sorted): {batch: [ac_id], records:
  [{id: str, declared_files: [{path: str, state: ''exists''|''to_be_created''|''neither''}],
  test_dirs: [{path: str, exists: bool}], reference_files: [{path: str, exists: bool,
  same_type: bool, same_area: bool}]}]}; paths repo-root-relative POSIX. Non-zero
  exit and no report on error.'
- 'Fail-closed: an error yields a non-zero exit and no report; the workflow treats
  that as batch failure (ACD-2500c-2).'
- Must complete within 2 seconds for a batch of 50 records.
- 'Ships to consumer projects with the plan-feature workflow: canonical source and
  deployed copy kept in parity through the build (ADR-001, ADR-013) and verified from
  the deployed layout after a rebuild.'
```
