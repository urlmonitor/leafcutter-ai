# Auto-regenerate docs/INDEX.md via a pre-commit transform hook

## Actor / Goal

In order to keep the pull-based documentation index trustworthy, we need
`docs/INDEX.md` to be regenerated automatically whenever documentation changes
are committed, so that BA / IT-PO agents (which read the index first to decide
what docs to pull) never plan against a stale or partial index.

## Context

`docs/INDEX.md` is auto-generated by `scripts/generate_doc_index.py`
(`generate_index(root)` walks the docs tree and returns the index content).
Today it is only regenerated:

1. **At build time** — `build.py`'s doc-index phase regenerates it on every
   `build.py` run, idempotently ([scripts/build.py](../../scripts/build.py),
   `generate_doc_index_phase`).
2. **Manually** — `python scripts/generate_doc_index.py`.

It is **never regenerated per-commit / per-PR**. Nothing in
`.pre-commit-config.yaml` refreshes it. Consequences observed 2026-07-14:

- The committed index drifted ~2 weeks stale (missing ADR-017..020, several new
  component docs, the `workflow-authoring-contract` reference, etc.).
- A `generate_doc_index.py` run launched from the **wrong working directory**
  silently overwrote the main-clone index with an empty shell (`No docs found.`
  in every category) — an easy foot-gun with no guard.

This ticket closes the gap by adding a **pre-commit transform hook** that
regenerates and re-stages the index whenever docs change, mirroring the existing
`transform-doc-frontmatter` hook
([templates/scripts/commit_guardian/transform_doc_frontmatter.py](../../templates/scripts/commit_guardian/transform_doc_frontmatter.py)).

**Portability constraint:** `generate_doc_index.py` currently lives in
`scripts/` and is imported by `build.py`, but it is **not deployed** to consumer
installs. The hook must be able to `import generate_index` at commit time on any
install, so this ticket also deploys the generator alongside the commit-guardian
scripts.

**Pattern references (mirror these):**
- Hook script: `templates/scripts/commit_guardian/transform_doc_frontmatter.py`
  (staged-file discovery via `git diff --cached`, in-place write, `git add`
  re-stage, always exit 0 fail-open).
- Manifest registration: `hooks_manifest.hooks[]` in
  `templates/scripts/commit_guardian/commit_guardian.json` (build regenerates
  `.pre-commit-config.yaml` from it via `build_precommit_config`).
- Tests: `unit_tests/commit_guardian/test_transform_hooks_and_autofix_emission.py`.

## Acceptance Criteria

- [ ] AC-1: A new hook `transform_doc_index.py` exists under
  `templates/scripts/commit_guardian/`. When run with at least one `docs/**/*.md`
  path staged (added, modified, or deleted), it regenerates `docs/INDEX.md` via
  `generate_index(<project_root>)`, writes it, and `git add`s it. When no
  `docs/**/*.md` path is staged, it makes no changes. It always exits 0
  (fail-open: any error is logged to stderr and never blocks the commit).
- [ ] AC-2: The hook is registered in the `hooks_manifest.hooks` list in
  `commit_guardian.json` with `tier: transform`, ordered **before**
  `transform-doc-frontmatter` (so frontmatter injection still applies to the
  freshly-generated index). After a build, the generated `.pre-commit-config.yaml`
  contains the `transform-doc-index` entry ahead of `transform-doc-frontmatter`.
- [ ] AC-3: `generate_doc_index.py` is deployed to consumer installs such that
  `from generate_doc_index import generate_index` resolves from the deployed
  commit-guardian hook at runtime (reachability, not just presence).
- [ ] AC-4 (reachability / behavioral): In a simulated consumer install with the
  hooks deployed, staging a new `docs/**/*.md` file and running the deployed
  `transform-doc-index` hook regenerates `docs/INDEX.md` to include the new file
  and re-stages it, exiting 0 — with no file-not-found or import-resolution error.
- [ ] AC-5: The regenerated index is never empty when docs exist — i.e. the hook
  never produces `No docs found.` for a category that has files (guards against
  the wrong-directory foot-gun by resolving the project root deterministically).
- [ ] AC-6: `docs/reference/pre-commit-hooks.md` documents the new hook (purpose,
  trigger glob, fail-open behavior, ordering relative to `transform-doc-frontmatter`).

## Implementation Tasks

- [ ] Write `templates/scripts/commit_guardian/transform_doc_index.py` mirroring
  `transform_doc_frontmatter.py`: discover staged `docs/**/*.md` via
  `git diff --cached --name-only --diff-filter=ACMRD`; if any, call
  `generate_index(project_root)`, write `docs/INDEX.md`, `git add` it; exit 0.
  Resolve `project_root` deterministically (e.g. `git rev-parse --show-toplevel`),
  NOT from CWD — this is the AC-5 guard.
- [ ] Register `transform-doc-index` in `commit_guardian.json` `hooks_manifest.hooks`
  immediately before the `transform-doc-frontmatter` entry.
- [ ] Deploy `generate_doc_index.py` to installs so the hook can import
  `generate_index` (add to the build deploy path used by the commit-guardian
  scripts; audit `build.py` / `build_phases.py` for the correct mechanism).
- [ ] Add `unit_tests/commit_guardian/test_transform_doc_index.py`: (a) staged doc
  → INDEX regenerated + re-staged; (b) no staged docs → no-op; (c) generator
  import resolves from the deployed layout; (d) populated tree never yields
  `No docs found.`.
- [ ] Document the hook in `docs/reference/pre-commit-hooks.md`.
- [ ] Run `build-self.sh`, then behaviorally verify by staging a real docs file
  and confirming the hook regenerates + re-stages INDEX.md (real-artifact check).

## Out of Scope

- Changing the index format or the categories `generate_doc_index.py` emits.
- A CI verify-gate for index freshness (the transform hook makes it moot; revisit
  only if the hook proves insufficient).

## Risk & Safety

- Touches money? No.
- Touches data? Only `docs/INDEX.md` (auto-generated, fully derived). Fail-open
  design means a hook error never blocks a commit.
- Reversibility? Fully reversible; the hook is additive and idempotent.
