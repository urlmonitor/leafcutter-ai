# Being a leftover is not a licence to delete work

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-4100e-2-i` — Being a leftover is not a licence to delete work — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-4100e-2-i`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a discovered leftover that holds work which has not reached the shared
  main line,
When its removal is requested,
Then the removal is refused on the same grounds any other workspace holding
  work would be refused on,
And the leftover and its contents are byte-identical to what they were before
  the request,
And the refusal names what it still holds.
```

- [ ] AC-1: the removal is refused on the same grounds any other workspace holding
- [ ] AC-2: the leftover and its contents are byte-identical to what they were before
- [ ] AC-3: the refusal names what it still holds.

## Implementation Notes

```yaml
- 'The verdict must come from BO-4100c-1''s assessment applied to the discovered entry
  -- not from a check written for the discovery path. A second verdict implementation
  IS the defect: it will drift from the first, and the discovery path is the one where
  drifting means deleting work.'
- No forced-removal path may bypass the verdict. If a force option exists for genuinely
  unreachable cases it must be the same option registered workspaces use, and must
  be subject to the same refusal; a --force that only the discovery path honours is
  how BO-4100e-2 gets satisfied by a delete that skips every check.
- The refusal must name what the leftover holds at the same granularity BO-4100c-2
  requires -- paths, commit identifiers, stash reference -- not a count or a category.
- A leftover whose own state cannot be read reaches BO-4100c-3's no-verdict refusal,
  not removal. Discovery must not turn an unreadable workspace into a deletable one.
- The refusal path must be inert; byte-identity of the leftover's whole directory
  is asserted.
```
