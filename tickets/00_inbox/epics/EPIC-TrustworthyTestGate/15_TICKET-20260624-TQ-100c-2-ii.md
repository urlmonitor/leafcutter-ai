# Downgrading an AC from done to not-done while its test is failing is flagged, not silently relaxed

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `TQ-100c-2-ii` — Downgrading an AC from done to not-done while its test is failing is flagged, not silently relaxed — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `TQ-100c-2-ii`. Component: `testing-quality`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given an AC whose work_status is done and a covering test that is currently
  failing,
When that AC's work_status is changed from done back to not-done (which would
  otherwise downgrade the failing test from enforced to informational),
Then a pre-pytest integrity check detects the downgrade-while-failing situation
  and fails loudly (non-passing outcome with a message identifying the AC and
  its failing covering test)
And the gate is not silently relaxed for that test
And a real regression in a shipped feature cannot be hidden by flipping its AC
  back to not-done.
```

## Test Requirements

- `test_done_to_not_done_downgrade_while_failing_flagged`: The integrity check flags an AC downgraded from done to not-done while its covering test is failing, rather than silently relaxing it.
