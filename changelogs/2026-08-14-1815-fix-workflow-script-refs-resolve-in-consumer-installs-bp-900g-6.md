description: "Third and final instalment of the BP-900g deploy-reachability family. BP-900g-4 taught the broken-reference guard to see output-root-form script references in agent and skill templates; BP-900g-5 deployed the six dead scripts that surfaced. Both missed workflows entirely: extract_script_path_refs scanned only templates/agents/ and templates/skills/, and only .md files, so templates/workflows-js/*.js was outside the scan on two counts (extension and directory). The scan now covers templates/workflows/*.md and templates/workflows-js/*.js via a shared _SCAN_TARGETS helper, and surfaced scripts/pause_store.py as a genuine undeployed reference from plan-feature.js and finalize-feature.js. Separately, every workflow addressed its helper scripts at a bare `scripts/...` path, which resolves only inside this package repo: a consumer's own scripts/ directory holds just three shim symlinks (commit_guardian, doc_compliance, feedback), everything else deploys under the configurable output root, and a freshly-cut git worktree of a consumer repo has no scripts/ directory at all because those shims are untracked. That is why /fast-lane-build has worked for us while being dead on arrival for every consumer. Fixing it required first fixing the mechanism: workflow .js was deployed BYTE-VERBATIM (build_workflow_scripts -> _emit_workflow_variant is an identity transform and inject_config was never applied), so a {{config.output_root}} token in a .js file would not have substituted at all. Hardcoding `.leafcutter/` was rejected because output_root is documented as configurable per consumer project, so build_workflow_scripts now applies inject_config to .js before the compare-before-write guard — verified non-destructive, since the only `{{` occurrences in workflows-js are JSDoc annotations that cannot match _PLACEHOLDER_RE. Seven script paths across fast-lane-ship.js, fast-lane-build.js, plan-feature.js and finalize-feature.js were then repointed to {{config.output_root}}/scripts/..., and pause_store.py and injection_builders.py were added to the BP-900g-5 deploy spec (no build.py edit was needed — the manifest derives from that one spec, which is the drift-proofing from the previous PR paying off). Two residual limits are recorded rather than glossed: the extractor deliberately does not extract JS template-literal paths (${var}/scripts/...) because doing so would falsely flag ${baselineTmpPath}/scripts/build.py, where the variable holds a full source clone — so injection_builders.py, referenced only through such a prefix, is deployed but still invisible to static analysis, with a deployed-tree behavioral test as the compensating control; and fast-lane-build.js invokes injection_builders.py as a CLI although that module has no argparse and no __main__ block, so the path now resolves but the call is a no-op — a functional defect needing its own AC. Covered by AC BP-900g-6 and 11 tests across unit_tests/test_bp_900g_6.py and unit_tests/test_bp_900g_6_paths.py, the latter asserting against a real build.py --target-dir install that no unsubstituted token survives, that every referenced path exists in the deployed tree, and that the newly deployed scripts import cleanly in a fresh subprocess."
