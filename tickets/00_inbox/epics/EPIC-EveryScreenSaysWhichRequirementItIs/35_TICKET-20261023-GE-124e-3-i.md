# The declaration gate and the test-proof gate fail independently on the same criterion

## Acceptance Criteria

```gherkin
Given a finished user-interface criterion that nothing on screen claims and
  that no test asserts
When both the reverse-direction declaration gate and the existing test-proof
  gate run
Then two separate failures are reported for that criterion
And each names which obligation was unmet — nothing claims it, and nothing
  proves it
And neither failure is suppressed by the presence of the other

Given a finished user-interface criterion that is declared on screen and that
  no test asserts
When both gates run
Then the reverse-direction declaration gate passes for that criterion
And the test-proof gate still fails for that criterion

Given a finished user-interface criterion that a test asserts and that nothing
  on screen claims
When both gates run
Then the test-proof gate passes for that criterion
And the reverse-direction declaration gate still fails for that criterion
```

## Implementation Notes

```yaml
- 'TWO SEPARATE CI JOBS OR TWO SEPARATE INVOCATIONS, NEITHER READING THE OTHER''S
  RESULT. check_ui_ac_declared.py and check_done_proof.py must have no data path between
  them: no shared verdict cache, no ''skip if the other already failed'' short-circuit,
  no combined exit-code aggregation that lets one satisfy the other. The composition
  is ADDITION, never substitution — both must hold.'
- 'DO NOT EXTEND check_done_proof.py TO ALSO CHECK DECLARATIONS. Folding the declaration
  obligation into the existing done-proof gate is the shortest path to ''one failure
  per criterion'' and it is exactly the substitution GE-124g forbids: whichever obligation
  is checked first would then be able to short-circuit the other. Two gates, side
  by side.'
- THEY MAY SHARE READ-ONLY INFRASTRUCTURE — the AC index (GE-124c-2-i) and the store
  path — but nothing that carries a VERDICT. Sharing the index is desirable (one walker);
  sharing a result is the defect.
- BOTH FAILURES MUST BE VISIBLE IN ONE RUN, not one-at-a-time. If the two jobs are
  separate CI jobs, both must run on the same commit rather than the second being
  gated on the first passing; a reviewer must see both obligations at once or they
  will fix one, re-push, and discover the other.
- 'EACH FAILURE NAMES ITS OWN OBLIGATION IN ITS OWN VOCABULARY: ''nothing claims it''
  for the declaration gate, ''nothing proves it'' for the test-proof gate. Identical
  or near-identical wording is how a reader concludes they are two reports of one
  problem and dismisses one.'
```
