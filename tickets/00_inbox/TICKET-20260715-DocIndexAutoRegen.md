# Auto-regenerate docs/INDEX.md via a pre-commit transform hook

## Actor / Goal

In order to keep `docs/INDEX.md` from silently going stale, we need it
regenerated and re-staged automatically whenever a `docs/` file changes at
commit time, so BA/IT-PO agents always read an accurate pull-based index
without anyone remembering to run `generate_doc_index.py` by hand.

## Context

`docs/INDEX.md` is auto-generated by `scripts/generate_doc_index.py`, but the
generator only runs (a) manually and (b) inside `build.py` at *deploy* time —
**never per-PR**. Nothing in `.pre-commit-config.yaml` or CI regenerates it, so
it drifts: on 2026-07-15 the committed index was ~2 weeks stale, and a
generator run launched from the wrong working directory had earlier wiped it to
an empty "No docs found." shell (recovered manually in a prior session).

The project already has the correct pattern for this class of fix: the
`transform-doc-frontmatter` and `transform-description-field` pre-commit hooks
regenerate-and-restage staged docs before their validators run. A doc-index
refresh fits the same mold and should mirror `transform_doc_frontmatter.py`.

**Frontmatter interaction (the tricky part).** `generate_doc_index.py` currently
emits the index body with **no YAML frontmatter**, but the committed
`docs/INDEX.md` carries `title` / `type` / `status` / `created` / `description`
(injected today by `transform-doc-frontmatter` + `transform-description-field`).
If a new transform hook simply overwrites the file with the frontmatter-less
generator output, it will fight those hooks and/or trip `check-doc-frontmatter`
and `check-description-field`. The clean fix is to make the **generator itself
emit a stable frontmatter block** so its output is self-consistent and passes
all doc-frontmatter validators without depending on hook ordering.

Related code / patterns to mirror (list duplicate-logic locations up front):
- `templates/scripts/commit_guardian/transform_doc_frontmatter.py` — the
  regenerate-and-`git add` transform pattern to copy.
- `templates/scripts/commit_guardian/transform_description_field.py` — sibling
  transform; do not duplicate its description-fill logic, rely on it.
- `scripts/commit_guardian/commit_guardian.json` — `hooks` manifest where the
  new hook is registered (build.py regenerates `.pre-commit-config.yaml` from it).
- `scripts/generate_doc_index.py` — `_HEADER_TEMPLATE`, where the frontmatter
  block must be emitted.

## Acceptance Criteria

- [ ] AC-1: `generate_doc_index.py` emits a YAML frontmatter block
  (`title`, `type: index`, `status: active`, `created`, `description`) at the top
  of `docs/INDEX.md`. `created` is **stable across runs** — preserved from the
  existing file's frontmatter when present, else set to today — so repeated runs
  are idempotent (only the `Generated:` timestamp line and real content changes).
- [ ] AC-2: A new pre-commit transform hook `transform-doc-index` regenerates
  `docs/INDEX.md` and re-stages it (`git add`) whenever at least one staged file
  is under `docs/` (excluding `INDEX.md` itself). It follows the fail-open
  contract (exit 0 on any internal error) exactly like `transform_doc_frontmatter.py`.
- [ ] AC-3: The hook is ordered so its output survives validation — it runs
  before `check-doc-frontmatter` / `check-description-field`, and its emitted
  frontmatter satisfies both validators with zero further transformation needed.
- [ ] AC-4: The hook is registered in `commit_guardian.json` and appears in the
  generated `.pre-commit-config.yaml` after `build.py` runs (no hand-edit of the
  `@package-managed` file).
- [ ] AC-5: Behavioral spot-check (real artifact, fresh process): stage a real
  new `docs/**/*.md` file, run the hook, and assert `docs/INDEX.md` now lists it,
  carries valid frontmatter, and is staged — and that committing a change with NO
  `docs/` files does NOT rewrite the index.

## Risk & Safety

- Touches money? No.
- Touches data? No — regenerates a derived docs artifact only.
- Reversibility? Fully reversible (remove the hook entry + revert the generator
  change). Blast radius: runs in every consumer's commit pipeline, so the
  fail-open contract and the "no-op when no docs staged" guard are mandatory —
  a bug here must never block an unrelated commit.

## Out of Scope

- Reworking the other transform hooks or the doc-frontmatter validators.
- A CI-side "index is stale" verify gate (viable alternative/companion; author a
  separate ticket if the pre-commit approach proves insufficient).
