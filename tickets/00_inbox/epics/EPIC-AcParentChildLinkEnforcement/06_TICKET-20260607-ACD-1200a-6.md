# Epic folder name is concise and descriptive, not a naive title concatenation

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `ACD-1200a-6` — Epic folder name is concise and descriptive, not a naive title concatenation — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `ACD-1200a-6`. Component: `ac-driven-dev`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given goal_to_epic.py assembles an epic folder for a goal AC
  whose title is "Cross-field constraints and relational references
  are enforced together",
When the system derives the EPIC folder name,
Then it produces a concise PascalCase name of at most 5 words
  (e.g. "EPIC-AcRelationalIntegrity" or "EPIC-CoveredByEnforcement"),
And the name captures the essential intent of the goal AC,
And the name does NOT naively concatenate all words from the title
  (rejecting results like "EPIC-Crossfieldconstraintsandrelationalreferencesareenforcedtogether"),
And a model (LLM) is used to summarise the title into the concise name
  when the naive PascalCase result exceeds 40 characters,
And if the model is unavailable or errors, the system falls back to
  truncating the PascalCase name at 40 characters with no trailing
  partial word.
```
