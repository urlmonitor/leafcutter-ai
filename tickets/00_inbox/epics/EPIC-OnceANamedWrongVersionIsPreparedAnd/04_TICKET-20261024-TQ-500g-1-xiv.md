## Implementation Notes

```yaml
- 'Line tracing uses the standard library only (coverage.py is not a dependency of
  the package or of a consumer project and must not become one): a new pytest plugin,
  scripts/build_orchestration/_wvr_trace_plugin.py, loaded with -p into the SAME single
  baseline pytest run the runner already makes, beside the kind plugin and, when present,
  the database plugin. It uses sys.monitoring LINE events where the interpreter has
  it and sys.settrace otherwise, and records only the absolute paths it is given (through
  an environment variable, like the kind plugin''s output path). Output: one JSON
  file {<pytest nodeid>: {<absolute path>: [line numbers]}, "": {...}} written to
  a temporary path the runner deletes afterwards.'
- 'Attribution: lines executed during a test''s setup, call and teardown (pytest_runtest_protocol)
  belong to that test only, so a line run by another test never counts. Lines executed
  outside any test''s protocol (module import during collection) are recorded under
  "" and count as run by every test of the run (IT-PO decision: a module-level change
  reaches every test that imported the module; confirmed by the user, BrainCandy,
  2026-10-24, and now a criteria clause).'
- _wvr_pytest.run_selected takes a list of extra plugins (module, environment) instead
  of one, so the database plugin (TQ-500g-2-i) and the trace plugin share one run;
  the existing single-extra callers keep working unchanged. The trace plugin's directory
  joins the child's PYTHONPATH exactly as the database plugin's does.
- 'Reading the trace (new module scripts/build_orchestration/_wvr_trace.py): run_traced(nodes,
  files) returns, per test identity (the same identity the kind rule uses, parametrised
  cases folded), {repo-relative path: set of executed lines}, and the set of altered
  files that are not traceable. A file is traceable only when it ends in .py and lies
  inside the repository; any other file (SQL, JS, YAML, ...) is not traceable. An
  unreadable or missing trace output makes every file of that run not traceable (fail
  safe: verdicts then come from the run as before), and is logged at WARNING.'
- 'Changed lines (new module scripts/build_orchestration/_wvr_effect.py, pure functions):
  the as-written line numbers a wrong version changes, from the as-written bytes and
  the altered bytes of each file (difflib opcodes on the LF form: every as-written
  line of a replace or delete opcode; for an insert opcode the as-written line just
  before the insertion point, or line 1 at the top). reached(test, files) gives "reached"
  when the test ran at least one changed line of a traceable file, "not reached" when
  every altered file is traceable and it ran none, and "not traceable" otherwise.'
- 'Runner (wrong_version_runner.py, kept at or under 400 counted lines; it is at 309):
  the baseline run traces the union of the files any named wrong version alters (from
  the prepared alterations, the fix undone excluded). For every named wrong version
  (pinned, freshly prepared or declared) and every test whose own entry names it,
  a "not reached" test gets the row result not_executed with detail exactly "not executed:
  the test runs none of the changed lines", whatever its outcome under the alteration;
  a "not traceable" test keeps its run-decided result and its detail gains "; run-or-not-run
  could not be traced for <file>". "The fix undone" is judged by its group rule as
  today and is never reported not_executed. The runner may skip the pytest run of
  a wrong version that no holder reaches.'
- 'Verdict (_wvr_verdict.py): not_executed is an unfinished result (UNFINISHED gains
  it; it is blocking), its unfinished entry carries result "not_executed", it never
  appears in survivors, and the verdict reason is "unfinished" when no blocking survivor
  exists (a survivor still outranks it). A to-run-later extra''s not_executed row
  is demoted to non-blocking like its other rows (_wvr_extras.demote).'
- 'Cost: tracing is limited to the altered files, so the baseline run takes at most
  1.5 x its untraced time on the refresh fixture; measured as a relative check, never
  an absolute budget.'
- 'Deploy manifest: the three new modules sit in scripts/build_orchestration/, deployed
  by build_build_orchestration_scripts'' directory glob, so no deploy-list edit is
  needed. Because the plugin is loaded by module name inside a pytest child, prove
  it from the deployed layout (the shared_reference_layout fixture, shared_layout_reader
  marker): the deployed runner''s baseline loads the deployed plugin, never the source
  tree''s.'
```
