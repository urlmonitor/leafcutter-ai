# KI-CG-20261116-pre-commit-run-files-is-vacuous-for-index-reading-hooks — a `pre-commit run --files` pre-run passes hooks that read the index

> Index: [commit-guardian.md](../commit-guardian.md).
> Filename severity is the three-level index bucket (`high`); the
> original grading is the `**Severity:**` line below.

- **Severity:** high. The hooks print `Passed` and exit 0 having checked nothing. No bad change
  lands, because the real commit stages the files first. But the pre-run that people use to avoid
  refusals is a false green, so the refusals then come one commit attempt at a time.
- **Status:** open, no AC.
- **Occurrences:** 1 (DIAGraph, three commits on PR #470 and PR #473, 2026-11-16). ·
  **First seen:** 2026-11-16 · **Last seen:** 2026-11-16
- **Where:** `templates/scripts/commit_guardian/commit_guardian.json` `hooks_manifest.hooks[]`
  (generated by `scripts/build_precommit.py` into `.pre-commit-config.yaml`; deployed as
  `.leafcutter/scripts/commit_guardian/commit_guardian.json` in a consumer). The index reads are in
  each script, for example `check_secrets.py:235` and `:261-263`, `check_feedback_id.py:142`,
  `hooks/check_files_touched_reconciliation.py:84` and `:676-678`, `hooks/check_ac_limits.py:138`,
  `check_ac_limits.py:383`, `check_contract_shrinking.py:344,417`, `_lint_git.py:100`
  (deployed under `.leafcutter/scripts/commit_guardian/`).

## Mechanism

1. `pre-commit run --files <paths>` uses the paths only to decide which hooks run (each hook's
   `files:` filter). It passes them to a hook as arguments only when `pass_filenames` is true.
2. On current main, 75 of the 82 `hooks_manifest` entries set `pass_filenames: false`.
3. Those scripts find their own input. A text scan finds `--cached` or a staged-file helper in
   59 of the 75 scripts. `check_secrets.py` has no argument parsing at all: `main()` calls
   `_get_staged_files()` and returns 0 when the list is empty (`:261-263`).
4. So with the changes unstaged, each of these hooks reads an index that does not contain them,
   and passes. The `--all-files` form has the same gap. Yet
   `templates/scripts/commit_guardian/INTEGRATION.md:148-154` says
   `pre-commit run --all-files` "runs every hook against every tracked file".
5. The manifest records 72 of the 75 as `change_set_source: handed_by_commit_path`. ADR-038
   (`:64`) defines that as "the commit path hands this check its file list; it derives nothing".
   For these hooks pre-commit hands them no files, and the scripts run `git diff --cached`
   themselves. `change_set_source.py` checks only the `self_derived` entries, so nothing catches
   the mismatch.

## Reproduced (2026-11-16, current main `8d76d670a`)

A scratch repo held the same `check-feedback-id` entry as DIAGraph (`files: ^tickets/.*\.md$`,
`pass_filenames: false`) and a ticket with a sign-off heading that has no `feedback-id:` line:

```
$ pre-commit run --files tickets/T1.md          # ticket not staged
Check Feedback ID in Signoff Comments....................................Passed
$ git add tickets/T1.md
$ pre-commit run --files tickets/T1.md
Check Feedback ID in Signoff Comments....................................Failed
[check-feedback-id] BLOCK: new comment headings found without feedback-id:
```

Calling the deployed `check_secrets.py` directly with the path as an argument gave the same
result: `check_secrets.py leak.py` on an unstaged file with an AWS-key-shaped literal gave
`exit: 0` and no output. After `git add leak.py`, the same command gave `[AWS_KEY] leak.py:1` and
`exit: 1`.

## Seen

DIAGraph, session `feeb7c15`. A coder's `pre-commit run --files` over five changed files passed
"every hook that applied", and it noted that "the lint gate reported 0 staged files". The commit
agent then hit these refusals, one per attempt: `check-predone-scope`, `check-feedback-id`,
`check-ticket-ac-limits`, `check-contract-shrinking`, `check-secrets` and `check-ac-tree-limits`.
All six are `pass_filenames: false` and read `git diff --cached`. The session summary said it took
"about eight refused rounds ... because several hooks only check staged files". `fail_fast: true`
in the consumer config made it worse: each attempt showed only the first failing hook.

## Fix direction

- Let each index-reading hook take an explicit file list (argv), and use the index only when it is
  given none. Or have a hook say "examined 0 staged files" whenever it was given paths but read
  the index. Either way, a pre-run over unstaged files must not print `Passed` silently.
- Correct the `change_set_source` records. A hook that runs `git diff --cached` itself is not
  "handed" its files. Make `change_set_source.py` text-scan `handed_by_commit_path` entries too.
- Until then, document the dry run that works (DIAGraph found it): stage the exact paths in a
  scratch clone, run `pre-commit run --hook-stage pre-commit`, then `git reset`. Put it in
  `INTEGRATION.md` and the consumer `CLAUDE.md` template.

that exit 0 having checked nothing), KI-CG-20260907 (renames invisible to the AC index query),
