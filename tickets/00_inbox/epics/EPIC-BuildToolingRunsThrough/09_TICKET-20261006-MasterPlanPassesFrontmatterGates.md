# 09: The generated Master_Plan passes both frontmatter gates with no hand editing

## Actor / Goal

As the epic generator, I want the Master_Plan I write to carry every field that
check-doc-frontmatter and `ticket_frontmatter_guard` require. Then a freshly
generated epic can be committed and edited without anyone hand-fixing its
frontmatter. When either gate's required set grows, the generator's test fails
until the generator catches up.

## Context

Part of EPIC-BuildToolingRunsThrough (design section 6c). Implements ACD-1200a-8-i,
approved on this branch on 2026-10-06 (it was a draft).

**Root cause**
- `scripts/ac_store/epic_master_plan.py::_render_master_plan` (163-198) emits only `epic_name`, `created`, `status`, `components` and `source_ac`.
- check-doc-frontmatter requires `title` and `depends_on` (`scripts/commit_guardian/commit_guardian.json`, `ticket_frontmatter.required_fields`).
- The authoring-time ticket guard adds `requires_diagram`, `requires_adr`, `change_target` and `risk_surface` (`.claude/hooks/ticket_frontmatter_guard.py::validate`).
- The DK-400 E1 Master_Plan had to be hand-fixed before it could be committed.

**Fix**
- Write the frontmatter with `yaml.safe_dump`, because the titles contain ":".
  - `title: "EPIC: <goal title>"`, `type: epic`, `depends_on: []`;
  - `change_target` and `risk_surface`: the union across the epic's tickets;
  - `requires_diagram` and `requires_adr`: a tri-state roll-up across tickets. Any `true` gives `true`; otherwise any `false` gives `false`; otherwise `null`;
  - keep the existing fields (`epic_name`, `created`, `status`, `components`, `source_ac`).
- Pass the goal title through `scripts/ac_store/epic_phases.py::_write_master_plan_safely` (210-251) from both entrypoints (`run()` and `build_epic_from_ids()` in `scripts/ac_store/epic_pipeline.py`).
- Fix the stale comment at `epic_master_plan.py:82` ("depends_on in ticket frontmatter are AC IDs, not ticket nums"). After ticket 08 they are epic ticket filenames.
- Never weaken a gate, remove a field from a required set, or exempt generated or Master_Plan files (ACD-1200a-8-i). Only the generated artifact changes.

**Why after ticket 07.** Both change `epic_pipeline.py`.

## Constraints

- **Test placement.** `unit_tests/ac_store/test_master_plan_generation.py` measures 722 / 400, so the ratchet refuses growth. The tests go in a new file, `unit_tests/ac_store/test_master_plan_frontmatter_gates.py`.
- **No field list in the test.** ACD-1200a-8-i's coverage note forbids it: generate a real epic, then run the **real** gates over the real file.
- Python sizes (measured / limit):
  - `epic_master_plan.py` 195 / 400;
  - `epic_phases.py` 129 / 400;
  - `epic_pipeline.py` 168 / 400.

## Acceptance Criteria

- [ ] AC-1: A Master_Plan generated by `build_epic_from_ids` and by `run()`, with no hand editing, passes the real check-doc-frontmatter ticket validation.
- [ ] AC-2: The same file passes the real `ticket_frontmatter_guard.validate` with no errors.
- [ ] AC-3: Its frontmatter has `title: "EPIC: <goal title>"`, `type: epic` and `depends_on: []`, and keeps `epic_name`, `created`, `status`, `components` and `source_ac`.
- [ ] AC-4: `change_target` and `risk_surface` are the union of the tickets' values. `requires_diagram` and `requires_adr` are the tri-state roll-up: any true gives true, else any false gives false, else null.
- [ ] AC-5: A goal title containing ":" and quotes survives a `yaml.safe_load` round trip exactly.
- [ ] AC-6: When the test adds a field to a gate's required set, acceptance fails until the generator emits that field. No gate is weakened and no file is exempted.
