# Merges to main are performed by the merge queue only after required checks pass

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-1800b-2` — Merges to main are performed by the merge queue only after required checks pass — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-1800b-2`. Component: `build-orchestration`. Assigned agent: `documentation-expert`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given a pull request targeting the hub `main`,
When the change is landed on `main`,
Then it is landed by the merge queue, not by an agent-issued merge command,
And the merge queue lands it only after the required status checks all pass:
  ruff lint, the full test suite, and the schema-diff check (each configured as a
  REQUIRED check, not advisory),
And the merge is built against the latest `main` and serialized with other queued
  merges,
And a pull request whose required checks are failing or missing is not landed.
```
