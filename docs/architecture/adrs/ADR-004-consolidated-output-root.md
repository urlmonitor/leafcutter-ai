# ADR-004: Consolidated Output Root — All build.py Artifacts Under .leafcutter/

## Status

Accepted (2026-05-27)

## Context

`build.py` currently scatters its output across the consumer project:
- `.claude/agents/`, `.claude/skills/`, `.claude/commands/`, `.claude/hooks/` — agent and skill definitions
- `scripts/commit_guardian/`, `scripts/doc_compliance/`, `scripts/feedback/` — hook scripts
- `docs/vision.md`, `docs/roadmap.json`, `docs/glossary.md` — generated documentation
- `.pre-commit-config.yaml`, `.gemini/`, `.antigravity/` — tool configs at project root

This means leafcutter-owned files are mixed with the consumer's own project files. The user cannot tell at a glance which files are "theirs" and which are generated by leafcutter. Running `git status` surfaces leafcutter artifacts alongside real project changes.

ADR-001 established the self-hosting boundary (source in `leafcutter-ai/`, build outputs at root), but noted as a negative consequence that `scripts/` and other outputs remain at root. This ADR resolves that.

### Claude Code Discovery

Claude Code loads agents from `.claude/agents/`, skills from `.claude/skills/`, commands from `.claude/commands/`, and hooks from `.claude/hooks/`. These paths are conventional — Claude Code reads them via standard filesystem APIs. Symlinks are transparently resolved by the OS on Linux and macOS. On Windows, symlinks require Developer Mode or administrator privileges; without these, symlink creation fails with `PermissionError`.

Empirical conclusion: a shim layer is needed that creates either symlinks (preferred) or file copies (Windows fallback) at the canonical `.claude/` paths, pointing into `.leafcutter/`.

## Decision

All `build.py` output artifacts are written into a single `.leafcutter/` directory at the consumer project root. Tools that require files at fixed canonical paths (Claude Code, pre-commit, Gemini) are bridged by a shim layer that runs after the main build phases.

Specifically:

1. **Output root**: `.leafcutter/` (dot-prefix, follows the convention of `.claude/`, `.gemini/`, `.antigravity/`). Configurable via `skills_config.json` key `output_root` (default: `.leafcutter`).

2. **Shim strategy**: After build phases write to `.leafcutter/`, an `install_shims()` step creates pointers at canonical paths:
   - `.claude/agents/` → `.leafcutter/agents/`
   - `.claude/skills/` → `.leafcutter/skills/`
   - `.claude/commands/` → `.leafcutter/commands/`
   - `.claude/hooks/` → `.leafcutter/hooks/`
   - `.pre-commit-config.yaml` → `.leafcutter/pre-commit-config.yaml`
   - `.gemini/` → `.leafcutter/gemini/`
   - `.antigravity/` → `.leafcutter/antigravity/`

   Strategy is configurable via `shim_strategy` key (`"symlink"` | `"copy"` | `"auto"`). Default `"auto"` attempts symlinks, falls back to file copies on `PermissionError`.

3. **Git posture**: Configurable per consumer. The recommended default is git-ignored (`.leafcutter/` is a build artifact, regenerated by `build.py`). Consumers who prefer checked-in config can commit it. Both approaches are documented.

4. **Internal layout**: `.leafcutter/` mirrors the old scattered layout:
   ```
   .leafcutter/
   ├── agents/          (was .claude/agents/)
   ├── skills/          (was .claude/skills/)
   ├── commands/        (was .claude/commands/)
   ├── hooks/           (was .claude/hooks/)
   ├── settings.json    (was .claude/settings.json)
   ├── scripts/         (was scripts/)
   ├── docs/            (was docs/ — generated portions only)
   ├── gemini/          (was .gemini/)
   ├── antigravity/     (was .antigravity/)
   ├── pre-commit-config.yaml  (was .pre-commit-config.yaml)
   └── .leafcutter-build-manifest.json
   ```

## Consequences

**Positive:**
- Consumer project files are fully isolated from leafcutter artifacts
- `git status` only shows `.leafcutter/` (or nothing if git-ignored) — no leafcutter noise
- Single folder to delete or regenerate — clean uninstall is `rm -rf .leafcutter/`
- Self-documenting: the folder name tells developers what it is
- Supersedes ADR-001's "Negative" note about root-level `scripts/` outputs

**Negative:**
- Shim layer adds complexity: two representations of each path must stay in sync
- Windows without Developer Mode gets file-copy shims (two copies of every file, must rebuild to sync)
- Existing installs require a migration step (`build.py --migrate`) to detect and remove stale files at old locations
- `.claude/settings.json` and `.claude/settings.local.json` are NOT shimmed — these are user-owned config files, not build outputs

**Neutral:**
- Pre-commit hooks continue to work because `.pre-commit-config.yaml` stays at project root (via shim)
- Claude Code continues to work because `.claude/` paths exist (via shim)

## Alternatives

1. **Status quo (no consolidation)**: Rejected. The user explicitly wants isolation; the scattered layout causes confusion.

2. **Physical copies only (no symlinks)**: Viable but wasteful — doubles disk usage for every artifact. Kept as the Windows fallback, not the default.

3. **Move .claude/ entirely into .leafcutter/**: Rejected. Claude Code's discovery path is `.claude/` at project root. We'd still need shims, and hiding the `.claude/` folder inside another dot-folder adds confusion.

4. **Subfolder of .claude/ (e.g. .claude/leafcutter-out/)**: Rejected. Doesn't solve the `scripts/`, `docs/`, `.gemini/`, `.pre-commit-config.yaml` scattering.

5. **Non-hidden folder name (leafcutter-project/)**: Rejected in favor of dot-prefix to match the ecosystem convention (`.claude/`, `.gemini/`, `.vscode/`).
