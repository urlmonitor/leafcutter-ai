## Implementation Notes

```yaml
- 'Deliver the shared test support module (e.g. unit_tests/build_orchestration/_workspace_maker_fixtures.py):
  (1) a locator that resolves the DEPLOYED maker from the shared deployed layout (the
  CI build step''s `build.py --target-dir .`, or TQ-600a''s session-scoped layout
  once it lands) and FAILS -- never skips, never falls back to templates/ -- when
  it is absent; (2) an override seam used only by the meta-test to point at a faulted
  copy; (3) fixture builders for real temp projects with a bare hub, the dev and consumer
  layouts, a stub build entry point installing a real rejecting hook, and helpers
  for every BO-4300b-1 starting point.'
- 'Meta-test: copy the deployed maker, inject a fault only into the copy (source unchanged),
  run the relevant proof subset against it via the override seam, and require that
  it fails naming the broken behaviour.'
- Delete or re-point tests that exercise the tracked scripts/ copy as 'DEPLOYED_SCRIPT'
  (unit_tests/build_orchestration/_bo2400f13_fixtures.py and its users).
- 'NO SECOND COPY (KI-TQ-20260831-mutation-probe-lands-in-the-wrong-copy, KI-TQ-004):
  the locator resolves only the DEPLOYED maker and resolver module; it never accepts
  a path under the package repository''s scripts/ or templates/ as the maker, so a
  tracked stray copy can never become the thing under test (the mutation probe of
  KI-TQ-20260831 landed in the wrong copy for exactly this reason). The tracked-file
  test that forbids a copy outside templates/scripts/ is BO-4300a-1''s; this record
  keeps the locator from ever reaching one.'
- The fixture module also owns the ONE legacy-worktree fixture helper (a real `git
  worktree` registration in a temp project, for BO-4300f-3's cut-over tests and for
  tests that migrate off hand-built worktrees under BO-4300f-2's census). It is the
  census's only test-side exemption; no other test spells the worktree add/remove
  commands.
- 'Git spelling in fixtures (KI-CG-20260925-commit-delegation-hook-misses-git-dash-c):
  fixture commits run git with its working directory set to the repository, never
  as `git -C <path> commit`; -C is used only with non-commit verbs.'
- 'Tests must not spawn the package''s own scripts/build.py (CLAUDE.md ''Tests must
  not spawn their own build.py''): the deployed maker comes from the shared deployed
  layout, and fixture projects carry a minimal stub build entry point that installs
  a real, rejecting hook in well under a second. A test that must mutate the package
  and build its own copy says so and justifies it in its ticket.'
- All temporary projects, hubs and workspaces live under the test's temp directory
  and run git with an isolated global and system config; afterwards the developer's
  own repository's branches, registered worktrees and local git config are unchanged
  (BO-4300f-4-i, F14, KI-TQ-012).
```
