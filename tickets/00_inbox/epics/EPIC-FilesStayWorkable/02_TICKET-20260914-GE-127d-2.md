# The length a file is quoted at is one the author can arrive at themselves by following a published measurement rule

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-127d-2` — The length a file is quoted at is one the author can arrive at themselves by following a published measurement rule — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-127d-2`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a file of a kind the size standard covers stands above its permitted
  length under the measurement rule in force,
When the author performs an ordinary commit,
Then the commit does not complete, and the outcome states the length the
  standard arrived at, the length permitted, and what the stated length
  measures,
And the measurement rule the standard applied is published,
And applying that published rule independently to the same file arrives at
  exactly the length the standard quoted,
And given the measurement rule in force is changed in any way that alters the
  length arrived at for one particular file, and nothing else changes,
When the author performs an ordinary commit staging that file,
Then what is published states the changed rule, and applying it independently
  to that file arrives at exactly the length the standard now quotes —
  establishing that what is published is taken from the rule actually in force
  rather than maintained alongside it,
And given a file containing content that the rule in force does not count
  towards its length, so that the length quoted for it and the total number of
  lines it contains are different quantities,
When that file is refused,
Then an author who counts every line in the file and arrives at the other
  quantity can tell from the outcome alone which of the two the standard
  stated, and reconcile the difference without inspecting anything else,
And given a file containing no content that the rule in force declines to
  count,
When its length is quoted,
Then the length quoted and the total number of lines it contains are the same
  number.
```

## Implementation Notes

```yaml
- 'THE MEASUREMENT RULE ITSELF — DECIDED, AS THE BA REQUIRED, AND IT IS "KEEP THE
  RULE, PUBLISH IT". The rule in force stays: discard triple-quoted blocks in both
  Python quote styles and C-style /* */ block comments, then count every remaining
  line, including blank lines and hash comments. It is not changed here for two reasons
  that both point the same way. First, this record''s own notes concede the rule is
  defensible on the merits — a file is hard to work in because of how much there is
  to reason about, and a module''s docstrings are not that. Second, and decisively:
  changing the rule changes the population. Under the rule in force 200 of 845 tracked
  .py files stand above 400; under a raw count 314 do. Adopting the raw count as part
  of this record would add 114 Python files to GE-127b-1''s ratchet in the same change
  that publishes the rule, entangling a transparency fix with a scope expansion nobody
  costed. If the rule is later judged wrong, that is its own record with its own measured
  population.'
- THE RULE HAS A KNOWN ASYMMETRY THAT MUST BE PUBLISHED, NOT JUST THE RULE'S SHAPE.
  Under the rule in force, deleting blank lines and hash comments DOES reduce the
  quoted number and deleting docstrings does NOT. The refusal message currently forbids
  both in one breath, naming the action that works and the action that does nothing
  without distinguishing them. Publishing "which lines are counted" is not sufficient
  on its own — the published statement must make that asymmetry legible, and the refusal
  message must stop forbidding an action that cannot help the author anyway. This
  is the concrete shape of the problem the record closes and the reason it is not
  cosmetic.
- ONE MEASUREMENT FUNCTION, AND THE PUBLISHED STATEMENT DERIVED FROM IT RATHER THAN
  MAINTAINED BESIDE IT. The same pure function that GE-127a-1's threshold comparison
  and GE-127b-1's before- and-after comparison call must be the one whose behaviour
  is published and the one the reproducibility clauses re-derive against. The published
  statement must be generated from, or mechanically checked against, that function
  — a hand-written sentence is the "satisfied by editing a sentence" failure the parent
  L1 names and this tree has already shipped once, exactly that way. It is also the
  BA's named injection 2 and the descriptor that catches it.
- THE OUTCOME MUST STATE WHAT THE QUOTED NUMBER MEASURES, NOT ONLY THE TWO NUMBERS.
  The incumbent shape prints an arrived-at number and a permitted number and nothing
  about what the first of them counts. That is the shape that will be reached for
  and it is the BA's named injection 1. The refusal must carry enough for an author
  who counts every line in the file and gets a different figure to reconcile the difference
  from the outcome alone.
- 'NO PACKAGE SURFACE — MEASURED. This record adds no hooks_manifest.hooks id (it
  changes the outcome text of the gate GE-127a-1 registers, and adds a published statement)
  and no new top-level mapping key to commit_guardian.json. IF the measurement rule
  is later made configurable, its keys go NESTED under the existing `file_size` section
  at line 13, which WATCHED_REGISTRIES does not see — the mapping_keys container is
  bound to dotted path "", the document''s own top level, only. That is the recommended
  home if configurability is wanted; a new top-level key is not, and would drag a
  package-surface declaration and the structured five-field spec onto this record.
  Do NOT mint a config_schema_fragment key to clear the validator: the BP-100k-4 /
  BP-100k-4-i precedent BP-1600a-2-ii records produced two keys that were never created
  and are still absent from commit_guardian.json''s 36 top-level keys.'
- THE PUBLISHED STATEMENT BECOMES ONE MORE SURFACE GE-127d-1 COMPARES — WIRE IT, DO
  NOT BUILD A PARALLEL CHECK. Whichever of these two records lands second inherits
  the other's surface. If GE-127d-1 lands first, add wherever this measurement statement
  lives to its configured published-surface list in the same change. If this record
  lands first, its statement must be machine-comparable so GE-127d-1 can consume it.
  Two reconciliation checks over overlapping surface sets is the drift both records
  exist to prevent.
- ASSERT REPRODUCIBILITY BY RE-DERIVATION, NEVER AGAINST A LITERAL. Every equality
  clause must be discharged by applying the published rule to the file at run time
  and comparing against the number the gate emitted, with the file's content VARIED
  between runs so the two numbers must move together. A test carrying a hard-coded
  expected length asserts the author's belief about today's rule and stays green when
  the rule and the published statement drift apart together — which is the failure
  this record exists to forbid. Same by-variation construction BP-1600a-2-ii requires
  of its stated counts, for the same reason.
- 'THE DEGENERATE ARM IS A BOUNDARY CHECK THAT MUST SURVIVE A LATER RULE CHANGE. A
  file containing nothing the rule declines to count must be quoted its total number
  of lines. Implement it as a consequence of the rule rather than as a special case:
  if a later record changes the rule to count everything, that arm becomes the whole
  behaviour and the divergence arm simply never arises. Neither arm may name what
  the rule discards.'
- HOST, LAYERING AND THE BUILD. The measurement function and the derivation of its
  published statement belong in the same sibling module inside templates/scripts/commit_guardian/
  that holds GE-127b-1's previous-length resolution — build_commit_guardian copies
  that directory whole, so no scripts/build_phases.py deploy entry is needed; a module
  imported from outside it does need one. templates/scripts/commit_guardian/ is canonical;
  scripts/commit_guardian/ and the repo-root .pre-commit-config.yaml are untracked
  build outputs; templates/commit-guardian/ is a decoy. config.py:19 resolves the
  config beside the DEPLOYED script, so `python scripts/build.py --target-dir .` is
  part of this change.
- 'Must follow the repo error-handling policy: specific-exception try/except around
  file I/O and any decode; log at WARNING or higher or re-raise; no bare or blind
  excepts. A file whose length cannot be established has no quotable number at all
  and takes GE-127a-1-i''s INDETERMINATE path, never a quoted length of zero.'
```
