# The startup check reads the registry itself instead of asking an agent to read it

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `ACD-2100b-5` — The startup check reads the registry itself instead of asking an agent to read it — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `ACD-2100b-5`. Component: `ac-driven-dev`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given an environment in which no agent can be dispatched -- every dispatch
  attempt fails immediately with a transport error,
And an agent registry that is present readable and lists the agent the route
  uses to create the authoring worktree with permission to run repository
  commands,
When a run starts and reaches the startup check,
Then the check completes with the permitted verdict and the run proceeds past it,
And the run's record of what it dispatched contains no dispatch made on behalf of
  the check,
And repeating the run with dispatch available reaches the same verdict.
```

- [ ] AC-1: an agent registry that is present readable and lists the agent the route
- [ ] AC-2: the check completes with the permitted verdict and the run proceeds past it
- [ ] AC-3: the run's record of what it dispatched contains no dispatch made on behalf of
- [ ] AC-4: repeating the run with dispatch available reaches the same verdict.

## Implementation Notes

```yaml
- The change must land under templates/. The deployed workflow is build output and
  does not carry this step at all today.
- The verdict must be a function of the registry contents alone. It must be identical
  whether dispatch is available or not -- 'skip the check when dispatch is unavailable'
  is a fail-open regression wearing this record's clothes and is explicitly forbidden.
- The startup path must reach this check and pass it with no network available.
- 'Removing the round-trip must not remove the halt: the four outcomes ACD-2100b-1
  through -3 specify still stop the run, and ACD-2100b-4 still holds over them.'
- If a helper that dispatches for this purpose remains in the source for another caller,
  this behaviour is not satisfied by its absence from the file -- what must be observable
  is that no dispatch is made on the check's behalf during a run.
- 'Must satisfy the repository error-handling policy: the local read replaces a network
  call, so its failure paths are the ones ACD-2100b-1 and ACD-2100b-2 own and must
  not be swallowed.'
- Must not add a per-run cost beyond a single local file read -- this record removes
  latency from startup and must not reintroduce it elsewhere.
```
