## Acceptance Criteria

```gherkin
Given the main checkout, in which every check already resolves its prerequisites today,
And a recorded baseline of the verdict each check produces there against a fixed fixture of
  staged changes, captured before the shared resolution facility is adopted,
When each check is executed in the main checkout after adoption against that same fixture,
Then each check produces the same verdict as its recorded baseline,
And no check that previously located its prerequisites now fails to locate them,
And no check that previously reported a violation now reports a clean result,
And the only observable difference between before and after is confined to working copies
  in which resolution previously failed.

Coverage note: the baseline must be captured by execution before the change, not asserted
from memory or from the check sources afterwards. A comparison against a baseline recorded
after the change proves nothing.
```

## Implementation Notes

```yaml
- THE BASELINE IS AN ARTIFACT, captured by EXECUTION before the first line of GE-120b-2
  is written, and stored so the after-run is diffed against it mechanically. Record
  the commit SHA of the pre-sweep tree alongside it. A baseline recorded after the
  change, or reconstructed from the check sources, proves nothing — that is the criterion's
  own coverage note and it is the single way this AC is most likely to be faked.
- CAPTURE IT WITH THE GE-120c-1 HARNESS, not with an ad-hoc script written by the
  agent performing the migration. An implementer's own before/after apparatus is the
  failure mode GE-120c-2 exists to prevent, and this AC has the same exposure at smaller
  scale.
- 'THE FIXTURE MUST PROVOKE A REAL VIOLATION FOR EVERY CHECK in hooks_manifest.hooks[]
  (54 entries today, 48 judgment + 6 transform). A clean fixture makes every check
  agree trivially — including a check that has silently stopped running altogether.
  This fixture is SHARED WITH GE-120b-4: build it once and own it in one place; two
  fixtures will diverge and the family-wide claims will stop meaning the same thing.'
- 'The third clause is the load-bearing one: no check that previously reported a violation
  now reports clean. Assert PER CHECK BY ID, never in aggregate — an aggregate pass
  rate hides exactly one check going quiet, which is the consolidation bug this AC
  guards against.'
- Transform-tier hooks (6 today) mutate files. Run each baseline and each after-run
  from an identical fixture state so one check's mutation cannot change a later check's
  input; otherwise the diff reports order effects as regressions.
- 'SCOPE OF PERMITTED DIFFERENCE: only working copies in which resolution previously
  FAILED. Any main-checkout difference is a regression, not an improvement, and fails
  this AC.'
- Capture the baseline against the DEPLOYED copies (.leafcutter/scripts/commit_guardian/),
  because that is what pre-commit actually runs. A baseline taken against templates/
  measures a layout no commit uses (ADR-001).
```
