# A passing front-end test run makes a JS-covered AC eligible to be marked done

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-2500e-2` — A passing front-end test run makes a JS-covered AC eligible to be marked done — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-2500e-2`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given an active AC whose only linked test is a "// covers:<id>" test in a .ts/.tsx file, and that
  test passes when the JS test runner (vitest) executes it,
When the done-status of that AC is evaluated,
Then the oracle runs the JS test runner, observes the genuine pass, and reports the AC eligible
  to be marked done,
So a real, passing front-end test counts as proof-of-done exactly like a passing Python test.
```

- [ ] AC-1: the oracle runs the JS test runner, observes the genuine pass, and reports the AC eligible
