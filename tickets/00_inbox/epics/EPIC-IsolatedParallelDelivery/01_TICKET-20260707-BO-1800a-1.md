# Each drive runs in an independent copy with its own object store, isolated from every other drive

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-1800a-1` — Each drive runs in an independent copy with its own object store, isolated from every other drive — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-1800a-1`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `L`.

## Acceptance Criteria

```gherkin
Given two drives A and B are started at the same time for two different features,
When the isolation layer provisions each drive,
Then drive A and drive B each get their own working copy backed by its OWN git
  object store and ref namespace (an independent clone), NOT a git worktree that
  shares one repository's `.git/objects` and `refs/`.
And while both drives are running, any commit, branch creation, ref update, or
  garbage-collection that drive A performs is observable only inside drive A's
  object store and leaves drive B's object store and refs byte-for-byte unchanged
  (and vice versa).
And no manual repair of a shared object store is ever required as a result of the
  two drives running concurrently.
```
