# An empty authored change set is inspected as empty, never widened back to the whole staged tree

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-120e-1-i` — An empty authored change set is inspected as empty, never widened back to the whole staged tree — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-120e-1-i`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `S`. Complexity: `low`.

## Acceptance Criteria

```gherkin
Given a commit in which the author wrote nothing of their own — every line of the staged
  tree is identical to one of the states the commit is built on, and the carried-in work
  contains content a check objects to,
When a check that works out its own change set runs on that commit,
Then the change set it inspects is empty, it raises no objection, and the commit is not
  blocked,
And it does not fall back to the whole staged tree on finding the change set empty,
And an empty change set is reported as "nothing of the author's to inspect" and is
  distinguishable in the output from the could-not-check outcome GE-120a-1 defines, so a
  reader can tell a commit with nothing to inspect from a check that never looked.

Coverage note: the fallback clause is the load-bearing one and it fails silently — an
implementation that treats an empty change set as "no filter applied" reproduces the
original defect exactly on the one commit shape where the narrowing matters most, and
every other test in this tree still passes. Cover it by executing the check as a process
against a repository in that state and asserting no objection is raised, with the
carried-in content present in the staged tree and known to trip that check.
```

- [x] AC-1: the change set it inspects is empty, it raises no objection, and the commit is not
- [x] AC-2: it does not fall back to the whole staged tree on finding the change set empty
- [ ] AC-3: an empty change set is reported as "nothing of the author's to inspect" and is

## Implementation Notes

```yaml
- THE NAMED ANTI-PATTERN. There must be no branch anywhere in the shared source or
  in any consuming check of the form 'if the narrowed set is empty, use the staged
  diff'. An empty authored change set is a value, not a signal to widen. This is the
  single load-bearing constraint of this AC and it is the one that reads like defensive
  programming to a reviewer, so state it in the implementation as a comment tied to
  this AC id.
- EMPTY MUST BE AN EXPLICIT STATE, NOT AN ABSENCE. The shared source must return an
  explicitly represented empty result that consumers can distinguish from 'no derivation
  was made'. Two Python falsy values that both mean 'nothing here' will collapse under
  the first refactor and reinstate the widening.
- REUSE GE-120a-1'S OUTPUT VOCABULARY FOR THE DISTINCTION. Do not define a second
  vocabulary for reader-facing outcomes. If a new token is needed to say 'nothing
  of the author's to inspect', add it to GE-120a-1's vocabulary and record that decision
  on this AC rather than inventing a parallel one here — the AC notes make this an
  explicit instruction, not an option.
- EMPTY IS A PASS, NOT A SKIP. Exit status must be success and the commit must proceed.
  Reporting the empty case as a skip re-reads as 'this check did not run', which is
  precisely the GE-120a false negative this L1 must not trade itself for.
- 'TEMPLATE/DEPLOYED PARITY (ADR-001): verify in the deployed layout, not only the
  source tree. Run build.py and execute the deployed check — a clean auto-merge is
  the commonest shape of the observed case and it must be exercised where the commit
  path actually runs.'
```
