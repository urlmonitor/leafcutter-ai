# The AC store is read once per session and the enforced set is stable across repeated runs

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `TQ-100b-1-iii` — The AC store is read once per session and the enforced set is stable across repeated runs — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `TQ-100b-1-iii`. Component: `testing-quality`. Assigned agent: `test-runner`. Estimated complexity: `S`.

## Acceptance Criteria

```gherkin
Given a suite of tests tagged "# covers: <AC-ID>" covering a mix of done and
  not-done ACs, and a fixed AC store that does not change between runs,
When the suite is run several times in succession, including runs with
  different randomized test-ordering seeds,
Then the AC store is read once per session (not re-read per test)
And the set of tests classified as enforced versus informational is identical
  across every run regardless of test ordering
And the overall pass/fail outcome does not change between runs for an unchanged
  store.
```

## Test Requirements

- `test_ac_store_read_once_per_session`: The AC store is read once per pytest session and the classification is cached, not re-read per test.
- `test_enforced_set_stable_across_runs`: The enforced/informational partition is identical across repeated runs of the same store and suite.
