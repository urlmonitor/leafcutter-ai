# The oracle discovers // covers:<id> tags in front-end tests through the shared seam

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-2500e-1` — The oracle discovers // covers:<id> tags in front-end tests through the shared seam — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-2500e-1`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a front-end test file (.ts or .tsx) containing a "// covers:<id>" tag for an active AC id
  (e.g. // covers:UXP-596-1),
When the done-proof oracle extracts covers-tag linkage from the test tree,
Then the "// covers:<id>" tag is discovered and linked to that AC,
And the extraction uses the SAME single tag-extraction routine that discovers Python
  "# covers:<id>" tags — one shared seam, not a second parser,
So JS and Python covers-linkage semantics cannot drift apart.
```

- [ ] AC-1: the "// covers:<id>" tag is discovered and linked to that AC
- [ ] AC-2: the extraction uses the SAME single tag-extraction routine that discovers Python
