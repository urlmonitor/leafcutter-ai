# An unknown flow id shows 'Flow not found' (404) and never falls back to another flow

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `UXP-591-1-ii` — An unknown flow id shows 'Flow not found' (404) and never falls back to another flow — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `UXP-591-1-ii`. Component: `ux-prototyping`. Assigned agent: `frontend-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given no flow has the id leafcutter/flow-render-pipline (a typo of
  leafcutter/flow-render-pipeline),
When a person opens /flows/leafcutter/flow-render-pipline,
Then the Atlas answers 404 and shows a 'Flow not found' notice whose text quotes
  'leafcutter/flow-render-pipline' verbatim and offers an 'Open the Flows view' link to /flows,
And the flow selector is shown with Source Real, Kind User and Realization All,
And no flow is drawn and the breadcrumb is empty: neither leafcutter/deliver-a-feature nor any
  other flow is drawn in its place,
And the address bar keeps /flows/leafcutter/flow-render-pipline so the link can be corrected,
And /flows/leafcutter (a product with no flow) and /flows/leafcutter/flow-render-pipeline/resolve
  (a step written as a path segment) each produce the same 404 state, with a notice explaining
  that a flow link names a product and a flow, for example /flows/leafcutter/deliver-a-feature,
And /flows/leafcutter/flow-render-pipline?step=resolve shows only the 'Flow not found' notice,
  with no 'Step not found' notice and no drawer.
```

## Implementation Notes

```yaml
- 'The 404 is a real HTTP status: leafcutter-web/app/flows/[...id]/page.tsx calls
  notFound() from next/navigation for a two-segment id missing from the loaded flow
  set and for any segment count other than two, and the ''Flow not found'' state renders
  from the route-segment boundary leafcutter-web/app/flows/[...id]/not-found.tsx.
  No loading.tsx or Suspense boundary may wrap the segment above the notFound() call,
  because a streamed response commits a 200 first.'
- Next.js 14 passes no params or searchParams to not-found.tsx, so the requested id
  (the path after /flows/, verbatim and still percent-encoded as requested) reaches
  it through a request-scoped channel, e.g. a request header set in leafcutter-web/middleware.ts
  and read with headers(). The quoted id is in the server-rendered 404 HTML, not filled
  in after hydration. UXP-591-1-iii reuses this channel.
- The notice copy is the leafcutter/atlas-flows dataset's two variants, chosen by
  the shape of the requested id (two segments matching ^[a-z0-9-]+/[a-z0-9-]+$, or
  not), never by comparing against example ids.
- 'The requested id is attacker-controlled: render it as React text only, never through
  dangerouslySetInnerHTML and never into an href (the action link is the fixed /flows).'
- The not-found state hosts the Flows view's own selector and filter controls with
  the full flow catalogue at Real/User/All, so UXP-591-5-v can re-pick a flow from
  it. It never draws a fallback flow and ignores any ?step= (no drawer, no 'Step not
  found').
```
