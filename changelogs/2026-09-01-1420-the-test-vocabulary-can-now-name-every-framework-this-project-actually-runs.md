summary: "The list of test frameworks a specification is allowed to name was written when this project was Python-only and never updated after it gained a web application, so twenty-eight specifications were rejected for describing their own tests truthfully. The list now names the frameworks in use, a check holds its two hand-copied halves in step, and the whole three-thousand-record store passes for the first time in six weeks."
description: "A specification in this project may state which framework its tests run under, chosen from a fixed list. That list said Python and only Python, because it was written before the project shipped a web application. The web application's suite runs under a JavaScript test runner that is installed, wired up, and executed by the automated checks on every change — and twenty-eight specifications said so, accurately, and were rejected for it. The rejection was not a small one: the tool that validates the whole specification store stopped before it could report anything at all, so the store had been unable to produce a clean result for six weeks and the failure looked like a broken tool rather than an out-of-date list. Nobody noticed, because the automated check that runs on every change only ever inspects the specifications that change touched, and none of these had been touched since before that check existed. The list now names the frameworks in use, including a browser-driving one that is specified but not yet installed — naming a tool is not a claim that it is present, and the list now says so in as many words. The important part is that the list exists twice: once for specifications and once, hand-copied, for the work items generated from them, with the value carried straight across. Widening only the first would have moved the failure one step downstream and made it silent, because nothing enforces the second, so a work item would have quietly contradicted the contract handed to whoever writes its tests. Both were widened together, and a new check now fails if the two ever disagree again — it passes today and passed yesterday, by design, since it guards against a future drift rather than proving a present fix. Two further things were done on purpose rather than as tidying. A quieter defect was written down before the fix landed, not after: the tool that turns a specification into a work item forces a Python file extension onto every test filename it derives, no matter which framework the specification named, and the tool that later looks for proof the work is done decides which test runner to ask by reading that extension. So a browser test gets a Python filename and the wrong runner is asked whether it passed. Until now the rejected specifications were the only thing keeping that family visible; the fix makes them validate and look healthy, so it was recorded first, deliberately. And the entry describing all of this carried a false obstacle — it asserted the change would be blocked by a protection rule covering a list of watched files, naming the real rule and the real refusal but getting the membership wrong. It was struck through rather than deleted, with the correction beside it, because a wrong claim that names real machinery reads as verified and is the expensive kind: it plausibly kept the fix waiting a week. Finally, the record of which specifications the store refuses was regenerated, in its own separate change, because the guard that compares against it is the only store-wide protection against validation quietly getting weaker over time and the honest response to it turning red was to re-measure and explain, not to relax the comparison. It went from twenty-eight refusals to none, with nothing added and no existing message altered, which is the shape that tells the two cases apart. One caveat is recorded rather than glossed: the underlying gap is not closed. The automated check still cannot see any specification that predates it and has not since been edited, which is most of them, and the only component that was demonstrably failing is no longer failing — so the argument for closing that gap now has to stand on its own without an example."
