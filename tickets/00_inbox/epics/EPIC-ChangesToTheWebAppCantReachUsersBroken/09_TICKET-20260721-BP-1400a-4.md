# Every web-app check reports its result on the pull request and gates the merge

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BP-1400a-4` — Every web-app check reports its result on the pull request and gates the merge — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BP-1400a-4`. Component: `build-pipeline`. Assigned agent: `python-coder`. Estimated complexity: `S`. Complexity: `low`.

## Acceptance Criteria

```gherkin
Given the web-app build/type-check, style, and route-render checks defined for
  the repository,
When a pull request that changes the web app is evaluated,
Then each web-app check reports its pass/fail result visibly on the pull
  request,
And a pull request for which any web-app check reports a failing result cannot
  be merged,
And a pull request merges only once every applicable web-app check has reported
  a passing result.
```

- [ ] AC-1: each web-app check reports its pass/fail result visibly on the pull
- [ ] AC-2: a pull request for which any web-app check reports a failing result cannot
- [ ] AC-3: a pull request merges only once every applicable web-app check has reported

## Implementation Notes

```yaml
- Wire all THREE web-app check names — the build/type-check job (BP-1400a-1), the
  style job (BP-1400b-1), and the route-render job (BP-1400c-1) — into the main branch's
  required-status-checks list so a failing web-app check blocks the merge and each
  result is visible on the PR.
- 'Making these checks REQUIRED is a repo-admin / branch-protection RULESET step —
  it is NOT achievable in .github/workflows/ci.yml alone. Mirror how the Python ''Test
  suite (pytest)'' gate became required (BP-1200c): the current main protection is
  a Ruleset (`require-ci-lint`), so the required-checks change is a ruleset edit,
  applied as settings-as-code via the GitHub branch-protection/rulesets API with a
  DOCUMENTED MANUAL fallback runbook.'
- The three check names added to the required list MUST match the exact ci.yml job
  names verbatim (the stable `name:` values pinned in BP-1400a-1 / BP-1400b-1 / BP-1400c-1).
  A mismatched name silently fails to enforce.
- 'Reconcile with the path-scoping in BP-1400a-2: because the web-app jobs are path-filtered,
  a required-status-check that never runs on a non-web-app PR must not permanently
  block that PR. Verify a non-web-app-only PR still merges under the chosen required-check
  mechanism (skipped-as-neutral, or a no-op success job on non-web changes).'
- 'EMU/account constraint (CLAUDE.md): branch-protection/ruleset API calls require
  the non-EMU urlmonitor account. The settings-as-code script must run under (or document
  switching to) `gh auth switch --user urlmonitor`; verify with `gh auth status` before
  invoking the API. Note the repo main protection is a Ruleset (id 17810993), so use
  the Rulesets API/UI, not classic branch-protection endpoints.'
- 'The settings-as-code change must be idempotent: re-running against already-correct
  protection converges to the same required-checks set without duplicating or dropping
  the existing required checks (Lint (ruff), Component vocab style, Test suite (pytest)).'
```
