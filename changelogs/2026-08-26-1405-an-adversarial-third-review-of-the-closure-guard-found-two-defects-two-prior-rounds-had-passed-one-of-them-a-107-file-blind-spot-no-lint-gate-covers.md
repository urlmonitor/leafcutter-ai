description: "KI-BP-022 is new and high. The closure walk reads and parses each deployable script inside two handlers, and both return early on failure, so the script's closure comes back empty and the guard reports zero missing dependencies for it. A script with real undeployed intra-package imports is therefore indistinguishable from one that has no dependencies at all. A WARNING is emitted, so this is not literally silent, but it does not change exit status and nothing downstream distinguishes the two outcomes, which is the entire value the guard was built to provide. The obvious objection is that a committed Python file containing a syntax error would be caught by the required lint gate long before this mattered, and that objection holds for forty-five of the guard's inputs and fails for the other hundred and seven. Continuous integration runs ruff over the scripts, tests and unit test directories only, and the workflow file states in its own header comment that the templates tree is excluded. Measured on the branch by resolving every entry in the guard's deployable set through the source-path resolver and recording where each one lands: of one hundred and fifty-two sources, one hundred and seven are parsed out of the templates tree and only forty-five out of the linted scripts tree. That larger share is not an arbitrary slice. It is the entire commit-guardian template directory, every acceptance-criteria hook and schema validator in the repository, which is the most consequence-bearing deploy population there is. A syntax error in any of them is caught by neither the lint gate nor this guard, and the guard actively reports the file clean. Recorded at the same boundary is a second, milder defect: the read handler catches only OSError, while a file containing invalid UTF-8 raises UnicodeDecodeError, which is a subclass of ValueError, so it escapes the handler and aborts the build with a raw traceback rather than the guard's designed message. That behaviour fails closed and is therefore a diagnosability problem rather than a false green, and it has the side effect of protecting against the read-failure half of the main symptom. Exposure today is nil, verified: all one hundred and fifty-two sources parse, none raise on read, and the two silent-skip branches in the guard's own loop fire zero times. KI-BP-023 is new and medium. The function that computes the guard's deployable set unions eight per-phase manifest helpers and documents itself as covering every script the build will deploy, but the build has at least ten deploy families that ship Python files. The documentation-compliance phase, which copies a whole template directory into the target's scripts tree and whose command-line entry point has five real sibling imports, is absent, as is the platform-sync script, which the standalone-script helper cannot see because that helper globs only the top level of the templates scripts directory while the file sits one level deeper. Because neither path enters the deployable set, the guard's loop never calls the closure computation on them at all; an entire deployed Python package is invisible to it with no warning and no error. Verified directly against the function: one hundred and fifty-two entries, zero documentation-compliance, zero platform-sync. Exposure today is nil and the reason is worth recording, because it explains why nobody noticed: both phases copy their whole source directory recursively rather than working from a curated list, so every sibling ships automatically and both are structurally immune to the forgotten-file defect this ticket exists to close. It is filed regardless on two grounds. The docstring's completeness claim is the sentence a future author will read before deciding whether a new phase needs registering, and no test asserts it against the actual set of build phases. And the immunity is a property of the deploy mechanism rather than of the guard, so the moment either phase is refactored toward a curated deploy map, which is exactly the pattern the acceptance-criteria store phase used until this ticket replaced it, the blind spot becomes a live silent regression vector while the refactor looks safe because it matches the shape of the fix that just landed. Finally, KI-BP-021 is widened from the sys.path lens specifically to the reference lens generally, adding three further idioms the same review round found unhandled: dynamic imports through import_module or the import builtin, which are invisible with no log output; a relative import of a sibling subpackage, which never generates an init-file candidate and is likewise silent; and a local variable introduced by an annotated assignment rather than a plain one, which at least reaches the warning path. All three are latent, with greps returning zero live instances across both trees."
