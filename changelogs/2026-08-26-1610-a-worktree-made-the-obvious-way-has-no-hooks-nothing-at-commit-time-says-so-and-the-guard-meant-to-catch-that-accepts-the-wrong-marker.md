description: "The provisioning routine in the ticket-worktree setup script does the right thing and the new entry says so in its opening line: it no-ops when the markers are already present, prefers a symlink to the install tree, falls back to copying the configuration file on filesystems where symlinking raises, warns when neither source exists, and then a fail-fast probe converts that final warn-and-continue into a hard error so a drive never proceeds with hooks disabled. None of the entry is a criticism of that code. The defect is that it is the only path that runs it. Creating a worktree with the plain git command is the obvious way, it is what the git documentation teaches, and it performs none of this, so the resulting worktree has no pre-commit configuration, every commit runs with the allow-no-config escape set, and the entire package hook suite is skipped in silence. Three worktrees created in one session, all by the same operator, all with the plain git command, all lacking the configuration. It surfaced only because one commit happened to refuse outright rather than proceeding; the other two would have committed clean with no hooks running at all. The cost is not hypothetical, because once the configuration was in place the acceptance-criteria guards on just one of those branches caught three real defects in a fifty-one record commit: a new record with no author attribution, eight missing parent back-links at the third tier of the hierarchy, and a side-effect declaration that disagreed with its own criteria. A second and separable defect is recorded in the same entry. The fail-fast probe's success condition is a disjunction, and the comment above it states that an install-tree symlink alone is a valid established state. It is not. The pre-commit tool reads a configuration file at the repository root and nothing else. This was observed twice in the same session: with the symlink present and correct, the commit still reported that no configuration file was found and began running hooks only once the file itself was copied in, and this workspace's install tree contains no such file for the symlink to supply. So the probe passes a worktree in which hooks are entirely disabled, which is a fail-open inside the guard written specifically to prevent a fail-open. The project's own documented check has the same disjunctive shape and therefore the same blind spot. The fix direction leads with detection at commit time rather than provisioning at creation time, on the grounds that provisioning only ever covers worktrees created the blessed way while a commit-time check covers every creation path including ones that do not exist yet, and it closes by ruling out the obvious non-fix: do not add a step to a checklist, because there already is one, it is marked mandatory, it carries both repair recipes, and it was missed three times in one session by an operator who had read it. Separately, this register's instructions for adding an entry now specify a date-and-slug identifier in place of appending the next free number. Existing numbered entries keep their identifiers and must not be renumbered, since inbound references would break. The sequential form requires every author to read the same file at the same moment and act on it before anyone else does, which fails under any parallelism at all; it produced ten collisions in a single day on 2026-08-25, one of which reached the main branch, and this register already carries two renumbering notes as scar tissue from earlier collisions. The remedy was diagnosed and named in an existing build-orchestration entry; this is the first record to adopt it. Both identifier forms sort and search identically on the shared prefix."
