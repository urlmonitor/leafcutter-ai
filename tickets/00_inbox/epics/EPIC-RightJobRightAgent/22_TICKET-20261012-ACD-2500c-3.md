## Implementation Notes

```yaml
- 'Extends the test_spec item schema in config/ac_store_schema.json with the per-entry
  keys the code-aware step writes (outcome clause proved, code file exercised, to-be-created
  flag, convention test file) and adds record-level provenance (authorship mark {step,
  date}, opened-files list). additionalProperties: false stays on test_spec items.'
- 'Builds ON the existing optional test_spec[].must_catch (TQ-500f-2, PR #911: non-empty
  list of non-blank strings, copied verbatim onto the ticket and kept identical in
  shape to config/test_requirements.schema.json) and the existing angle value ''discrimination''
  (TQ-500f-1). Neither is redefined, renamed or re-shaped here; the new per-entry
  keys are added alongside them.'
- 'The design-entry key set otherwise stays closed: any key the schema does not declare
  is rejected, naming the key, at every enforcement point (the check-ac-schema hook
  including its manual fallback, and validate_ac_schema.py).'
- 'Declaration rule (settled on the TQ side, 2026-09-27): the presence of must_catch,
  or of angle ''discrimination'', on a test_spec entry IS the test designer''s bug-fix/gate
  declaration. No new schema key is added for that declaration.'
- 'Writer rule: only the code-aware test-design step (ACD-2500c-1 / ACD-2500d-5) writes
  must_catch; the technical planner (it-po) never does.'
- 'Legacy test_spec (no provenance, no new keys) stays valid: the new keys are optional
  in the schema, and their presence on code-aware designs is enforced by ACD-2500c-1-i,
  not by the schema.'
- The ticket generator passes the new keys through or drops them without producing
  a ticket that violates config/test_requirements.schema.json (the two schemas are
  coupled by hand).
- Field rows are added to docs/reference/ac-schema.md in the same change.
- A by-author query in the store's existing reporting tooling returns code-aware designs
  by step and lists the rest as legacy.
- The commit-time check and validate_ac_schema.py read the one schema file and give
  identical verdicts.
```
