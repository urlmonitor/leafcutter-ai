## Implementation Notes

```yaml
- Keep, don't delete (resolves the conflict with TQ-500g-1-ix decision 2f). The write
  step's first filesystem action (today _wvw_write._clean) MOVES the alterations.json
  and copies/ an earlier preparation left in <git-dir>/leafcutter/work/<work-key>/
  into <git-dir>/leafcutter/work/<work-key>/history/<NNNN>/ (four digits, one more
  than the highest existing number, starting 0001), before the reply is read. Only
  a leftover alterations.json.tmp (a partial write, never a manifest) is deleted.
  The move is os.replace per item within the same filesystem; a move that fails stops
  the step with exit 1 and no new manifest, so the earlier manifest is never left
  at the current path. plan.json and the pin store are not moved.
- 'The TQ-500g-1-ix guard stays true: after the move no manifest remains at <git-dir>/leafcutter/work/<work-key>/alterations.json,
  so an unreadable reply leaves no manifest to be read in its place; the runner reads
  only the --alterations path finish hands it and never lists, searches or falls back
  to history/. Nothing in history/ is ever deleted, overwritten, rewritten or handed
  to the runner; the moved manifests keep their altered_copy paths as written (history
  is read-only evidence).'
- 'Identity in every row. The runner copies three additive keys from the manifest
  entry onto every result row of that wrong version: alteration_id (TQ-500g-1-xi:
  "sha256:" + 16 hex over the ordered replacements alone), source, and replacements
  ([{path, old, new}], so a reader sees each file, old text and new text). For "the
  fix undone" source is "fix undone", replacements is null, and alteration_id is computed
  by the same _wvp_store function over [{path, base content SHA-256}] of the restored
  files. Baseline rows (wrong_version "") carry null for all three. Rows keep test,
  wrong_version, result, blocking and detail unchanged.'
- 'Source vocabulary, one set across TQ-500g-1-xi, -xii, -xiii, -xvi and -xvii, written
  by the write step from the plan: "prepared: not pinned" (no pin held for the name),
  "pinned", "re-prepared: <reason>" (target changed, old text found N times, did not
  load, changes nothing, changes no line the tests naming it run, not in scope, pin
  reset by the operator), "declared". The runner never derives a source itself; it
  only copies it.'
- 'Retention: history/ is unbounded (BA decision; it lives under the worktree''s git
  directory and goes with the workspace). The write step logs at INFO the number of
  history folders it keeps, so growth is visible; no cap is added here.'
- 'Deterministic: the manifest content stays byte-identical for the same reply, plan
  and code (no run number or time inside it); only the history folder number depends
  on how many runs came before.'
- wrong_version_runner.py stays at or under 400 counted lines (at 309); the row-labelling
  helper lives in _wvr_verdict.py. No new module; nothing to add to any deploy list.
```
