## Acceptance Criteria

```gherkin
Given a reader who needs to know how a ticket comes to be recorded finished, and who has
  not read the drivers,
When they open the architecture documentation for the close of a ticket,
Then a sequence diagram is present that shows the close from the moment a drive decides a
  ticket is finished to the moment the recorded state changes,
  And every participant that can write the ticket's recorded state appears in it, so that
    a route which is not drawn is a route which does not exist,
  And the checking mechanism is shown reading the ticket's own record and deciding from
    what it read, not from what the caller passed it,
  And both drivers are shown -- the one that carries a whole epic and the one that carries
    a single ticket -- and both are shown reaching that same mechanism, so a reader can
    see whether the two have diverged,
  And the refusal is drawn as its own path, ending with the recorded state unchanged and
    the outstanding step named, rather than the diagram showing only the successful close,
  And the blanket override is drawn as a path that exists and is marked as absent from the
    ordinary close,
  And exactly one path in the diagram ends in the finished state being written, and that
    path passes through the checking mechanism,
So the diagram answers the question this feature exists to answer -- how many doors are
  there -- rather than only illustrating the happy path through one of them.
```
