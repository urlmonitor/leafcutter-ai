description: "Closes BO-2600a-2-i. Pointing the fast lane at BO-1500a-5 resolved a build set of fifteen criteria and attempted all of them in a single run and pull request. The cause is one absent token: the select_connected invocation in templates/workflows-js/fast-lane-ship.js omitted --exclude-structural-parent, so a depends_on entry naming a criterion's own structural L0/L1 parent was treated as a genuine prerequisite and expanded into that composite's entire not-done subtree, with every leaf added that way re-queued so hierarchy expansion and dependency hops alternated without limit. Reproduced against the real store both ways: fifteen ids without the flag, exactly three with it. The flag itself is not new. It landed in #409 under BO-2600a-1, and templates/agents/build-ac.md has passed it since; fast-lane-ship.js is the only other select_connected caller and never picked it up, across three subsequent edits to that file. The more useful finding is why that drift survived: BO-2600a-1 specified the resolver capability, BO-2600a-2 the CLI surface, and BO-2600a-3, -4 and -5 the build-ac consumers, but no criterion ever required the fast-lane consumer to pass the flag, so nothing could fail. BO-2600a-2-i is added to close that hole, which makes this a missing acceptance criterion rather than only a missing token. The default exclude_structural_parent=False in scripts/build_orchestration/fast_lane.py is deliberately unchanged, because BO-2600a-1 fixed that default as a backward-compatibility invariant and asserts it in its own test. Scale, measured by sweeping all 1,776 not-done leaf targets in the store through the shipped resolver: 1,560 of them, 88 percent, resolve to a strictly smaller set with the flag on; 95 targets exceed twenty criteria; the worst single case is TKT-500f-1 at fifty-six by default and one with the flag. The covering test is behavioural rather than a search for the flag in the source, which would pass against dead code and is disallowed for workflow criteria in this repository. It drives fast-lane-ship.js under the engine harness, captures the select_connected invocation the workflow actually composes at runtime, runs that captured command against a fixture store whose target names its own structural parent in depends_on, and asserts on the resolved id set. A negative control resolves the same fixture without the flag and asserts a strictly larger set containing the parent's other children, which ties the size difference to the flag rather than to an empty store or a load failure. Verified by reverting the one-token change and confirming the test returns to red, then restoring it and confirming green; 173 tests pass across every suite that references select_connected. One caveat is recorded rather than fixed: --exclude-structural-parent guards only the immediate structural parent of the node being expanded, so a criterion whose depends_on names a non-ancestral composite still triggers full subtree expansion. The flag is a strong mitigation, not a bound, and a real cap or an operator gate on resolved-set size remains the durable fix."
