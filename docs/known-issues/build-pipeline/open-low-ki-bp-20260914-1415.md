# KI-BP-20260914-1415 — a test asserts a literal string appears exactly twice in `build.py`'s source text, so relocating either function fails a fixture premise far from the cause

> One known issue, split out of `docs/known-issues/build-pipeline.md` on
> 2026-09-14. Index: [build-pipeline.md](../build-pipeline.md).
> Filename severity is the three-level index bucket (`low`); the
> original grading is the `**Severity:**` line below, unchanged.

- **Severity:** low — it fails loudly with an accurate message, and no wrong answer is produced
- **Status:** open
- **Occurrences:** 1 near-miss (2026-09-14, caught during the BP-1500g-1 headroom extraction)
- **Where:** `unit_tests/test_bp_900g_8_ii.py:778` — `original_build.count(_CORE_CONFIG_TUPLE_ANCHOR)` with `assert anchor_count == 2`

**What it does, and why it is defensible.** The test proves that `build.py`'s deployed-dependency
guard actually SEES a newly-declared core-config entry. Proving that requires adding a declaration
and re-running the build, and the cheapest honest way is to edit the declaration in source text.
It does this on a COPY, never the live repo, and it guards the edit with a count check so a
changed declaration shape fails loudly instead of silently replacing the wrong thing. The failure
message even says "update this test's anchor." None of that is wrong.

**The cost is coupling to physical file layout.** `assert anchor_count == 2` encodes that the
anchor appears once in `_get_source_deployable_scripts` and once in `_get_source_paths_for_guard`
— i.e. that both functions live in `build.py` and neither has moved. It is a structural assertion
wearing a fixture's clothes.

**The near-miss.** During BP-1500g-1, `build.py` was over the file-size ratchet and needed ~50
lines of headroom. `_get_source_deployable_scripts` was the natural extraction target and would
have made this premise false — a test in an unrelated suite failing on a refactor that has nothing
to do with its own AC. It was caught only because the coder ran a blast-radius check before
touching the function, and routed around it by extracting the ten `_manifest_*` helpers instead.
The extraction that shipped is therefore shaped partly by this test rather than purely by what
belongs together — recorded in `scripts/build_deploy_manifest_helpers.py`'s own docstring.

**Why this will recur.** `build.py` is permanently over the ratchet, so every future change to it
must shed lines, which means extraction is the standing remedy — and this test silently narrows
which extractions are legal. The interaction between the two guards is invisible from either side.

**Fix direction.** Drop the `== 2` and assert `>= 1`, then perform the replacement on every
occurrence — the test's real subject is "the guard sees a new declaration", which does not depend
on how many functions declare it or where they live. Alternatively, locate the declaration by
parsing rather than by literal text (`ast`), so a move is followed rather than fought. Either way
the loud-failure property should be kept; it is the good part.

**Related.** `GE-127a-1` / `GE-127b-1` (the ratchet that makes extraction mandatory) ·
`KI-CG-20260908-ratchet-reads-pre-merge-head` (same ratchet, different blind spot).

**Pattern:** two guards, each correct alone, whose constraints intersect in a space neither one
can see — so the only way to discover the conflict is to trip it.
