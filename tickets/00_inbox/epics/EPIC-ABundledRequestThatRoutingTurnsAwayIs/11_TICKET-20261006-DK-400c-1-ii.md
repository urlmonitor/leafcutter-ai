# A proposal with circular or unknown dependencies never reaches the gate

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `DK-400c-1-ii` — A proposal with circular or unknown dependencies never reaches the gate — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `DK-400c-1-ii`. Component: `decision-kernel`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a bundled goal waiting for its split proposal,
When the host proposes either three parts where p1 waits for p2 and p2 waits for p1, or parts
  where p3 waits for a part p9 that the proposal does not contain,
Then the proposal is not shown at the split gate and no part runs,
And the host's answer is refused with a message naming the circular chain "p1 -> p2 -> p1", or
  the unknown part "p9",
And the host may send a corrected proposal within the repair attempts allowed for any host
  answer.
```

- [ ] AC-1: the proposal is not shown at the split gate and no part runs
- [ ] AC-2: the host's answer is refused with a message naming the circular chain "p1 -> p2 -> p1", or
- [ ] AC-3: the host may send a corrected proposal within the repair attempts allowed for any host

## Implementation Notes

```yaml
- Dependency validation runs over the whole proposal before the quote check. A cycle
  (a self-dependency included) or a dependency on an id the proposal does not contain
  refuses the host answer with a message naming the cycle as 'p1 -> p2 -> p1' (ids
  in cycle order, first id repeated) or the unknown id; state is unchanged and the
  decompose_goal interaction stays pending. Duplicate part ids are refused the same
  way.
- 'Repairs follow the existing host repair rule: host.max_repair_attempts, with the
  packet returned in error.details.pending_interaction.'
- 'When the repair attempts run out the split is abandoned, never failed: no gate
  and no part; the subject goes on exactly as for fewer than two parts (DK-400c-3)
  by its trigger; the run''s limitations name the refused proposal and why; no host_only
  gap observation is recorded for the decomposition.'
- 'Tests enable splitting explicitly: split.enabled true through a config override
  (false only where a test compares with the off switch). None relies on the shipped
  default, which stays false until E3 merges (dec-9925ebf1895222f4, see DK-400a-1).
  A test asserting that no split starts must run with splitting on, or it passes for
  the wrong reason.'
```
