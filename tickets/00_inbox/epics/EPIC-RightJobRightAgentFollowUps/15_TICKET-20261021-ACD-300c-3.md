## Acceptance Criteria

```gherkin
Given the technical planner has enriched the AC batch and set readiness: reviewed,
  and the test-design stage has then completed for the batch,
When the workflow presents the final gate to the user,
Then it displays: all ACs in the batch with their enriched fields
  (assigned_agent, estimated_complexity, delivers_to, expects_from) and their test design,
And it prompts the user to set a priority (critical/high/medium/low)
  for the batch,
And it offers three actions:
  - "approve" — the approval is applied as ACD-300c-4 specifies: readiness: approved and
    the chosen priority on every AC the approval-hold report releases, held ACs stay
    reviewed; the pipeline completes successfully,

    (loop until approved),
  - "defer" — set readiness: reviewed but do NOT promote to approved;
    ACs stay in store but are not scanner-eligible,
And if the user approves, the workflow reports the count of ACs approved and the count held.
```
