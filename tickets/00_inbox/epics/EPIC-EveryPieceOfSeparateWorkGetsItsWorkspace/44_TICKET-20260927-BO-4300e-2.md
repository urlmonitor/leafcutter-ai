# Clearing a workspace answers at once and never waits for someone to say yes

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-4300e-2` — Clearing a workspace answers at once and never waits for someone to say yes — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-4300e-2`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given an unattended run, with no person available to answer questions, asks the
  workspace maker to clear two workspaces: "alpha", holding nothing that has
  not reached the shared project, and "beta", holding one unpushed commit and
  one uncommitted change, with no authorisation to lose work given,
When each clearing request is made,
Then each request ends with an answer without waiting for any input,
And "alpha" is gone completely,
And "beta" is refused, and the refusal names the unpushed commit by identifier
  and the uncommitted file by path,
And "beta"'s files and commits are identical before and after.
```

- [ ] AC-1: each request ends with an answer without waiting for any input
- [ ] AC-2: "alpha" is gone completely
- [ ] AC-3: "beta" is refused, and the refusal names the unpushed commit by identifier
- [ ] AC-4: the uncommitted file by path
- [ ] AC-5: "beta"'s files and commits are identical before and after.

## Implementation Notes

```yaml
- remove never reads stdin or prompts (finalize's teardown deadlock); it classifies
  unsent work with the BO-4100c-1 verdict -- commits on the workspace's branch reachable
  from neither origin/<branch> nor origin/main after a fetch, plus uncommitted and
  untracked changes -- and refuses UNSENT_WORK listing unsent.commits and unsent.files
  unless discard was authorised up front (BO-4300e-3).
- Deletion removes the whole folder (Windows extended-length path prefix where needed),
  runs no prune and changes nothing in the main checkout; the answer is ok only after
  a post-check finds nothing left at the location.
- The maker never reads stdin and never prompts; every decision it needs arrives as
  an argument of the request, so an unattended caller can never stall on it.
- Answers conform to the result contract delivered by BO-4300c-2 (one JSON object
  on stdout, status/code/exit mapping, workspace_path absent on every non-ok answer).
- Proof runs the DEPLOYED maker -- the copy an install delivers, resolved through
  the shared test locator delivered by BO-4300f-4 -- as a separate process against
  real temporary git repositories with a real bare hub. No mock of git, no import
  of the maker module, no grep of its source (CLAUDE.md 'Gate / Workflow ACs -- Verify
  Behaviorally, Not by Grep'); a test never falls back to the templates/ source copy.
- All temporary projects, hubs and workspaces live under the test's temp directory
  and run git with an isolated global and system config; afterwards the developer's
  own repository's branches, registered worktrees and local git config are unchanged
  (BO-4300f-4-i, F14, KI-TQ-012).
```
