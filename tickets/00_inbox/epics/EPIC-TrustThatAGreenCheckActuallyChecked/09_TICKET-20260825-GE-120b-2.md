# Checks obtain their prerequisites through one shared resolution path, not one private copy each

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-120b-2` — Checks obtain their prerequisites through one shared resolution path, not one private copy each — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-120b-2`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `L`. Complexity: `high`.

## Acceptance Criteria

```gherkin
Given the family of checks under the guardrail engine that today each carry their own
  project-root walk to locate the helpers, configuration, and data files they need,
When a check needs to locate any such prerequisite,
Then it obtains it from a single shared resolution facility rather than from its own
  private search,
And a check from which the private search has been removed entirely still resolves every
  prerequisite it declares when executed from a separate working copy — demonstrated by
  executing that check, not by inspecting it,
And every check registered in the hook manifest, executed from a separate working copy,
  resolves the prerequisites it declares or reports a could-not-check outcome per
  GE-120a-1; none of them silently reports success,
And a newly added check resolves its prerequisites from a separate working copy without
  contributing any new root-walking logic of its own.

Coverage note: the load-bearing clauses are the two that begin "executed from a separate
working copy" — they are covered by running the checks through the GE-120c-1 harness. A
test that counts occurrences of a resolution function name across the check sources
measures tidiness, not behaviour, and does not cover this criterion on its own.
```
