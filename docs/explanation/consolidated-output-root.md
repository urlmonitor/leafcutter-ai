# Why leafcutter puts all files in .leafcutter/

## The problem: mixed files

Before the consolidated output root, `build.py` scattered its artifacts across the consumer project:

- `.claude/agents/`, `.claude/skills/`, `.claude/commands/` — agent definitions
- `scripts/commit_guardian/`, `scripts/doc_compliance/` — hook scripts
- `.pre-commit-config.yaml`, `.gemini/`, `.antigravity/` — tool configs
- `docs/glossary.md`, `docs/vision.md` — generated documentation scaffolds

These leafcutter-owned files mixed with the project's own files. Running `git status` surfaced leafcutter artifacts alongside real project changes. A developer couldn't tell at a glance which files were "theirs" and which were generated.

## The solution: .leafcutter/

All `build.py` output artifacts now live under a single `.leafcutter/` directory at the project root. The internal structure mirrors the old scattered layout:

```
.leafcutter/
  agents/          (was .claude/agents/)
  skills/          (was .claude/skills/)
  commands/        (was .claude/commands/)
  hooks/           (was .claude/hooks/)
  settings.json    (was .claude/settings.json)
  scripts/         (was scripts/commit_guardian/, doc_compliance/, etc.)
  gemini/          (was .gemini/)
  pre-commit-config.yaml  (was .pre-commit-config.yaml)
```

## How tools still work: the shim layer

Claude Code expects agents at `.claude/agents/`. Pre-commit reads `.pre-commit-config.yaml` from the repo root. Gemini reads `.gemini/`. These paths can't be moved.

After writing everything into `.leafcutter/`, `build.py` runs an `install_shims()` step that creates pointers at the canonical paths:

- `.claude/agents/` -> `.leafcutter/agents/` (symlink)
- `.pre-commit-config.yaml` -> `.leafcutter/pre-commit-config.yaml` (symlink)
- `.gemini/` -> `.leafcutter/gemini/` (symlink)

On Linux and macOS, these are symlinks — transparent to all tools. On Windows, symlinks require Developer Mode; when unavailable, `build.py` falls back to file copies.

## Trade-offs

**Git posture is configurable.** The recommended default is to git-ignore `.leafcutter/` (treat it as a build artifact that's regenerated by `build.py`). This keeps the repo clean but requires running `build.py` after cloning. Alternatively, you can commit `.leafcutter/` for a zero-setup-after-clone experience.

Recommended `.gitignore` entry:

```gitignore
# leafcutter build output — regenerate with: python leafcutter-ai/scripts/build.py
.leafcutter/
```

**Windows caveat.** Symlinks on Windows require Developer Mode or admin privileges. Without these, `build.py` uses file copies instead. File copies mean two copies of every artifact on disk; they must be kept in sync by re-running `build.py` after any template change.

**User-curated files stay at project root.** Files that `build.py` creates once but the user then edits (vision.md, glossary.md, roadmap.json, ticket folders) are NOT moved into `.leafcutter/`. They stay at their original locations because they're user-owned content, not build artifacts.
