# Authoring agents update parent covered_by when creating a child AC

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `ACS-100i-5` — Authoring agents update parent covered_by when creating a child AC — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `ACS-100i-5`. Component: `ac-store`. Assigned agent: `llm-expert`. Estimated complexity: `S`.

## Acceptance Criteria

```gherkin
Given a requirement-authoring agent (business-analyst-v3, product-owner-v3,
  or it-po-v3) creates a new child AC file with id "ACS-100i-3",
When the agent writes the child AC YAML file to the feature folder,
Then in the same write batch the agent also updates the parent AC file
  (ACS-100i.yaml) to append "ACS-100i-3" to the parent's covered_by list,
And the parent file is not overwritten -- only the covered_by field is
  modified (existing fields and values are preserved),
And the child AC's depends_on field includes the parent AC ID ("ACS-100i"),
And if the parent's covered_by field already contains the child ID,
  the agent does not add a duplicate entry.
```
