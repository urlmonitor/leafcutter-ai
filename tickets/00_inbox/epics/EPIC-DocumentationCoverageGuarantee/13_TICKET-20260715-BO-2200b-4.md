# Generating a ticket from a doc-triggering AC injects both the writer and the verifier

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-2200b-4` — Generating a ticket from a doc-triggering AC injects both the writer and the verifier — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-2200b-4`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given the ticket generator building a ticket from a leaf AC whose classification
  triggers a documentation demand (per the BO-2200a policy),
When the generator injects `documentation-expert` into the ticket's agents map,
Then it also sets the ticket frontmatter flag `documentation_required: true`.
And it injects `documentation-verifier` into the same agents map with status `needed`.
And when the AC does NOT trigger a documentation demand, the generator sets neither
  `documentation_required: true` nor `documentation-verifier`.
```
