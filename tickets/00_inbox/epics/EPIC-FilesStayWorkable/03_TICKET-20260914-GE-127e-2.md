## Acceptance Criteria

```gherkin
Given two tracked files of a kind the size standard covers, holding different
  content, are both refused for their length in the same commit,
When the author reads the refusal,
Then the parts named for the first file and the parts named for the second are
  not the same set, and the division named for each is stated in terms of that
  file's own parts,
And given a single refused file is then rearranged so that its constituent
  parts are different while its measured length is exactly what it was before,
  and the same file is refused again,
When the author reads the second refusal,
Then the parts named and the division named have MOVED from what they were in
  the first refusal,
And given instead the refused file is copied byte for byte to a second path, of
  the same covered kind, and refused there,
When the author reads that refusal,
Then the parts named and the division named are the same as those named for the
  original — so what the author is told follows from the file's content and not
  from its name, its path, its kind, or the length it happens to measure.
```

```yaml
- 'NO PACKAGE SURFACE — MEASURED, NOT ASSUMED. WATCHED_REGISTRIES binds two containers
  on commit_guardian.json: hooks_manifest.hooks (by id) and the document''s own top
  level (by mapping key). This record adds neither — it registers nothing at all,
  because it adds no output and no configuration; it constrains what GE-127e-1''s
  description is COMPUTED FROM. `check-file-size` is already a manifest id and `file_size`
  is already a top-level key, both read in this worktree. Plain-list spec form, and
  no config_schema_fragment invented to satisfy the structured-spec validator.'
- THIS RECORD ADDS NO CODE PATH OF ITS OWN, AND THAT IS THE CONSTRAINT, NOT AN EXCUSE.
  There must be exactly ONE description function, the one GE-127e-1 builds, and it
  must take the refused file's CONTENT as its input. A second derivation path added
  to satisfy this record — a "content-aware mode", a per-file override, anything selected
  at run time — leaves GE-127e-1's path unconstrained and is the failure this record
  exists to prevent. The whole of the work here is that the single path reads content,
  plus the paired-run tests that prove it.
- 'NOTHING OUTSIDE THE FILE''S CONTENT MAY REACH THE DESCRIPTION. Not the path, not
  the file name, not the extension beyond choosing HOW parts are recognised, not the
  measured length, not the clock, not a per-run nonce, not a counter, not the position
  of the file in the staged set. The byte-identical-copy arm is what enforces this,
  and it is enforceable only if the description is a pure function of content: given
  identical bytes it must produce an identical description, every time, in any order,
  at any path. Make that determinism a property of the function rather than something
  the tests happen to observe.'
- KEYING ON THE MEASURED LENGTH IS THE SPECIFIC PROHIBITION, AND IT IS EASY TO DO
  BY ACCIDENT. Apportioning a fixed per-kind inventory across the measured length
  produces output that varies between files, looks derived, and is not — and it passes
  any single-run assertion. The rearrangement arm holds the measured length constant
  on purpose so that content is the only variable left. Do not let the length participate
  in selecting or naming parts; it participates only in the reconciliation arithmetic
  GE-127e-1 pins.
- 'THE PAIRED-RUN CONSTRUCTION IS BP-900c-4-i''s AND IS REUSED, NOT REINVENTED. That
  record already settles the epistemics for a guard whose remediation must be read
  from the input it describes: run the guard BEFORE and AFTER changing that input
  and require the advice to MOVE, because a hard-coded selector passes every single-run
  assertion. Follow it; do not invent a second construction, and do not weaken any
  arm here into an assertion about one refusal.'
- THE REARRANGEMENT FIXTURE MUST STATE ITS OWN LENGTH INVARIANCE. Construct the rearranged
  file so its measured length under count_content_lines is unchanged, and assert that
  invariance IN THE TEST from the gate's own quoted number rather than assuming it.
  If the counting rule GE-127d owns makes an exactly length-preserving rearrangement
  awkward, the fallback the BA permits applies — the advice must move further than
  the length does — but the fixture must report both numbers so a reader can see which
  case was exercised. A silently drifting length turns this arm into a test that a
  length-keyed implementation also passes.
- THE COPY ARM IS A REGRESSION FENCE AND MUST NOT BE WEAKENED TO MAKE THE OTHER TWO
  PASS. If an implementation cannot make the two moving arms red-then-green without
  also disturbing the copy arm, the description is not a function of content — it
  has acquired a second input. Resolve that by removing the second input, never by
  relaxing the copy arm to "similar" or "equivalent" advice. The two descriptions
  must be equal.
- 'Must follow the repo error-handling policy: specific-exception try/except around
  the file read and any parse; log at WARNING or higher or re-raise; no bare or blind
  excepts. Note the interaction with GE-127e-3-i: a parse failure on one of a pair
  of files must produce that record''s could-not-be-described state, never a fallback
  description that would silently satisfy this record''s arms with generic text.'
- CANONICAL VERSUS BUILD OUTPUT, AND THE BUILD IS PART OF THE CHANGE. Edit templates/scripts/commit_guardian/
  only — scripts/commit_guardian/ and the repo-root .pre-commit-config.yaml are untracked
  build outputs overwritten by build.py, and templates/commit-guardian/commit_guardian.json
  is a decoy. Re-run `python scripts/build.py --target-dir .`; config.py resolves
  the config beside the deployed script, so an unbuilt change leaves the running gate
  on the old behaviour.
```
