## Acceptance Criteria

```gherkin
Given the security allowlist contains the well-formed entry
  "ENTROPY_HIGH:src/config/foo.py:*",
And "src/config/foo.py" no longer contains any high-entropy token, because the
  value that entry was written for has since been removed,
When that file is scanned through the multi-file entry point with that
  allowlist in force,
Then no warning of any kind is emitted about that entry,
And the run's result is unaffected by its presence,
Because a suppression that outlives the problem it covered is not a mistake in
  the author's instruction — it is an instruction that is simply not needed
  today and may be needed again tomorrow.

Given the security allowlist contains the well-formed entry
  "GENERIC_SECRET:secrets.py:12",
And the run scans only "src/config/foo.py", so "secrets.py" is never looked at,
When the run completes,
Then no warning is emitted about that entry,
Because most entries have nothing to match in most runs — a single commit
  touches a handful of files — and reporting them would bury the warnings that
  identify a real mistake.

Given the security allowlist contains the entry
  "ENTROPY_HIGH:src/config/foo.py:*  # kept for the rotated token" alongside
  the two well-formed entries above,
And no file in the run produces any finding at all,
When the run completes,
Then exactly one warning is emitted, and it names the line carrying the
  appended note,
Because the distinction being drawn is between an entry that cannot match
  anything ever, which is knowable from the entry alone, and an entry that
  matched nothing this time, which is knowable only afterwards and means
  nothing on its own.
```

## Implementation Notes

```yaml
- The warning trigger is a property of the entry as read and must be computed before
  any file is scanned. It must not depend, directly or indirectly, on how many findings
  the entry went on to suppress.
- Do not accumulate per-entry match counts, hit flags or last-matched state for the
  purpose of warning. Introducing that state is what makes the rejected second signal
  cheap to add later by accident.
- The never-matched-this-run signal is explicitly out of scope. If it is ever built,
  it belongs on a separate, deliberately-run surface and must not be delivered through
  this commit-time warning.
- Reuse the single allowlist-diagnostic convention and keep it non-fatal; nothing
  in this criterion may change the scan's exit status.
- Edit the canonical template at templates/skills/security-scanner/scripts/scan_secrets.py
  and propagate with build.py; never edit a deployed copy (ADR-001).
- Tests must never create, modify or delete a .security-allowlist at any real project
  root, workspace root or worktree root; every fixture allowlist lives under tmp_path/tempfile.
- Fixture files must use ordinary source filenames — the per-file scan short-circuits
  environment-named files and never reads their content.
```
