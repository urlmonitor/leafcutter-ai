# Ordinary directories are not reported as leftover workspaces

## Actor / Goal

## Acceptance Criteria

```gherkin
Given a directory sitting where workspaces are created that carries none of a
  workspace's own identifying state -- an unrelated folder, or an empty one,
When the set of workspaces is listed,
Then that directory does not appear in the listing,
And the listing's entry count is unchanged by its presence or absence.
```

- [ ] AC-1: that directory does not appear in the listing
- [ ] AC-2: the listing's entry count is unchanged by its presence or absence.

## Implementation Notes

```yaml
- The discriminator for 'is a workspace' must be the presence of a workspace's OWN
  identifying state on disk (a linked worktree's .git file pointing at a gitdir under
  this repository), never the directory's name, its position in the listing order,
  or merely its being non-empty.
- 'Both shapes must be excluded: an unrelated POPULATED folder and an EMPTY one. An
  implementation that filters on emptiness excludes one and admits the other, and
  passes half of this record.'
- The entry count must be computed from the same pass that produces the entries, so
  a listing cannot hide a stray folder from the rendering while still counting it.
- A directory carrying a .git file that points OUTSIDE this repository is another
  project's worktree, not a leftover of this one. It must be excluded, or a shared
  parent directory turns every neighbouring project into a reported remnant.
```
