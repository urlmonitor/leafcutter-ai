## Implementation Notes

```yaml
- THE DESIGN NAME IS A SEPARATE NAMESPACE WITH A SEPARATE RESOLVER. `data-screen`
  values resolve against the PRODUCT-TRUTH store (mockup screen ids, reachable via
  docs/product-truth/index.json), not against the acceptance-criteria store. Do NOT
  route them through GE-124c-2-i's AC-id resolver — that resolver answers one question
  and must keep answering only that one. Two namespaces, two resolvers, and the finding
  codes must differ too.
- 'THE ATTRIBUTE IS READ BY THE SHARED READER IN THE SAME PASS as data-ac (GE-124b-1),
  and recorded on the pin/element record as screen_attr. The mock-data invariant binds
  them: AcDeclaration.screen_attr != null iff is_page_root, and it then equals its
  FrontendComponent.screen. One pass, two attributes, one record.'
- PAGE-ROOT IDENTIFICATION MUST BE STATED, NOT INFERRED FROM DEPTH. The reader has
  no DOM and no JS AST; 'the page root' must be a rule an implementer can apply to
  text — the recommended rule is the outermost element of the file's rendered markup
  in a file whose in-scope role is page-root, with the role itself derived from the
  application's routing convention (for Next.js, a file under app/ or pages/ that
  default-exports a route component). Whatever rule is chosen, record it, because
  GE-124f-1-i enforces its negative.
- ONLY THE FIRST HOP IS THIS AC'S WORK. The product-truth store already resolves a
  design to its flow step and on to the criteria the step implements (mockup.screen,
  step.screen, step.implements). Consume that existing resolution; do not re-implement
  the later hops. The chain record this AC emits is built-file -> design plus a reference
  into the existing chain.
- AN UNRESOLVABLE DESIGN NAME IS ITS OWN FINDING CODE, distinct from unresolved-ac-id
  and from missing-component-declaration. Same shape of defect (a stated name that
  resolves to nothing), different namespace and different remedy (register the design,
  or fix the typo). The scenario's typo `plant-lsting` is what the defect looks like
  in practice.
- 'SEQUENCING: GE-124b must land first. This AC must NOT re-specify the attribute
  mechanism — GE-124b owns data-ac and the reader; this AC adds one more attribute
  to an existing pass.'
- Must handle errors gracefully per the project error handling policy, and must announce
  rather than pass silently if the product-truth store cannot be read (GE-120's rule
  applies to this resolver too).
```
