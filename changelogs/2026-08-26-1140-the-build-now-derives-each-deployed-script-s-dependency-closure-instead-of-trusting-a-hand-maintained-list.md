description: "In a real consumer install, validate_ac_schema.py deployed and then raised ModuleNotFoundError for _ac_components, because build_ac_store's deploy_map is a hand-maintained list of eleven source-and-destination pairs and its helpers were not on it. The register's own assessment of that list is the design constraint this change was written against: it records the fourth recurrence of one failure mode, notes that five of the eleven entries carry a comment explaining why that specific module must not be forgotten, and concludes that a list needing a warning per entry is not a list but a trap with annotations. The remedy was therefore explicitly not to add the missing module. A new module, scripts/build_referential_integrity.py, derives each deployed script's intra-package dependency closure from what the script actually resolves — import statements, path construction relative to its own location, and sys.path mutation — computes that closure transitively so a chain correct at its first hop and broken at its second fails rather than passes, and exits non-zero naming the deployed script, the dependency it needs, and the deploy phase that would have to carry it. The hand-maintained list and its four warning comments are deleted; those deletions are the change rather than a loss. Separately, _manifest_ac_store_scripts in build.py now derives from the deploy map the build actually deploys from instead of scanning the source directory, which removes an over-claim of five files that were never deployed at all. Two review rounds each found something real. The first blocked on 248 lines of working, needed implementation sitting uncommitted and attested by no sign-off — the phantom-done pattern in a new shape — which is now committed and closes a sys.path.insert blind spot that previously produced zero log output at any level. The second verified rather than trusted, confirming the named work is present and unchanged in substance, and discharged the origin/main merge concern by demonstration rather than inspection: the two sides of the merge touched a disjoint set of files, seven on the branch and four hundred and thirty-two on main with an empty intersection, so no hunk could have been dropped. Two gate statuses were reconciled in the ticket record by the operator rather than by forged agent sign-offs, each with its evidence stated. pr-reviewer moved to signed off because it asked to be re-run after remediation, was, and cleared it. documentation-verifier moved to not needed because it was dispatched outside its own conditional: the agent is documented as conditional on a requires_documentation_verification field that is absent from this ticket, and BP-900g independently carries an empty documentation_triggers list with an explicit rationale that no user-facing surface is introduced. Its blocker was correct twice over, since the Agent Contracts line really was unparseable and it fail-closed rather than guessing, but repairing that line converts a parse blocker into a missing-document blocker for a document the acceptance criterion says must not exist. The pull-request phase refused to open the pull request at all while those two gates read failed and neither had re-run, which is the correct refusal and is the AR-200a-1 fix working end to end: the agent had a write tool, recorded its verdict with a full manifest, and the driver counted it outstanding rather than complete. Three items are carried forward without blocking: the sys.path lens handles insert and append but not extend or slice assignment, with the same silent empty-closure shape and no live instance anywhere the guard scans; one commit message claims a generality the code does not have; and generate_ticket_from_ac.py emits an Agent Contracts line that no fail-closed gate can parse when the parent acceptance criterion has no documentation triggers, warning at generation time and emitting it anyway."
