# Absent live_surface_testing block is treated as disabled (default false)

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-2100b-1-i` — Absent live_surface_testing block is treated as disabled (default false) — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-2100b-1-i`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `S`. Complexity: `low`.

## Acceptance Criteria

```gherkin
Given a project `skills_config.json` that contains NO `live_surface_testing` block
  at all (the key is entirely absent)
When enablement is evaluated — including PortRegistry._is_enabled() in
  scripts/port_registry.py
Then the capability is treated as DISABLED (safe default = false)
  And no port is allocated and no live-app check runs.
Note: this drives a known defect fix — PortRegistry._is_enabled() currently
  returns True when the `enabled` key is absent; the correct behavior is to
  default to false so an absent block never silently enables live testing.
```

## Implementation Notes

```yaml
- PortRegistry._is_enabled() must treat an absent live_surface_testing block, or an
  absent `enabled` key within it, as disabled (safe default false).
- When evaluated as disabled, no port may be allocated and no live-app check may run.
- A malformed or partial config block must be handled per the project error-handling
  policy (log at appropriate severity or raise a typed error) rather than defaulting
  to enabled or throwing on a missing key.
```
