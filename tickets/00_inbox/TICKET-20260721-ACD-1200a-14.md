## Acceptance Criteria

```gherkin
Given a ticket whose path is not under the worktree passed to the generator — for
  example a tickets-root located outside that worktree,
When the back-reference is written into the AC's implemented_by list by
  _write_implemented_by,
Then the recorded value is still a repo-relative path (for example
  tickets/00_inbox/epics/EPIC-.../NN_TICKET-....md) with no leading "/", no
  absolute filesystem prefix, and no "worktrees/..." or other per-checkout
  segment,
And the same AC records an identical repo-relative value regardless of which
  tickets-root or worktree location the ticket lives in,
And the repo root used for relativisation is derived canonically from the
  repository (git rev-parse --show-toplevel or the shared repo-root helper), and
  both the incoming path and every existing implemented_by entry are normalised
  through that same repo root rather than against the passed worktree directory.
```
