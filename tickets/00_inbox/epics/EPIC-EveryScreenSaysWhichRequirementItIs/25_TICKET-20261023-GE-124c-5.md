## Implementation Notes

```yaml
- PLACE AND NAME IT BY THE HOUSE CONVENTION. Author under docs/architecture/diagrams/
  as a c3-level sequence diagram, taking the next sequence number from scripts/next_diagram_seq.py
  rather than inventing one (GE-122 exists because unnumbered and colliding diagrams
  are an established drift shape in this repo). c3-done-proof-evaluation-sequence.md
  is the closest existing sibling and the shape to follow. It must satisfy check_diagram_naming,
  check_mermaid_complexity and check_mermaid_parent_link, and be linked from docs/architecture/components/commit-guardian.md.
- 'THE PARTICIPANTS ARE THE REAL ARTIFACTS: the staged set (git index), the in-scope
  decision (GE-124a-3), the shared declaration/pin reader module, the shared AC-id
  resolver entry point (GE-124c-2-i), and the commit. Naming real modules rather than
  abstract roles is what makes the diagram checkable against the code and reachable
  from it.'
- DRAW THE DOWNGRADE AS A REPLACEMENT, NOT AS AN ADDITIONAL OUTCOME. A downgrade drawn
  as an extra arrow invites an implementation where an opt-out finding sits beside
  a block finding, which the mock-data invariant forbids outright (verdict == 'block'
  implies suppression_reason == null). This is the single most consequential drawing
  decision in the diagram.
- PLACE THE DEDUPLICATION STEP AT THE POINT THE (subject, code) KEY IS APPLIED — before
  the verdict set is rendered and before the exit code is decided. A deduplication
  step drawn in the wrong place produces the double-report GE-124c-1-i rules out,
  and a diagram is the artifact people trust over prose when the two disagree.
- SHOW ALL FOUR VERDICT BRANCHES INCLUDING THE TWO QUIET ONES. Not-reported must be
  visibly a branch that leaves the sequence before any verdict is computed — not a
  pass arrow — or the diagram itself teaches the not-examined-is-passed conflation
  GE-124c-3 forbids.
- change_target stays `code` under the L0's tree-wide instruction; the deliverable
  is the diagram document.
```
