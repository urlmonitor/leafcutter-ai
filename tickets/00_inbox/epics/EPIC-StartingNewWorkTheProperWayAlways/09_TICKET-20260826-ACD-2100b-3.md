# An agent missing from the registry and an agent denied permission produce different reports

## Actor / Goal

## Context

## Acceptance Criteria

```gherkin
Given two runs that differ only in their agent registry -- the first registry is
  readable and interpretable and does not list the agent the route would use to
  create the authoring worktree; the second lists that same agent and withholds
  permission to run repository commands from it,
When the startup check runs in each,
Then the first run stops with a report that names the agent and states it was not
  found in the registry,
And the second run stops with a report that states the agent is listed and is not
  permitted to run repository commands,
And the two reports differ from each other,
And only the second report directs the reader at the permission setting to
  change.
```

- [ ] AC-1: the first run stops with a report that names the agent and states it was not
- [ ] AC-2: the second run stops with a report that states the agent is listed and is not
- [ ] AC-3: the two reports differ from each other
- [ ] AC-4: only the second report directs the reader at the permission setting to

## Implementation Notes

```yaml
- The change must land under templates/. The deployed workflow is build output.
- 'Fail closed in both cases: both runs stop. This L1 refines the reporting of the
  gate introduced by BO-1500f-1 (work_status: done) and must not supersede it -- a
  child that relaxes either halt to a warning is the wrong fix.'
- Only the denial outcome may name a permission setting. Naming it on the absence
  outcome sends the operator to audit an agent entry that does not exist and is the
  defect this record removes.
- Both reports must name the agent the check was looking for, taken from the value
  the check actually resolved rather than a literal in the message, so a change to
  which agent creates the worktree cannot make the report lie.
- The distinction must be established from the registry contents -- 'entry present'
  versus 'entry present and permission withheld' -- and not from a default applied
  when the lookup returns nothing.
- Must satisfy the repository error-handling policy.
- The denial case does not exist in the real registry (the worktree-creation agent
  carries permission today), so it must be constructible from a registry supplied
  to the run rather than requiring the project's own file to be edited.
```
