description: "The skill's written procedure had drifted from what this repository actually is, in four ways that a real run surfaced. It told the reader to record a branch from the current directory, but sessions here frequently start in an untracked workspace parent that is not a git repository at all, so there is no branch to record. It offered, on main, to warn and then commit anyway — but main is PR-only under the require-ci-lint ruleset, so confirming produced work that could never be pushed. It prescribed a flat six-field AC record, which the hierarchical store rejects outright, and said nothing about the two-axis component vocabulary, the L2 child cap of five, or the parent covered_by back-link that the guardian hooks read from the git index rather than from the store. It trusted a relayed pass/fail verdict, on precisely the run where pytest_ac_enforcement downgrades a failing test to xfail because the AC is new and therefore not done. And it had no changelog phase at all, so every quick-fix pull request was born failing a required status check. Isolation is now conditional rather than absent: an existing worktree on a non-default branch is still used in place, unchanged. Otherwise the workflow calls the canonical script, which also bootstraps pre-commit into the new worktree — a hand-rolled git worktree add gets none of that and silently skips all forty-nine package hooks. A mandatory staleness gate runs first, because create-only roots its branch at local main rather than origin/main, alone among that script's subcommands. Three surfaces changed together, which matters because the command invokes the workflow script first and falls back to the skill only on older installs: a prose-only change would have documented behaviour that never happened. Two live defects were found during the work and fixed rather than written into the specification. The test-runner result carried only a boolean, so a collection error, ImportError or empty selection reported as not-passed and the red phase read a test that never executed as a healthy baseline before applying a fix to it; the result now carries a three-state outcome checked before the boolean. And the green phase ran only the newly written test, so a fix that repaired its own test while breaking a neighbour reached commit unchallenged; a related-test pass now runs between green and commit, selecting by import or reference rather than by directory co-location, since co-located neighbours may never touch the changed code while the callers that regress usually live elsewhere. A third defect was left as an open gap rather than silently built: duplicate-AC detection is specified and marked done but has no implementation. Separately, the component fallback was removed — a target file matching no directory pattern now stops and asks instead of defaulting to build-pipeline, a real component that would otherwise absorb another's criterion into a permanent file. The record of that cost is in this repository: BP-600f.yaml was created misfiled by a live quick-fix run and stayed wrong for six weeks. Its covering test had been loosened to accept the defaulting behaviour it was meant to forbid. Fourteen BP-600 criteria were amended in place, per the store's documented amendment convention rather than supersession, which is reserved for replacement under a new id. Clauses that remained true were kept, including the prohibitions on dispatching worktree-agent and on hand-rolling a worktree; a ticket-file artifact promised by five records and never built by any implementation was removed with its history recorded rather than erased. Test coverage moved from eighteen assertions that grepped the workflow source to twenty-four that drive it under the E2 engine harness and assert on dispatch order, on the terminal payload, and on values threaded between phases. The difference is not stylistic: a grep for setup_ticket_worktree.py passes against an isolation branch disabled with if (false && ...), which is exactly the mutation used to verify the new tests. Disabling the isolation branch turns six red, the related-test guard one, the runner-error guard one; restoring each returns green. Full suite 3729 passed. The strict-enforcement flag was required throughout, and printed its own justification during the mutation runs: NOT masked (AC_ENFORCE_STRICT=1); reported as a real failure."
