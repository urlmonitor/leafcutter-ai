# The internal test-support endpoints never ship to production

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `UXP-610` — The internal test-support endpoints never ship to production — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `UXP-610`. Component: `ux-prototyping`. Assigned agent: `frontend-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a production build of the Atlas,
When the build is produced and served,
Then the CI-only helper endpoints /api/drift-guard and /api/mock-toggle-check are not compiled
  into the production build,
And a request to either path on a production deployment returns a not-found response,
So a public deployment cannot be probed through them.
```

- [ ] AC-1: the CI-only helper endpoints /api/drift-guard and /api/mock-toggle-check are not compiled
- [ ] AC-2: a request to either path on a production deployment returns a not-found response

## Test Requirements

  framework: vitest

## Implementation Notes

```yaml
- The /api/drift-guard and /api/mock-toggle-check route handlers under leafcutter-web/app/api/
  must be excluded from the production build via build-time gating (e.g. leafcutter-web/next.config.mjs
  route gating / conditional compilation), not merely returned early at runtime, so
  the handler code is not compiled into the production bundle.
- On a production deployment a request to either path must return a plain not-found
  response and disclose no filesystem paths, stack traces, or internal detail (see
  UXP-610-1).
- The gating must key off the same single production-detection signal used elsewhere
  in mock mode (UXP-608-3), so production presence/absence of the endpoints is consistent
  and testable.
```
