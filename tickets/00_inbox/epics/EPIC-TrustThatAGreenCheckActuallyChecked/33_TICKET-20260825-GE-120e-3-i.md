## Acceptance Criteria

```gherkin
Given a differential pair in which both arms raise no objection,
When the verification evaluates that pair,
Then it accepts the pair as evidence only when the same check, in the same verification
  run, is also shown objecting to content the author did introduce,
And a pair whose two arms agree without that control present is reported as inconclusive
  and the verification reports a failure,
And a check that has been switched off, or that has been given no change set at all,
  causes the verification to report a failure rather than a run of agreeing pairs,
And the inconclusive report names the check and states that the control was missing, so it
  is not read as a passing pair.

Coverage note: demonstrate by switching off the check under test and asserting the
verification fails. A verification that cannot be made to fail is not evidence — the same
standard GE-120c-1 sets for its harness. Asserting only that today's pairs agree is the
always-green assertion this whole tree exists to eliminate.
```

## Implementation Notes

```yaml
- THE CONTROL IS A PROPERTY OF THE VERIFICATION, EVALUATED PER CHECK PER RUN. Implement
  it once in the pair evaluator so every check added to the sweep inherits it, rather
  than as a per-check assertion each future author must remember.
- 'THE CONTROL MUST BE LIVE, IN THE SAME RUN, ON THE SAME CHECK: the check observed
  objecting to content the author actually introduced. A control read from a previous
  run, a recorded snapshot, a fixture file or a hard-coded expectation does not count
  — a stale control agrees with a disabled check just as happily as two silences do.'
- 'SELF-DEMONSTRATION IS A DELIVERABLE. Two states must be shown to make the verification
  fail: (a) the check under test switched off, and (b) the check handed no change
  set at all. Both produce a run of perfectly agreeing silences, which is exactly
  what every mis-implementation of this L1 looks like.'
- INCONCLUSIVE IS A FAILURE, NEVER A SKIP AND NEVER AN XFAIL. This repository has
  a recorded history of xfail-masked AC enforcement that made CI under-report failures;
  an inconclusive pair recorded as a skip is that failure mode reintroduced at the
  point it matters most.
- THE INCONCLUSIVE REPORT MUST BE VISUALLY DISTINCT FROM A PASS and must name the
  check and state that the control was missing. Two silences printed in the same form
  as a verified pair is the whole defect at the reporting layer.
```
