# Architecture Docs Folder Layout

Reference for what belongs in each subdirectory of `docs/architecture/`, which files in
this repo's own tree are currently misplaced relative to that layout, and what a fresh
consumer install must scaffold so every namespace root the commit-time uniqueness gate
depends on actually exists.

---

## Scope note — deliberately narrower than the future numbering-rules doc

This document covers **physical folder layout only**: what subdirectory a file belongs
in, and what `build.py` / `--seed-docs` must create so those subdirectories exist. It
does **not** state the numbering rules themselves — identifier shape, the free-number
lookup algorithm, the never-reuse rule, or the enrolment table deciding which documents
must take a number at all. That content is reserved for `docs/reference/artifact-numbering.md`
(not yet created — tracked under GE-122a-3 / GE-122b-4 / GE-122d-5). Once that file
exists, this doc will link to it directly; until then, treat any mention of it below as
plain-text pointer only.

---

## Namespace roots the uniqueness gate depends on

`check_identifier_uniqueness.py` (see
[ADR-037](../architecture/adrs/ADR-037-whole-collection-uniqueness-pass.md)) treats four
numbered namespaces as first-class and hardcodes their roots:

| Namespace | Root | Resolved by |
|---|---|---|
| `acceptance-criteria` | `docs/acceptance-criteria/` | scanned directly |
| `decisions` | `docs/architecture/adrs/` | scanned directly |
| `diagrams` | `docs/architecture/diagrams/` | hardcoded in `check_identifier_uniqueness.py` (`root / "docs" / "architecture" / "diagrams"`) |
| `work-items` | `tickets/` | via `tickets/ticket_lifecycle.json` |

Two of these four roots — `adrs/` and `diagrams/` — are not reliably scaffolded for a
fresh consumer install today. This is tracked as an open, high-severity known issue: see
[KI-BO-4 — `build.py` does not scaffold two of the four namespace roots](../known-issues/build-orchestration.md#ki-bo-4-buildpy-does-not-scaffold-two-of-the-four-namespace-roots).
This document is the design answer that known issue is waiting on.

## Survey of `docs/architecture/` in this repo (snapshot as of 2026-08-25)

### Top level

| File | flight_level | diagram_type | Numbered? |
|---|---|---|---|
| `agent_knowledge_plane.md` | `L2-Container` | `data_flow` | No |
| `agent_delivery_workflows.md` | `L3-Component` | `agent_flow` | No |
| `agent_knowledge_system.md` | `L2-Container` | `agent_flow` | No |
| `feedback-lifecycle.md` | `L3-Component` | `dataflow` | No |

No `README.md` or `FRONTMATTER.md` lives at `docs/architecture/` root in this
self-hosted repo — those exist only as consumer-facing seed templates under
`templates/docs/architecture/`.

**Finding.** All four files above carry `flight_level` and `diagram_type` frontmatter.
By the project's own frontmatter schema (see `templates/docs/architecture/README.md`'s
Frontmatter Quick Reference), that makes them diagram documents — yet they live outside
`docs/architecture/diagrams/` and carry no `c{level}-{seq}` filename prefix. A grep found
roughly 142 references to these four filenames across the repo (other docs, tickets,
agent cards, and other diagrams' `related_docs:` / `children:` frontmatter lists).

**Recommendation: do not move these four in this pass.** Flag them as a known
pre-existing inconsistency for a future, dedicated migration decision. This mirrors the
same reasoning GE-122e's binding scope decision already applied to the unnumbered
population of `diagrams/` itself (see below): an absent number or a misplaced-but-linked
file is not ambiguous and breaks no reference today, while a rename risks exactly the
dangling-reference damage the numbering-repair work exists to avoid. No ticket ID is
proposed for this here — it is future work, not part of this scaffold design.

**This 11-file population is a BINDING, DELIBERATE, PERMANENT exemption**, decided by
the user (BrainCandy) at the PO gate on 2026-08-17, recorded in
`docs/acceptance-criteria/guardrail-engine/GE-122-numbers-mean-one-thing/GE-122e.yaml`
and `GE-122b.yaml`: these files are not retro-numbered, not renamed, not moved, ever,
under this work. This is the single most important "do not touch" fact in this document
for both the implementing coder and the AC author.

**Identifier namespace.** The diagrams identifier is the pair `(level, sequence)` read
from the filename regex `^c(\d+)-(\d+)-.*\.md$` — source: `_DIAGRAM_FILENAME_RE` in
`templates/scripts/commit_guardian/_uniqueness_scanners.py`, matching the same allocator
regex used by `scripts/next_diagram_seq.py`'s `_SEQ_RE` (`^c([1-4])-(\d{3})-`). Two files
collide when they resolve to the same `c{level}-{seq}` string (e.g. two files both named
`c2-004-*.md`) regardless of slug. Files that do not match the regex at all — including
all 11 files above, plus any component/ADR/index file — are invisible to the uniqueness
scan by construction. That is a separate, different promise (whether a document is
*required* to take a number at all), owned by the not-yet-built GE-122b enrolment work.
It is noted here for context only; this document does not restate its rules.

### `docs/architecture/components/`

26 descriptively-named files, no numeric identifier at all, each describing one system
component. These are, and should remain, entirely outside the `diagrams/` numbering
namespace — they are the canonical example the project's own (not-yet-built) enrolment
rule cites as an exempt location, precisely because no allocator exists for
component-description documents (only for the diagrams location).

## Purpose of each directory

| Directory | Purpose | Filename convention | Identifier / allocator |
|---|---|---|---|
| `docs/architecture/adrs/` | One Markdown file per Architecture Decision Record. | `ADR-NNN-<slug>.md` | Integer, contiguous, never reused even for a retired ADR (see [ADR-029](../architecture/adrs/ADR-029-adr-number-collision-prevention.md)). `README.md` is a generated index; `ADR-template.md` (seeded from `templates/docs/architecture/adrs/ADR-template.md`) is the authoring starting point. |
| `docs/architecture/diagrams/` | One Markdown file per C4/sequence/ERD/state/dataflow diagram authored via the `write-c4-diagram` skill (`templates/skills/write-c4-diagram/SKILL.md`). | `c{level}-{seq:03d}-{slug}.md` | Pair `(level, seq)`; `level` is the C4 tier digit 1-4, `seq` is a zero-padded 3-digit number allocated by `scripts/next_diagram_seq.py` (max-existing-plus-one, scanned recursively under `docs/architecture/`, so it already accounts for files physically inside `diagrams/`). |
| `docs/architecture/components/` | One Markdown file per system component, descriptive prose + structure, no numbering. | descriptive slug, no prefix | None — not part of any numbered namespace. |

### `write-c4-diagram` skill summary (grounded in `templates/skills/write-c4-diagram/SKILL.md`)

- **Flight-level decision tree** (Section 2): a 5-question tree selects
  `L1-Context` / `L2-Container` / `L3-Component` / `L4-Code`, taking the first `YES` in
  order. L3 further branches by `diagram_type`: `sequence`, `state`, `erd`, `dataflow`,
  or plain `component`.
- **Filename convention**: `c{level}-{seq:03d}-{slug}.md`, where `{level}` is the C4 tier
  digit 1-4 and `{seq}` is the zero-padded 3-digit sequence from
  `scripts/next_diagram_seq.py`.
- **Format rule** (Section 3): Mermaid only. PlantUML, draw.io, Structurizr, hand-drawn
  SVG, and inline ASCII are unconditionally banned except one documented escape hatch
  (a `>15`-lifeline sequence diagram, requiring explicit user approval before falling
  back to PlantUML).
- **Single-concept rule** (Section 2a): a diagram must cover exactly one concept, flow,
  or boundary; split by distinct actors, distinct temporal phases, or distinct bounded
  contexts.
- **Bidirectional parent/child linking** (Section 6a, mandatory): a prose `Parent:` line
  immediately after the first mermaid fence, plus the parent doc's `children:`
  frontmatter list updated to include the new file. Both directions are enforced by the
  `check-mermaid-parent-link` hook.
- **Collision definition**: two diagrams collide when they resolve to the same
  `(level, seq)` pair in the filename — independent of slug or file content.

## What a fresh consumer install should get

**Design decision.** An existing-but-empty root passes the uniqueness gate cleanly by
contract: `check_identifier_uniqueness.py`'s namespace scan reports
`passed=True, inspected_count=0` for a real, resolved, empty directory (2026-08-25 fix,
recorded in that module's DECISION HISTORY — "a root that EXISTS as a real, empty
directory... still passes cleanly"). A **missing** root, by contrast, is a fail-closed
blocking misconfiguration. Because git cannot commit an empty directory, both `adrs/`
and `diagrams/` need a placeholder file the moment `build.py` runs — **not** gated
behind the opt-in `--seed-docs` flag, since the uniqueness gate must be safe to register
for every consumer, including ones who never run `--seed-docs`.

| # | Root | Recommendation |
|---|---|---|
| 1 | `docs/architecture/adrs/` | Already has a seed source (`templates/docs/architecture/adrs/README.md` + `ADR-template.md`). Recommend `build.py`'s BASE install path (not just `--seed-docs`) guarantee at least `README.md` exists — matching how `docs/acceptance-criteria/` already gets an unconditional `README.md` + `index.yaml` per KI-BO-4's own comparison. |
| 2 | `docs/architecture/diagrams/` | Needs a **new** `templates/docs/architecture/diagrams/README.md` template (does not exist today) so the directory has content to seed unconditionally. Draft below. |
| 3 | `config/paths.json` | Add `docs.architecture_diagrams: "docs/architecture/diagrams/"` to the `paths.docs` object. Verified by direct read: no such key exists today — only `architecture`, `architecture_adrs`, and `architecture_components` / `architecture_components_optional` are present. Mirror the existing `architecture_adrs` entry: **non-optional**, since the gate hard-requires the root to exist. Do NOT mark it `_optional` — `architecture_components` is optional because nothing fails without it; `diagrams` is not, per KI-BO-4. |

### Draft: `templates/docs/architecture/diagrams/README.md`

```markdown
---
title: "Architecture Diagrams"
type: reference
status: active
created: YYYY-MM-DD
last_updated: YYYY-MM-DD
components: []
---

# Architecture Diagrams

This folder holds one Markdown file per C4/sequence/ERD/state/dataflow diagram,
authored via the `write-c4-diagram` skill.

## Filename convention

`c{level}-{seq:03d}-{slug}.md`

| Segment | Meaning |
|---|---|
| `{level}` | C4 tier digit: `1` Context, `2` Container, `3` Component, `4` Code. |
| `{seq}` | Zero-padded 3-digit sequence, allocated by `scripts/next_diagram_seq.py`. |
| `{slug}` | Lowercase, hyphen-separated, 3-6 words. |

Two files collide when they resolve to the same `c{level}-{seq}` pair, regardless
of slug.

## Allocating the next number

Run `scripts/next_diagram_seq.py` before creating a new diagram — do not guess
the next sequence number by hand.

## Full numbering rule

The complete identifier-shape rule, free-number lookup, and never-reuse policy
live in `docs/reference/artifact-numbering.md` (once that document exists).

See also `docs/architecture/README.md` and the `write-c4-diagram` skill.
```

This draft is 38 lines, well under the repo's mechanically-enforced `check-doc-length`
gate on `docs/**/*.md`.
