## Implementation Notes

```yaml
- 'THREE INPUT SHAPES, THREE CODE PATHS, ONE OUTCOME: a marker with no value at all,
  a value that is a placeholder token, and a value that is only whitespace. An implementation
  that checks ''is the key present'' passes the first; one that checks ''is the string
  non-empty'' passes the second and third. Cover all three explicitly.'
- THE PLACEHOLDER LIST IS SHORT, CASE-INSENSITIVE, AND EXPLICIT — at minimum n/a,
  na, none, tbd, todo, -, ?, x — held as a named constant so it can be extended by
  a reviewer rather than rediscovered in a regex. Do not attempt to judge whether
  a longer reason is a GOOD reason.
- 'DELIBERATE NON-REQUIREMENT: no minimum length, no required author name, no required
  date. A quality bar the check cannot judge would be theatre; the visibility of the
  reason in the diff is what makes it accountable, and a reviewer is the judge of
  whether it is a good reason. Do not add a length threshold.'
- THE REFUSAL IS EXPLAINED, NOT SILENT. The report must state that an opt-out was
  found and refused for want of a reason — distinct from the plain missing-declaration
  message, because the author's next action is different (write a reason, not add
  a declaration). An author who typed the marker and meant to fill it in must be told.
- A REFUSED OPT-OUT LEAVES THE VERDICT AT BLOCK; it does not fall through to warn
  even if the path happens to be warn-listed. Precedence when both are present is
  GE-124d-3's; this AC only requires that a refused reason contributes nothing.
```
