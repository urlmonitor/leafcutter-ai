# A blocking style check runs on every web-app pull request and fails on any style-rule violation

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BP-1400b-1` — A blocking style check runs on every web-app pull request and fails on any style-rule violation — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BP-1400b-1`. Component: `build-pipeline`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given the continuous-integration configuration for the repository,
When a pull request is opened or updated with one or more changed files under
  the web-app directory (leafcutter-web/),
Then a dedicated web-app style check runs automatically over the web-app code,
And the check reports a failing (non-passing, blocking) result whenever a
  changed web-app file violates a style rule,
And the check reports a passing result only when the web-app code satisfies
  every style rule,
And the check is a hard, blocking check — not an advisory or informational one
  that a pull request can be merged despite.
```

- [ ] AC-4: the check is a hard, blocking check — not an advisory or informational one

## Implementation Notes

```yaml
- Add a NEW web-app style job to .github/workflows/ci.yml, distinct from the build/type-check
  job (BP-1400a-1). The job MUST run `next lint` (the leafcutter-web/ `lint` script
  — Next.js ESLint with eslint-config-next, already a devDependency) in the leafcutter-web/
  working directory after `npm ci`.
- 'The job MUST be blocking: do NOT set continue-on-error — any style-rule violation
  fails the job and the check. Reuse the SAME leafcutter-web/** paths filter as BP-1400a-2
  so it runs only on web-app changes.'
- Pin a stable `name:` on the job; this name is the cross-AC contract added to the
  required-status-checks list by BP-1400a-4. Match ci.yml conventions (actions/checkout@v4,
  actions/setup-node with npm cache, runs-on ubuntu-latest, pull_request targeting
  main + push to main).
- 'PREREQUISITE: `next lint` must already pass clean on the current leafcutter-web/
  tree before the check is made blocking, or every web-app PR is blocked. Verify a
  clean baseline first (analogous to BP-1200a-1).'
- Prepare-step (npm ci) failures must fail the job loudly (non-zero exit), not skip
  to a misleading green.
```
