# Recovery is non-destructive by default: it prints exactly what it will do and only acts on explicit confirmation

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-1600d-2` — Recovery is non-destructive by default: it prints exactly what it will do and only acts on explicit confirmation — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-1600d-2`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given the human has started the recovery entry point against a damaged shared
  repository
When recovery runs without an explicit execute confirmation (the default, dry-run-first mode)
Then it prints the exact ordered list of actions it would take — naming each
  specific target (for example "remove 3 zero-byte loose objects: <listed paths>",
  "re-fetch objects from origin", "reset branch <name> to reflog entry <ref>",
  "rebuild the index cache-tree") — and makes no change to the repository
And it exits after printing the plan, having performed zero git writes, so a reader
  can review the plan before anything happens
And only when the human supplies the explicit execute confirmation (an execute flag
  or an interactive yes) does recovery carry out the printed actions
And the set of actions actually executed matches the plan that was printed for that
  same repository state — recovery does not execute an action it did not first show
```
