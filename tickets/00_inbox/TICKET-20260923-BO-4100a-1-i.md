# Commits sitting only on the machine's local copy never reach the new workspace

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-4100a-1-i` — Commits sitting only on the machine's local copy never reach the new workspace — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-4100a-1-i`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `S`. Complexity: `low`.

## Acceptance Criteria

```gherkin
Given the machine's local copy of the main line carries two commits that are
  not present on the shared main line,
When a workspace is created,
Then the commit the new branch is rooted at is the shared main line's tip,
And neither of the two local-only commits is reachable from the new branch,
And the machine's local main-line copy is left unchanged by the creation.
```

- [ ] AC-1: the commit the new branch is rooted at is the shared main line's tip
- [ ] AC-2: neither of the two local-only commits is reachable from the new branch
- [ ] AC-3: the machine's local main-line copy is left unchanged by the creation.

## Implementation Notes

```yaml
- Creation must not write to the machine's local main ref, its reflog, its index or
  its working tree. Fetching into remote-tracking refs is permitted; fast-forwarding,
  resetting, merging or checking out local main is not. That mutation is the cheap
  wrong fix this record exists to forbid.
- Whether a local-only commit reached the workspace is decided by reachability from
  the new branch, not by comparing commit counts, messages or dates -- those agree
  with the wrong implementation.
- Both the canonical template and its scripts/ build output must carry the change
  (ADR-001).
- The no-mutation guarantee holds for every creation path, including the reconnect/reuse
  path where an existing branch is checked out rather than freshly cut.
- This record is a deliberate, operator-approved reversal of the 2026-05-12 18:30
  DECISION HISTORY entry in setup_ticket_worktree.py ('Fixed silent stale-worktree
  bug. Changed _create_worktree() to branch from local main instead of origin/main
  so that unpushed commits on local main -- e.g. the ticket-creation commit from /create-ticket
  -- are always included. Fixes TICKET-20260512.'). That fix protected /create-ticket,
  which is retired under ADR-012; the workflow it protected no longer exists, and
  this record forbids exactly the behaviour it introduced. The implementer must add
  a new DECISION HISTORY entry to setup_ticket_worktree.py recording this deliberate
  reversal and citing both TICKET-20260512 and ADR-012, so the two entries read as
  a documented supersession rather than a contradiction.
```
