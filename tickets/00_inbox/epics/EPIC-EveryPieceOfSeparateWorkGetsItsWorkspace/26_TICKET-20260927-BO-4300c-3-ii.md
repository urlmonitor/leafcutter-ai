## Acceptance Criteria

```gherkin
Given the agent asked to obtain the workspace declines, stating that the task is
  outside its role,
When the workflow receives the decline,
Then the workflow ends with a failure that names the decline,
And it does not send a different command in place of the one declined,
And no later step is dispatched.
```

## Implementation Notes

```yaml
- A decline (the agent states the task is outside its role) is a failure naming the
  decline; the workflow never re-sends a different command, to the same or another
  agent, in its place (the incident's step 3-4).
- Proof runs the workflow under unit_tests/_workflow_engine_harness.py -- the deployed
  copy the build produces, so the build's workflow transform is exercised -- with
  label-scripted agent replies, and asserts on the RECORDED dispatch list, never on
  workflow source text. The harness must be able to model a workspace step that declines
  its task, answers in prose, answers exit 0 with a non-JSON path, or answers JSON
  without status (F13); extending the harness for this is in scope of the first AC
  that needs it.
- Workflow edits are made in templates/workflows-js/*.js and reach .claude/workflows/
  only through the build; the deployed copy is what the tests run.
- 'HARNESS DEFAULT (duplication audit C2 item 11, KI-BO-009): unit_tests/_workflow_engine_harness.py''s
  agent() stub today answers any unscripted dispatch with {status: ''ok'', exit_code:
  0, passed: true, ...}, so a workflow that mishandles a refusal is never exercised.
  The default must stop being a success: a dispatch with no scripted reply either
  returns an error-shaped reply (status ''error'', naming the unscripted label) or
  fails the test loudly; in both cases the harness result records the unscripted dispatch
  so a test can assert on it. A success reply is only ever returned because a test
  scripted it.'
- The harness must be able to script, per label, a refusal (the agent declines as
  outside its role), a prose paragraph, a non-JSON reply (including exit 0 with a
  bare file path), and JSON without status -- delivered to the workflow in the shape
  the real engine delivers them, not pre-parsed into an ok object.
- 'Blast radius: every existing harness-driven test that relied on the ok default
  must script its replies explicitly (the existing script-specific defaults in _default_label_responses_for_script
  / _default_args_for_script are scripted replies and may stay). The ticket for this
  record lists the tests that changed; no test is skipped or xfailed to absorb the
  change.'
```
