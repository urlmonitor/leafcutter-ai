# 03: Wire llm-expert into registry and docs

## Goal

Register the llm-expert agent in `config/agent_registry.json`, add it to ticket-supervisor's spawn_allowlist, and document it in the agents README.

## Context

Stub generated by create-epic. Harden with create-ticket (depth 2).

The llm-expert agent must be discoverable and dispatchable by the ticket-supervisor. This ticket wires the agent into three places:
1. `config/agent_registry.json` — the agent registry (with tier, role, trigger conditions, skills, spawn_allowlist, spawned_by)
2. `ticket-supervisor`'s spawn_allowlist in the registry — to declare that ticket-supervisor may invoke llm-expert
3. `docs/agents/README.md` — the agent table in the phase agents section

The registry entry must declare:
- `id: "llm-expert"`
- `tier: "phase"` (it's a ticket-phase agent like python-coder, not a utility like research-agent)
- `role: "authoring"`
- `portable: true`
- `is_ticket_phase: true` (so ticket-supervisor recognizes it as dispatchable)
- `default_status: "not_needed"` (so existing tickets are unaffected until explicitly opted in)
- `spawn_allowlist: ["research-agent"]` (llm-expert may spawn research-agent for cross-file search)
- `spawned_by: ["ticket-supervisor"]` (ticket-supervisor spawns llm-expert)
- `skills_used: ["add-agent-to-package", "add-skill-to-package", "signoff"]`
- `trigger_conditions` with DSL rule matching files_touched patterns for agent/skill templates
