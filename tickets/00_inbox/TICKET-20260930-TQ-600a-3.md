## Implementation Notes

```yaml
- THE RECORD MUST BE TAKEN BEFORE ANY CONSUMER RUNS. Capture it immediately after
  the single deploy returns. A record captured lazily on first consumer request is
  blind to that consumer's own mutation, which is the likeliest first offender.
- COMPARE BY CONTENT DIGEST, NOT BY MODIFICATION TIME. A deploy writes its whole tree
  within a second, so mtimes are near-identical and an mtime-based comparison cannot
  see a rewrite. Cover all three difference kinds — added, changed, missing — and
  prove each separately.
- 'EXCLUDE `__pycache__/` AND `*.pyc` FROM THE COMPARISON. Importing from the deployed
  tree generates bytecode as a side effect of reading it, so an unfiltered comparison
  reports a difference on every clean run and the check is disabled within a week.
  This repo has already been bitten by exactly this tree: idempotency tests that read
  every deployed file as UTF-8 crashed on `__pycache__/*.pyc` under pytest (recorded
  in CLAUDE.md).'
- A COMPARISON OVER ZERO FILES IS A FAILURE, NOT A PASS. Report the compared file
  count on every path. The repo's AC-store validator globbed zero files, printed a
  success-shaped message and exited 0 for eight days; a count in the output is the
  cheap defence against repeating it here.
- 'THE CONSUMER COUNT IS REPORTED ALONGSIDE THE FILE COUNT AND IS NOT A FAILURE AT
  ZERO. The 2026-09-28 clause requires a second figure: how many consuming tests ran
  between the two states. The file count cannot see the case it catches — a comparison
  that ran correctly over a complete layout that no test ever touched — and while
  the deploy-site migration is incomplete that is the ORDINARY case, not an edge one,
  so without it this guard would spend the whole migration reporting clean about a
  layout nobody used. Deliberately NOT a failure at zero: at zero consumers TQ-600a-1-i
  requires that no layout be produced at all, so failing here would contradict that
  laziness claim. Stating the figure is enough; the record that FAILS while the population
  is unconverted is TQ-600a-8. Both figures must be present on every path, including
  the clean one.'
- 'STATE THE SCOPE THE COMPARISON ACTUALLY HAS, AND VERIFY IT AGAINST THE SHIPPED
  PRODUCER RATHER THAN ASSUMING. Corrected at this pass: the earlier form of this
  requirement said "under pytest-xdist the shared layout is per worker, so the comparison
  and its offender attribution are per worker". TQ-600a-1 shipped (PR #941) with cross-process
  coordination — scripts/suite_performance/_shared_layout_coordination.py derives
  run identity from `PYTEST_XDIST_TESTRUNUID` and serialises production on a file
  lock, so one layout is produced per RUN and shared across workers, which is also
  what TQ-600a-6''s whole-run clause requires. Attribution is therefore across the
  run''s consumers, not within one worker''s. Read the producer before writing the
  scope line into the output: a report claiming per-worker scope over a run-scoped
  layout understates what an offender contaminated.'
- Must complete in a few seconds over the deployed tree so it can run at teardown
  without re-introducing the cost this goal removes. Digest the tree once at capture
  and once at comparison; do not re-walk per consumer unless the per-test attribution
  mode is explicitly requested.
- Failure must be non-zero for the run and must name the test that ran between the
  last matching state and the first differing one.
```
