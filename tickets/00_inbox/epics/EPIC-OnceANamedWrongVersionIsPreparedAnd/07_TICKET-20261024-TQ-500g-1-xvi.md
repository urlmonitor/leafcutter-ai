## Implementation Notes

```yaml
- 'The operator command is a fourth step of the writer CLI, the module that owns the
  pins: python <root>/{{config.output_root}}/scripts/build_orchestration/wrong_version_writer.py
  reset --work-key <key> [--name <must_catch name>] --test-root <worktree root>. Argument
  parsing only in wrong_version_writer.py; the clearing logic in _wvp_store (TQ-500g-1-xi).
  stdout: exactly one JSON object, fixed key order {work_key: str, cleared: [{name:
  str, alteration_id: str}], not_pinned: [str], error: str|null}. Exit 0 when the
  command ran, including when nothing was cleared; exit 1 when the work key is not
  one plain path segment, the git directory cannot be resolved, or the pin file cannot
  be read or written, with cleared [] and error set. Logging to stderr only.'
- 'Matching: --name is compared with the pin keys through _wvr_scope.norm_name (trim
  and case-fold), the same lookup the plan uses. A name the work holds no pin for
  (or only a reset marker for) clears nothing and is listed by name under not_pinned.
  Without --name every pin of the work is cleared.'
- 'Clearing leaves a reset marker in place of the pin: {name, reset: true, cleared_alteration_id:
  <the cleared identity>, replacements: [], alteration_id: null, failed_check: null},
  written atomically (temporary file plus os.replace). The plan treats a reset marker
  as "no usable pin" with decision source "re-prepared: pin reset by the operator";
  a later passing preparation replaces the marker through the pin step. A whole-work
  reset with no pin file is cleared [] and exit 0.'
- 'Scope of the reset: only <git-dir>/leafcutter/pins/<work-key>.json of the named
  work changes. It never touches another work key''s pin file, history/, plan.json,
  the current manifest, copies, journals or the working tree (git status --porcelain
  unchanged).'
- 'Nothing else clears a pin: no list, write, pin or finish step, no recover or put-back
  (wrong_version_runner.py recover, RunGate.restore), no new or resumed workflow,
  and no code change removes or rewrites a pin; only a re-preparation that passed
  every check replaces it, through the pin step''s compare-and-swap (TQ-500g-1-xi).'
- 'A reset while a gate run of the same work is in progress (BA default, kept): the
  running gate keeps the plan it already read; its pin step''s compare-and-swap sees
  the marker, leaves it in place and logs a WARNING, so the reset takes effect from
  the next run.'
- Finishes within 1 s. No new module beyond _wvp_store (TQ-500g-1-xi), deployed by
  the build_orchestration directory glob; wrong_version_writer.py stays at or under
  400 counted lines (at 56).
```
