# A check's refusal is established by putting its declared known-bad input through the entry point the protected surface uses, and the record says what was observed rather than what was declared

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-120f-1` — A check's refusal is established by putting its declared known-bad input through the entry point the protected surface uses, and the record says what was observed rather than what was declared — so that the acceptance criterion is satisfied.

## Acceptance Criteria

```gherkin
Given every protective check declares one known-bad input it must reject together
  with the observable rejection that input must produce, held where the check is
  registered and read by machine rather than by a person reading prose,
And the record of what happened when that input was last put through the check can
  say that the rejection was observed, that it was not observed, that the attempt
  could not be run to a verdict, or that the attempt has never been made,
When the liveness run examines a check,
Then it puts the declared input through the entry point the surface that check
  protects uses to invoke it, observes what the check then does, and writes that
  check's record from that observation,
And no part of the record is taken from the declaration: a check whose declared input
  has not been put through it carries the value that the attempt has never been made,
  however completely and however well-formed its declaration is written,
And given a check whose record says the rejection was observed is altered so that the
  declared input no longer produces the declared rejection, while its declaration is
  left exactly as written,
When the run repeats,
Then that check's record says the rejection was not observed,
And given the alteration is reverted and nothing else in the repository changes,
When the run repeats again,
Then that check's record says the rejection was observed.
```

## Implementation Notes

### DECISION 2026-09-14 (BrainCandy) — the runner is guarded twice, and the second guard is not its own regime

`architect-review` surfaced an unspecified case: the runner becomes a
`hooks_manifest` entry like every other gate, so does it declare and demonstrate
its *own* negative control? Ruled:

**Both, and deliberately overlapping.**

1. **The runner carries its own `hooks_manifest` entry with its own
   `negative_control`.** It is not exempt from the regime it enforces. A liveness
   checker that proves every other check can refuse, while carrying no declaration
   of its own, is the precise asymmetry `KI-CG-021` already cost this repository
   once.

2. **AND its existence and reachability are additionally pinned by unit tests that
   do not route through the liveness regime at all.** This is the load-bearing half.
   Guarding the runner *only* by its own regime is circular: if the runner silently
   stops running, the regime that would have reported that is the thing that stopped
   running, and the absence reports as an absence of findings. An independent unit
   test is the only guard that survives the runner itself failing.

The tests must therefore assert, without invoking the liveness run to do it, that
the runner exists at its registered path, that its `hooks_manifest` entry resolves
to it, and that invoking it through `run_hook.py` reaches it. A test that proves
this by asking the liveness run does not satisfy this decision.

The same two-guard rule applies to every later record in this tree that adds a
surface. Carry it into `GE-120f-2`, which owns the run's outcome.

  has not been put through the check yields `unverified` — the schema''s own honest
  placeholder for an attempt never made — however complete it is. The discriminator
  is the alter-and-revert pair: the declaration is held byte-identical while the check''s
  behaviour changes, so no implementation that reads the declaration can pass.'

  scripts/commit_guardian/ is canonical; scripts/commit_guardian/ and .leafcutter/scripts/
  commit_guardian/ are build outputs. An alteration applied to a copy the run does
  not load fails GREEN — instance one of this same family, and GE-126c-5's subject.
  The test must state which copy it altered and which copy the run loaded, and assert
  they are the same.
- 'HOST AND DEPLOYMENT. Put the runner and its helpers INSIDE templates/scripts/commit_guardian/,
  which build_commit_guardian copies verbatim, so no scripts/build_phases.py deploy-map
  entry is needed. Anything imported from OUTSIDE that directory MUST be added to
  that deploy map in the same change or the deployed runner raises ModuleNotFoundError
  at runtime while source-tree unit tests stay green. Note the naming consequence:
  hook_parity.hook_script_patterns is ["check_*.py", "run_hook.py", "regenerate_*.py"],
  so naming the runner check_*.py puts it into BP-1600a-2''s census and it MUST then
  carry a hooks_manifest entry or a grounded declared-non-gate record. Decide the
  name deliberately and record the decision.'
- 'THE RUNNER MUST BE REACHED BY SOMETHING THAT ACTUALLY BLOCKS, AND THE TICKET MUST
  NAME IT. A runner whose refusal changes no gate''s verdict is inert — that is KI-CG-021''s
  shape exactly, a main() hardened over six review rounds that no runner called. Acceptable
  reaching surfaces, in order of preference: a hooks_manifest entry emitted onto an
  entry line; a job in .github/workflows/ci.yml; or a test module under unit_tests/
  that ci.yml''s existing `test` job already collects (`python -m pytest tests/ unit_tests/
  -q`). Whichever is chosen must be named in the ticket AND demonstrated by the reachability
  descriptor below, which asserts the run''s non-zero outcome propagating into that
  gate''s own outcome. Registration in a config section that no entry line executes
  is not reaching — that is the trap KI-TQ-007 records, where configuration presence
  reads as evidence of registration.'
- 'OUT OF PROCESS, DEPLOYED LAYOUT, SOURCE TREE OFF THE IMPORT PATH. Extend GE-120c-1''s
  harness (unit_tests/portability/) rather than growing a second one: it already builds
  a real second working copy, scrubs PYTHONPATH, runs the interpreter isolated, and
  keeps cwd off the source tree. Build the copy ONCE per sweep, never once per check,
  and mark the sweep slow rather than letting it quietly narrow its subject list to
  stay fast.'
- SEVERAL COMMIT-GUARDIAN HOOKS IGNORE argv AND READ THE GIT INDEX OR HOOK_TEST_FILES.
  For any check invoked through run_hook.py, the run must establish that the check
  actually SAW the known-bad input before reading its verdict. A clean exit from a
  check that was handed nothing is the never-attempted state wearing a pass, and recording
  it as `passing` is this whole tree's defect committed by its own tooling.
- 'REUSE THE SCHEMA''S FOUR STATE VALUES VERBATIM — passing / failing / blocked /
  unverified. Do not mint synonyms, do not collapse `blocked` into `failing` (GE-120f-2-i
  forbids it), and do not omit the block for an unrun control: the schema already
  states that an unrun control records `unverified` "rather than omitting the block,
  so ''we never fed it bad input'' is visible in the artifact instead of silent".'
- NO POPULATION FIGURE IN THE IMPLEMENTATION OR IN ANY TEST EXPECTATION. Every assertion
  is count-and-membership over the run's own emitted output. The parent records the
  count as disputed and forbids one below it.
- AC_ENFORCE_STRICT=1 on every pytest invocation. Without it pytest_ac_enforcement
  xfail-masks these tests, all of which cover a not-done AC on the day they are written.
- 'Error-handling policy applies to the runner''s own subprocess, filesystem and JSON
  I/O: specific exceptions, logged at WARNING or higher or re-raised, never swallowed.
  A swallowed invocation error must never become an absent record or a silent `passing`
  — it is `blocked`, which GE-120f-2-i converts into a named, non-zero outcome.'
