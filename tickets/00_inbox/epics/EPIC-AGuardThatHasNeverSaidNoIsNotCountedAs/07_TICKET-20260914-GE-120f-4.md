# A check joins the protected family only by declaring what it must refuse, read from where it is registered — so the next check inherits the requirement by existing rather than by someone remembering

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-120f-4` — A check joins the protected family only by declaring what it must refuse, read from where it is registered — so the next check inherits the requirement by existing rather than by someone remembering — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-120f-4`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `L`. Complexity: `high`.

## Acceptance Criteria

```gherkin
Given the place where a protective check is registered is also the place its declaration
  is held — one known-bad input it must reject, and the observable rejection that input
  must produce,
When a check is registered, or an existing registration is changed,
Then a registration carrying no such declaration is refused at the point of registration,
  naming the check and stating what the declaration must contain,
And the requirement is applied to whatever the registration surface holds when it is read,
  so a check registered afterwards is subject to it without anything being added to the
  thing that applies it, and a check that merely resembles an already-declared one inherits
  nothing,
And a declaration written only in prose beside the check — in its own description, in a
  guide, or in a note — does not satisfy the requirement, which is satisfied only by what
  is read from the registration surface,
And a registration that carries a declaration is accepted here without the rejection having
  been demonstrated, and that check is thereby counted among those whose refusal has never
  been demonstrated rather than among the protected — passing this point is not a
  demonstration and must never be reported as one.
```
