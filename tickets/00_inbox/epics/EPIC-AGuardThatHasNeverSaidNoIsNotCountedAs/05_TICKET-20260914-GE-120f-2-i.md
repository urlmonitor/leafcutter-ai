# The finding is the run's own outcome, never a note printed beside a success — and a run that could not reach a verdict is unresolved rather than either

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-120f-2-i` — The finding is the run's own outcome, never a note printed beside a success — and a run that could not reach a verdict is unresolved rather than either — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-120f-2-i`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `S`. Complexity: `low`.

## Acceptance Criteria

```gherkin
Given a liveness run that completed and named at least one check whose declared rejection
  was not observed, or at least one whose attempt has never been made,
When the run finishes,
Then the outcome it hands back to whatever invoked it is a refusal, and the named checks
  appear in the same output a reader of that refusal sees,
And a run that completed, examined at least one check, and found every examined check's
  rejection observed or exempted on an accepted ground hands back an acceptance,
And no run hands back an acceptance carrying a note that some check's refusal was not
  observed or has never been demonstrated,
And given a run that could not reach a verdict for a check — the attempt was made and
  produced no answer — that check is reported as unresolved under its own wording, the run
  hands back a refusal, and the check is counted neither among those whose rejection was
  observed nor among those whose rejection was not observed,
And given the run itself cannot proceed at all, it says so and hands back a refusal rather
  than an acceptance — announcing an internal difficulty and continuing to a clean answer
  is the condition this whole tree exists to make impossible, and is a different thing from
  the component's convention of not hard-blocking on a single unreadable input while the
  check still ran.
```

## Implementation Notes

```yaml
- THE FINDING IS THE OUTCOME, NOT A NOTE BESIDE ONE. The value handed back to whatever
  invoked the run is a refusal whenever any examined check's rejection was not observed,
  was never attempted, or could not be run to a verdict. Printing every finding and
  returning success satisfies the parent's naming clauses completely and is the failure
  this record exists to prevent — run the injection below rather than describing it,
  because fail-open is the reflex this component reaches for by habit.
- 'THE ACCEPTANCE ARM IS NOT DECORATION. A run that completed, examined AT LEAST ONE
  check, and found every examined check''s rejection observed or exempted on an accepted
  ground hands back an acceptance. Without this the requirement is satisfiable by
  a run that always refuses, which is the same inert shape one level up (GE-120f-1-ii).
  The examined-at-least-one qualifier belongs to GE-120f-3 and is consumed here, not
  restated: this record must not be satisfiable by a run that examines nothing and
  accepts.'
- FOUR VALUES, FOUR DISPOSITIONS — DO NOT COLLAPSE `blocked` INTO `failing`. A check
  whose attempt was made and produced no answer is reported as unresolved under its
  OWN wording, the run refuses, and the check is counted neither among those whose
  rejection was observed nor among those whose rejection was not observed. The two
  conditions have opposite remedies — repair the check, against repair the run — and
  a reader who cannot tell them apart repairs the wrong one and concludes the tooling
  is unreliable.
- THE STANDING FAIL-OPEN CONVENTION IS NOT REPEALED, AND THE LINE IS NARROW. GE-116a-1-iii's
  convention — a guard that meets one input it cannot handle announces and does not
  hard-block — stands, and its subject is a check that RAN. This record's subject
  is a run whose verdict is already known and would be discarded, or a run that never
  reached a verdict at all. Implement the distinction explicitly; the last descriptor
  below asserts both sides of it in one run so the convention is not flattened by
  accident.
- 'THE OUTCOME MUST REACH THE CALLER, AND THE TICKET MUST NAME THE CALLER. A non-zero
  return that no gate reads is the same inertness one layer out. Assert propagation
  into the invoking gate''s own outcome — the hooks_manifest entry line, the ci.yml
  job, or the pytest collection named in GE-120f-1''s it_requirements. This is the
  clause KI-CG-021 would have caught on day one: "the fail-closed contract was never
  wired to the exit code", and nothing read that exit code.'
- THIS RECORD ADDS NO NEW FINDING. It constrains what the run does with the findings
  it already has. Anything that reads like a second classification pass is wrong.
- AC_ENFORCE_STRICT=1 on every pytest invocation; exercise the DEPLOYED copy out of
  process. Any module imported from outside templates/scripts/commit_guardian/ goes
  into the scripts/build_phases.py deploy map in the same change.
- 'Error-handling policy: specific-exception try/except around subprocess and I/O,
  logged at WARNING or higher or re-raised. An exception escaping the run must produce
  a refusal with a stated reason, never an acceptance and never a traceback the caller
  reads as success.'
```
