## Implementation Notes

```yaml
- bundled_accepted is caught at routing on the root work item (depth 0), in the same
  route pass that selected the capability, not inside the decision or research capability;
  the selected capability is not invoked for the root while the split is open.
- The routing result that selected the capability (its RoutingAssessment id, or the
  intent-bound binding, with capability id and version) is kept on the split record
  as kept_routing and is the only source a kept-whole rejection or a too-few-parts
  outcome resumes from; it is not re-routed and no second routing Jev call is made
  on resume.
- 'No options request, criteria proposal, precedent search or assessment runs for
  the whole goal before the gate answer: no host.generate_options packet and no decision
  Jev batch exists for the root.'
- A bundled root resolved to research (evidence answer kind) is caught the same way
  with subject_kind research_request.
- 'Tests enable splitting explicitly: split.enabled true through a config override
  (false only where a test compares with the off switch). None relies on the shipped
  default, which stays false until E3 merges (dec-9925ebf1895222f4, see DK-400a-1).
  A test asserting that no split starts must run with splitting on, or it passes for
  the wrong reason.'
```
