# Orphan scan never kills unrelated processes and guards against PID reuse

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-2100c-3-i` — Orphan scan never kills unrelated processes and guards against PID reuse — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-2100c-3-i`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a host running unrelated processes whose command lines partially resemble
  the configured `startup_command`
When live_surface_startup.py `scan-orphans` runs to reap orphaned servers
Then the match pattern (startup_command with `{port}` widened) is anchored tightly
  enough that no unrelated process is selected
  And only PIDs that both match the pattern AND are absent from the registry are
  killed
  And before killing a PID the scan verifies it still refers to a live-surface
  server (guarding against PID reuse where the OS has reassigned a recorded PID to
  an unrelated process).
```

## Implementation Notes

```yaml
- The orphan-match pattern must be anchored tightly enough that no unrelated process
  is ever selected — a partial command-line resemblance must not be sufficient to
  match.
- Only PIDs that BOTH match the pattern AND are absent from the registry may be killed.
- Before killing, the scan must verify the PID still refers to a live-surface server,
  guarding against OS PID reuse of a recorded PID.
- Process inspection and kill must follow the project error-handling policy (handle
  ProcessLookupError / permission errors explicitly, no bare or silent excepts).
```
