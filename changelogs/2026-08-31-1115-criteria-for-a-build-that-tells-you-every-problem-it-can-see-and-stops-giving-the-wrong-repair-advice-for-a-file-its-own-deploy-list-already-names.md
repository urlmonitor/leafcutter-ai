description: "While writing the must-block test for the deploy fail-closed criterion, deleting a declared source produced a report saying to add a deploy phase for a file that a deploy phase already declares by name, and the test itself passed for the wrong reason because an earlier check ended the run before the one under test could execute. Neither observation was written down anywhere durable, which is the whole reason this exists: a note in a pull-request description is not a work queue and nobody encounters it again. The first observation is now two records. The behaviour requires that when a broken reference names a path that a deploy declaration lists individually, the advice names that declaration and the two repairs that actually exist — restore the source, or drop the entry — and specifically not the add-a-deploy-phase text. An existing sibling already branches this advice on state, but its test keys on directories that a phase ships wholesale, so a declaration that lists individual files falls through to the default; that is why this is a fourth record rather than a duplicate, and the reasoning is written into it. Its technical constraint requires the state to be read from the declarations the build actually ships from, pinned by editing a declaration between two otherwise identical runs and requiring the advice to move, plus a third run against a differently shaped declaration, because a rule written against the one shape that produced the defect passes everything else and leaves the other shapes broken. The test contracts assert on the parsed record the real entry point emits, never on log text and never by calling the advice selector directly, because the current implementation already emits a well-formed record with an accurate path and only the advice is wrong — so a test that checks a finding appeared is green against the broken code and the fixed code alike. They also require all three states to appear correctly in a single run, since a single-entry assertion is satisfied by an implementation that emits the corrected wording unconditionally while the other two states silently become wrong. The second observation had no honest home. It spans three separate checks, each of which already promises to report everything it finds within its own scope, and none of which owns what the run as a whole reports. The business analyst declined to force it under a poor parent and said so; the product owner confirmed every rejection independently, found that one candidate had a free slot and rejected it on scope rather than capacity, and wrote a new feature-level criterion under the parent concerned with whether the build's account of its own work is complete and true. That criterion is decisive where it had to be: every check runs and the run produces one combined account, because the project has already ratified exactly this argument one level down — halting at the first finding turns a set of repairs into that many build-fix-build cycles with a green build between each, and nothing about that argument stops applying when the findings sit across checks rather than inside one loop. The cost is stated rather than hidden: a check that cannot give a meaningful verdict after an earlier failure must be reported as not run, never omitted and never passed. It also requires each finding to name the check that produced it, which is the minimum that lets a must-block test tell which check actually fired, and this is where the authors did the careful thing. That fourth field contradicts an approved, completed record which fixes the emitted format at exactly three keys. Neither author widened that record. The amendment it would need is written out in the open, with the sequencing spelled out — it must land on the record it belongs to, by its owner, before anything emits a fourth field — and with the alternative stated plainly, that if the amendment is refused the attribution requirement comes out and the gap is recorded as accepted, because three checks attributed and one not is worse than either consistent choice. The enrichment then made that prohibition mechanical rather than advisory, with a test asserting set equality on the record's keys so that an implementer who reaches for a fourth field goes red instead of quietly contradicting an approved criterion."
