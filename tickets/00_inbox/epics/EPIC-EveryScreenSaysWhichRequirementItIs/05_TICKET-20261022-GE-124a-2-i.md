## Implementation Notes

```yaml
- THE OUT-OF-REGION COMMENT IS DETECTED, NOT MERELY IGNORED. The reader must run a
  second, whole-file scan for a misplaced @ac comment ONLY to build the remediation
  message, and must keep its result strictly out of declares[]. Ignoring the misplaced
  text is cheaper and produces a bare 'missing declaration' — being blocked for putting
  the right text in the wrong place with no hint where it belongs is the most annoying
  possible false stop.
- 'THE MESSAGE CARRIES THE REMEDIATION, per the GE-117 house shape: it must name the
  required location in the terms of THIS file''s dialect (above the first import for
  .tsx/.jsx; above the first <template>/<script>/<style> for .vue/.svelte; above the
  first element for .html) and quote the misplaced comment verbatim with its line
  number.'
- 'The whole-file rescan must not leak into the pin surface: an id found in a misplaced
  comment is neither a declaration (GE-124a-1) nor a pin (GE-124b-1), and must appear
  in no collection — only in the message text.'
- 'The finding raised is still code ''missing-component-declaration'' with a richer
  message, not a new verdict code. A distinct code here would multiply the how-to''s
  section list (GE-124c-4) for a case whose remedy is identical: move the comment.'
```
