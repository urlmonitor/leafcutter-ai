description: "An adversarial review proved by direct execution -- writing a real file to disk via budget.constructor.constructor -- that round 1's Object.setPrototypeOf(sandbox, null) closed only the one escape route it was tested against. Every injected mock global was still built in the driver realm before being placed into the sandbox, so its own .constructor.constructor chain still reached a live driver-realm Function, through globals the AC itself requires be present. Fixed by constructing every mock global (agent, parallel, pipeline, phase, log, workflow, budget, args, console) inside the vm context via a bootstrap vm.runInContext() call that runs before the target script, so nothing in the sandbox's reachable graph is ever a driver-realm value. Finishing this PR required verifying that fix and correcting two records that overclaimed it. A true per-test red/green re-derivation (reverting only this fix, running each test in test_bp_1100b_4_sandbox_fidelity.py individually, not as a group) found that of the file's original 5 escape tests, 3 (object-literal, async-function, and generator-function constructor routes) could never have failed under any fix at all -- a literal evaluated inside the sandboxed body always resolves against the vm context's own intrinsics, confirmed by running them against the harness from before any escape-closing fix existed. They are replaced with 3 tests through injected mock globals (budget, args, console.log) that are genuinely red before this fix and green after. The other 2 (globalThis-rooted routes) were real, just coverage of round 1, not this fix specifically; they are kept. The fix itself also introduced a regression: its bootstrap declared internal bookkeeping (captured calls, contract violations) as top-level vars, which attach as string-keyed properties of the sandbox's global object and are therefore reachable from the workflow body itself via Object.getOwnPropertyNames(globalThis) -- silently failing the harness's own namespace-enumeration test on a fresh checkout. Fixed by returning that state as the bootstrap IIFE's completion value instead of writing it to any property of the sandbox object at all (a Symbol-keyed property was tried first and found not to survive across separate vm.runInContext calls). BP-1100b-4's own record previously claimed all 5 escape tests were 'confirmed RED without the fix and GREEN with it' -- false for 3 of them -- and is corrected in place rather than argued around. Full unit_tests/workflows/ suite: 484 passed (the true count, unbroken by the namespace-leak fix); the 6 harness-importing test files outside that directory (including unit_tests/_plan_feature_e2_runner.py's 5 importers, missed by earlier verification rounds): 85 passed plus 57 passed / 1 pre-existing xfailed. Zero regressions from any fix in this pass."
