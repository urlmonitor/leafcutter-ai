# PR creation tolerates the active gh account silently reverting to an EMU account

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-1500e-3` — PR creation tolerates the active gh account silently reverting to an EMU account — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-1500e-3`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given the active gh CLI account has silently reverted to an Enterprise Managed
  User (EMU) account that cannot open pull requests,
When the authoring workflow reaches the PR-creation step,
Then it switches the active gh account to the account authorized to create the
  PR immediately before attempting creation,
And if the CLI create path is still blocked, it creates the pull request via the
  REST API fallback,
And the pull request is opened to main by one of these paths,
And the workflow surfaces the resulting PR number and URL (per BO-1500d-1)
  rather than failing the delivery.
```
