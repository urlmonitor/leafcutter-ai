description: "KI-BP-021 is new and records that the closure guard shipped in BP-900g-8 has a hole of exactly the shape it was written to eliminate. The guard derives each deployed script's dependency closure so that a module missing from the deploy declaration fails the build, and one of the three reference shapes it must see is a directory pushed onto sys.path. Its lens for that shape, _is_syspath_mutation_call, matches only insert and append. A script that writes sys.path.extend or a slice assignment yields no candidate directory at all, so every plain import resolving through that path is dropped and the script's derived closure comes back empty, which is indistinguishable from a script that genuinely has no intra-package dependencies. The build then reports that script clean. The two unsupported forms fail at different depths and this matters for whoever fixes it: extend at least reaches the predicate and is rejected by the tuple check, so widening the tuple covers it, although extend takes a sequence rather than a single path so the argument-extraction helper needs the matching change or the result is a spurious warning instead of a resolution; a slice assignment is an assignment node and never becomes a call node, so the tree walk skips it before any predicate runs and widening the tuple does nothing for it. The module's own docstring promises that no path through it produces an unresolved intra-package reference with zero log output, and that promise holds only for a mutation the lens recognises and cannot evaluate. For a mutation it does not recognise the loop continues before any logging is reached, at every log level, so the docstring should be corrected in the same change or it will be read as coverage the code does not have. Nothing is mis-derived today: a grep of the scripts and templates trees for both idioms returns two hits, both comments mentioning sys.path index zero, and no executable instance of either, so this is a latent gap that opens the moment somebody writes one of the two idioms, neither of which any gate or reviewer would flag as unusual. The entry additionally records that the commit which introduced the lens describes it in general terms the code does not support, so the git log over-states the fix; that message is left in history rather than rewritten and the register carries the correction, which is itself a live instance of this repository's rule that commit messages must match the diff. KI-ACD-002 gains a second occurrence and, with it, a third distinct defect in the same emitted line. The generated Agent Contracts line reproduced the original malformed form exactly as the entry had predicted a week earlier, and the drive played out as described there: documentation-verifier fail-closed on the missing pipe delimiters, the blocker was classified cross agent, and the phase was skipped. The new finding is the more serious one. The genre resolver reads the parent feature acceptance criterion's documentation triggers and, when that list is empty, warns and returns an unspecified genre marker, after which the caller emits the contract line anyway. But an empty list is not a missing value. It is the store's way of declaring that the change requires no documentation, and the parent in this case says exactly that with a written rationale that no user-facing surface is introduced. So the generator takes a deliberate no-documentation declaration, converts it into a marker meaning the genre is unknown, and emits a documentation obligation the governing criterion explicitly disclaims. That compounds the original defect rather than sitting beside it: repairing the pipe delimiters converts a parse blocker into a missing-document blocker for a document the criterion says must not exist, so no form of the line both parses and is satisfiable. The only correct resolution on this ticket was to record the verifier as not needed, verified against its own documented dispatch condition rather than against the line it was choking on. The warning this defect does emit goes nowhere useful, being written to the generator's standard error at ticket-generation time, hours or days before the drive that trips over it, where no gate reads it and nothing carries it forward. The fix direction gains a third step accordingly: an empty documentation triggers list on the parent should suppress the subsection entirely and stop marking documentation-expert as needed, reserving the unspecified genre marker for a parent that is genuinely unresolvable, and the accompanying test should assert that no contract line is emitted at all in that case."
