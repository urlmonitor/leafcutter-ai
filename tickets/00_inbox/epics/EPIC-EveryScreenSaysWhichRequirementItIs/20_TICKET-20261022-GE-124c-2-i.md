## Implementation Notes

```yaml
- 'THE ENTRY POINT MUST BE CREATED, NOT MERELY CALLED. scripts/ac_store/ac_coverage_resolver.py
  exposes no id-resolution function as of 2026-08-25 (public API: resolve_coverage,
  compute_verdict, verify_ticket_coverage, main; the only record load is the private
  path-based _load_ac_record). Add one public function there — id in, resolved record
  or None out — implemented over scripts/commit_guardian/_ac_store_index.get_ac_index,
  which is the store index that already exists and is already fingerprint-cached.
  Do NOT add a third walker.'
- MIGRATE GE-111 AND GE-117 ONTO IT IN THE SAME CHANGE, or this AC has not been satisfied.
  GE-117a-1's own it_requirements currently direct it to resolve component names against
  docs/components.json via check_components_integrity's loader, and its symbol-AC
  surface resolves ids by its own route; GE-111's reconciliation reads AC records
  for itself. This AC is a REFACTOR of two existing consumers plus one new one, not
  a greenfield addition — size it accordingly and expect to touch check_declaration_traceability
  and the GE-111 reconciliation check.
- SCOPE THE MIGRATION TO AC-ID RESOLUTION ONLY. GE-117's component-name resolution
  against docs/components.json is a DIFFERENT namespace and must stay where it is;
  folding it in would make the shared resolver answer two unrelated questions and
  reintroduce the ambiguity this AC removes.
- NO CACHE OF ITS OWN, NO SNAPSHOT. The entry point must observe the store as it stands
  at call time, invalidating through _ac_store_index's existing fingerprint mechanism.
  A resolver holding a private snapshot agrees with its siblings today and disagrees
  after the next authoring run — the second drift shape the criteria's second scenario
  targets.
- THE DEPLOYED LAYOUT MUST WORK. ac_coverage_resolver.py is already in build_ac_store's
  deploy_map; whatever it now imports (_ac_store_index and its disk-cache helper)
  must be reachable in the deployed layout too. Verify by running the deployed hooks
  after a build.py round-trip, not only the source-tree tests.
- Fail-open behaviour on an unreachable store belongs to GE-124c-2-ii and to each
  check's own policy; the shared entry point must surface 'could not read the store'
  as a state distinct from 'resolved to nothing', or all three checks lose the ability
  to honour GE-120.
```
