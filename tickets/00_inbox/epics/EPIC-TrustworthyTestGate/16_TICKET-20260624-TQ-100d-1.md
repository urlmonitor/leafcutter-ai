# A failing test on a valid, unexpired allowlist entry does not block the run

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `TQ-100d-1` — A failing test on a valid, unexpired allowlist entry does not block the run — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `TQ-100d-1`. Component: `testing-quality`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given a known-failing-tests allowlist in which an entry names a specific test
  (by its test id/path) and carries both a ticket reference and an expiry date
  that has not yet passed, and that named test is currently failing,
When the suite is run,
Then the named failing test does not count against the overall run outcome
  while its allowlist entry is valid (present and unexpired)
And the run can still report a passing overall outcome despite that test
  failing
And only tests with a matching valid allowlist entry are exempted; every other
  failing test is treated normally.
```

## Test Requirements

- `test_valid_unexpired_allowlist_entry_exempts_test`: A failing test named by a present, unexpired allowlist entry does not count against the overall run outcome.
- `test_only_matching_entries_exempted`: A failing test with no matching valid allowlist entry is treated normally (exemption is narrow and per-named-test).
- `test_absent_allowlist_keeps_gate_strict`: When config/known_failing_tests.yaml is absent or unreadable, no test is exempted (the gate stays strict, fail-safe).
