## Acceptance Criteria

```gherkin
Given the allowlist file's fourth line is an entry naming every rule, the path
  "secrets.py", and every line,
And "secrets.py" contains four lines the scanner's content rules recognise,
When the file is scanned through the scanner's multi-file entry point — the
  same entry point the pre-commit secrets check calls,
Then exactly one warning about that entry is emitted, on the error stream and
  not on the stream that carries the findings report the pre-commit secrets
  check consumes,
And the warning names the allowlist file it came from, states the 1-based line
  number 4, and quotes the offending line verbatim,
And it additionally names "secrets.py" as the file the entry would have left
  with nothing able to report on it.

Given the same allowlist, whose remaining lines are well-formed entries naming
  other rules and other paths,
When the run completes,
Then every one of those other entries is still loaded and still applied,
Because declining one over-broad line must not withdraw the author's other
  suppressions.

Given the same allowlist and the same file,
When the run completes,
Then the run completes normally and raises nothing,
And its exit status is determined by the findings that were reported and by
  nothing else — the declined line by itself neither blocks the commit nor
  changes the exit status,
Because this check runs on every commit, so treating a too-broad suppression
  line as fatal would turn one author's mistake into a repository-wide commit
  outage, whereas declining the line already fails closed: the author
  immediately sees the findings they were trying to hide.
```
