# A paused run picks up at the decision it was waiting on when the answer arrives

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `ACD-2100c-3` — A paused run picks up at the decision it was waiting on when the answer arrives — so that the acceptance criterion is satisfied.

## Acceptance Criteria

```gherkin
Given a run that has paused at a decision point with drafted work on disk and the
  process no longer running,
When the route is started again in a new process supplying the person's answer
  for that decision point,
Then the new run continues from that decision point rather than repeating the
  steps before it,
And the drafted work present when it paused is the work the resumed run carries
  forward unchanged,
And the answer supplied is the one applied to that decision,
And once the resumed run has moved past the decision point no record of it
  waiting remains on disk.
```

- [ ] AC-1: the new run continues from that decision point rather than repeating the
- [ ] AC-2: the drafted work present when it paused is the work the resumed run carries
- [ ] AC-3: the answer supplied is the one applied to that decision
- [ ] AC-4: once the resumed run has moved past the decision point no record of it

## Implementation Notes

```yaml
- The change must land under templates/. The deployed workflow is build output.
- The steps before the decision point must not re-execute on resume. Re-running them
  is observable as duplicated or rewritten drafted work and is the failure this record
  exists to prevent.
- The waiting record must be cleared as part of moving past the decision point, not
  on process exit. A record left behind makes the run look permanently paused to anything
  that lists waiting runs, and the next resume then re-applies an answer to a decision
  already made.
- Clearing the record and applying the answer must not be separately observable in
  a way that leaves the run both resumed and still listed as waiting if the process
  dies between them; the later of the two must be the one that commits the run past
  the gate.
- The supplied answer must reach the decision through the same evaluation ACD-2100c-4
  governs -- resume must not be a second, unguarded way to answer a gate.
- 'Must satisfy the repository error-handling policy: reading and removing the record
  are external I/O.'
- 'Resume must be safe to attempt when no record exists: it reports that there is
  nothing to resume rather than starting a fresh run under the old run''s identity.'
```
