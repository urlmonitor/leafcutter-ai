## Implementation Notes

```yaml
- 'A separate rule family in the ACD-2500a-1 requirement rule-check report (declared
  files versus ''modifies'' documentation links), not a variant of the specialist-versus-surface
  family. Findings use the ACD-2500a-1 shape unchanged: disposition ''needs a decision'',
  one finding per (file, record_id, rule_family, path) with the path as the subject,
  message naming the record and the path, detail carrying the path.'
- Declared files are read only through the declared-files seam (scripts/ac_store/declared_files.py,
  ACD-1600c-4); the rule never parses declared_files itself. Documentation-link paths
  and declared paths are compared in the seam's normalised repo-root-relative POSIX
  form (ACD-1600c-4-iii), not as raw text.
- Only links whose relationship value is exactly 'modifies' are compared; every other
  relationship (describes, related, ...) is ignored by this rule -- data-driven, never
  keyed on paths or ids.
- 'No repair: the rule never writes a record. Neither the declared list nor doc_links
  is changed by the run (ACD-2500a-2: a repair is applied only when fully determined
  by store data; this disagreement has two valid resolutions).'
- 'A record in the ''no declared files'' state is listed ''not evaluated: no declared
  files'' for this family, verbatim, and excluded from the passed count (ACD-1600c-4-ii
  vocabulary).'
- 'Verdict: any finding of this family makes the rule check''s verdict failed for
  the authoring stage, exactly as for every other family under ACD-2500a-1 / ACD-2500a-2.
  ''Advisory'' means human-decided and never auto-applied, not verdict-neutral; the
  rule gets no carve-out.'
- Runs within ACD-2500a-1's determinism and time budget (byte-identical report for
  an identical folder; 5 seconds for 100 records) with the family added.
```
