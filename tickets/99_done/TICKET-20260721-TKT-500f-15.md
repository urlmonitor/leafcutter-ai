# A scalar-string components field becomes a single-element graph-id list, never a per-character shatter

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `TKT-500f-15` — A scalar-string components field becomes a single-element graph-id list, never a per-character shatter — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `TKT-500f-15`. Component: `ticket-creation`. Assigned agent: `python-coder`. Estimated complexity: `S`. Complexity: `low`.

## Acceptance Criteria

```gherkin
Given a leaf AC whose components field is a SCALAR string rather than a YAML
  list (for example components: ticket-creation written as a bare string, or a
  scalar underscore graph id components: ticket_creation_pipeline),
When a ticket is generated from that AC by generate_ticket_from_ac.py
  (_build_components_list),
Then the generated ticket's components LIST is a single-element list holding that
  one component's underscore components.json graph id (for example
  ["ticket_creation_pipeline"]),
And the LIST is never a per-character shatter of the scalar string — it never
  contains one single-character element per letter of the string (for example it
  is never ["t", "i", "c", "k", "e", "t", ...]),
And the resulting single element is the components.json graph id, not the raw
  scalar left verbatim when the scalar was an index.yaml kebab namespace key.
```

- [ ] AC-2: the LIST is never a per-character shatter of the scalar string — it never
- [ ] AC-3: the resulting single element is the components.json graph id, not the raw
