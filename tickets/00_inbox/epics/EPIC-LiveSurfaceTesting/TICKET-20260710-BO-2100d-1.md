# Missing requests package fails the check loudly instead of silently timing out

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-2100d-1` — Missing requests package fails the check loudly instead of silently timing out — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-2100d-1`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `S`. Complexity: `low`.

## Acceptance Criteria

```gherkin
Given live-app testing is enabled and started but the `requests` package is not
  installed in the environment
When live_surface_startup.py attempts the health check during startup
Then it fails fast with a clear, visible error that names the missing `requests`
  prerequisite and exits with a non-zero status
  And it does NOT silently return a failed probe that lets startup run to the full
  timeout and report an ambiguous "did not become ready" result.
Note: today _probe_health returns False when requests is absent, so startup polls
  until the timeout and reports a generic timeout rather than the real cause.
```

## Implementation Notes

```yaml
- Absence of the `requests` prerequisite must fail fast — before the startup polling
  loop — with a clear message that names `requests` and a non-zero exit status.
- 'The failure must be distinguishable from a genuine readiness timeout: it must not
  degrade into a generic ''did not become ready'' result when the real cause is a
  missing prerequisite.'
- Error handling must follow the project error-handling policy (typed/named exception
  path, logged at appropriate severity, not silently swallowed).
```
