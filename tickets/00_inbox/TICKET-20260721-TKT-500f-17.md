As the leafcutter-ai system, I want to implement AC `TKT-500f-17` — An unresolvable component value is warned about and validated against components.json, not silently emitted — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `TKT-500f-17`. Component: `ticket-creation`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a leaf AC whose component value cannot be resolved to any valid
  components.json graph id (it matches neither a known index.yaml kebab-namespace
  mapping nor an existing underscore graph id — for example a typo such as
  ticket_creaton_pipeline),
When a ticket is generated from that AC by generate_ticket_from_ac.py
  (_build_components_list),
Then the generator emits a WARNING that names the unresolved component value (it
  does not silently place an unknown/invalid id into the components LIST),
And graph-id validity is determined by membership in docs/components.json — the
  single ~42-entry source of truth loaded at generation time — rather than by a
  partial hard-coded kebab-to-graph-id map embedded in the generator,
And adding a new component to docs/components.json makes that id resolvable
  without any change to the generator's code.
```
