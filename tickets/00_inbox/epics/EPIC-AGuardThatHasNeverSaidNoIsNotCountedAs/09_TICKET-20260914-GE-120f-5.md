# The rule is written where the next check author is already looking, in the vocabulary the machine reads, and the written procedure and the enforced procedure say the same thing

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-120f-5` — The rule is written where the next check author is already looking, in the vocabulary the machine reads, and the written procedure and the enforced procedure say the same thing — so that the acceptance criterion is satisfied.

## Context

## Acceptance Criteria

```gherkin
Given the procedure for adding a protective check is written down where an author of a
  new check is already directed to look,
When that procedure is read,
Then it states that a check carries a declaration of one known-bad input it must reject
  and the observable rejection that input must produce, names the place that declaration
  is read from, and states plainly that a declaration is not a demonstration,
And it uses the names the machine reads for the known-bad input, for the exemption and
  its ground, and for the value that records an attempt never made, rather than a second
  set of words for the same things,
And it states what an author must do to have a refusal counted — that the declared input
  is put through the entry point the protected surface invokes and the refusal observed —
  and states that a check which has never been asked to refuse is reported as unproven
  rather than counted as protection,
And an author who follows the written procedure exactly and omits the declaration is
  refused by the registration surface, so the written procedure and the enforced procedure
  agree at the point where they could disagree,
And the document describes the requirement as in force rather than as forthcoming,
  optional, or as something a later pass will supply.
```
