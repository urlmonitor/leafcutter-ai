## Implementation Notes

```yaml
- THIS AC CREATES THE CI GATE. New script templates/scripts/commit_guardian/check_ui_ac_declared.py
  with its deployed twin at scripts/commit_guardian/check_ui_ac_declared.py — the
  check name the mock-data artifact uses for every ci-tier finding. Model it on scripts/commit_guardian/check_done_proof.py,
  which already asks the same shape of question about tests and already carries the
  --mode / --base argument surface; do not invent a parallel idiom.
- ADD ITS CI JOB TO .github/workflows/ci.yml MIRRORING THE EXISTING done-proof JOB
  (which runs `python scripts/commit_guardian/check_done_proof.py --mode ci-changed
  --base origin/${{ github.base_ref }}`), including the install_shims build step that
  job performs before invoking the check. Without the job the gate is a script nobody
  runs; without install_shims it resolves .leafcutter incorrectly.
- 'SELECTION IS TWO AXES, BOTH REQUIRED: change_target includes `ui` AND work_status
  == `done`. Read the store through the shared AC index (GE-124c-2-i / _ac_store_index.get_ac_index)
  rather than walking the store again — this gate and check_done_proof will otherwise
  hold two walkers over the same corpus.'
- change_target MAY BE A SCALAR OR A LIST — the AC schema permits both (anyOf string|array).
  A membership test that assumes a string silently drops every record whose change_target
  is a list, which would shrink the selected set without any error. Normalise before
  testing.
- THREE OUTCOMES, NOT TWO, AND ALL THREE ARE RECORDED. Selected; skipped-with-reason
  (UI but not done); out-of-scope (not UI). A non-UI criterion recorded as PASSING
  would inflate every figure built on this gate by the entire non-UI store — precisely
  the number GE-124g-3 forbids. The mock-data Ac entity encodes this as declaration_status
  == 'n-a' iff change_target != 'ui'.
- SKIPPED IS NOT BLOCKED. A UI criterion still in progress is skipped, never failed
  (mock record gf-ci-km-adm-003-skipped, code 'not-done', verdict 'skip'). Blocking
  in-progress work would make the gate hostile to the normal case.
- Must handle errors gracefully per the project error handling policy, and must announce
  rather than silently pass if the store cannot be read (GE-124c-2-ii's rule applies
  to this tier too; the IT-PO recommendation for the CI tier is to BLOCK, since a
  CI run that could not read the store produced no evidence).
```
