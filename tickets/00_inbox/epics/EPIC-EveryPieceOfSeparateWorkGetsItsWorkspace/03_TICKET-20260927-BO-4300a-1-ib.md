# Entry skills run the one maker and hand its answer to the workflow unchanged

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-4300a-1-ib` — Entry skills run the one maker and hand its answer to the workflow unchanged — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-4300a-1-ib`. Component: `build-orchestration`. Assigned agent: `llm-expert`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given an agent or a person starts a workflow that needs a workspace through its
  entry command or skill, or follows the workspace skill,
When a workspace is needed,
Then the workspace maker is run unchanged and its answer is passed on word for
  word as part of the workflow's input,
And no step asks an agent to create, copy, set up, link or repair a workspace
  by steps of the agent's own choosing.
```

- [ ] AC-1: the workspace maker is run unchanged and its answer is passed on word for
- [ ] AC-2: no step asks an agent to create, copy, set up, link or repair a workspace

```yaml
- 'Entry surfaces to change: templates/commands/plan-feature.md (today calls Workflow
  without the pre-flight, so that entry always stops with ''MISSING pre-flight''),
  templates/skills/plan-feature/SKILL.md, templates/commands/build-feature.md, templates/commands/fast-lane-build.md,
  templates/commands/quick-fix.md and templates/skills/quick-fix/SKILL.md, templates/commands/finalize-feature.md,
  templates/skills/build-single-ticket/SKILL.md, and templates/skills/feature/SKILL.md.'
- Exactly one skill is THE workspace skill. Prefer repurposing the existing `feature`
  skill (one maker invocation, stop on a non-zero exit, relay the JSON answer) so
  no new package surface is registered; if a new skill is created instead, it must
  be registered in config/skill_registry.json and the feature skill reduced to a pointer.
- Each entry runs the maker as ONE command with an absolute path (the path `worktree.py
  where` prints, or the resolved install path) -- never a cwd-relative `python scripts/...`
  and never a compound shell command (prompt-audit checklist). On a non-zero exit
  it stops and does not invoke the workflow; on exit 0 it passes the parsed answer
  verbatim as args.workspace.
- Entries that cannot know the work identity before the workflow resolves it (e.g.
  build-feature's epic resolution) leave the workspace to the workflow's one verbatim
  dispatch (BO-4300a-1-ia); the skill text must not describe any other way.
- No surface keeps its own step-by-step recipe (clone, worktree add, symlink or copy
  of .leafcutter / .pre-commit-config.yaml, manual build); the epic recipe in the
  feature skill and its project-specific 'import settings' check are deleted.
- Skill and command templates reach consumers only through the build; edit templates/,
  never .claude/ directly.
- 'TICKET LOCATION (KI-BO-20260925-build-single-ticket-treats-ticket-path-final-as-worktree-path;
  routed from BO-4300a-1-ii, lands in the SAME change set as it): templates/skills/build-single-ticket/SKILL.md''s
  step 1 runs the maker with --ticket <the ticket''s main-copy path> and maps TICKET_PATH
  ONLY from ticket_path_in_worktree of the ok answer. The ''ticket_path_final -> TICKET_PATH
  (the ticket''s path inside the worktree)'' mapping is deleted, and no step of the
  skill reads, edits or moves the ticket at the path it was given.'
- 'Commit spelling (KI-CG-20260925-commit-delegation-hook-misses-git-dash-c): no entry
  surface this record rewrites spells a commit as `git -C <path> commit` (build-single-ticket,
  quick-fix and plan-feature skills carry that spelling today); commits are delegated
  to the commit agent per CLAUDE.md Commit Delegation. -C is acceptable only for non-commit
  git verbs.'
```
