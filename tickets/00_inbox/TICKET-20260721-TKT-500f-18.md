# The kebab-to-graph-id mapping is obtained from a side-effect-free source that does not reconfigure global logging on import

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `TKT-500f-18` — The kebab-to-graph-id mapping is obtained from a side-effect-free source that does not reconfigure global logging on import — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `TKT-500f-18`. Component: `ticket-creation`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given the generator module scripts/ac_store/generate_ticket_from_ac.py is
  imported,
When the kebab-to-graph-id mapping used to normalise the components LIST is
  obtained,
Then the mapping is read from a side-effect-free source — parsing
  docs/components.json or importing a plain data module — rather than from a
  module whose import runs configuration side effects,
And importing the generator does NOT reconfigure global logging: no
  logging.basicConfig call (or equivalent root-logger reconfiguration) runs as a
  side effect of importing the generator or the mapping source,
And a program that imports the generator keeps whatever root logging
  configuration it had before the import (handlers and level are unchanged by the
  import).
```

- [ ] AC-1: the mapping is read from a side-effect-free source — parsing
- [ ] AC-2: importing the generator does NOT reconfigure global logging: no
- [ ] AC-3: a program that imports the generator keeps whatever root logging
