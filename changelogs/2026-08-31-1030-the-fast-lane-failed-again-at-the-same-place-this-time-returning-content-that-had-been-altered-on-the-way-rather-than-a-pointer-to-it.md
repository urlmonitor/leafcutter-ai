description: "The fast lane carries its layered context bundle from a Python assembler into the workflow through an agent's return value, as a text field the agent is asked to fill with the assembler's output verbatim. The first occurrence of this defect saw the agent write the bundle to disk and return the path instead of the text; the entry concluded that the payload was simply too large for that contract to hold and listed three possible shapes for a fix. The cheapest of the three was adopted: state the expected size in the prompt and refuse a reply that names where the text can be found rather than containing it. The entry described that option at the time as the least robust of the three, on the grounds that it argues with the model instead of changing the design. A run today, pointed at the technical-constraint child of the deploy fail-closed criterion, failed at the same phase anyway, and the manner of the failure is worse than the first. The agent did not return a pointer. It returned the content in the field, as asked, with every piece of markup in it escaped as though for display in a web page: the arrows in the architecture document's diagrams arrived as entity references, and the cache-breakpoint marker, which begins with an angle bracket, arrived escaped twice over. The source document on disk contains no such entities anywhere, so the alteration happens in transit and is not present in the input. Three consequences follow and each is more serious than the first occurrence. The guard introduced specifically to catch the first occurrence cannot see this one, and is not malfunctioning: it distinguishes a reference from content, and what arrived is content. It is simply content that is not what was sent. The size explanation is also wrong. The first occurrence carried about a hundred and fifty kilobytes and the entry reasoned that the contract was unsound at that scale; the agent reported just over eighteen kilobytes this time, which is below the twenty the prompt itself states as the expectation, so the contract failed at precisely the size it was designed for. Reproducing markup byte for byte is not something a model does dependably at any length. And the only reason this was caught at all is that the assembler happens to insert a marker whose absence the lane checks for cache-correctness reasons. Nothing in the lane compares what arrived against what was assembled. A bundle carrying no marker-shaped token would have been passed to the test-writing and coding dispatches as though intact, and the run would have finished green on a corrupted prompt. The entry now records that the shipped mitigation has been tried and has failed at its design size in a way its own new guard cannot detect, that the remaining fix shape which does not require a filesystem primitive the engine lacks is to have the assembler return a small verdict and gate on that rather than on the text, and that whichever shape is chosen the lane needs an integrity comparison — a size or digest produced at assembly and re-derived on what was received — because looking like content is demonstrably not the same as being the content. The operational consequence is stated plainly for whoever picks this up: the fast lane cannot currently complete a run on any target, and both occurrences abandoned a worktree several agents in."
