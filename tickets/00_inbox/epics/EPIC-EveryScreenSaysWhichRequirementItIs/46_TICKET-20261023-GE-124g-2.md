## Implementation Notes

```yaml
- THE BANNED-WORD SET IS AN EXPLICIT, IMPORTABLE CONSTANT — at minimum verified, covered,
  proven, tested, satisfied — checked against every message the declaration gate emits
  for a PASS, case-insensitively and including inflections (verify/verified/verification,
  prove/proven, cover/covered/coverage). Enumerating it is what makes this testable
  rather than a matter of taste. The message must say DECLARED and name where.
- THE MESSAGE CLAUSE IS NOT COSMETIC. A gate that behaves correctly while printing
  'UXP-607 verified' teaches every reader the wrong thing, and the reader is the mechanism
  by which the substitution actually happens — nobody writes a line of code saying
  a declaration is a test; they read a green message and stop looking.
- 'NO TOOL MAY DERIVE done FROM A DECLARATION-GATE PASS. Audit the writers, not just
  the gate: mark_ac_done.py, the fast-lane completion path, and any agent or workflow
  that flips work_status must have no code path in which the declaration gate''s result
  is an input to that decision. This is a search-and-assert obligation across the
  store''s write surfaces, not a property of one module — which is why this is M and
  not S.'
- THE TWO OBLIGATIONS ARE INDEPENDENT INPUTS TO 'IS IT FINISHED', COMBINED BY CONJUNCTION.
  A UI criterion is unfinished if EITHER is unmet, and each report names the specific
  obligation. GE-124e-3-i owns the enforcement-side independence (the two gates must
  FAIL independently); this AC bounds what PASSING one of them is worth. Both are
  needed and neither substitutes for the other.
- NO CONFIGURATION KEY MAY MAKE THE DECLARATION GATE SATISFY, RELAX OR STAND IN FOR
  THE TEST-PROOF OBLIGATION, and the key must be refused by name if supplied (GE-124g-1-i).
- 'THE WORKED CASE IS KM-ADM-004: pinned on a real element with covered_by empty.
  The mock-data artifact carries it deliberately so the dataset cannot be read as
  making a pin substitute for coverage — use it as the fixture rather than inventing
  one.'
```
