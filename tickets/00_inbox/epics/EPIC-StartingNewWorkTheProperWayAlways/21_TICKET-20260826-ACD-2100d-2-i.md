# An install that replaces a locally changed generated file says so rather than replacing it silently

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `ACD-2100d-2-i` — An install that replaces a locally changed generated file says so rather than replacing it silently — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `ACD-2100d-2-i`. Component: `ac-driven-dev`. Assigned agent: `python-coder`. Estimated complexity: `S`. Complexity: `low`.

## Acceptance Criteria

```gherkin
Given an installed route file that has been changed since it was installed so
  that its contents differ from what the installer would produce,
When the installer runs,
Then it states in its output for that run that a local change is being replaced
  and names the file,
And the file's contents after the install are what the installer produces,
And a file that has not been changed since it was installed produces no such
  statement.
```

- [ ] AC-1: it states in its output for that run that a local change is being replaced
- [ ] AC-2: names the file
- [ ] AC-3: the file's contents after the install are what the installer produces
- [ ] AC-4: a file that has not been changed since it was installed produces no such

## Implementation Notes

```yaml
- The install still wins. This does not make the installer refuse, preserve the local
  change, or prompt -- build output is generated and must be regenerated. The requirement
  is that the loss is announced, not prevented.
- The statement must fire only for files that actually diverged. Every generated file
  is replaced on every install; a message for each one is noise that gets filtered
  and then ignored, which is the same as no message.
- Divergence must be determined by the same computation ACD-2100d-2's delivery check
  uses. Two independent determinations will disagree, and a disagreement here means
  the check reports clean while the installer silently discards a repair -- the 2026-08-18
  incident exactly.
- The statement must name the file. A count of replaced files does not let the operator
  recover the change they are about to lose.
- The statement must appear in the installer's own output for that run, on a stream
  an operator running the installer normally sees -- not only in a log file that has
  to be sought out.
- 'Must satisfy the repository error-handling policy: reading the pre-install contents
  is external I/O and a failure to read must not silently suppress the statement.'
- Must not measurably slow a clean install -- the common case is that nothing diverged.
```
