# Whoever reads the reports afterwards finds every drive's reports in one place

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `INF-500d-4-v` — Whoever reads the reports afterwards finds every drive's reports in one place — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `INF-500d-4-v`. Component: `infrastructure`. Assigned agent: `python-coder`. Estimated complexity: `L`. Complexity: `high`.

## Acceptance Criteria

```gherkin
Given reports are filed from two different temporary workspaces belonging to two
  different drives of the same project,
When both workspaces have been removed,
Then both sets of reports are readable from the one durable location, without the
  later drive having overwritten or displaced the earlier drive's records.

Given the operational log directory also holds the agent-telemetry log and the
  knowledge-emission log, which are written by the same drives with the same
  workspace-relative lifetime and are destroyed the same way,
When the durable location is adopted for the report sink,
Then a reader looking for any of those logs after the workspace is gone finds them
  all in one place.
```

## Implementation Notes

```yaml
- EVERY READER'S DEFAULT IS THE DECLARED VALUE. Without an explicit path argument,
  aggregate.py, list_tags.py, link_feedback.py, resolve_feedback.py and trend_report.py
  read feedback_sink, and generate_health_report.py reads feedback_sink and operational_telemetry_stream,
  all from the workspace's own deployed config/knowledge_sink.json. This replaces
  the Path(__file__).resolve().parents[3] defaults, the _find_project_root walk, trend_report.py's
  upward search for debugging/logs/feedback.jsonl, and generate_health_report.py's
  CWD-relative defaults. One reader of the declaration, or several that read the same
  keys from the same artefact; never an independently computed root.
- 'link_feedback.py and resolve_feedback.py REWRITE records in the sink. They must
  rewrite the declared sink, and must not lose an append that a concurrent drive makes
  during the rewrite: hold the same exclusive lock submit_feedback.py takes for the
  whole read-modify-write.'
- EVERY READER STATES WHERE IT LOOKED. Each reader prints one stderr line naming the
  absolute sink it read and how many records it found (KI-FC-001's 'read N records
  from <path>'), so a low count can be traced to its cause. Existing stdout formats
  stay unchanged for their current consumers.
- 'RELOCATION IS STATED, NOT MIGRATED (INF-400c-4-v''s clause, applied to feedback).
  Where a populated feedback.jsonl exists at a known pre-declaration location that
  differs from the declared feedback_sink, a reader names both paths once. The candidate
  set is derived from the declaration and the output root, never hard-coded: <output_root>/debugging/logs/feedback.jsonl
  is the install-tree sink KI-FC-001 measured at 131 records on 2026-09-30. Readers
  never merge, copy, move or delete either file. reports/feedback-snapshots/ is the
  accepted one-off rescue of history.'
- NO FALSE-QUIET ZERO. With no usable declaration and no explicit path, a reader must
  refuse with a non-zero exit and a stderr line naming the expected declaration. It
  must not read a CWD-relative file and report 0 records, which is how a working subsystem
  came to be judged dead (KI-FC-001, 2026-09-30).
- Read-only readers (aggregate, list_tags, trend_report, generate_health_report) must
  create no file or directory as a side effect of resolving the path.
- Explicit --jsonl / --feedback / --telemetry arguments are honoured as given.
- 'Deployed/template parity (ADR-001): edit the sources and verify the deployed copies
  through the build round-trip. Any new shared module must be in the deploy manifest
  of every deployed reader.'
- Must handle errors gracefully per the project error handling policy.
```
