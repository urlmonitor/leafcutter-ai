## Acceptance Criteria

```gherkin
Given generation G32 is the active generation of repository R1
And a second repository R2 in the same database holds its own 4 generations
And a publication of generation G33 for R1 has stored 10,700 nodes and 28,000 relationships tagged to G33
When that publication then fails because its count check reports 28,814 relationships expected and 28,813 kept
Then before the publication operation returns, the store holds 0 nodes and 0 relationships tagged to G33
And no generation record for G33 remains in a state that reads as building or active
And G32 is still the active generation of R1 and its node and relationship counts are unchanged
And R2's 4 generations are unchanged in count, canonical identity and content
And the operation reports failure, carrying the original cause: the count check, the mismatched kind and both figures
And the result states that the failed generation G33 was removed, with the number of nodes and relationships removed
And that removal is reported separately from the count of retained generations reclaimed, which stays 0 for a failed publication

Given a publication of G33 for R1 has stored part of its generation
When that publication fails because the backend reports itself unavailable for a write
Then the same removal of G33's nodes and relationships is attempted within the same operation
And the operation reports failure carrying the backend-unavailable cause

Given a publication of G33 fails during snapshot validation, before any node or relationship of G33 is stored
When the operation returns
Then no removal is attempted
And the result states that nothing was stored for G33
```
