# A check registered without a cannot-run disposition is named as a gap, never silently defaulted

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-120a-2-i` — A check registered without a cannot-run disposition is named as a gap, never silently defaulted — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-120a-2-i`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `S`. Complexity: `low`.

## Acceptance Criteria

```gherkin
Given a check is added to the registry with no cannot-run disposition recorded,
When the guardrail engine validates its own registry,
Then it names the newly added check and states that its cannot-run disposition is
  missing,
And it does not assign a disposition on that check's behalf,
And the validation result is a failure, not a warning that scrolls past among other
  output,
And the same result is produced whether the registry is validated from the main
  checkout or from a separate working copy.

Coverage note: exercise this by adding a disposition-less entry to a registry fixture and
running the validation, asserting on the observed failure and the named check. A test
that only asserts every current check has a disposition passes forever and catches
nothing on the day check nineteen is added.
```

- [ ] AC-2: it does not assign a disposition on that check's behalf
- [ ] AC-3: the validation result is a failure, not a warning that scrolls past among other
- [ ] AC-4: the same result is produced whether the registry is validated from the main
