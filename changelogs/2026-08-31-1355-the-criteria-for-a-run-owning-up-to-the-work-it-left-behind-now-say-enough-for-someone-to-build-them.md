summary: "Technical enrichment of the seven criteria covering the half of the layered-epic defect that is about reporting rather than fixing: that work a run left unbuilt is counted, named, attributed to a cause only where the cause can actually be established, and never quietly reattributed to a cause the run cannot know."
description: "When driving an epic builds only the work that has no prerequisites, there are two separate failures and only one of them is about building. The other is that the run's account of itself is wrong: the twenty pieces it never scheduled were reported as work that had been added to the epic after the plan was fixed, which is a cause the run has no way to establish. Criteria covering this were authored five days ago and amended the same day precisely because the first draft demanded that attribution, and the amendment introduced an explicit not-determined outcome for cases where the evidence does not reach. What was missing was everything an implementer needs: no assigned agent, no complexity, no requirements mapping, and no test contract on any of the seven records. That layer is now written. The contracts are aimed at this family's specific way of looking correct while being wrong. The current implementation already emits a well-formed report with the right count and already withholds the finished claim, so a test asserting that unbuilt work was reported passes against the broken code and the fixed code alike; the discriminating assertion has to be on the value of the cause for a piece of work known never to have been selected, and on the emitted sentence rather than a field name, because renaming the field is the cheapest wrong repair and changes nothing an operator sees. The not-determined outcome is written as an obligation rather than an escape: one contract pins a case where the cause is establishable and requires the specific cause to be stated, and its pair pins a case where it is not and requires the explicit not-determined label instead of a guess, so an implementation that labels everything not-determined goes red. A further contract protects the verdict that was already right, because a change that fixes the label while losing the withheld completion claim would pass every attribution assertion. Eleven places where the behavioural criteria were under-specified for implementation are pinned in the requirements mapping rather than by editing the criteria: among them, that the count must be taken from the named set rather than by subtraction, with a boundary case adding one and removing one that only that assertion catches; that the breakdown and the count must be one object rather than three lists checked for agreement, which would recreate the disagreement; and that the remedy text must be selected by the cause in code rather than printed beneath it, which is the same right-by-accident shape the defect itself has. One departure from convention is recorded rather than taken silently: the reference page keeps a test contract instead of being marked untested, because the cause vocabulary lives in exactly two places and nothing else compares them, so parity in both directions is a real risk rather than documentation ceremony. Two wording questions were left open for the analyst rather than resolved by invention."
