## Acceptance Criteria

```gherkin
Given an AC is a candidate to be released to a builder,
When the implementation-readiness gate evaluates it,
Then an AC in the "no declared files" state (ACD-1600c-4-ii) is flagged NOT
  implementation-ready with the reason "missing file targets", even when its technical
  requirements or documentation links name file paths,
And an AC whose declared-files list names at least one file is never flagged
  "missing file targets", whatever its technical requirements say,
And an AC that lacks a test contract (a test_spec) is flagged NOT implementation-ready,
And a flagged AC is held back for enrichment instead of being dispatched to a coder,
And the flag names which of the two is missing, as "missing file targets" and/or
  "missing test contract",
And those two reasons are values of the store's single hold-reason list, which also holds
  "test design pending", "reference file pending" and "file finding undecided"
  (owned by ACD-2500b-2), so a record held for one of those other reasons is reported
  under that reason's own name and is never folded into one of these two.
```

## Implementation Notes

```yaml
- 'Canonical source to change: scripts/ac_store/scan_ac_store.py (the leaf-readiness/completeness
  gate; source-only Python, no templates/ counterpart).'
- The gate must raise 'missing file targets' exactly when the declared-files seam
  (ACD-1600c-4; AC field declared_files) answers 'no declared files' (ACD-1600c-4-ii),
  and must never raise it for a record whose declared list names at least one file.
  Paths named in it_requirements, doc_links (any relationship) or reference_file_path
  neither raise nor clear the reason.
- 'The gate must flag an AC lacking a test contract (a test_spec, or an explicit test_required:
  false) as NOT implementation-ready.'
- The flag must name which of {file targets, test contract} is missing — and both,
  when both are missing.
- Reason strings must come from the single hold-reason list (docs/reference/ac-schema.md
  plus one code constant) defined by ACD-2500b-2 — never a second, gate-local list.
  If this AC builds before ACD-2500b-2, it creates that one list holding its two values
  and ACD-2500b-2 extends it in place.
- 'The gate must not restrict its output to the two reasons it owns: a record carrying
  another listed reason must keep that reason in the report unchanged.'
- The held-back decision must be data-driven on the declared-files seam's answer and
  the test-contract fields, never keyed on specific AC ids, and the gate must not
  parse declared_files itself.
- Gates on enrichment COMPLETENESS, complementary to and distinct from the approval-readiness
  gate (ACD-1200b). Ship advisory before required and grandfather schema_version <
  2 ACs (ADR-026 rules 3-4).
- 'MIGRATION, EXPLICIT: no record written before ACD-1600c-4 declares files, so every
  such record carries ''missing file targets''. The advisory-first / schema_version
  < 2 exemption above therefore stays in force: while the gate is advisory, and for
  any record reading as schema_version < 2 (absent schema_version reads as 1 -- today
  that is every record, since ACD-1900a has not landed the slot), the reason is REPORTED
  but the record is NOT held back from dispatch. Holding applies only to schema_version
  >= 2 records or once the ADR-026 enforce flag is on (permitted only when zero schema_version
  < 2 records remain). This AC must not switch the flag on or bump any record''s schema_version.'
- Tests that assert holding run the gate in enforce mode (or on a schema_version >=
  2 fixture); a separate test asserts a schema_version-absent record is reported with
  the reason and still dispatchable in advisory mode.
```
