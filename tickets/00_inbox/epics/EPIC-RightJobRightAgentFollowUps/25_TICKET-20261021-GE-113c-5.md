## Implementation Notes

```yaml
- Canonical source templates/scripts/commit_guardian/check_adr_cross_reference.py.
- The check gets the project root only through the shared resolver of GE-113c-1-iv;
  no Path(__file__).parents[N] root remains in it.
- The proof runs the built, installed copy the way .pre-commit-config.yaml invokes
  it, in a temporary repository with staged fixture documents, independent of the
  developer's working tree.
- 'The ''read none of its targets is not a pass'' outcome: GE-120a-4 has no shared
  helper (its rule is implemented inside scripts/ac_store/validate_ac_schema.py, which
  is source-only). The reusable mechanism is the shared outcome vocabulary of GE-120a-1,
  templates/scripts/commit_guardian/check_outcome.py (emit_result with OUTCOME_COULD_NOT_CHECK):
  staged targets named but none readable emits that outcome and does not exit as a
  clean pass; no staged target in scope stays an ordinary pass (GE-120a-4''s boundary).
  check_outcome.py is imported, not changed, so it is not a declared file.'
- Canonical sources only; deployed and installed copies are regenerated by the build
  and never hand-edited (ADR-001).
- Every path the check reads (staged files, docs/components.json, the decision-record
  folder) resolves from that one project root. The check's strict setting is not changed.
- Before merge, run the working check once over every existing decision record. Each
  finding is fixed or filed as a known issue naming the document.
```
