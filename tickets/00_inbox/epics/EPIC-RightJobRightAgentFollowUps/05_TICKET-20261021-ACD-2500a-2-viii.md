```yaml
- 'A run with no before-state writes no file at all (user decision, 2026-10-16): the
  guarded writer is not invoked, whatever the stage or family.'
- Families that would repair without needing a before-state still evaluate and report
  the repair as 'needs a decision', with the value that would have been written in
  detail.
- 'The ''no before-state, nothing repaired'' statement is the additive top-level report
  key before_state, an object {given: bool, repairs_applied: bool} (false/false on
  such a run); under the report''s sort_keys output it sorts before family_counts
  and findings, which is how ''before any finding'' is met. stdout stays one JSON
  document and consumers ignore keys they do not know.'
- An authoring stage run without a before-state still ends with verdict failed (the
  existing fail-closed rule stays); the change is only that nothing is written.
- /plan-feature's stage-end runs, which always pass --before-ref, behave byte for
  byte as before.
```
