# Blind-catch handler is cleared only by genuine WARNING-or-higher logging

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-108b` — Blind-catch handler is cleared only by genuine WARNING-or-higher logging — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-108b`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Scenario: A user-defined function that merely shares a logger-like name does not clear the handler
  Given a production Python file with a blind `except Exception:` handler
    whose body's only call is to a locally defined function named `error()`,
    `info()`, or `debug()` that is not a project logger,
  When the exception-handling guard analyses the file,
  Then it emits a silent-handler (BLE001) violation for that handler,
  Because a name coincidence is not genuine WARNING-or-higher logging.

Scenario Outline: Logging below the WARNING threshold does not clear the handler
  Given a production Python file with a blind `except Exception:` handler
    whose body's only logging call is `<below_threshold_call>` and which does
    not re-raise,
  When the exception-handling guard analyses the file,
  Then it emits a silent-handler (BLE001) violation for that handler,
  Because the Error Handling Policy requires logging at WARNING or higher.

  Examples:
    | below_threshold_call |
    | logger.debug(...)    |
    | logger.info(...)     |
    | print(...)           |

Scenario Outline: Genuine WARNING-or-higher logging clears the handler
  Given a production Python file with a blind `except Exception:` handler
    whose body calls `<accepted_call>`,
  When the exception-handling guard analyses the file,
  Then no silent-handler (BLE001) violation is emitted for that handler.

  Examples:
    | accepted_call          |
    | logger.warning(...)    |
    | logger.error(...)      |
    | logger.critical(...)   |
    | logger.exception(...)  |

Scenario: Re-raising clears the handler regardless of logging level
  Given a production Python file with a blind `except Exception:` handler
    whose body re-raises the exception (bare `raise` or `raise NewError from
    exc`) and performs no WARNING-or-higher logging,
  When the exception-handling guard analyses the file,
  Then no silent-handler (BLE001) violation is emitted for that handler.
```
