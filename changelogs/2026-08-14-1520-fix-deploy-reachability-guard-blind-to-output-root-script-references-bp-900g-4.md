summary: "Fixed the /build-ac command failing immediately in any installed project, and closed the build-time blind spot that let it ship — the build now catches scripts an agent needs but never deploys."
description: "_PYTHON_INVOKE_RE in build_referential_integrity.py required whitespace immediately before 'scripts/', so every reference written in the output-root form agent templates actually use — 'python3 {{config.output_root}}/scripts/<path>.py' — never matched and was silently skipped by _check_script_reference_guard. The pattern now accepts an optional single-segment prefix (the literal {{config.output_root}}/ token or a rendered form such as .leafcutter/) and normalises the capture to the bare scripts/... deploy-namespace key; the prefix is bounded to ONE segment so an unrelated vendor path cannot produce the false-positive build failures EPIC-BuildGuardFalsePositive already had to fix once. The two sys.path.insert patterns are deliberately NOT widened, because the only output-root-form occurrence names a DIRECTORY (scripts/ac_store) that is absent from the .py-only deployable manifest and would abort every build. Three concrete defects the blind spot was hiding are fixed: (1) scripts/build_orchestration/ had no deploy phase at all, so the deployed build-ac agent died at Step 2b.1 with \"can't open file .../fast_lane.py\" — added build_build_orchestration_scripts() plus _manifest_build_orchestration_scripts() and a matching _get_source_paths_for_guard scan so the two sets stay 1:1; (2) goal_to_epic.py and build_ac_mode_detection.py were absent from the deployable manifest entirely, because the registration looked for them under templates/scripts/ where neither has ever lived, while build_ac_store deploys them into scripts/ac_store/ — now registered under their real deploy path; (3) scripts/ac_store/ac_parent_id.py was missing from build_ac_store's deploy_map, so even once fast_lane.py was present it still failed at module-scope import — caught only because the covering test EXECUTES the deployed script rather than asserting its presence. templates/agents/build-ac.md Step 2b.1 also had --ac-root pointing at an output-root-prefixed path that exists in no layout; it now reads docs/acceptance-criteria, matching the form the same template uses elsewhere. Widening the pattern made nine further pre-existing broken references visible (changelog/emit_entry.py, next_diagram_seq.py, retrospective/extract_epic_facts.py, agent-health/generate_health_report.py, roadmap_query.py, package_audit.py, and the sourceless check/prod_status_check.py); these are parked in a new, clearly-separated KNOWN_UNDEPLOYED_ALLOWLIST with AC BP-900g-5 to burn it down, so the build stays green and the gaps are explicit rather than silent. Covered by AC BP-900g-4 and seven tests in unit_tests/test_bp_900g_4.py, including a negative control against over-widening and an end-to-end test that runs the deployed fast_lane.py as a subprocess and asserts the GE-113c-3 connected set."
