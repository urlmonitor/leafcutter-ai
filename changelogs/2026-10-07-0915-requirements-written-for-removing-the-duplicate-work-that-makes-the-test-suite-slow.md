summary: "Several groups of tests each rebuild the whole package from scratch and then check different things about the one result. Nine acceptance criteria now describe building it once per group instead, without any test checking less than it does today."
description: "Adds TQ-600a-9, TQ-600a-10 and TQ-600a-13 with six technical-constraint children beneath them, under the existing feature criterion TQ-600a, 'Expensive setup is paid for once, not once per test'. They are written against a measured per-file analysis of the suite rather than an estimate: the full run is 6432 seconds, roughly 1700 of which sits in tests that each start a real build subprocess costing between thirteen and sixty seconds. TQ-600a-9 covers the groups whose members differ only in what they assert about one build, scoping the six-file BP-1500g family, the consumer-install test, and the tracked-files build guard; it requires the saving be counted from an actual run rather than asserted, and the elapsed time be at most two thirds of a baseline taken in the same sitting. Its three children carry the conditions that stop the change being a false economy: a member that writes gets its own copy, breaking one member's subject must redden exactly that member and no other, the tracked-files guard keeps building the expensive way because testing that path is its purpose, and the one case that would revise a previously recorded decision is separated out so it can be refused without blocking the rest. TQ-600a-10 covers a test file that copies the entire eleven-thousand-file checkout eight times where a twenty-times-smaller helper already exists for the same need; it deliberately states no figure, because the copy was never timed, and instead requires the measurement be taken and the change reverted if it shows nothing. Its children require that a path the smaller copy omits fails loudly, which matters unusually here because those tests assert that a build FAILS, so a smaller copy could turn a real pass into a coincidental one. TQ-600a-13 records that a naming convention claiming to exclude the slowest tests from the default run excludes nothing: the documentation states it, no marker, selection flag or skip hook implements it, and the timing data shows one such test ran. It leaves open whether the documentation or the behaviour changes, and its child requires that choosing exclusion must not quietly delete coverage. The parent's child limit was raised from twelve to thirteen with the reason recorded, and a false premise in the previous raise was corrected: two identifiers it described as authored elsewhere had only ever been reserved in prose."
