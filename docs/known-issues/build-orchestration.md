# Known Issues: Build Orchestration

Observed directly on 2026-08-19 while driving `EPIC-GE122UniquenessPassAndRepair`.

## KI-BO-1 — `build.py` generates tracked agent cards the frontmatter gate rejects

**Severity: medium.** A generated, tracked artifact cannot be committed without
skipping a gate.

`docs/agents/cards/*.card.md` are build outputs regenerated by `build.py`, and
they are tracked in git. Committing one fails `check-doc-frontmatter`:

```
FRONTMATTER VIOLATION: 'docs/agents/cards/documentation-verifier.card.md'
   Missing required field: 'components'
   unknown doc type: card; valid values: adr, architecture, explanation,
   how-to, reference, retro, tutorial
```

So the build produces a file the doc gate is not taught to accept. Hit while
trying to commit the card reflecting a genuine `documentation-verifier` template
change — the card was dropped from the commit rather than skipping a gate to land
a build output.

**Suggested fix.** Either teach `check-doc-frontmatter` the `card` type (and have
the card generator emit `components`), or stop tracking generated cards and add
them to `.gitignore` alongside the other build outputs. The current halfway state
— tracked, generated, ungateable — is the worst of the three.

**Note:** the hook's own error message points at `docs/FRONTMATTER.md`, which does
not exist in this repository. A second, smaller dangling reference.

## KI-BO-2 — Committed agent cards drift from the AC store

**Severity: low,** but it makes every build dirty the tree.

Running `build.py --force` regenerates eight agent cards with AC-store content
that is not in the committed versions (entries such as `ACD-1600g-*` and
`ACD-1800a-*`, belonging to unrelated components). The committed cards are simply
older than the store.

The practical consequence: any build during unrelated work leaves eight modified
files in `git status`, which must be excluded from every commit by hand, and
which makes a genuinely-related card change easy to miss in the noise.

**Workaround.** `git restore docs/agents/cards/` for the unrelated ones before
staging, keeping any card that reflects a change actually made in the commit.

**Suggested fix.** Resolve together with KI-BO-1. If cards stop being tracked,
this disappears; if they stay tracked, they need a regeneration commit and a gate
that keeps them current.
