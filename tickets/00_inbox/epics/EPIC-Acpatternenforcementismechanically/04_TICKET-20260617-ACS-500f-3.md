## Acceptance Criteria

```gherkin
Given the AC store schema is validated against an AC record whose id uses a
  hierarchical form with a lowercase L1 segment and a numeric leaf suffix
  (e.g. "ACS-500a-1"),
When that record is validated against the schema,
Then the record is accepted (the id format does not cause a validation failure).

Given an AC record whose id uses an L3 extension form (e.g. "ACS-500a-1-i"),
When it is validated against the schema,
Then the record is accepted.

Given a pattern AC record that includes a pattern_slots field holding a list
  of {word} placeholder strings,
When it is validated against the schema,
Then the record is accepted, and the pattern_slots field does not cause a
  validation failure.

Given the set of AC YAML records that already exist in the store under
  docs/acceptance-criteria/,
When every one of those records is validated against the schema,
Then no currently-valid stored record is rejected by the schema.

Given a root-level AC id of the documented base form (e.g. "ACS-100"),
When it is validated against the schema,
Then it is still accepted (no regression for the base id form).
```
