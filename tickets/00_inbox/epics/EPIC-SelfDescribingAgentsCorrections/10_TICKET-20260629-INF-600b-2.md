## Acceptance Criteria

```gherkin
Given a ticket that references multiple L2/L3 ACs via its
  ac_traceability frontmatter field
  (e.g. ac_traceability: [INF-600g-1, INF-600g-2, INF-600g-3])
And the ticket's agents map assigns multiple agents
  (e.g. python-coder: needed, test-writer: needed)
And each AC YAML file has an assigned_agent field
  (e.g. INF-600g-1.yaml has assigned_agent: python-coder,
   INF-600g-2.yaml has assigned_agent: python-coder,
   INF-600g-3.yaml has assigned_agent: test-writer)
When the ticket body or agent card is generated
Then it includes a per-agent AC assignment section that groups ACs
  by their assigned_agent:
  "### python-coder
   - INF-600g-1: spawned_by/spawn_allowlist reciprocity validation
   - INF-600g-2: __ticket_phase_agents__ redundancy detection
   ### test-writer
   - INF-600g-3: skills_invoked cross-reference"
And each agent can identify exactly which ACs it is responsible for
  without inspecting ACs assigned to other agents
And the grouping enables agents to implement one AC at a time
  (sequentially within their assigned set) rather than attempting
  all ticket work at once
```
