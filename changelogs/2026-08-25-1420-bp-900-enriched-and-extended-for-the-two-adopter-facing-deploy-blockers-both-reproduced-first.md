Two new L3 acceptance criteria cover dimensions the existing set could not express. BP-900h-4-i requires the fix to be independent of the package directory's name, proven across a layout matrix that includes a real git worktree and a self-hosted control, and plants a decoy at the path the current lookup spells out so that adding a third hardcoded candidate fails the criterion rather than passing it. BP-900h-5-ii derives its startability set by walking the deployed tree rather than reading the guardrail registry, because validate_ac_schema.py appears in no registry and is therefore invisible to the existing set. No new criteria were authored for the blockers themselves: four already existed and were already approved, so the remedy was never to write an AC but to build the four that exist. Two tickets were generated, from BP-900g-8 and BP-900g-8-ii, which together address both reproduced symptoms. A third, from BP-900h-4, was generated and then withdrawn because it depends on BP-900h-1, whose ticket lives in the unmerged EPIC-DeploymentCompleteness branch; check-doc-frontmatter caught the dangling reference, and the empirical-verification layer correctly stays todo behind that fixture.
