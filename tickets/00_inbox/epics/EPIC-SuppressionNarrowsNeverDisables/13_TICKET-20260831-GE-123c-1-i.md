## Acceptance Criteria

```gherkin
Given the security allowlist's second line is
  "ENTROPY_HIGH:C:\\Users\\dev\\project\\secrets.py:*" — an author on Windows
  pasting an absolute path,
And "secrets.py" contains a high-entropy token the ENTROPY_HIGH rule reports,
When the allowlist is loaded and the file is scanned through the multi-file
  entry point,
Then the finding is reported — the entry suppressed nothing,
And exactly one warning is emitted on the error stream naming the allowlist
  file, the 1-based line number 2, and the verbatim text of that line,
And the entry is skipped,
Because the field boundaries fall at the first two separators, so the drive
  letter "C" becomes the whole file path and the rest of the path becomes the
  line-number field — an entry that parses cleanly into something the author
  never wrote and can never match.

Given the security allowlist's third line is "GENERIC_SECRET:secrets.py:12:extra",
When the allowlist is loaded,
Then exactly one warning is emitted for line 3 — one warning per offending
  line, not one per surplus field,
And the entry is skipped,
Because everything from the third separator onward is absorbed into the
  line-number field, leaving a value that is neither the wildcard nor a decimal
  line number.

Given the security allowlist contains the well-formed entries
  "GENERIC_SECRET:scripts/commit_guardian/check_paths_integrity.py:*" and
  "ENTROPY_HIGH:docs/agents/README.md:429",
When the allowlist is loaded,
Then no warning is emitted for either line and both entries are loaded and
  applied,
Because entries with two or three fields and nothing surplus are the ordinary
  form and must stay silent.
```

  announcement contract inherited from GE-113c-3-v is what the assertion protects.'

  or separator translation here; making such paths suppressible is a separate change
  with its own matching semantics.

  and propagate with build.py; never edit a deployed copy (ADR-001).

  the pre-commit check parses must remain free of diagnostics.

  root, workspace root or worktree root; every fixture allowlist lives under tmp_path/tempfile.

  environment-named files and never reads their content.
