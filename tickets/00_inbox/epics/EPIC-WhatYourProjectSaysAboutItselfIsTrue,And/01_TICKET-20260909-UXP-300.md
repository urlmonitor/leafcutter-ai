# Product-truth artifacts live in docs/product-truth with one canonical dataset per entity per component

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `UXP-300` — Product-truth artifacts live in docs/product-truth with one canonical dataset per entity per component — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `UXP-300`. Component: `ux-prototyping`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given the product-truth store,
When a flow, mock-data, or mockup artifact is authored,
Then it lives under docs/product-truth/ (flows/, mock-data/, mockups/),
And each entity has exactly one canonical mock-data artifact per component (extend, never duplicate),
And flows link to acceptance criteria via step.implements (flow -> AC), while AC -> flow is derived,
And scripts/validate_product_truth.py passes for the store.
```

- [ ] AC-1: it lives under docs/product-truth/ (flows/, mock-data/, mockups/)
- [ ] AC-2: each entity has exactly one canonical mock-data artifact per component (extend, never duplicate)
- [ ] AC-3: flows link to acceptance criteria via step.implements (flow -> AC), while AC -> flow is derived
- [ ] AC-4: scripts/validate_product_truth.py passes for the store.
