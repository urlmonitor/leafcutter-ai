# Approved stage output is committed before the next agent is dispatched

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `ACD-300g-1` — Approved stage output is committed before the next agent is dispatched — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `ACD-300g-1`. Component: `ac-driven-dev`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given the /create-ac workflow has completed a stage (PO v3, BA v3, or IT PO v3)
  and the authoring agent has written AC YAML files to the AC store,
And the user has approved the stage's output at the confirmation gate,
When the workflow prepares to dispatch the next authoring agent,
Then a git commit containing all AC files from the approved stage is created
  before the next agent begins,
And the commit is confirmed to have succeeded (exit code 0) before dispatch,
And the committed files are present in the repository history.

Given the /create-ac workflow follows the strategic route
  (PO v3 -> gate -> BA v3 -> gate -> IT PO v3 -> final gate),
When the user approves gate 1 (after PO v3),
Then the L0 and L1 AC YAML files produced by PO v3 are committed,
And BA v3 is not dispatched until the commit succeeds.

Given the user approves gate 2 (after BA v3),
When the workflow transitions to IT PO v3,
Then the L2 and L3 AC YAML files produced by BA v3 are committed,
And the parent AC updates (covered_by additions) are included in the same commit,
And IT PO v3 is not dispatched until the commit succeeds.

Given the user approves gate 3 (final gate after IT PO v3),
When the workflow completes,
Then the enriched AC YAML files modified by IT PO v3 are committed,
And the workflow reports success only after the final commit succeeds.
```
