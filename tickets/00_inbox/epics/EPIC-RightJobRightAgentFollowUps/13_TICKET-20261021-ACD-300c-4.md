## Implementation Notes

```yaml
- 'IT PO decision (the BA''s open call): the store''s one approval step, scripts/ac_store/approve_acs.py,
  gains an explicit id-list mode and a priority option. Readiness, priority and the
  single amended_by entry are written by that one step in one write per record; there
  is no second priority-writing step.'
- The id-list mode approves each listed id at any level, never expands an id to its
  children, and leaves the existing --goal and --ac modes unchanged.
- 'The workflow takes the hold report from the same approval step (its dry-run JSON
  report) and passes it only the ids reported not held. The step still checks holds
  on every id it is given: an id it holds is reported held and never written.'
- The approval is a deterministic workflow step with no agent dispatch, and it replaces
  today's status-checker apply-approval dispatch. No agent writes readiness or priority.
- 'Field-targeted writes only: readiness, priority and one appended amended_by entry
  change; every other byte of the record is preserved, and the write-then-read-back
  check stays.'
- The step's --json output keeps its exact {approved, held} shape; anything added
  is an additive key.
- The approve_acs.py CLI change is documented in docs/reference/ac-readiness-and-assignment-gates.md
  in the same change.
- 'templates/workflows-js/plan-feature.js is over its size limit and its measured
  length must not grow (GE-127b-1 growth ratchet): lines added are paid for by lines
  removed or by rationale comments moved to docs/reference/plan-feature-workflow-rationale*.md.
  Build after GE-127h-1 so decision-history lines are free.'
- Canonical sources only; deployed and installed copies are regenerated by the build
  and never hand-edited (ADR-001).
- approve_acs.py is not deployed today, while /plan-feature runs scripts from .leafcutter/scripts/ac_store/.
  approve_acs.py (and every module it imports that is not deployed yet) is added to
  the ac_store deploy map in scripts/build_phases_ac_store_rc.py, and the workflow
  invokes the deployed copy; the existing deploy-map parity checks must pass.
```
