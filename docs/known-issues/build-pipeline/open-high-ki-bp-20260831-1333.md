# KI-BP-20260831-1333 — `check-output-drift` blocks a commit on a gitignored cache file, so the gate fails on something no commit could ever contain

> One known issue, split out of `docs/known-issues/build-pipeline.md` on
> 2026-09-14. Index: [build-pipeline.md](../build-pipeline.md).
> Filename severity is the three-level index bucket (`high`); the
> original grading is the `**Severity:**` line below, unchanged.

- **Severity:** high
- **Status:** open — no AC
- **Occurrences:** 2 recorded through 2026-09-28, then repeated refusals on the BO-4300 epic drive
  through 2026-10-09 (see "Observed again" below; the 2026-09-28 count may already include that
  drive's first one)
- **First seen:** 2026-08-31 · **Last seen:** 2026-10-09
- **Where:** the `check-output-drift` pre-commit hook (leafcutter Direction B), its
  `gaps` classification

**Symptom.** A commit touching only `scripts/knowledge/`, `tests/knowledge/`,
`docs/acceptance-criteria/` and `changelogs/` was refused:

```
Check Output Drift (leafcutter Direction B).....Failed
- hook id: check-output-drift
- exit code: 2
UNCOMPARABLE: GAP .claude/.cache/readme_markers/fallback-125345.json
              action=run build.py to register it
RESULT verified=476 uncomparable=6 exempt=5 gaps=1 drifted=0 missing=0 unreadable=0
```

Note `drifted=0`. Nothing had drifted. The single `gap` is the whole failure.

**The file is gitignored.**

```
$ git check-ignore -v .claude/.cache/readme_markers/fallback-125345.json
.gitignore:15:.claude/.cache/    .claude/.cache/readme_markers/fallback-125345.json
```

So it can never appear in any commit, cannot be staged, and is unrelated to the diff being
refused. Its contents point at a *different* file again — `scripts/changelog/README.md` —
which the commit did not touch.

**The prescribed fix does not work.** `action=run build.py to register it` was followed:
a scoped `build.py --target-dir <worktree> --force` ran to completion, and the hook failed
identically afterwards. The marker was created during worktree bootstrap (timestamp 12:49,
before any of the work) and a sibling worktree from an earlier run does not have the
directory at all. Unblocked only by moving the file out of the tree by hand.

**Why this is worse than a nuisance.** A gate that fails on untracked, gitignored, machine-
local state makes its verdict a function of the developer's filesystem rather than of the
change. Two people with identical diffs get different answers, CI and local disagree, and
the documented remedy is a no-op — so the natural next move is `--no-verify`, which disables
every *other* hook in the same run. A gate that cannot be satisfied honestly teaches people
to skip the gate.

**Fix direction.** Exclude gitignored paths from the drift comparison entirely — if git will
not track it, the hook has no business gating on it. If cache markers genuinely need
verifying, that belongs in `build.py`'s own self-check, not in a commit gate. Failing that,
`gaps` on an ignored path should be reported as INFO and not affect exit status: `drifted=0`
should mean the hook passes.

**Related.** `KI-BP-20260826-1331` (shared deployed `.leafcutter/` as a per-worktree collage
— same root theme: build-output state that varies per checkout being treated as
commit-worthy truth).

**Occurrence 2 — 2026-09-27/28, still live, and why the scan reaches `.claude/.cache/` at all.**
Windows 11, leafcutter-ai worktree. A commit was blocked by
`UNCOMPARABLE: GAP .claude/.cache/readme_markers/fallback-<pid>.json action=run build.py to register it`,
the same shape as the first occurrence. Cleared by removing the marker by hand. Session observation. Reported by session leafcutter-6d (closed PR #928; carried over to main with its user's approval).

Mechanism, verified by reading the code on main `8ed47463` (line numbers below re-checked on `ae85a2a1`, where `check_output_drift.py` had shrunk):

- The marker is written by `templates/hooks/readme_marker_recorder.py` (`:29` `fallback-{ppid}`, `:53` the `.claude/.cache/readme_markers/` path) and is gitignored by `.gitignore:15` (`.claude/.cache/`).
- `check_output_drift.py` scans the union of its floor dirs (`.claude/agents`, `/skills`, `/commands`, `/hooks`, `/workflows`, `:825-831`) and the parent directory of every manifest key (`_derive_scan_dirs`, `:253-297`). The manifest has keys directly under `.claude/` (`.claude/settings.json`, `.claude/precommit-autofix.json`, `.claude/changelog_categories.md`), so `.claude/` itself becomes a scan dir.
- `_collect_output_files` then runs `rglob("*")` over it (`:247`) and excludes only `__pycache__`. It never consults `.gitignore`, so everything under `.claude/.cache/` is enumerated, and any file not in the manifest becomes a GAP (`:383-393`).

So the fix direction above can be made precise: skip git-ignored paths in `_collect_output_files` (one `git check-ignore --stdin` call over the collected list), or stop deriving a recursive scan from a key that sits at the top of `.claude/`. `_derive_scan_dirs` exists so that manifest and gate cannot disagree about where outputs live. It was not meant to make the gate own everything below `.claude/`.

## Observed again, 2026-10-09

**Where:** the epic worktree of EPIC-EveryPieceOfSeparateWorkGetsItsWorkspace, during the
`/build-feature` drive (2026-09-28 to 2026-10-09).

**What happened.** The gate refused ticket commits on
`GAP .claude/.cache/readme_markers/fallback-<n>.json action=run build.py to register it`. Ticket 02's
commit agent recorded the first one on 2026-09-28: `fallback-36684.json`, whose content named
`unit_tests/build_orchestration/README.md`, the ticket's own new README. The agent took the printed
remedy at face value ("it must be fixed (run `build.py` to register the new README), not bypassed").
The coordinator reports the same GAPs recurring for the rest of the drive, alongside the
rebuilds of the epic worktree (`build.py --target-dir <worktree>`) that each template-changing ticket
needed (`KI-BP-20261009-epic-worktree-install-goes-stale-per-ticket`).

**Why it costs more on an epic drive.** The printed remedy is the one action that does not clear it
(this entry, "The prescribed fix does not work"), but on an epic it is also the action the worktree
needs for a different gate, `check-build-drift`. So the agent's rebuild looks like the right fix,
clears the build drift, and leaves the GAP. A phase agent cannot tell the two apart from the hook
output.

**Duplicate in this register.** `KI-CG-20260929-output-drift-scans-gitignored-cache` records the
same defect, with the same remedy analysis, under `commit-guardian/`. The two should be merged.
This note is filed here because this is the earlier entry and the one that carries the
occurrence count.
