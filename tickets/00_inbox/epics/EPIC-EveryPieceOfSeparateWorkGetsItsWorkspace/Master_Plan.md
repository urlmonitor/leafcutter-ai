# EPIC-EveryPieceOfSeparateWorkGetsItsWorkspace

## Goal

This epic implements AC BO-4300: Every piece of separate work gets its workspace one dependable way.
It covers the 59 build ACs beneath BO-4300 (the L0/L1 records BO-4300 and BO-4300a..f are
composites with no ticket of their own; the superseded split records BO-4300a-1-i and BO-4300f-2-i
are not built).

## Re-cut 2026-09-28

The epic was first generated by `goal_to_epic.py` with one ticket per AC (59 tickets). Driving it
failed structurally:

1. **Dependencies followed the AC tree, not the code.** Tickets needed producers that were
   scheduled later (e.g. the old 02 / BO-4300a-1-ia needed the WORKSPACE-ANSWER block, the result
   schema and `args.workspace`; the old 56 needed the old 58's fixture module).
2. **files_touched was empty or wrong** (old 14 and 59: `[]`; old 04: only `scripts/build.py`; old
   46's fix lived in `worktree_admin.py`). Coders correctly refused out-of-scope edits and
   ac-fulfillment-gate could never auto-set `work_status`.
3. **Nearly every ticket edited the same maker files** (`worktree.py`, `worktree_git.py`,
   `worktree_admin.py`), so parallel tickets collided in the one shared worktree.
4. **Deadlock:** a ticket closes only when its source AC is done (check-ticket-ac-status-parity) and
   a composite AC closes only when all its children are done (check-done-proof); with one ticket per
   AC, parents and children had to be ordered by hand, and two composites (BO-4300a-1, BO-4300f-2)
   still listed a superseded child in `covered_by`, so they could never close.

User decision (2026-09-28): (a) re-cut by deliverable into tickets grouped by the files each owns,
each covering several ACs, with `depends_on` derived from the ACs' Expects From contracts; (b) one
new narrow `shell-runner` agent (`permits_shell: true`, runs one exact command, relays output
verbatim) that every shell-running workflow step moves to, with no existing agent's charter
changed -- delivered by ticket 10. The 58 generated tickets 02-59 were deleted (git history keeps
them); their review findings were harvested into the new tickets' Implementation Notes. Partial,
unreviewed code from the failed run is pinned at `refs/wip/bo4300-attempt1` (a stash commit;
untracked files in its `^3` parent) and is referenced as a starting point that must be
re-verified, never applied wholesale.

**How a multi-AC ticket satisfies the hooks.**
- `ac_traceability` uses the list form (`ac_path` + `l2` + `l3`), which
  `ac_coverage_resolver.py` resolves to every AC of the ticket, so ac-fulfillment-gate verifies and
  auto-fixes each one (work_status / implemented_by / covered_by) before commit. Accurate
  `files_touched` is what makes that auto-fix possible.
- `source_ac` names one anchor AC per ticket (the one most downstream tickets expect from); it is
  what check-ticket-ac-status-parity and `mark_ac_done.py --ticket` read.
- Every composite L2 AC sits in the same ticket as all of its children, listed children-first, so
  check-done-proof sees the children done in the same commit that marks the parent done. No ticket
  needs a parent AC done before another ticket finishes a child. The one cross-ticket composite is
  BO-4300a-1 (ticket 01): 01 depends on tickets 06, 09 and 10, which cover its three children.
- BO-4300a-1-i and BO-4300f-2-i were removed from their parents' `covered_by` (they are
  `status: superseded_by` their -ia/-ib splits, which remain listed).
- The L1s BO-4300a..f and the L0 BO-4300 close at epic finalisation via `mark_ac_done.py`, whose
  composite check passes once every child is done; this Master_Plan's `source_ac: BO-4300` means
  the plan itself can only be set `done` after that.

## Decided 2026-09-28 (recorded in the AC records and the tickets)

- **Q4 naming -- ticket 06** (contract: ticket 03; fixtures: ticket 02; cut-over: ticket 12): one
  scheme `<kind>/<slug>` for every kind; legacy spellings (`EPIC-<Name>`, `ac-authoring/`, `fast-lane/`,
  `feature/`) are per-kind aliases resolving to the same workspace. A hub line held only under a legacy
  spelling is resumed, never twinned; two spellings that both hold lines are refused `AMBIGUOUS_LINE`.
  ACs: BO-4300a, a-1, a-2, d-3-i, f-3, c-2, f-4.
- **Q5 landing place -- ticket 04**: sibling folder per project,
  `<parent-of-project>/<project-dir-name>-worktrees/<kind>/<slug>`, in the dev layout too; only an
  explicit `--landing-root` overrides it, and the maker validates it (USAGE when invalid).
  ACs: BO-4300b, b-2, b-2-i, a-1, f-4.
- **Q6 `leafcutter-ai/.leafcutter/` -- ticket 14**: must not exist -- deleted, and `scripts/build.py`
  refuses to build into the package repository without an explicit `--target-dir` (CI, build-self.sh
  and the maker all pass one). ACs: BO-4300b, b-2-ii, f-2, a-1.
- **Q8 remove authorisation -- ticket 08** (contract: ticket 03; docs: ticket 13): the `UNSENT_WORK`
  refusal returns a one-time `discard_token` bound to that workspace and its unsent set; only
  `remove --discard-token <that token>` discards; invalid for any other workspace or once the set
  changes; never env/config, never remembered. ACs: BO-4300e, e-3, e-3-i, e-5, a-5, c-2.
- **ADR folder in the f-2 census -- ticket 14** (coordinator): `docs/architecture/adrs/` is a record
  folder, excluded by folder with the other six.
- **Doc AC proof -- ticket 13** (coordinator): a-3, a-4, a-5, c-5, d-5, e-5 now declare
  `test_required: true` with a `test_spec` naming `test_bo_4300_docs.py` (one `# covers:` test each) and a
  `test_rationale`; no waiver.
