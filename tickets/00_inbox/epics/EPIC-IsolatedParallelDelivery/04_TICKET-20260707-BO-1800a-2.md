# Drive copies are created by the fastest safe strategy available, in a fixed preference order

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-1800a-2` — Drive copies are created by the fastest safe strategy available, in a fixed preference order — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-1800a-2`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given a new drive copy must be created from a warm local clone and a hub remote,
When the isolation layer creates the copy,
Then it attempts the creation strategies in this exact preference order and uses
  the first one that succeeds:
  1. a copy-on-write reflink copy of the warm local clone
     (`cp --reflink=auto`),
  2. else `git clone --reference <local-cache> --dissociate <hub>`,
  3. else a plain `git clone <hub>`.
And whichever strategy is used, the resulting copy has a fully independent object
  store — it borrows no objects from the warm clone or the cache at rest (a
  `--reference` clone is always `--dissociate`d), so it is safe to garbage-collect
  on its own without risking any other copy.
```
