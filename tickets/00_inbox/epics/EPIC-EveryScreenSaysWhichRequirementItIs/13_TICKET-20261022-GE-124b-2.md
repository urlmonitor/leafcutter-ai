## Implementation Notes

```yaml
- THE FLOOR TEST READS declares[] ONLY. The commit-tier decision 'does this file satisfy
  the component-level floor?' must be a function of the declaration record alone;
  pins[] must not appear anywhere in that predicate — not as a fallback, not as a
  downgrade input, not as a tie-breaker. The two collections are already separate
  at the reader (GE-124a-1-ii); this AC forbids re-joining them at the decision.
- THE PIN MAY ONLY ENRICH THE MESSAGE. Per GE-124c-1-i the single missing-component-declaration
  finding for such a file states that the file does pin KM-ADM-004 and that an element
  attribute never satisfies the floor. That is message content, produced from pins[]
  after the verdict is already fixed — verdict first, message second, never the reverse.
- 'NO PIN IS EVER REQUIRED PER DECLARED CRITERION. There must be no code path, and
  no configuration key, that emits a finding because a declared criterion has no matching
  pin. Scenario 2 is the load-bearing half: a criterion with nothing to point at (a
  validation rule, a sort order, a debounce) has no element, so demanding a pin would
  make the optional surface compulsory by the back door and contradict GE-124b-1 and
  GE-124e-2.'
- THIS AC IS ABOUT THE FLOOR, NOT ABOUT COVERAGE. Do not restate here that a pin is
  not a covering test — that guarantee is GE-124g's, decomposed across four places,
  and a fragment of it here would be the flattening the PO warned against.
```
