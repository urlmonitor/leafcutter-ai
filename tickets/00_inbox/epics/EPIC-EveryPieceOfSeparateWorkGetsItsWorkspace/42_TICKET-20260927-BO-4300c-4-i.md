# A location handed in by a caller is confirmed with the maker before any step runs

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-4300c-4-i` — A location handed in by a caller is confirmed with the maker before any step runs — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-4300c-4-i`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `S`. Complexity: `low`.

## Acceptance Criteria

```gherkin
Given a workflow is started with a workspace location supplied by whoever
  started it,
When the workflow begins,
Then it asks the workspace maker whether that location is a ready workspace for
  this work before any authoring, phase or delivery step runs,
And when the maker does not confirm it, the workflow ends with a failure naming
  the location it was given,
And when the maker confirms it, the workflow proceeds in that location.
```

- [ ] AC-1: it asks the workspace maker whether that location is a ready workspace for
- [ ] AC-2: when the maker does not confirm it, the workflow ends with a failure naming
- [ ] AC-3: when the maker confirms it, the workflow proceeds in that location.

## Implementation Notes

```yaml
- A location supplied by the starter (args.worktree_path / args.workspace_path) is
  confirmed by one verbatim `worktree.py verify --path <L>` (or locate) request before
  any working step; only an ok answer whose workspace_path equals L (path-equivalence,
  both spellings) lets the run proceed. Retires build-ticket.js's 'trust it -- no
  ambient check'.
- 'Workflow bodies run in the E2 engine with no filesystem or process access (ADR-030).
  They reach the maker only through (a) args.workspace -- the maker''s JSON object
  passed verbatim by the entry command or skill (BO-4300a-1-ib) -- or (b) exactly
  one agent() dispatch, carrying a result schema, to an agent whose registry entry
  has permits_shell: true, instructing it to run one exact absolute command unchanged
  and return stdout verbatim. Never status-checker (permits_shell: false), never free-form
  set-up steps.'
- Proof runs the workflow under unit_tests/_workflow_engine_harness.py -- the deployed
  copy the build produces, so the build's workflow transform is exercised -- with
  label-scripted agent replies, and asserts on the RECORDED dispatch list, never on
  workflow source text. The harness must be able to model a workspace step that declines
  its task, answers in prose, answers exit 0 with a non-JSON path, or answers JSON
  without status (F13); extending the harness for this is in scope of the first AC
  that needs it.
- Workflow edits are made in templates/workflows-js/*.js and reach .claude/workflows/
  only through the build; the deployed copy is what the tests run.
```
