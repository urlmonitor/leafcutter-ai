# The host proposes two to five parts, each quoting your words, and no part runs until you answer

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `DK-400c-1` — The host proposes two to five parts, each quoting your words, and no part runs until you answer — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `DK-400c-1`. Component: `decision-kernel`. Assigned agent: `python-coder`. Estimated complexity: `L`. Complexity: `high`.

## Acceptance Criteria

```gherkin
Given the reusable-criteria goal waiting for its split proposal,
When the host proposes four parts, each naming decision as the capability that will run it:
  p1 "Decide which new file type the reusable categories are put into (needs evaluation)",
    quoting "we can should put them into a new file type (needs evaluation)", waiting for no
    part,
  p2 "Decide how the reusable categories are then also put into Neo4j", quoting "and then also
    into neo4j", waiting for p1,
  p3 "Decide how the reusable categories are clustered", quoting "we must make sure that we are
    able to cluster them somehow", waiting for p1,
  p4 "Decide whether to mine the reusable categories from Langfuse as a start", quoting "As a
    start we can probably mine them from langfuse", waiting for no part,
Then the split gate offers p1 to p4 in that order, each with its quote, the parts it waits for
  and its capability,
And the run waits for a person's answer (run status waiting_human) with every part not run,
And the parts come only from the host's proposal: Jev is not asked to write, merge or reword any
  part.
```

- [ ] AC-1: the split gate offers p1 to p4 in that order, each with its quote, the parts it waits for
- [ ] AC-2: its capability
- [ ] AC-3: the run waits for a person's answer (run status waiting_human) with every part not run
- [ ] AC-4: the parts come only from the host's proposal: Jev is not asked to write, merge or reword any

  one_question_rewording: string | null}. The proposal schema accepts 0 parts up to

  execution_mode host_handoff, routing fixed (never offered to Jev), request_kinds

  the allowance deterministically (ADR-053 section 5), and anything cut stays visible
  as not_covered.'

  or judge parts, and every conversion check is deterministic code (ADR-053 sections
  2 and 5).
- 'Conversion order is fixed: schema validation; dependency validation over all proposed
  ids (DK-400c-1-ii); allowed-capability check (DK-400b-1); quote check and set-aside
  (DK-400c-2); release of dependencies on set-aside proposals; part count (DK-400c-3);

  split gate opens with run status waiting_human. Conversion is total: any failure
