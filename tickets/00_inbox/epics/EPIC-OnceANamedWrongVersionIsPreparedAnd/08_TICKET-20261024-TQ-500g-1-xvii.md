## Implementation Notes

```yaml
- 'Field (IT-PO decision on the shape): one new optional test_spec item field, declared_replacements:
  an object whose keys are must_catch names of THE SAME entry, spelled exactly as
  that entry''s must_catch spells them, and whose values are non-empty lists of {path:
  str, old: str, new: str} (path and old non-empty, at least one non-whitespace character;
  new may be empty; no other key). Replacements apply in list order, each against
  the result of the one before, exactly as the writer applies a reply''s.'
- 'Enforcement on the gate that actually runs. (1) config/ac_store_schema.json: the
  property is added to the test_spec item, with additionalProperties false kept on
  the item and set on each replacement object, so the unknown-key check (_ac_schema_test_spec_validators._declared_entry_keys
  reads the schema) accepts it and still refuses every other unknown key. (2) The
  load-bearing, entry-naming check is in scripts/ac_store/_ac_schema_test_spec_validators.py,
  called from test_spec_entry_errors beside the must_catch check: a key that this
  entry''s must_catch does not list is refused with a message naming the file, the
  entry and the name; a non-object value, an empty list, a replacement missing path/old/new
  or holding a non-string, and a blank path or old are refused, each naming the entry
  and the rule. Both run under validate_ac_schema.py and the check-ac-schema hook.
  No new ac_store module is created; if one is, it is added to build_phases_ac_store.py''s
  deploy map in the same change, because the hook runs the deployed validator.'
- 'Not copied onto generated tickets (as in_scope_files): generate_ticket_from_ac.py
  is not changed, so config/test_requirements.schema.json is not changed either.'
- 'Reading (runner side, one reader): _wvr_scope reads declared_replacements from
  the same AC records the declared-scope reader already loads (_wvr_records.load_records),
  beside _must_catch_by_name and _in_scope_by_name, and attaches to each owed name
  its declaration and declared_by [{ac_id, entry}]. Never a second parse of the store.
  Two entries declaring different replacements for the same name (after norm_name)
  make the name unfinished with a reason naming both requirement ids and entries;
  identical declarations are one declaration.'
- 'Precedence in _wvp_plan (TQ-500g-1-xi): declared > pinned > prepared. A declared
  name is never put in to_prepare, and its pin is neither applied, nor changed, nor
  cleared while the declaration exists; once the declaration is removed from the entry
  the pin is planned again through every check of TQ-500g-1-xiii. A declaration is
  never written to the pin store.'
- 'Checks: the declared replacements go through the same _wvp_checks functions as
  a pin (TQ-500g-1-xiii: in scope and the writer''s path refusals for a test file,
  outside the repository and inside the version-control folder; old text exactly once;
  changes something; loads; reaches a line). A failure makes the manifest entry could_not_prepare
  with the reason exactly "declared on <ac_id>, entry <entry name>: <failed check>";
  the name is unfinished, never sent to the preparer, never replaced by the pin.'
- 'Row: the manifest entry for a declared name has source "declared" and the additive
  key declared_by [{ac_id, entry}], which the runner copies onto every row of that
  wrong version beside alteration_id, source and replacements (TQ-500g-1-xv), so the
  row names TQ-9101 and T1''s entry.'
- Every changed Python file stays at or under 400 counted lines (_wvr_scope.py is
  at 275, _ac_schema_test_spec_validators.py at 84). Logging to stderr only.
```
