# A run the observation could not watch is reported as unwatched, never as unreached and never as reached

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-2900a-2-ii` — A run the observation could not watch is reported as unwatched, never as unreached and never as reached — so that the acceptance criterion is satisfied.

## Context

## Acceptance Criteria

```gherkin
Given a proof-of-done test whose run the observation cannot watch, in any of
  these ways:
    the proof launches a program the observation has no way to watch,
    the program the proof launched installs an observation of its own part-way
      through and displaces the one watching it,
    the program the proof launched is started in a way that prevents the
      observation being carried into it at all,
When the proof is evaluated for whether it reached the code through the way in,
Then the answer is that the run could not be watched — an answer distinct from
  both "it reached the code through the way in" and "it did not",
  And a criterion whose only proof is unwatched receives no verdict from the
    reachability rule: it is neither refused nor credited on that basis,
  And the unwatched case is announced, naming the proof and what made the run
    unwatchable, so proofs the observation cannot see stay countable instead of
    passing silently,
  And a run in which the observation was displaced part-way through is reported
    as unwatched rather than as a run in which nothing was reached,
  And an observation that was installed and recorded nothing at all is reported
    as unwatched rather than as every proof having reached nothing.
```

## Implementation Notes

```yaml
- 'THREE DISTINGUISHABLE STATES, NOT TWO BOOLEANS. Carry observation: ''watched''|''unwatched''
  separately from reached_through: ''reached''|''not_reached''|''undecidable''. When
  observation is ''unwatched'', reached_through MUST be ''undecidable''. The existing
  fail-closed dict (scripts/ac_store/done_proof.py, the observation_ok False mapping
  around line 588) sets reached_through False alongside observation_ok False — that
  co-occurrence IS the defect this AC removes, because it hands a plausible negative
  to a caller that reads only the verdict.'
- NO CONSUMER MAY DERIVE unwatched FROM not_reached, AND NO CODE PATH MAY MAP unwatched
  ONTO EITHER VERDICT. The refusal path must require the literal 'not_reached', never
  falsiness of a boolean. Keep observation_ok available as a derived alias (observation
  == 'watched') only so existing call sites do not silently change meaning — and forbid
  any new consumer from deriving a verdict from it.
- 'DISPLACEMENT MUST BE DETECTED ON PURPOSE, IN AN ATEXIT HANDLER, PER PROCESS. At
  process exit compare the currently-installed callback against the function the observer
  installed (sys.getprofile(), or sys.monitoring''s registered callback on 3.12+).
  A mismatch means a launched program installed its own tracer and evicted the observer:
  that process is unwatched with cause observer_displaced, and every record whose
  ancestry chain passes through it becomes undecidable. This is a named ship blocker
  — eviction leaves a WELL-FORMED record that is silent about the code under proof
  and is otherwise indistinguishable from an honest not_reached.'
- 'THE CAUSE VOCABULARY IS CLOSED AND ENUMERATED: non_python_child, isolated_interpreter
  (a child started with -S, -E or -I), observer_displaced, recorded_nothing, propagation_failed,
  and unknown. Each is a distinct value, each resolves to unwatched, none resolves
  to a refusal. An unrecognised condition takes cause ''unknown'' and is unwatched
  — never watched. Adding a cause that resolves to not_reached violates this AC.'
- RECORDED-NOTHING IS PER PROCESS. The observer must confirm it observed at least
  one frame in each process it claims to have watched; a process that installed the
  observer and recorded zero frames is unwatched with cause recorded_nothing. BO-2900a-2's
  self-validation constraint already requires this for one process and is restated
  only because a tree makes it a per-process property — an observer that recorded
  nothing anywhere makes every proof look like a direct import and blocks the whole
  store.
- 'EVERY UNWATCHED RECORD IS ANNOUNCED, THROUGH THE SAME COUNTABLE FINDING CHANNEL
  BO-2900a-1-ii DEFINES, naming the proof nodeid and the cause. Silence on an unwatchable
  proof is the phantom-done vector this AC exists to close: it is a failure of this
  AC even when the verdict itself is correct, because a pure-spawn proof that nothing
  judged is today marked done with no reachability evidence at all.'
- NO UNWATCHED ANNOUNCEMENT MAY NAME A CLEARING ACTION. BO-2900e-1 requires every
  refusal to give an action the reader can carry out on the code; an unwatched run
  has none, which is exactly why it must not be phrased as a refusal. The announcement
  states what could not be watched and why, and asks for nothing. 49 criteria hold
  the wrong version of this message today.
- A CRITERION WHOSE EVERY LINKED PROOF IS UNWATCHED CONTRIBUTES NOTHING TO ELIGIBILITY.
  The verdict must equal, in every key, the verdict the same evaluation returns with
  the reachability rule not invoked. This is an equality property to be asserted by
  comparison — not a flag to be inspected.
- THE COVERAGE CEILING IS ACCEPTED, NOT ENGINEERED AROUND. Non-Python children and
  interpreters started with -S/-E/-I are genuinely unobservable and must not be made
  observable by rewriting the child's command line, injecting arguments, or refusing
  to run it. Count them and name them.
```
