# Generated ticket frontmatter carries an ac_traceability entry (AC id + store path)

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `TKT-500f-9` — Generated ticket frontmatter carries an ac_traceability entry (AC id + store path) — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `TKT-500f-9`. Component: `ticket-creation`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a leaf AC with id "BO-1000c-1b" stored at a known path in the AC store
  (for example
  "docs/acceptance-criteria/build-orchestration/BO-1000-live-automation-progress/BO-1000c-1b.yaml"),
When a ticket is generated from that AC by generate_ticket_from_ac.py,
Then the generated ticket frontmatter carries an ac_traceability entry that
  names both the AC id "BO-1000c-1b" and the AC's store path,
And the ac_traceability entry is present in addition to (not merely) a bare
  source_ac scalar,
And the ac_traceability entry is structured so ac-validator and
  ac-fulfillment-gate can resolve the source AC from the ticket rather than
  silently no-opping when only a bare source_ac is present.

Given a leaf AC for which a ticket is generated,
When ac-fulfillment-gate or ac-validator later reads that ticket,
Then it can locate the source AC file from the ac_traceability entry's store
  path without scanning the whole store.
```
