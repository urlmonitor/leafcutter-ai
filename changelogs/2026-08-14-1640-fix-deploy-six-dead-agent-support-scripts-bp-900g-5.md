summary: "Six features that appeared to be installed but failed the moment you used them — changelog generation, retrospectives, architecture diagrams, roadmap queries and the package audit — now actually work in an installed project."
description: "BP-900g-4 taught the broken-reference guard to see script references written in the output-root form and parked the nine pre-existing breakages it surfaced in KNOWN_UNDEPLOYED_ALLOWLIST. This empties that set. Six leafcutter scripts existed in the package source, were invoked by deployed agents and skills, and were shipped by no build phase — so changelog-agent, epic-supervisor, retrospective-agent, architect-review, architecture-diagram-author, the roadmap-query/roadmap-steward skills and package-audit all died at their first command in any consumer install. Added build_agent_support_scripts(), which deploys scripts/changelog/, scripts/retrospective/ and scripts/agent-health/ recursively plus next_diagram_seq.py, roadmap_query.py, roadmap_query_audit.py and package_audit.py. The phase, _manifest_agent_support_scripts() and the tracked-source guard scan all derive from ONE module-level spec (AGENT_SUPPORT_SCRIPT_DIRS / AGENT_SUPPORT_SCRIPT_FILES), so the deployed set and the declared set cannot drift — a manifest disagreeing with reality was itself the BP-900g-4 defect. roadmap_query_audit.py is deployed although no template names it: roadmap_query.py exec_module()s it from its own directory at MODULE SCOPE, so roadmap_query.py is not importable without it — the same presence-is-not-reachability trap that ac_parent_id.py sprang in BP-900g-4. The seventh parked entry needed no deploy phase at all: status-checker.md invokes 'python debugging/scripts/check/prod_status_check.py', a path in the CONSUMER's own repository, which BP-900g-4's prefix allowance had mis-normalised into a scripts/... deploy key by accepting any single leading segment. The prefix now accepts only an output root — the {{config.output_root}} token or a dot-prefixed root such as .leafcutter/ — so host-project paths and package-development prose (leafcutter/scripts/build.py) are no longer captured; a negative-control test pins both. KNOWN_UNDEPLOYED_ALLOWLIST is now empty and a test asserts it stays empty, making any future re-parking a CI failure rather than a silent suppression. Covered by AC BP-900g-5 and four new tests in unit_tests/test_bp_900g_4.py, including one that imports every newly deployed script in a fresh subprocess from a real build.py --target-dir install rather than asserting file presence."
