# Deterministic render-smoke runner helper for the frontend sign-off gate

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-570-1` — Deterministic render-smoke runner helper for the frontend sign-off gate — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-570-1`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given a ticket whose changed surface includes one or more frontend files
  (e.g. a route/page or component the user can see),
When the render-smoke runner is invoked against that changed frontend surface,
Then it performs a real dev/route render of the affected surface locally
  (a dev/route render, not a static or lint check),
And it returns a deterministic verdict that classifies the outcome as one of:
  render-success, render-error (a render-time-only defect was hit at route
  render time — e.g. a component with server-side rendering disabled that
  only throws at render), or tooling-unavailable (the render runner could
  not start / its dependencies are not installed),
And on render-error the verdict names the render failure as the blocking
  reason so the sign-off gate that consumes it can record a failure,
And on tooling-unavailable the verdict is reported as a distinct third state
  naming the reason (never collapsed into render-success),
And the verdict carries the surface that was rendered so the consuming
  sign-off gate can record auditable evidence of what was checked.
```
