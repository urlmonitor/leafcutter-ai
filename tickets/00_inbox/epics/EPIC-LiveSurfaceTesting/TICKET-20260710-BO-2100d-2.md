```gherkin
Given a `live_surface_testing` config block whose `enabled` is `true` but whose
  `startup_command` is missing or an empty/whitespace-only string
When the config is validated (config_loader.py validate_config)

  `startup_command` must be a non-empty string when `enabled` is true
```

## Implementation Notes

```yaml
- Validation must reject enabled:true with a missing, empty, or whitespace-only startup_command
  by raising ConfigValidationError whose message names the `startup_command` field.
- The rejection must happen at config-validation time, before any server-start attempt,
  so a misconfiguration never masquerades as a runtime failure.
- This AC places existing behavior under explicit coverage (see notes); the coverage
  must fail loudly if the safeguard regresses.
```
