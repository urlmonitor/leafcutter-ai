description: "CI's mypy job is diff-scoped -- it only type-checks files a PR touches. That makes it permanently green on main while 107 errors accumulate unseen across 29 test files, each waiting for whoever touches that file next. This is not hypothetical: PR #533 added five '# covers:' comment lines to tests/knowledge/test_harvest_learnings.py and went red with three pre-existing errors the commit did not write. Clears all 107 (43 union-attr, 31 attr-defined, 25 arg-type, 8 other) to zero under CI's exact flags. Five distinct root causes got five distinct fixes; no blanket type: ignore was used. The dominant one is the dynamic-import idiom -- spec_from_file_location returns ModuleSpec | None and spec.loader is Loader | None, both used unguarded -- fixed with a narrowing assert that also converts a confusing AttributeError into a named failure. Fixed in place per file rather than behind a shared helper: tests/ and unit_tests/ are separate top-level trees so a helper would need a new cross-directory importable location, and this repo has already recorded a shared-test-helper change breaking isolation. Two fixes go beyond typing. test_bp_900g_4.py and test_bp_900g_6_paths.py used 'import build', which collides with the installed PyPI build package (the PEP 517 frontend); at runtime a sys.path.insert made the local script win, but that made the test silently dependent on sys.path ordering to avoid exercising the wrong package -- now loaded by path, removing the footgun. test_enforce_commit_delegation.py gained a real assertion: it now fails loudly if a hook calls sys.exit() with a non-int code, which the test's own (int, str) contract already assumed. Full suite unchanged at 3984 passed / 0 failed before and after. Separately investigated three tests in test_ge_118c_doc_types_deployed_resolution.py that fail in a full local suite but pass in isolation: confirmed a FALSE RED and deliberately not 'fixed'. Nineteen sibling worktrees each carry an identically-named copy of that file under unit_tests/commit_guardian/ with an __init__.py at commit_guardian but none at unit_tests, so every copy resolves to the same dotted module name; a pytest run whose rootdir spans more than one worktree caches the first copy collected and reuses it for the rest, running one worktree's paths against another's deploy state. Not reproducible in CI or a clean checkout. One dormant occurrence of the same unguarded idiom remains in test_git_recovery.py inside an untyped function body that mypy skips by default; left alone as out of scope."
