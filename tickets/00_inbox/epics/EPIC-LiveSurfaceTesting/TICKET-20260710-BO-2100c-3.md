# Teardown kills the whole server process group, not just the shell wrapper

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-2100c-3` — Teardown kills the whole server process group, not just the shell wrapper — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-2100c-3`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given the development server is started through a shell wrapper (subprocess with
  shell=True), so the recorded PID is the shell's PID and the actual server runs
  as a child of that shell
When teardown stops the server (via stop or finalize)
Then the entire process group is terminated — the server is launched in its own
  session (start_new_session) and teardown signals the group (os.killpg), not only
  the single shell PID
  And after teardown no child server process from that group remains running
  And the port previously held by the server is free.
```

## Implementation Notes

```yaml
- The server must be launched in its own session (start_new_session=True) so a process
  group exists to signal.
- Teardown must signal the whole process group (os.killpg), not only the recorded
  shell PID; after teardown no member of that group may remain running.
- Subprocess and signal handling must follow the project error-handling policy — an
  already-dead process (ProcessLookupError) must be handled gracefully, not swallowed
  silently.
- The port previously held by the group must be free after teardown.
```
