# A check may only refuse over material the commit itself changed

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-4100b-1` — A check may only refuse over material the commit itself changed — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-4100b-1`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a workspace whose branch is 39 commits behind the shared main line,
And a commit whose changed-file set contains no file belonging to the
  supporting-material tree,
When the checks that compare supporting material against its expected content
  run,
Then the commit is not refused,
And no item outside the commit's changed-file set appears as a reason for a
  refusal,
And the same commit is accepted identically whether the branch is 39 commits
  behind the shared main line or level with it.
```

## Implementation Notes

```yaml
- 'check-build-drift and check-output-drift both declare change_set_source: handed_by_commit_path
  in templates/scripts/commit_guardian/commit_guardian.json while running with pass_filenames:
  false and always_run: true -- so neither is handed a change set and neither reads
  one. The declaration and the behaviour must be brought into agreement: either consume
  the shared derivation (_authored_change.get_authored_change(), ADR-038) or declare
  self_derived and derive it. A manifest entry naming a source the hook never reads
  must not survive this work.'
- Scoping applies to the REFUSAL, not to the SCAN. The gates may still hash the whole
  tree -- that breadth is what makes them useful. What they may not do is let an item
  outside the commit's changed-file set drive a non-zero exit or appear as a reason
  in the BLOCKED block.
- 'Every refusing exit path must be scoped, not only the hash-mismatch one. check_build_drift.main()
  today refuses through four independent conditions: violations, missing and unreadable
  (return 1) and gaps (return 2). The observed evidence -- refused while reporting
  drifted=0 missing=0 -- points at the gaps path, so a fix applied only to violations
  leaves the defect exactly where it was.'
- Both gates must change together and must keep reporting in one vocabulary; their
  RESULT lines are required by their own docstrings to be comparable, and a reader
  who cannot compare two runs cannot diagnose which gate refused.
- The verified == 0 floor (a gate that compared nothing must not exit as if it had
  compared everything) must survive the scoping change. Narrowing the refusal must
  not create a new way for a gate to pass while having checked nothing.
- Both the canonical templates under templates/scripts/commit_guardian/ and their
  deployed scripts/commit_guardian/ copies must change together and be verified in
  parity via the build.py round-trip (ADR-001). The hook runs from the deployed layout;
  source-tree unit tests alone do not prove the deployed gate changed.
```
