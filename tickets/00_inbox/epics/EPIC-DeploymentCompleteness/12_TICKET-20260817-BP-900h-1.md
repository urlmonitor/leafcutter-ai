# CI installs the package into an empty project and the build succeeds

## Actor / Goal

As an adopter installing leafcutter into my own repository, I want every change
to the package proven against a real clean install, so that I never receive a
release whose install is broken.

## Context

This ticket was generated from AC store entry `BP-900h-1`. Component:
`build_pipeline`. Assigned agent: `python-coder`. Estimated complexity: `M`.

Added to this epic on 2026-08-17, after the epic was scoped. BP-900a..BP-900g
verify deployment completeness *statically*, from inside the build. Nothing
verifies it *empirically*, by performing an install and looking at the result —
which is why phase_1 exit criterion 1 in [docs/roadmap.json](../../../../docs/roadmap.json)
has no automated check, and why seven consumer-install defects (BP-900g-4/-5/-6,
BP-015, BP-016, BP-017, BP-018) shipped and were hotfixed after release between
2026-08-13 and 2026-08-17.

The nearest existing coverage is not a substitute:
`unit_tests/portability/test_build_deployment.py` asserts byte-identity for the
`build_commit_guardian` phase only, and `tests/test_build_clean.py` exercises the
`--clean` flag rather than a clean install.

## Acceptance Criteria

```gherkin
Given a scratch directory containing no files other than a minimal skills_config.json,
And the package checked out into leafcutter-ai/ beneath it, simulating a consumer install,
When CI runs "python leafcutter-ai/scripts/build.py --target-dir ." from that directory,
Then the build exits 0
And the deployed output root exists and contains scripts/ and agents/
And every script path referenced by a compiled agent template or skill file
  resolves to a file that exists in the deployed tree
And the job fails with the unresolved paths named on stderr if any does not
```

## Implementation Notes

- Build the scratch project from an **empty directory**, never from a copy of
  this repository. Copying the repo reintroduces the source-tree bias that hides
  every missing-deploy defect.
- Assert against the **deployed** tree only. Do not add the package source
  directory to `sys.path` when checking that references resolve.
- The job must run on `pull_request`, so it gates before merge.
- Reuse the reference-resolution logic that BP-900b-1/-2 build inside the build
  rather than reimplementing the matching rules. The new value here is the
  empty-project execution context.

## Test Requirements

Per CLAUDE.md "Gate / Workflow ACs — Verify Behaviorally, Not by Grep", a test
that only greps `ci.yml` for the job name is not acceptable coverage — it passes
on a job that never runs.

- `test_consumer_simulation_build_succeeds_in_empty_project` — run the real
  `build.py --target-dir` into an empty `tmp_path` containing only a minimal
  `skills_config.json`; assert exit 0 and that the deployed output root contains
  `scripts/` and `agents/`.
- `test_consumer_simulation_detects_unresolved_reference` — negative case: remove
  one deployed script after the build, re-run the reference check, and assert it
  reports a non-zero result naming that path. This is the test that proves the
  gate can actually fail.

Target dir: `unit_tests/portability/`.
