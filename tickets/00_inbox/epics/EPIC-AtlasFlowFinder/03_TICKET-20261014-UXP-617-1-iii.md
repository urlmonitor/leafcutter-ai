## Implementation Notes

```yaml
- 'Facet semantics follow the dataset invariant: OR within a facet, AND across facets;
  product, kind, realization, level and entity are flow facets; actor, uses, produces,
  io and screen are step facets that one node must meet all at once.'
- Each option's count is computed by the same listing function with that option alone
  in its facet and q and the other facets kept; a zero option stays rendered and disabled,
  so the panel never reflows.
- 'Chosen values are held as stored values per facet; labels are applied only at render.
  Chips are listed in address order, each remove button named ''Remove filter <facet
  label>: <option label>''; ''Clear all'' removes every facet value and keeps q.'
- Uses field / Produces field options are picked by type-ahead over the index's field
  keys and list only the chosen fields; entity options are sorted by name and screen
  options by title.
- The facet panel and chips live in leafcutter-web/components/flows/finder/.
- Expected values come from the leafcutter/atlas-flows v4 dataset records, replayed
  against a frozen finder-index fixture in leafcutter-web/fixtures/flow-finder/ produced
  by the finder's own index builder from docs/product-truth/flows/ at the dataset's
  measurement commit (provenance recorded in the fixture); tests never pin counts
  against the live store, which grows. fixtures/** is already excluded from vitest
  collection.
```
