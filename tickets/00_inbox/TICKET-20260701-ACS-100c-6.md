# Superseded children do not count toward the child-count cap

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `ACS-100c-6` — Superseded children do not count toward the child-count cap — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `ACS-100c-6`. Component: `ac-store`. Assigned agent: `python-coder`. Estimated complexity: `S`.

## Acceptance Criteria

```gherkin
Given an L1 AC "ACS-100a" has 6 L2 child AC files in its feature folder,
And 1 of those child files has status "superseded_by" (its superseded_by
  field naming the replacement child),
And the default L1 child-count cap is 5,
When the check-ac-tree-limits hook counts the parent's children for the
  ACS-100c cap,
Then it counts only the 5 children whose status is not "superseded_by"
  (children with status "active" or any non-superseded status are counted),
And it excludes the 1 superseded child from the count,
And the effective child count is 5, which does not exceed the cap of 5,
And the hook passes without requiring a child_limit_override on the parent,
And the superseded child file remains present on disk in the feature folder
  (it is omitted from the count only, not deleted or moved).
```

### Also covered (edge cases)
- **ACS-100c-6-i** (L3): a parent whose children are ALL `superseded_by` has an effective count of 0 and passes; all files remain on disk. Read `docs/acceptance-criteria/ac-store/ACS-100-structured-requirements/ACS-100c-6-i.yaml`.
- **ACS-100c-6-ii** (L3): the status exclusion composes with `child_limit_override` — the filtered count is compared against `max(default_cap, N)`; once enough children are superseded the count falls under the default and the override becomes unnecessary. Read `.../ACS-100c-6-ii.yaml`.

## Implementation Notes
- Both `superseded_by` AND the legacy `superseded` status form must be excluded (per `docs/reference/ac-schema.md` lifecycle table — both are "excluded from active enforcement").
- Edit the CANONICAL tracked source `templates/scripts/commit_guardian/check_ac_limits.py`. If `templates/scripts/commit_guardian/hooks/check_ac_limits.py` is a separate copy (not a symlink) carrying the same counting logic, apply the same change there; if identical/symlinked, note that and change only the canonical one. Do NOT edit the gitignored deployed `scripts/commit_guardian/` build output (ADR-001 boundary).
- Apply the status filter in the single place children are counted (the shared child-count computation, ACS-100h-7a's surface) — do not add a second traversal. `scripts/ac_store/ac_parent_id.py` derives child→parent attribution; read it to find where the count is assembled.
- Preserve `child_limit_override` semantics exactly: effective cap = `max(default_cap, N)`, compared against the FILTERED (post-exclusion) count.
- Follow the Error Handling Policy: reading each AC's `status` crosses the file boundary already handled by the existing loader; do not swallow parse errors silently.
- After the change, a self-build (`build.py`) redeploys the hook; the coder need not hand-edit the deployed copy.
