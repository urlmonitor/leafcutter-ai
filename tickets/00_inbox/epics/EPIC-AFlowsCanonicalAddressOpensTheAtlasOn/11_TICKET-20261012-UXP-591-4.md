## Implementation Notes

```yaml
- Drawer open writes ?step=<id> with window.history.replaceState, replacing the current
  history entry and never adding one (owner decision 2026-10-09). The Next.js 14 App
  Router (14.1+) integrates replaceState with usePathname/useSearchParams without
  a server round-trip. router.push, pushState and router.replace (which re-runs the
  server route for the new search params) are not used for drawer actions; the explorer
  does not remount or refetch on one.
- Drawer open, switch and close (UXP-591-4-i, -ii) call one replace-entry function
  owned by leafcutter-web/components/flows/flows-view.tsx or a module it uses; flow-explorer.tsx
  and flow-drawer.tsx only report the intent.
- 'Each replace writes the entry''s view state {crumbs: string[] (Flow ids, entry
  flow first), filters: {source: ''real'' | ''mock'', kind: ''user'' | ''data'' |
  ''architecture'', realization: ''all'' | ''built'' | ''spec'' | ''mock''}} together
  with the URL, kept in history.state under one namespaced key, merged into, never
  overwriting, the App Router''s own keys (__NA, __PRIVATE_NEXTJS_INTERNALS_TREE);
  not sessionStorage (owner decision 2026-10-09), so Back/Forward can restore it (UXP-591-5-ii).
  Overwriting the App Router''s keys makes Back trigger a full reload.'
- On the bare /flows entry the replaced URL is flowHref(defaultEntryFlowId, stepId)
  from the single default-entry constant (owner ruling 1); the default flow keeps
  rendering with no remount.
- 'The push/replace decision lives in one pure function shared with UXP-591-5 (proposed
  leafcutter-web/components/flows/flow-navigation.ts: entry state + action -> {op:
  ''push'' | ''replace'', url, state}), so the dataset''s FlowNavigation sessions
  can be replayed against it as unit tests.'
- jsdom does not run the App Router's history integration, so the real-browser behaviour
  (history length under the App Router, Back/Forward without a page reload) is proven
  by this AC's Playwright spec in leafcutter-web/e2e/, run in CI against `next build`
  + `next start` (owner decision 2026-10-09; harness set up under UXP-591-1).
```
