summary: "A check meant to spot work that changes something real was accepting the phrase before any test is written as proof that it did. Four acceptance criteria were blocked by it in one day, none of them wrongly."
description: "The acceptance-criteria store carries a declaration marking work that produces a durable, observable change, and that declaration force-routes an end-to-end smoke phase into the generated ticket. The routing is deliberately non-overridable, so a wrong declaration does not merely mislabel a record — it puts a phase agent in front of work that has no surface for it to invoke, and blocks it. The derivation behind the declaration accepted a bare is written or are written anywhere from the first Then clause onward. That accepted a notice going to the error stream, which is observable but gone when the terminal closes; a reported clause whose subject is a document and whose write belongs to a different criterion; a relative clause merely naming where entries are kept; and ordinary authoring language such as before any test is written, which describes a person writing a test later. Four criteria tripped it in a single day and every one was a false positive. Compounding it, an honest correction was impossible to record: the validator rejects an authored value that disagrees with the derivation, so on a false positive the only available moves were to declare an effect the work does not have, or to reword the requirement until the expression stopped objecting. Two records had already been reworded that way before it became clear the tool was wrong rather than the records. The fix keys on the object written rather than the verb, since no property of the verb separates a record file is written into that project's tree from before any test is written. Two shapes are now admitted: a durable noun governing the verb, and a write naming a destination that is not a stream, terminal or console. The authority is the parent criterion's own words, which define a durable change as a file that exists and can be read back afterwards, a record that is persisted, or a command that leaves the system in a different state; a line on standard error is none of those, so the implementation had been wider than the requirement it implements. Everything was measured against the real store rather than assumed. Simply deleting the two loose alternatives was measured first and rejected: it cut the marked set from 139 records to 31 and dropped genuine positives. The object-aware form gives 88, flips 51 to false, and marks nothing new, so it is a strict narrowing that cannot have added a routing obligation anywhere. Seven records that carried the declaration purely on the old reading are corrected, each judged individually rather than swept. Eight records that already disagreed before this change are pinned in a test allowlist and left for their owners, because deciding records in unrelated trees would be the same bulk edit in the opposite direction. A ninth had to be settled: adding a child to the criterion that introduced this derivation required staging the parent, and the ratchet then refused the commit until its own stale declaration was resolved, which means a record cannot gain a child while it holds one. A second over-match was found, implemented, measured and reverted rather than bundled, and is now recorded in the function's own documentation together with the three records it would affect."
