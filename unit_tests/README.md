# Unit Tests

**Read this before writing or changing a test here.** It is not an overview — it is the
short list of ways a test in this repository can look correct, pass, and constrain nothing.
Every item below is a defect that actually shipped, most of them inside the machinery built
to prevent exactly that.

This repository's founding concern is **phantom-done**: work marked done that never runs. A
test that cannot fail is that defect at its purest, because its greenness is later cited as
proof the invariant holds.

---

## 1. A passing test is not evidence until you know it can fail

The pipeline's only mechanical evidence that a test constrains anything is the **red
baseline**: the suite must fail before the coder runs.

That evidence is **structurally unavailable** to a whole class of test. A *negative control*
asserts an **absence** — that some input changes no outcome, that a valid case is *not*
reported. If the implementation is correct, such a test is **green on arrival by
construction**. There is no red phase to capture.

`CLAUDE.md` says a green `test-writer` phase is a TDD-order violation. **That rule inverts
here** — green is the expected result — so the one mechanism that would have asked "can this
fail?" is not merely absent, it is documented to mean the opposite.

**Where a red baseline is unavailable, you owe a mutation proof instead.** Inject the exact
leak the test forbids, confirm the test goes RED, revert, confirm green again. Record what
you injected.

Known issue: `KI-TQ-010`.

### 1a. Mutate the copy the test actually imports — this trap fails *green*

Commit-guardian modules exist **twice**:

| path | role |
|---|---|
| `templates/scripts/commit_guardian/…` | canonical **source** |
| `scripts/commit_guardian/…` | **build output** (symlink → `.leafcutter/…`), regenerated by `build.py` |

Tests import the **build output**:

```python
_COMMIT_GUARDIAN_DIR = _REPO_ROOT / "scripts" / "commit_guardian"
sys.path.insert(0, str(_COMMIT_GUARDIAN_DIR))
```

So a mutation applied to `templates/` **is never loaded by the test meant to catch it**.

Observed on `BP-1100g-5-i` (2026-08-31), same injection, both copies:

| mutation target | result | what it looks like |
|---|---|---|
| `templates/…` | **4 passed** | "the negative control is dead" |
| `scripts/…` (deployed) | **3 failed**, 1 passed | the control is sound |

This is worse than an ordinary footgun because **it fails in the green direction**. A
mutation that does not land is indistinguishable from a test that cannot fail — so it
manufactures a false positive for the very defect the proof exists to detect, and the
natural response is to "fix" tests that were already correct.

**Rule:** mutate `scripts/commit_guardian/…`, or re-run `build.py` after mutating the
template. Confirm the injection landed before drawing any conclusion — the mutated module's
`__file__` at import time is enough. A weaker tell: run time. The template-mutation run took
0.24s, the landed one 33.5s, because the deployed hook subprocess only does real work once
findings appear.

Known issue: `KI-TQ-20260831-mutation-probe-lands-in-the-wrong-copy`.

## 2. The two axes are orthogonal — do not conflate them

| axis | question | values |
|---|---|---|
| `type` | what **level** does it run at? | `unit`, `integration`, `e2e`, `behavioral` |
| `angle` | what **kind of proof** is it? | `criterion`, `reachability`, `seam`, `real_artifact`, `deployed`, `boundary`, `failure` |

An `integration` test is not automatically a `reachability` test. A `unit` test can carry a
`boundary` angle. Tag both honestly — `BP-1100g-3` makes each test state its kind, and
`BP-1100g-4` refuses a commit that promised a kind no test claims.

## 3. Fixture realism is not failure capability

The most instructive rejection in the store: a defect with **textbook fixture realism** —
real on-disk artifacts, the real serializer, the real production entry point, and explicit
anti-vacuity assertions — was **still inert**.

Anti-vacuity assertions ("otherwise this test proves nothing") guard against a fixture being
*empty or trivial*. **None of them can detect that a fixture, while non-trivial, does not
span the failure mode.** Self-certified non-vacuity is not falsifiability.

---

## 4. Build fixtures with the project's own writer

Never hand-type YAML or markdown a tool produces. Use `yaml.safe_dump`, the signoff SKILL's
own recipe, the real generator.

A hand-typed fixture reproduced an indentation bias and hid a parser **no-op on every real
ticket** through **seven green sign-offs**: real `files_touched` lists serialize with dashes
at column 0, the parser regex required indented dashes, and the fixtures were indented. Even
the first remediation spot-check reused indented fixtures and missed it.

---

## 5. Assert over emitted artifacts, never source presence

A test that greps source for a string, asserts a call site exists, or checks that an
instruction is present in a template **passes on dead code** and on an implementation that
never records anything.

The fast lane — built specifically to defeat phantom-done — itself shipped a phantom-done
runner: it passed its grep-only structural tests while **never executing** its red/green
gates.

For a gate, hook, or workflow: execute the behaviour, or assert the results are **consumed
in control flow**. The strongest form is a counterfactual — *withhold only this finding,
everything else identical, and the decision must flip.*

---

## 6. Report per item, never one aggregate verdict

The incident that drove this is a 4×3 table: three of four tests caught an injected fault,
and the fourth — carrying the headline claim — slept through it. A single boolean would have
said "the suite catches it" and that test would still be inert today.

Report outcomes per *(test, alteration)* pair. Aggregation hides both a test that never
objected and an alteration nothing noticed.

---

## 7. A guard is only real if the deployed copy runs

Two separate failure modes, both shipped:

- **Not in the deploy manifest.** A hook importing a module not deployed raises
  `ModuleNotFoundError` at commit time, while unit tests importing from the source tree stay
  green. Everything inside `templates/scripts/commit_guardian/` is deployed automatically;
  anything imported from outside it needs a `scripts/build_phases.py` entry.
- **Not registered.** `check_ticket_signoff_parity.py` was deployed, documented as live
  "with `--enforce`", and named by **no** `entry:` line — so it never ran. 19 scripts are
  currently in that state (`KI-CG-20260831-hook-scripts-never-invoked`).

A reader not reachable from a registered hook is inert. Give such work a `reachability`
descriptor that runs the real entry point:

```bash
python .leafcutter/scripts/commit_guardian/run_hook.py \
       .leafcutter/scripts/commit_guardian/<hook>.py <staged paths>
```

## 8. A check that examined nothing must not look like a check that found nothing

Shipped at least four times: `KI-CG-034` examined 169 files, skipped 169, compared **zero**,
and exited **0**. The AC-store validator matched a bare directory, printed `No YAML files to
validate.` and exited 0 — for eight days, while being the documented defence against store
rot.

Assert a **positive count**. "Fails when it compared nothing" is satisfiable on one branch;
"states how many it compared" makes the empty state unrepresentable in the output. And
assert the count by *varying the population and requiring the number to move* — four
hardcoded numbers satisfy a stated-count requirement while proving nothing.

## 9. Running the suite

```bash
# Everything
python -m pytest unit_tests/ tests/ -q

# One file, with xfail-masking disabled — see below
AC_ENFORCE_STRICT=1 python -m pytest unit_tests/commit_guardian/test_x.py -q
```

**`AC_ENFORCE_STRICT=1` matters.** `pytest_ac_enforcement` (loaded via `pytest.ini`'s
`addopts`) xfails failures belonging to not-done ACs, so a plain run **undercounts** and can
exit 0 over real failures. Set it when you need the truth. Note it also breaks
`mark_ac_done`'s own gate, so prefix that command rather than exporting it globally.

`--continue-on-collection-errors` is on by default: **a collection error does not stop the
run and is easy to miss**. Read the summary line, not just the exit code.

---

## 10. Before you call a test done

- [ ] Red baseline captured — **or** a mutation proof, with the injection named
- [ ] The mutation was applied to the copy the test imports (§1a)
- [ ] `type` and `angle` both stated, and honest (§2)
- [ ] Fixtures built by the project's own writer (§4)
- [ ] Asserts over emitted artifacts, not source text (§5)
- [ ] Per-item results, not one verdict (§6)
- [ ] If it guards a commit: reachable from a registered hook, deps deployed (§7)
- [ ] Cannot pass having examined nothing (§8)
