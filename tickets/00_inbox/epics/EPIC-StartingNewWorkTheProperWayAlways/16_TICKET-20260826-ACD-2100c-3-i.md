## Acceptance Criteria

```gherkin
Given a run paused at one decision point with drafted work on disk,
When the route is started again supplying an answer that names a different
  decision point,
Then the answer is not applied to the decision being waited on,
And the run remains paused with its record still on disk,
And it reports which decision it is waiting on,
And the drafted work is unchanged and nothing is discarded.
```

- [ ] AC-1: the answer is not applied to the decision being waited on
- [ ] AC-2: the run remains paused with its record still on disk
- [ ] AC-3: it reports which decision it is waiting on
- [ ] AC-4: the drafted work is unchanged and nothing is discarded.

## Implementation Notes

```yaml
- The change must land under templates/. The deployed workflow is build output.
- A mismatch must leave the run paused rather than fail it. The person is still owed
  the question; a failure that clears the record makes the recovery from a mistyped
  resume a full re-run.
- The record must be unchanged on disk after the mismatch -- not rewritten, not re-timestamped
  in a way that loses which decision is outstanding.
- The report must name the decision the run is actually waiting on, so the operator
  can correct the answer without inspecting the store by hand.
- The subject binding must be checked before any part of the answer is acted on. Checking
  after the branch has been taken is not a check.
- Must satisfy the repository error-handling policy.
- 'Must be idempotent: repeated mismatched resumes leave the run in the same waiting
  state each time.'
```
