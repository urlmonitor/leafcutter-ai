# The reference states where the exemption applies, in one place, as a closed list

## Acceptance Criteria

```gherkin
Given the reference that documents the secrets scanner's rules and its
  suppression forms,
When a reader wants to know whether a particular file they are about to
  commit is exempt from the generic-credential rule,
Then the reference answers it from one section without the reader consulting
  the check itself, by stating: the five enumerated prose locations, the four
  admitted non-executing file kinds, the closed list of recognised
  non-credential value shapes, and the one value shape that is exempt in
  every file regardless of location,
And it states that all three lists are closed — a value, a location or a kind
  that is not on its list is treated as a credential,
And it states that source and configuration never inherit the exemption, and
  that a file inside a prose location whose kind is not admitted does not
  either.

Given the same reference,
When a reader wants to know what happens when an exemption is granted,
Then the reference states that a notice naming the file, the 1-based line
  number and the granting shape goes to the error stream, that the
  notice never reproduces the matched value, and that it does not change
  whether the commit succeeds.

Given a reader who wants to widen the exemption to a new location or a new
  value shape,
When they consult the reference,
Then it states that each list is extended by a deliberate edit with a
  recorded reason, and that resemblance to an existing entry is never
  sufficient,
Because a reference that describes the lists without saying they are closed
  invites exactly the silent inheritance this feature is designed to prevent.
```

## Implementation Notes

```yaml
- The reference is templates/skills/security-scanner/SKILL.md, which already carries
  the allowlist, path-matching, detection-rules and false-positive-guidance sections.
  The new material belongs as one section beside those, not scattered across them,
  because the criteria promise a reader can answer the question from one place.
- That file is the canonical copy per ADR-001. Edit it under templates/ and verify
  through the build.py round-trip; the copies under .claude/ and .leafcutter/ are
  build outputs and must never be hand-edited.
- This AC must land after GE-123d-1, GE-123d-2, GE-123d-4 and GE-123d-5 have settled.
  The reference records behaviour, and a reference written from the ACs rather than
  from the shipped lists documents an intention — which is the failure the expects_from
  contract already names and the reason the ordering is a hard constraint rather than
  a preference.
- The three lists in the reference must be enumerated in full and must match, item
  for item, the lists the implementation actually reads. A reference that paraphrases
  the lists cannot be checked for drift and will not survive the first extension.
- The reference must state explicitly that each list is CLOSED and extended only by
  a deliberate edit with a recorded reason. The criteria make this the load-bearing
  scenario; a section that lists five locations without that sentence reads as an
  example set, which is the silent inheritance the whole feature is built to prevent.
- 'Self-referential hazard, and it is live rather than theoretical: this section documents
  credential-shaped text and is therefore liable to be blocked by the very check it
  documents. Every example value in the section must itself be in one of the recognised
  non-credential shapes. The file is a Markdown file in the skill-prompt area, so
  it is an admitted kind in a named location once the code lands — which is exactly
  why the ordering constraint above is not negotiable: written first, the section
  blocks its own commit.'
- Do not duplicate the hand-written-suppression guidance that GE-123c owns. Cross-reference
  it rather than restating it, so there is one place to keep in step.
- The section must not reproduce a matched value anywhere, in prose or in an example,
  for the same reason the notice does not.
```
