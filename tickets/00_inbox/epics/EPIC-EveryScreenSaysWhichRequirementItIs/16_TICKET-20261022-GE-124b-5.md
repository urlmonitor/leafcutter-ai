## Implementation Notes

```yaml
- 'Author under docs/reference/ with check_doc_frontmatter-compliant frontmatter (title,
  type: reference, status, created, last_updated, components, description) and stay
  within the check_doc_length budget.'
- 'NAME THE FOUR CONSUMERS BY THEIR REAL ARTIFACTS, not by role: the commit-tier check
  (scripts/commit_guardian/check_frontend_ac_declaration.py), the CI-tier gate (scripts/commit_guardian/check_ui_ac_declared.py),
  the Atlas (leafcutter-web), and the derived test selector (GE-124f-3). A reference
  that names roles rather than artifacts cannot be checked for staleness and cannot
  be reached from the code.'
- STATE THE TWO GRAMMARS AND WHY THEY DIFFER. The @ac comment line tolerates commas
  and whitespace (GE-124a-1); the data-ac attribute value is whitespace-separated
  ONLY, because the derived selector uses the CSS attribute-membership operator `[data-ac~="<id>"]`,
  which splits on whitespace. A comma inside a data-ac value produces a selector that
  matches nothing. This is the single most likely authoring mistake and it belongs
  here, not in a how-to.
- RECORD THE FRAMEWORK-COVERAGE GAP FROM GE-124b-3. The production strip is implemented
  for leafcutter-web via the Next.js SWC transform, which is React-only; a Vue, Svelte
  or plain-HTML application joining the repo needs its own equivalent. Stating the
  gap is what stops a future reader assuming the contract is enforced everywhere.
- THE 'DOES NOT PROVE' SECTION IS REQUIRED CONTENT AND MUST NOT DRIFT FROM GE-124g'S
  WORDING — presence, not proof; on screen, not correct; a signpost, not a result.
  GE-124g-5 holds the standing rule; this doc is where a consumer-author lands first,
  so it must carry the same line or the rule is discovered too late.
- Cross-link to GE-124g-5's evidence reference rather than restating its four blocked
  places; one authoritative statement, reachable from here.
- change_target stays `code` under the L0's tree-wide instruction; the deliverable
  is the reference document.
```
