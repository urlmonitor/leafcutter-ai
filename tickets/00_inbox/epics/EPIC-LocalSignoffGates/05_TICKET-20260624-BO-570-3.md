# Deterministic repo-ruff runner helper for the python sign-off gate

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-570-3` — Deterministic repo-ruff runner helper for the python sign-off gate — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-570-3`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `M`.

## Acceptance Criteria

```gherkin
Given a ticket whose changed surface includes one or more Python files,
When the ruff-runner is invoked against that ticket's new and changed
  Python files,
Then it runs the repository's own ruff configuration against exactly those
  files (so the result matches what CI enforces, with no divergent local
  ruleset),
And it returns a deterministic verdict that classifies the outcome as one of:
  clean (no violations), violations (one or more ruff violations found —
  e.g. a violation that the project's error-handling Ruff rules forbid), or
  tooling-unavailable (ruff is not installed, or the repository ruff
  configuration cannot be located from the worktree root),
And on violations the verdict carries the violation detail so the sign-off
  gate that consumes it can record the lint violations as the blocking reason,
And on tooling-unavailable the verdict is reported as a distinct third state
  naming the reason (never collapsed into clean),
And the verdict carries the file set it was run against so the consuming
  sign-off gate can record auditable evidence of what was checked.
```
