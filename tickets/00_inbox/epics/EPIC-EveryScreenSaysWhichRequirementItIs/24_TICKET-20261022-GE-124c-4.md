## Implementation Notes

```yaml
- 'Author under docs/how-to/ with check_doc_frontmatter-compliant frontmatter (title,
  type: how-to, status, created, last_updated, components, description) and stay within
  the check_doc_length budget.'
- SECTIONS ARE KEYED BY THE VERDICT CODE AS THE CHECK PRINTS IT — a heading or anchor
  containing the literal code string (missing-component-declaration, unresolved-ac-id,
  and any further code the check emits), so an author can paste the code from the
  terminal and land on the right section. The block report must name this page and,
  ideally, the anchor.
- THE SECTION SET MUST MATCH THE CHECK'S CODE SET EXACTLY — no missing sections and
  no sections for codes the check does not emit. The test contract asserts this against
  the code enum the check exposes, so adding a code without a section fails; make
  the enum importable rather than a set of scattered string literals so that assertion
  is possible at all.
- KEEP THE TWO REMEDIES VISIBLY DIFFERENT. The whole point of the missing/unresolved
  split is that they have different fixes; a single 'how to satisfy the frontend declaration
  check' page re-merges them at the moment the author most needs them apart. State
  in the unresolved-id section, in words, that this is not a missing declaration.
- DO NOT RE-DOCUMENT THE DECLARATION SYNTAX. GE-124a-4 owns the five file shapes and
  their placement; link to it. Two pages carrying the syntax drift, and this page's
  reader already has a file open.
- 'COVER THE NOT-REPORTED CASE AS REASSURANCE, per the criteria: an untouched file
  is never reported, so an author who sees a neighbouring legacy component unflagged
  is not looking at a bug. Also state the reverse — that the same file WILL be flagged
  the day they edit it (GE-124c-3 scenario 3) — so the backfill is expected rather
  than surprising.'
- change_target stays `code` under the L0's tree-wide instruction; the deliverable
  is the how-to document.
```
