# Every check in the manifest reaches an identical verdict from either working copy

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-120b-4` — Every check in the manifest reaches an identical verdict from either working copy — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-120b-4`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `L`. Complexity: `high`.

## Acceptance Criteria

```gherkin
Given the full set of checks registered in the guardrail engine's hook manifest,
And one fixture of staged changes that provokes a genuine violation for each of those
  checks, so that a check which stops working is visible rather than trivially green,
When every check is executed against that fixture from the main checkout, and again from a
  separate working copy,
Then every check reports the same verdict from both,
And any check whose two verdicts differ is reported by name together with both verdicts,
And the comparison covers every check in the manifest — a check that the sweep did not
  exercise is reported as a gap rather than counted as agreeing,
And the sweep reports a failure when any check disagrees or any check is uncovered.

Coverage note: this criterion is the family-wide generalisation of GE-120b-1 and is
meaningful only when executed. It is covered by running the GE-120c-1 harness across the
manifest; a per-check unit test that imports from the source tree cannot distinguish the two
layouts and therefore cannot cover it.
```

- [ ] AC-1: one fixture of staged changes that provokes a genuine violation for each of those
- [ ] AC-2: every check reports the same verdict from both
- [ ] AC-3: any check whose two verdicts differ is reported by name together with both verdicts
- [ ] AC-4: the comparison covers every check in the manifest — a check that the sweep did not
- [ ] AC-5: the sweep reports a failure when any check disagrees or any check is uncovered.

## Implementation Notes

```yaml
- 'The expected set is templates/scripts/commit_guardian/commit_guardian.json -> hooks_manifest.hooks[],
  READ AT RUN TIME. 54 entries today: 48 tier=judgment, 6 tier=transform. Never a
  hand-maintained list and never a hard-coded count — a new check must enter the sweep
  by being registered, not by being remembered.'
- 'HANDLE BOTH INVOCATION SHAPES present in the manifest: the run_hook.py wrapper
  form used by most entries (''python <root>/scripts/commit_guardian/run_hook.py <root>/scripts/commit_guardian/<check>.py''),
  and the direct-script form used by precommit-canary. Handle the five checks that
  live under templates/scripts/commit_guardian/hooks/. A sweep that silently drops
  a hook because its entry shape is unfamiliar is the uncovered-check case this AC
  must REPORT, not skip.'
- 'THE FIXTURE IS THE HARD PART and is a criterion, not an implementation detail:
  it must provoke a genuine violation for EVERY manifest check. A clean fixture makes
  the sweep pass trivially — every check agrees because every check finds nothing,
  including one that has stopped running. SHARED WITH GE-120b-2-i: build it once,
  own it in one place.'
- 'Report per disagreeing check: the check id AND both verdicts. A boolean pass/fail
  is not actionable and cannot be triaged.'
- An uncovered check is a FAILURE of the sweep, not an omission from it. Consume GE-120c-3's
  manifest-to-harness coverage comparison as the completeness guarantee; do not reimplement
  it here — two independent completeness rules will disagree, and the sweep's own
  completeness is the property a silent-pass culture erodes first.
- 'The sweep executes the DEPLOYED checks OUT OF PROCESS through the GE-120c-1 harness.
  It must not import any check module: importing from the source tree reintroduces
  the blindness the harness exists to remove (ADR-001 — the deployed layout is what
  pre-commit runs).'
- 'ORDER-INDEPENDENCE: transform-tier hooks mutate files. Run each copy from an identical
  fixture state and do not let one check''s mutation change a later check''s input,
  or the two copies will disagree for reasons unrelated to layout and the sweep will
  report false positives.'
- 'RUNTIME BUDGET: one process per manifest check per copy is 108 subprocesses today.
  Build each working copy ONCE per sweep, not once per check, and mark the sweep slow
  rather than letting it quietly narrow its subject list to stay fast — a shrinking
  subject list is the exact decay GE-120c-1-i''s exercised-count clause exists to
  catch.'
```
