## Implementation Notes

```yaml
- The commit-ish every creation path hands to worktree creation must come from ONE
  shared resolution point. Three independent literals that happen to agree today is
  not parity -- a fourth creation path added later must inherit the behaviour rather
  than re-decide it. The observed defect is exactly a divergence between three sites.
- The change must land in BOTH templates/scripts/setup_ticket_worktree.py (canonical
  source) and its build output scripts/setup_ticket_worktree.py, and the two verified
  identical through the build.py round-trip (ADR-001). Editing one side only ships
  a fix the deployed script does not have.
- _create_worktree currently roots at local main HEAD under a documented branching
  policy (module DECISION HISTORY, 2026-05-12, 'Fixed silent stale-worktree bug').
  That policy is being reversed. The reversal and its reason must be recorded against
  that entry, or the next reader restores it as a fix.
- The shared tip must be resolvable from a local remote-tracking ref in a fixture
  repository, so the tests run with no network access.
- At most one additional remote read per creation request -- not one per path, and
  not one per git invocation.
- Failure to establish the shared tip must surface as a typed failure per the project
  error handling policy and must never degrade to a local starting point. The refusal
  behaviour itself is BO-4100a-3 and is not re-derived here.
```
