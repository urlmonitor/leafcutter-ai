## Acceptance Criteria

```gherkin
Given a rule asking the observation whether a proof reached the code under
  proof through the unit's way in,
When the rule asks the question without naming which code is under proof,
Then the observation answers that the question cannot be decided, and the rule
  reaches no verdict from it,
  And no criterion is refused on the strength of a question that named no code,
  And the answer to an unnamed question is never the same as the answer "the
    code under proof was not reached through the way in", so the two can never
    be confused for one another.

Given the same rule asking the same question, this time naming the code under
  proof — the code belonging to the unit the criterion's record names,
When a proof enters the way in for an unrelated action and then reaches that
  code by a separate route,
Then the answer is that the code was not reached through the way in,
  And the answer keeps "the way in was entered" and "the code under proof was
    reached through it" as two separate facts that a reader can tell apart,
  And a rule that reads only the first of those two facts cannot produce a
    refusal.
```

## Implementation Notes

```yaml
- 'THE REFUSAL TO ANSWER LIVES ON THE ANSWERING SIDE, NOT AT THE CALL SITE. The observation''s
  own entry point must reject an empty, whitespace-only or None subject and return
  reached_through ''undecidable'' with cause subject_not_named. Fixing only the caller
  is insufficient: today''s call site passes "" (scripts/ac_store/_done_proof_entry_point_gate.py
  line 202, _observe_reachability(test_file, test[''function''], "", entry_point)),
  and as long as an unnamed question can come back with a plausible negative, the
  next caller repeats the mistake and no test of that caller catches it.'
- 'THE SUBJECT IS DERIVED FROM THE RUN AGAINST THE DECLARED UNIT, NEVER LOOKED UP
  IN A STORE FIELD. No field anywhere in the store names a callable: surface_invoked
  holds 271 records across 368 occurrences and ZERO are of ''<module>:<callable>''
  shape (166 are free prose), and reference_file_path is schema-defined as a registration
  edit surface. The subject is therefore the SET of code belonging to the declared
  unit — every frame whose resolved co_filename equals the declared unit''s resolved
  source path — and ''reached through'' is true when any member of that set was entered
  while an entry-point frame of that same unit was a live ancestor.'
- NO NEW STORE FIELD, NO NEW AC-RECORD KEY, NO SCHEMA CHANGE IS PERMITTED BY THIS
  AC. Reaching for a field to hold a function name recreates the empty-question defect
  with more ceremony — asking the store for a name it does not hold is how target_spec=""
  arose in the first place.
- 'THREE DISTINGUISHABLE ANSWERS: ''reached'', ''not_reached'', ''undecidable''. ''undecidable''
  must not be representable as False, must not compare equal to ''not_reached'', and
  must not be the default value of the field. A consumer that ignores the distinction
  must be structurally unable to produce a refusal from it: the refusal path must
  test for the literal ''not_reached''.'
- 'entered_entry_point AND reached_through STAY TWO SEPARATELY READABLE FACTS, AND
  A CONSUMER READING ONLY THE FIRST MUST BE UNABLE TO REFUSE. That degeneration is
  the measured defect, not a hypothesis: with the subject empty, reached_through is
  structurally negative for every proof ever judged, so the rule fell back to the
  only fact left and now ACCEPTS a proof that calls main([''noop'']) then calls the
  code directly, while REFUSING an honest direct-import proof. Both verified by execution.'
- THE POSITIVE HALF IS PART OF THE CONTRACT. When the subject is named and a proof
  enters the way in for an unrelated action and then reaches the code by a separate
  route, the answer is 'not_reached' — a real, non-undecidable negative. Without this,
  'always answer undecidable' satisfies the AC and the rule is inert.
- THE ANSWER IS PER (nodeid, declared unit), NOT PER RUN. A run reaching several members
  of the declared unit's code set answers once for the unit; a run reaching code belonging
  to some other unit contributes nothing to this answer, however thoroughly it was
  exercised.
- 'INHERITED, NOT RESTATED: ancestry remains one fact about one live call chain (BO-2900a-2),
  and no code path may read the proof''s source text to decide any of this. This AC
  constrains only the well-formedness of the question and the arity of the answer.'
```
