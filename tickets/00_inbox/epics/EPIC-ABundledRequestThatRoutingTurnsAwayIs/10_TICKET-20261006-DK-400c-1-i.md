```gherkin

  words from the goal and none waiting for a later part,
```

## Implementation Notes

```yaml
- 'The offered parts are the first split.max_parts parts of the run order (dependency
  order, ties broken by proposed order: the same ordering function the scheduler uses
  in DK-400e-1), so the offered set is always dependency-closed. The others become
  not_covered entries in proposed order, each with its id, text and quote, reason
  ''beyond the five-part cap'' and no depends_on.'
- Offered parts are shown in proposed order. not_covered entries are read-only; the
  semantic check of leafcutter.split_answer.v1 (ADR-067 §4.4), which reads the offered
  part ids from the pending gate, refuses any review, edit or tick that names them.
- The gate wording (template text) tells the person that the request holds more than
  five parts and that the not-covered ones can be asked again as a request of their
  own.
- 'The run''s remaining part allowance (split.max_parts_per_run) caps the offer the
  same way; fewer than two parts left within the allowance means no split (the DK-400c-3
  path). Not-covered reasons (ADR-067 Open Question 2, settled by the IT PO): DK-400c-1-i
  is right that the per-run allowance cuts parts into not_covered; the mock v6 invariant
  is too narrow and goes to the mock-data author. Each split''s not_covered entries
  share one reason naming the limit that bound the offer: ''beyond the five-part cap''
  when split.max_parts bound it, ''beyond the run''s part allowance'' when the run''s
  remaining allowance (below split.max_parts) bound it. The gate wording names that
  limit and says the not-covered ones can be asked again as a request of their own.'
- split.max_parts is bounded to 2..5 by the config schema, so the product invariant
  of 2 to 5 parts cannot be configured away.
- 'Tests enable splitting explicitly: split.enabled true through a config override
  (false only where a test compares with the off switch). None relies on the shipped
  default, which stays false until E3 merges (dec-9925ebf1895222f4, see DK-400a-1).
  A test asserting that no split starts must run with splitting on, or it passes for
  the wrong reason.'
```
