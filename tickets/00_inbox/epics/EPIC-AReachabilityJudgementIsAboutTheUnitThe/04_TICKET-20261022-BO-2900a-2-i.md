# A proof that drives the way in as a separate program it launches is watched, not invisible

## Actor / Goal

## Acceptance Criteria

```gherkin
Given a unit that exposes a runtime way in,
  And three proof-of-done tests for the same criterion over that unit:
    test S, which reaches the code under proof only by launching the unit as a
      separate program and giving it the action under proof,
    test H, which both imports the unit and launches it, and reaches the code
      under proof through the program it launched,
    test B, which launches the unit as a separate program but gives it an
      action whose handler never reaches the code under proof, and which the
      launched program finishes successfully,
When each test is evaluated for whether the proof reached the code through the
  way in,
Then test S and test H are both judged to have reached it,
  And test B is judged not to have, even though the program it launched ran to
    a successful finish and was given the unit's own way in,
  And test S receives the same judgement as an otherwise identical proof that
    drove the same action without launching a separate program, so where the
    way in ran changes nothing about the answer,
  And a way in entered by a program launched by a program the proof launched is
    judged the same as one the proof launched itself,
  And each of the three judgements is attributable to the one test it is about,
    so no test inherits the reachability of a sibling in the same file,
  And the three judgements are produced in one exercise, so neither a
    judge-everything-reached nor a judge-nothing-reached mechanism can satisfy
    the set.
```

## Implementation Notes

```yaml
- 'HOST THE OBSERVATION IN THE PYTEST RUN THAT ALREADY HAPPENS. BO-2900a-2''s own
  constraint already requires this and it is restated only to bind the process-tree
  work to it: install the observation around the existing subprocess in scripts/ac_store/done_proof.py::_run_pytest_and_parse
  (line 1306), and add NO second pytest run and NO second bespoke runner per AC. The
  shipped code violated that constraint and this AC must not repeat it.'
- RETIRE _REACHABILITY_RUNNER_SCRIPT AND _observe_reachability AS THE OBSERVATION
  MECHANISM (scripts/ac_store/done_proof.py, lines 433-557 and 560 onward). It calls
  _test_func() with zero arguments (line 522), so every proof whose test function
  takes pytest fixture arguments — 47% of an in-scope sample, 129 of the 862 covers-tagged
  functions by shape census — cannot execute at all. A mechanism that cannot run a
  proof cannot judge it. Do not extend it to the process tree; replace it.
- MATCH FRAMES ON THE RESOLVED FILE PATH, NEVER ON THE NAME A RUNNING PROGRAM REPORTS
  FOR ITSELF. The current spec is f"{frame.f_globals.get('__name__')}:{frame.f_code.co_name}"
  (done_proof.py:479); a script launched as `python hook.py` reports __name__ == '__main__',
  so a name-keyed spec can never match a child. Compare Path(frame.f_code.co_filename).resolve()
  against the resolved declared unit path. Stem comparison is equally forbidden —
  .leafcutter/ and scripts/ hold same-stem copies of the same file and a stem cannot
  tell them apart.
- PROPAGATION MUST BE RE-ENTRANT. Whatever carries the observer into a launched program
  must detect that it is already installed in that interpreter and return without
  chaining. A naive sitecustomize chain recursed 245 times in the measured prototype.
  This is a named ship blocker, not a theoretical risk.
- PROPAGATION MUST SURVIVE A REPLACED ENVIRONMENT. A test that hands subprocess.run/Popen
  a bare env={...} drops whatever the observer travelled in, and the proof then reads
  as not reaching the code — a false negative that looks exactly like a correct one.
  Five proof files under unit_tests/ac_store/ pass a bare env today. The observation
  must merge its own variables into the environment a test supplies rather than relying
  on inheritance, and a child whose environment could not be reached at all is unwatched
  (BO-2900a-2-ii), never not-reached.
- 'ANCESTRY MUST SURVIVE THE PROCESS BOUNDARY AS ONE FACT, NOT TWO. reached_through
  stays a single property of one live call chain (inherited from BO-2900a-2, which
  forbids computing it as a conjunction of independent booleans). Across processes
  the chain is: an entry-point frame live in process P, and a code-under-proof frame
  entered in P or in any descendant created while that frame was still live. Each
  process record must carry its pid, its parent pid, and the entry-point frame that
  was live at spawn time, so the join is by ancestry and not by ''both things happened
  somewhere during the run''.'
- 'READING THE LAUNCHED ARGV OR THE CHILD''S EXIT CODE IS NOT AN ACCEPTABLE ANSWER,
  EVEN AS A FALLBACK. The measured prototype''s load-bearing negative is a child that
  was given the unit''s own way in, ran to a successful finish, and never reached
  the code under proof: argv-plus-zero-exit accepts it and it is a real defect. When
  frames from a child are unavailable the answer is unwatched, never reached.'
- PER-TEST ATTRIBUTION IS KEYED ON THE PYTEST NODEID. Under one pytest process the
  per-test boundary must come from pytest's own per-test hooks (pytest_runtest_protocol
  or the equivalent dynamic-context mechanism), and every process spawned during a
  test's protocol phase attributes to that test's nodeid. A run-level or file-level
  record makes every test in a file inherit the reachability of its most thorough
  sibling — the inherited per-test constraint is restated here only because a tree
  of programs makes it newly easy to lose.
- DECOY IMMUNITY IS INHERITED IN FULL AND MUST NOT BE RELAXED BY THE WIDENING. No
  code path in the observation may read, parse, tokenize, import-for-inspection or
  regex a proof file's source, in the runner process or in any child. Decoy immunity
  stays a property of the mechanism rather than a filter enumerating comment, docstring
  and dead-helper forms.
- OVERHEAD BUDGET. The observation must not more than double the wall-clock time of
  the per-AC done-proof pytest run it is hosted in, and must add no process spawn
  of its own per AC beyond the children the proofs themselves launch. done_proof already
  invokes pytest per AC inside a required CI gate.
- DEPLOY MANIFEST. Every new module (the observer and the interpreter-startup shim)
  must be added to build_ac_store's deploy_map in scripts/build_phases_ac_store.py
  in the SAME change, and must be verified importable from the DEPLOYED layout, not
  only from the source tree. The deployed check_done_proof hook imports done_proof,
  which will import the observer; a module absent from the manifest crashes the required
  CI done-proof job with ModuleNotFoundError and blocks every merge.
- THE RECORD SHAPE IS BO-2900a-2's AMENDED reach_record. This AC populates its processes
  list and its reached_code set; it does not define its own record type and must not
  emit a second, parallel record shape alongside the parent's.
```
