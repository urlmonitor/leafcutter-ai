# Declarations are counted on their own axis and never added into a coverage figure

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `GE-124g-3` — Declarations are counted on their own axis and never added into a coverage figure — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `GE-124g-3`. Component: `guardrail-engine`. Assigned agent: `python-coder`. Estimated complexity: `M`. Complexity: `medium`.

## Acceptance Criteria

```gherkin
Given a set of criteria in which 8 are declared on screen, 3 are covered by a
  test, and 2 are both
When any report counts them — the build output, the proof-of-done report, or
  the Atlas
Then the declared count and the covered count are shown as two separate
  figures
And no figure is shown whose value is the two added together or otherwise
  combined

Given a criterion that is declared on screen and has no covering test
When it is displayed anywhere coverage is shown
Then it is not shown in the same visual state as a criterion that has a
  covering test
And its state names what it has — declared — rather than a degree of coverage

Given a reader opens any of those reports
When they read the declared figure
Then the report states what a declaration means and what it does not: that
  something on screen claims the criterion, and that this is not evidence the
  criterion works

Given any attempt to configure a report to include declarations in its
  coverage figure
When the configuration is loaded
Then no such setting exists
```

## Implementation Notes

```yaml
- THREE CONSUMERS, ONE COUNTING FUNCTION. The build output, the proof-of-done report
  and the Atlas must all derive their figures from ONE shared two-axis counting function
  rather than each computing its own. A rule enforced in one report and not the others
  fails at whichever surface a given person happens to read, and the Atlas is the
  one most likely to be missed because it renders the store directly and does not
  go through the build output.
- 'CROSS-STACK BOUNDARY — FLAG FOR SPLIT IF THE COUNTING CANNOT BE SHARED. The Atlas
  is TypeScript/React (leafcutter-web/, vitest); the build output and proof-of-done
  report are Python. A single shared function is only possible if the Atlas consumes
  a machine-readable artifact the Python side emits. Prefer that: emit the two-axis
  counts as structured data and have the Atlas render them. If the Atlas must compute
  its own, this AC needs a split into a python-coder half and a frontend-coder half
  with a matching delivers_to/expects_from pair — raise it rather than letting one
  implementer silently own both stacks.'
- TWO AXES ARE TWO INDEPENDENT COUNTS PLUS THEIR OVERLAP, NEVER A SUM. Report declared,
  covered, and both-as-an-overlap; never declared+covered, never a single percentage
  combining them. The worked figures in the criteria (8 declared, 3 covered, 2 both)
  are chosen so any summing or double-counting bug is visible in the output.
- THE VISUAL-STATE CLAUSE IS AS LOAD-BEARING AS THE COUNTING CLAUSE. A report can
  keep two honest columns and still colour a declared-only criterion the same green
  as a covered one, at which point every reader draws the conclusion the summed figure
  would have given them — and the numbers are defensible in the review that follows,
  which makes it worse. The declared-only state must be visually distinct AND must
  be labelled by what it has ('declared'), not by a degree of coverage ('partial',
  '50%', 'amber').
- THE CAVEAT SITS NEXT TO THE NUMBER, not in a linked document. Each report states
  inline what a declaration means and what it does not. A caveat one click away is
  a caveat nobody reads, and this is the surface where the false confidence is actually
  formed.
- THE FIGURES MUST NOT COUNT WHAT WAS NOT EXAMINED. Criteria that GE-124e-4's diff
  scoping did not evaluate, criteria that GE-124e-1 recorded out-of-scope, and pages
  GE-124f-1-ii recorded outside-the-chain must each be absent from or separately labelled
  in these figures — never folded into either axis. A figure counting the unexamined
  as satisfied is the friendlier face of the same defect.
- NO CONFIGURATION KEY MAY FOLD DECLARATIONS INTO A COVERAGE FIGURE, and such a key
  must be refused by name if supplied (GE-124g-1-i).
```
