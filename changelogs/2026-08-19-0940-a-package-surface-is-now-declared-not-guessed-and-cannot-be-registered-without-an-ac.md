summary: "The schema rule that demands a structured implementation spec used to infer 'this AC registers a package surface' from the assigned agent and the component name. It now requires an explicit package_surface: true. A new commit-msg hook reconciles that declaration against the registry entries a change actually adds, so a surface cannot come into existence without an acceptance criterion that declared it."
description: "The old trigger fired on assigned_agent: python-coder plus component in {build_pipeline, build-orchestration}. That proxy was wrong in both directions. It OVER-matched: 243 of 3232 records were refused for lacking a five-field it_requirements object they had no honest way to supply, blocking whichever unrelated commit happened to touch one of them, and it had already been deferred twice with a documented HOOK-SKIP by authors who did not write the offending records. It also UNDER-matched, which was the half nobody had measured: components.json graph ids use underscores while index.yaml namespaces use kebab, and the enum took one of each (build_pipeline, build-orchestration). So 440 records spelled build-pipeline were invisible to it, and of 1610 python-coder records the rule fired on 411 while missing 239 — 215 of which would have failed and had never been checked once. The proxy was false even of the population it caught: of 245 records carrying the object form, 73 set config_schema_fragment: null, having written an explicit null to get past a rule that did not apply to them. The trigger now keys on an explicit package_surface: true and consults neither assigned_agent nor component, so the kebab/underscore split can no longer decide whether a record is governed. Refusals on this rule across the real store drop from 243 to zero, while the 37 records failing for unrelated reasons are unchanged file for file — that second assertion is the anti-loosening guard, since reaching zero by weakening validation generally would shrink it. The it_requirements oneOf object branch is deliberately untouched: it carries its own required-five-fields independently, so an object-form spec is still held to all five whether or not a surface is declared. Because a declaration is something an author types, narrowing the trigger alone would have moved the hole rather than closed it. The new hook check-package-surface-declaration closes it at the other end: a change that adds a NEW entry to a watched package registry (agent registry, skill registry, path registry, or the commit-guardian manifest) is refused unless at least one acceptance criterion it cites carries package_surface: true. Editing or removing an existing entry needs no declaration — the obligation attaches to bringing a surface into existence, not to maintaining one. A cited record carrying package_surface: false is reported as a contradiction rather than a missing field, and one declaring record among several cited is sufficient. Measured against the last eight weeks of history, this would have refused roughly one commit a fortnight; 27 of 33 registry additions already cited an AC. The hook proved itself on its first outing by refusing the very commit that registers it, then accepting it once ACS-100i-8 — the criterion that mandates the hook — declared the surface and supplied a real structured spec. Specified by ACS-100i-6, -6-i, -6-ii, -7, -7-i, -8 and -8-i; 61 tests, all driving real validators and real git repositories rather than asserting on source text. Closes KI-ACS-005."
