# A broken consumer install blocks the merge, it does not just report

## Actor / Goal

As the maintainer, I want a broken clean install to stop a pull request from
merging, so that the install stays working without anyone having to remember to
check it.

## Context

This ticket was generated from AC store entry `BP-900h-3`. Component:
`build_pipeline`. Assigned agent: `python-coder`. Estimated complexity: `S`.

Added to this epic on 2026-08-17. Split from ticket 12 deliberately: a job that
runs and reports is not a gate. This repository has shipped that exact mistake
before — the fast-lane runner's red/green gates were found never to execute,
which is why CLAUDE.md carries the rule "Gate / Workflow ACs — Verify
Behaviorally, Not by Grep".

Depends on tickets 12 and 13, logically and physically (all three edit
`.github/workflows/ci.yml`).

## Acceptance Criteria

```gherkin
Given the consumer-simulation job from BP-900h-1 and BP-900h-2 exists,
When a pull request introduces a change that breaks the clean install
  (for example a script referenced by a template but not added to any deploy phase),
Then the consumer-simulation job reports a failing conclusion for that pull request
And the job carries no continue-on-error and no conditional that would let it pass on failure
And the job is registered among the repository's required status checks,
  so the pull request cannot merge while it is red
```

## Implementation Notes

- The job must not set `continue-on-error`, and must not be guarded by a
  condition that skips it on `pull_request` events.
- **Manual step, not automatable from this ticket:** registering the check as
  required is a repository ruleset change (ruleset `require-ci-lint`, id
  `17810993`) and needs an `admin:write` token. Surface this to the user as a
  handoff rather than silently signing the AC off as done.
- **Ordering:** make the job green on `main` FIRST, then add it to the
  required-checks ruleset. Marking a job required while it is red on `main`
  blocks every merge in the repository.

## Test Requirements

- `test_consumer_simulation_job_is_not_soft_failing` — parse `ci.yml` and assert
  the consumer-simulation job declares no `continue-on-error: true` and no `if:`
  that excludes `pull_request`.
- `test_consumer_simulation_job_fails_on_broken_install` — behavioral: run the
  job's underlying check against a deliberately broken install fixture and assert
  a non-zero exit. Definition-only assertions pass on a job that never executes.

Target dir: `unit_tests/portability/`.
