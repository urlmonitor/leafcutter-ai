```yaml
- 'Pin store (new private module scripts/build_orchestration/_wvp_store.py). It owns
  reading, writing and clearing pins and the alteration identity. One location rule,
  in one function (pin_path): <git-dir>/leafcutter/pins/<work-key>.json, git-dir from
  the same git rev-parse --absolute-git-dir the writer already uses (_wvw_write.run_write).
  Pins are kept OUTSIDE <git-dir>/leafcutter/work/<work-key>/, so no step that cleans
  or moves that folder (_wvw_write._clean today, the move into history of TQ-500g-1-xv)
  can reach them. Shape, fixed key order: {work_key: str, pins: {<pin key>: {name:
  str (the spelling when pinned), replacements: [{path: str, old: str, new: str}],
  alteration_id: str, failed_check: null | {check: str, files_sha256: str}, reset:
  bool, cleared_alteration_id: str | null}}}. The pin key is _wvr_scope.norm_name(name)
  (trim and case-fold, the alias rule''s normalisation); never a second normaliser.
  Written atomically (temporary file in the same folder, then os.replace); a crash
  never leaves a partial pin file. Deterministic: same pins give a byte-identical
  file. USER DECISION (BrainCandy, 2026-10-24): this location is decided, not a default.
  Pins are private to the workspace, never committed, and lost when the workspace
  is removed; the next run then prepares and pins again. It is NOT a durable location.
  The decision is revisitable; changing it changes only _wvp_store.pin_path and nothing
  else.'
- 'Alteration identity (one function in _wvp_store, alteration_id, reused by TQ-500g-1-xv,
  -xvi and -xvii): "sha256:" plus the first 16 hex characters of the SHA-256 of the
  canonical JSON of the ordered replacement list [{path, old, new}] (sort_keys true,
  separators "," and ":", UTF-8, no ASCII escaping). Computed from the replacements
  alone, never from an altered copy or a diff, so a change elsewhere in the file leaves
  the identity unchanged.'
- 'Plan (new private module scripts/build_orchestration/_wvp_plan.py). For each owed
  name of the shared reading (_wvw_list.derive_owed, unchanged as the one source of
  owed names and files) it decides exactly one of: use the pin, use a declaration
  (TQ-500g-1-xvii), or prepare. Under this AC a name is prepared when the work holds
  no usable pin for its key; TQ-500g-1-xii and -xiii add the other triggers inside
  this same module. "The fix undone" and its aliases are never planned, never pinned
  and never read from the pin store: they stay prepared from git by the runner on
  every run.'
- 'List step (wrong_version_writer.py list, logic in _wvw_list.list_payload and _wvp_plan).
  It gains an optional --work-key <key>. Without it the output is today''s plus to_prepare
  equal to owed and decisions [] (back-compatible for every caller, including the
  TQ-500g-1-v list-speed test). With it, stdout is exactly one JSON object, fixed
  key order: {owed: [...unchanged...], to_prepare: [the owed items that need preparation,
  each item byte-identical to its owed item (name, files, scope and any additive keys),
  in owed order], decisions: [{name: str, source: str, reason: str|null, alteration_id:
  str|null}], error: str|null}, one decision per owed name in owed order. On error
  owed, to_prepare and decisions are all [] and the exit is 1, as today. With --work-key
  the list writes exactly one file, the plan record <git-dir>/leafcutter/work/<work-key>/plan.json
  (atomic write), and nothing in the working tree; without --work-key it writes nothing
  anywhere.'
- 'Plan record and the write step. plan.json holds {work_key, fingerprint, decisions:
  [{name, source, reason, alteration_id, replacements: [{path, old, new}] | null}]}.
  fingerprint is a SHA-256 over the owed list JSON, the pin file''s bytes (or "" when
  absent) and the bytes of every file a planned replacement names. The write step
  (_wvw_write) reads the plan only when its fingerprint matches the current state;
  otherwise it recomputes the plan in-process with the same _wvp_plan function. It
  never takes the plan, the to_prepare list or any scope from the route or from the
  reply. Names whose decision is "pinned" are rebuilt by applying the pinned replacements
  to the files AS THEY NOW STAND through _wvw_prepare.alter (same path refusals, same
  exactly-once rule, same CRLF rule), never by reusing or copying an earlier altered
  copy. Names whose decision is prepare are taken from the reply as today (TQ-500g-1-ix
  name matching, all or nothing per name); a pinned or declared name the reply also
  answers is listed in ignored_reply_names and the answer is never used.'
- 'Manifest entries gain three additive keys, so every later step reads the replacements
  and not only the copies: replacements ([{path, old, new}] actually applied; [] when
  could_not_prepare), alteration_id (null when could_not_prepare) and source (the
  row wording of TQ-500g-1-xii, -xiii, -xv and -xvii; under this AC "pinned" or "prepared:
  not pinned"). name, status, reason, files and diff keep their TQ-500g-1-ix meaning;
  the runner still applies files[].altered_copy.'
- 'Pin step (new third step of wrong_version_writer.py, logic in _wvp_store): wrong_version_writer.py
```
