# On git older than 2.36 (no fetch --refetch), recovery falls back or refuses rather than running an unsupported command

## Actor / Goal

As the leafcutter-ai system, I want to implement AC `BO-1600d-3-i` — On git older than 2.36 (no fetch --refetch), recovery falls back or refuses rather than running an unsupported command — so that the acceptance criterion is satisfied.

## Context

This ticket was generated from AC store entry `BO-1600d-3-i`. Component: `build-orchestration`. Assigned agent: `python-coder`. Estimated complexity: `S`.

## Acceptance Criteria

```gherkin
Given the installed git version is older than 2.36 and therefore does not support
  "git fetch --refetch"
When the recovery step engine reaches the re-fetch-from-origin action
Then it detects the git version before invoking the refetch and does NOT run the
  unsupported --refetch flag
And it either uses a supported equivalent to restore the removed objects from origin
  (a plain fetch of the needed objects) or, if no supported equivalent can restore
  them, it stops and reports that the installed git version is too old for automatic
  re-fetch and names the minimum version required
And in the refuse case it makes no partial change that leaves the store worse than
  the halted state (the removed-objects step is not applied unless the refetch path
  is viable)
```
